# Benchmark 汇报视觉重构 · 三方向共同设计任务书

## 项目与目标

项目是 Gold Band 的管理层 Benchmark 阶段性汇报，已有可工作的九页 HTML，叙事和实验数据已经核对。用户这次要求用 huashu-design 重构视觉，不要求重新研究实验、不要求另写一套结论。第一阶段必须让用户实际看到三种有结构差异的方向，再决定完整九页如何深化。每个方向只做两页代表页，内容相同，设计方法不同；本任务书和 brand-spec.md 是共同输入，各方向不得观看其他方向产出。

## 受众与场景

听众是了解 AI 架构、不了解实现底层的管理者。场景是会议室投屏，观众可能在五至十米之外，不能把整页做成小字号网页。他们应在三至五秒内读出核心判断，然后由汇报人补充。气质应专业、自信、具体，既不是投资广告，也不是流水账技术复盘。避免为了显得严谨把每页塞满免责声明；阶段属性、单位和核心限制简明出现，其余证据沿用原报告。

## 输出格式与尺寸（所有方向完全一致）

- 每方向两份独立 HTML，画布严格 **1920×1080**，16:9。
- 文件位置：你的独占目录 `design-demos/<direction>/01-intent.html` 与 `02-results.html`。
- 每个 HTML 的 body 固定 1920×1080，margin 0、box-sizing border-box。父级概览墙负责整体 JS 缩放、letterbox、翻页、统一页码，不要在单页内写另一套导航或页码。
- 独立 HTML 包含自己的页面 CSS，不依赖另一个方向；允许引用 `../assets/fonts.css` 和共同本地字体。三枚 logo 建议用 `<img>` 的 data URI；多文件离线资产路径也允许，必须保持原色。
- 原始字号：正文至少 28px，标签 / 数据注释至少 20px；标题 84–124px；大数字 180–280px。极少辅助注记可 18px，但不能把关键限制藏成蚂蚁字。
- 不使用外部 CDN，不引入 React 或绘图库。原生 CSS Grid/Flex、真实 logo、简洁语义流程图足够。
- 不做长图或网页滚动，不用多张卡片拼出 app dashboard。两页各自拥有一个明确视觉重心。
- 父级使用 huashu-design 的 `assets/deck_index.html`，由主 agent 统一复制，不需要你重写概览墙。

## 第 1 页：测试意图

必须表达的同一组内容：

- 页面主张 / 问句：**「什么时候值得让多个 Agent 协作？」** 可换行，不可改成已经证明所有场景有收益的结论。
- 副文案核心：我们测的是从单体执行到工作流与 AUTO，质量收益能否覆盖额外的 token 和时间。
- 三项判断：
  1. 质量：是否通过独立测试与整体验收。
  2. 成本：token 与端到端耗时。
  3. 适用边界：从局部问题到长程工程。
- 对照身份：Claude Code 与 Gold Band（工作流 / AUTO）。两方真实 logo 要出现，不能只做假圆环。
- 必须有简短阶段标记：**「阶段性结果 · 2026.10.13」**。
- 执行框架对照，不是模型能力排名。可以用一句短注说明，不必罗列底层模型。
- 不要额外加 slogan、市场规模、效率倍数或「未来趋势」凑版面。

## 第 2 页：重量级已完成案例

必须表达的同一组内容：

- 标识：**SWE-Marathon / Kubernetes**，出现真实 Kubernetes logo，任务是 Rust 重写 Kubernetes。
- 核心判断：**「长任务中，完整验收开始体现编排价值」**。可缩短为「长任务，先看能否完整交付」，不改变含义。
- 两方数据必须完整，允许使用数字排印、表格或事实对照，但不制造假的时间轴 / 趋势曲线：
  - Claude Code：**1,405 / 1,407** 项通过，**约 325.8M token**，**97 分钟**。
  - Gold Band AUTO：**1,407 / 1,407** 项通过，**约 173M token**，**165 分钟**。
- 关键结果：AUTO 记录 token **约少 47%**，完整通过；**耗时仍更长**。后半句不能删掉或隐藏。
- 必须简洁注明：这是加入整体验收规则后的单次同题复测，token 不是账单金额。无需把全部实验局限堆在这张页上。
- 47% 来自 (325.84−173)/325.84，不能改成质量提升 47% 或费用节省 47%。
- 不必三版都把 47 做最大，可以选择完整通过的 1,407、执行链或全表为主角，但全部关键事实必须读得到。

## 共同品牌约束

先读本目录的 `brand-spec.md`。优先继承 Gold Band 真实交织带 logo、Inter/MiSans 字体和官网配色。浅色版本可反转官网的前景 / 背景色，并采用真实 logo 蓝色。色彩承担结构而不是噪音；不要三色反复涂在数字上。不要加无用图标、假摄影、重绘产品。此任务图片非内容必需，只有真实身份 logo 必需。

## 五问的共同答案

1. 叙事角色：意图页提出选择问题；数据页用一组已完成对照支撑价值边界。
2. 观众距离：以会议投影为主，兼顾笔记本预览；内容按画布整体缩放。
3. 视觉温度：可信、清楚、有力度，避免科幻炫技与营销亢奋。
4. 容量：意图页一个标题、三项判断、两个对照身份；数据页两个执行者、三项指标、一个判断。无需写满页面。
5. 视觉母题：**分工之后还要收敛到完整验收**。可从分岔与汇合、对照账页、最后两项缺口、任务交付边界等内容结构推导，不能凭空画网络节点装饰。

## 验证与收尾

完成后自查字体、颜色、logo、数值与画布边界；可以用自己的命名浏览器会话验证，不干扰其他会话。最终回复主 agent：两个文件路径、方向名、主视觉推导的一句话、预期需核查的点。不要继续完整九页，也不要替用户选择。

过度设计评审：只制作有界的六张静态样稿，共用本地资产，复用既有概览组件，不新增产品抽象。性能评审：无日志扫描、无后台轮询、无数据请求；本地字体共享缓存，概览最多六个真实 slide iframe，图库使用预生成截图而非大量重复 iframe。
