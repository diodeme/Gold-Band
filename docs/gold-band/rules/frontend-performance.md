# 前端性能规则

本文件是 Gold Band 前端状态边界、渲染范围、流式更新、Markdown 和 DOM 热路径性能约束的详细规则真源。跨前后端的数据加载、渐进加载、分页、刷新和 I/O 关键路径统一遵守 `data-loading.md`，本文件只补充前端消费约束。

## 1. 优化顺序

- 优化前先确认瓶颈、数据规模和可验收目标，不凭感觉增加复杂度。
- 优先级依次为：数据加载量与算法、刷新范围、状态与渲染边界、主线程工作量、分配与微优化。
- 优先修复根本设计缺陷，不使用零散 `React.memo`、`useMemo`、debounce 或缓存掩盖过大的状态域和接口。
- 开发模式下的主观流畅度不能替代生产构建、Profiler、性能时间线和内存证据。

## 2. 状态位于最小消费边界

- 输入框、表单草稿、筛选条件、展开状态等高频状态保存在真正消费它的最小组件中。
- 禁止把每次键盘输入提升到页面根组件、应用壳或大型 Context。
- 父组件只需要执行清空、提交、重置等低频命令时，使用稳定 callback 或 imperative handle，不订阅完整草稿。
- 表单抽屉必须拥有独立表单状态；输入一个字符不能重渲染背后的卡片列表、筛选栏、Tooltip 树或页面壳。
- Composer 输入更新不能重渲染历史消息、Markdown、右侧工作区或会话导航。
- 交互逻辑优先放在事件链中；不得用额外 effect 在大范围状态间来回同步。

典型验收：

- 输入一个字符时，只有输入组件及必要的校验、字数和尺寸逻辑更新。
- 已完成历史 Markdown 的 render 次数保持不变。
- textarea 高度每次输入最多测量一次。

## 3. 按更新频率拆分 Context

- 高频展示状态和低频命令接口不得放在同一个 Context value 中。
- Tabs、宽度、激活项等展示状态变化时，只消费 `openResource` 等命令的组件不应重渲染。
- Context 应按领域和更新频率拆分，例如 `WorkspaceStateContext` 与 `WorkspaceCommandsContext`。
- Context value 中的 callback 必须保持稳定，并通过 ref 读取最新状态。
- 禁止把不断变化的大对象作为 Context value 传给整棵页面树。
- 组件只订阅渲染所需的最小派生值；只在回调中使用的数据不得形成宽泛订阅。
- 第三方组件把 render prop、renderer 或 `children` 作为 React `ElementType` 使用时，必须传入模块级或其他稳定 identity 的组件，禁止在 render 中内联创建组件类型。
- 菜单、焦点、编辑器、拖拽和展开状态必须归属于稳定 DOM/组件生命周期；无关流式事件和父级重渲染不得通过卸载重挂清空这些交互状态。
- 修复此类 identity 问题时，回归测试必须触发无关父级更新，并断言目标 DOM identity 与已打开的交互浮层保持不变；真实删除、重命名或作用域切换导致的预期卸载除外。

## 4. 昂贵计算只依赖语义字段

- 工作流布局、树结构、索引和其他昂贵投影不得依赖整个业务对象。
- 为昂贵计算建立语义签名，只包含真正影响结果的字段。
- Inspector 中的目标文本、模型、权限等字段不影响画布拓扑时，不能重新计算整张工作流图。
- 运行状态、计时等字段不影响节点位置时，不能重新执行图布局。
- 不使用 `JSON.stringify(完整对象)` 作为昂贵计算的通用依赖。
- 重复查找和扫描热点集合时，先建立 Map、Set 或稳定索引，禁止在每次事件中反复扫描完整 timeline。

## 5. 前端渐进加载投影

- 通用数据重量、加载顺序、分页、刷新、I/O 和验收要求以 `data-loading.md` 为唯一真源。
- React 状态必须显式区分 `not-loaded / loading / ready-empty / error`；页面首次挂载或 workspace 尚未返回时，不得渲染误导性的空列表文案。
- 页面首次挂载只订阅当前可见领域和首批摘要；非激活 Tab 不挂载重型 DOM，也不请求正文或详情。
- App shell、Context、右侧 Tab 和轻量 UI preference 只保存摘要、稳定 locator、有限分页窗口和必要滚动恢复信息，不保存完整正文、Raw frames、system prompt 或完整工作流。
- Activity 折叠时不得构造或解析工具详情；Raw frame 未展开时不得 pretty-print；大字段只在打开、展开或进入对应资源后读取。
- 已有数据的后台刷新必须保留当前 DOM、选择、展开和滚动状态；分页合并与 LRU 裁剪必须保持稳定 DOM 锚点，并原子释放关联重数据。
- 页面隐藏、窗口失焦或最小化时，纯展示刷新应暂停或降频；非当前领域的结果不得引起页面壳和历史内容重渲染。

## 6. 流式数据合并且只保留最新值

- text、thought、tool 等累计快照按稳定 identity 使用 latest-wins buffer。
- 同一个 identity 只保留最新累计值，不排队保存所有中间大字符串。
- 高频事件按动画帧或短时间窗口合并发布；权限、错误、工具终态和 session 终态等关键事件可以立即发布。
- 每个流式组件最多存在一个可取消的 RAF 或定时任务。
- 用户滚动、拖拽或输入期间，非关键流式更新应延后，避免与交互争抢主线程。
- 流式发布缓冲必须有容量和背压边界；慢消费者不能让内存持续增长。

## 7. 长 Markdown 增量解析

- 流式 Markdown 的 block 边界、未闭合语法和补全语义必须由选定的 renderer/parser 统一解释；业务层不得使用正则、自制状态机或字符串启发式判断代码围栏、链接、HTML、表格等结构是否闭合。
- 性能优化必须复用 renderer/parser 的正式增量接口，并保留单一文档级解析上下文；不得通过拆分多个 renderer 实例破坏脚注、引用、列表等跨 block 语义。
- 追加式 Markdown 更新不能每帧重新解析整条累计消息。
- 已完成段落、列表和代码块保持稳定，跳过解析和 DOM reconciliation。
- 正常追加只重新解析最后一个可变尾块。
- 只有内容发生非追加改写时，才允许回退到一次全量解析。
- 已完成消息使用稳定 props 和 memo 边界；右侧 Tab、宽度和文件切换不能触发历史 Markdown 重渲染。
- 历史快照直接静态展示，不能因为重新进入页面而重播打字机动画。
- 流结束时必须在有限时间内收敛到最终文本，不能让积压动画长期占用主线程。
- 回归测试必须覆盖未闭合结构随后闭合、跨 block 文档语义、流结束立即收敛，以及前后消息或会话之间不复用临时解析状态。

## 8. Resize、Scroll、Pointer 等热路径

- 连续窗口缩放、拖拽和滚动属于 DOM 热路径。
- 几何尺寸优先交给成熟布局组件、CSS 和浏览器处理。
- ResizeObserver、scroll、pointermove 等高频事件最多每动画帧处理一次。
- 连续像素值优先写入 ref 或 CSS variable。
- React state 只发布单栏/双栏、左栏显示/隐藏等离散状态变化。
- 禁止把窗口每变化一个像素都写入页面根 state，导致 Markdown、编辑器和目录树共同重渲染。
- 尺寸偏好只在用户完成拖拽后持久化，不在每个 resize frame 写存储。
- scroll handler 必须保持稳定；能使用 passive listener 时使用 passive，并避免同步读写布局造成强制 reflow。

## 9. 性能验收与回归

性能修改不能只靠“感觉变快”，必须根据风险增加可回归的接口测试：

- 输入一个字符不会重渲染历史 Markdown。
- 打开和切换多个右侧文件不会重渲染历史会话。
- Inspector 文本变化不会重新计算工作流布局。
- 非当前 Tab 不发起领域数据请求。
- 尚未加载的数据不会显示为空结果，基础列表可以先于详情和正文呈现。
- 工具详情只在展开后请求，并且快速重复展开只产生一个请求。
- 流式缓冲每个 identity 只保留一个最新快照。
- 分页窗口、LRU 和事件缓存不超过约定上限。
- 页面隐藏时刷新降频或暂停。
- Resize 热路径在同一离散布局区间内不提交 React state。

必要时使用 React Profiler、浏览器 Performance、heap snapshot 和 memlab 记录 baseline、target 与 final；不得用主观判断替代测量。
