# UI 交互与响应式设计规则

本文件是 Gold Band 前端 UI 载体选择、状态生命周期、响应式布局和交互验收的详细规则真源。

## 1. 交互载体选择

选择交互载体时，先判断任务的复杂度、生命周期和上下文依赖，不得只因为实现方便而使用弹窗。

| 交互载体 | 适用场景 | 不适用场景 |
| --- | --- | --- |
| Dialog 弹窗 | 删除确认、风险提示、单次选择、少量字段的短流程；需要阻塞当前操作 | 复杂表单、连续编辑多个条目、需要查看背景信息、长时间停留的任务 |
| Sheet 抽屉 | 当前页面内的创建、查看、编辑；完成后需要返回原列表或继续处理其他条目 | 独立复杂工作、需要多任务切换、需要长期保留编辑状态 |
| 右侧工作区 Tab | 独立且复杂的工作对象；包含多个区域、长内容、预览或持续编辑；需要切换出去再回来 | 简单确认、一次性输入、与当前列表强绑定的轻量编辑 |
| 独立页面 | 产品一级模块、完整管理中心或需要独占主区域的流程 | 单条记录的临时查看和修改 |

决策顺序：

1. 是否只是一次简短且需要阻塞的决策？是则使用 Dialog。
2. 是否依赖当前页面上下文，完成后需要返回原位置？是则使用 Sheet。
3. 是否是可独立存在、需要长时间处理或切换保留的工作对象？是则使用右侧工作区 Tab。
4. 是否属于产品一级功能模块？是则使用独立页面。

禁止把复杂编辑、连续处理或多步骤流程塞进弹窗。

## 2. 抽屉工作流

- 同一业务流程中的设置、结果、查看和编辑必须由一个状态机统一管理。
- 任意时刻只允许一个活动 Sheet，不得叠加多个抽屉或焦点陷阱。
- 多层流程在同一工作流内切换，例如：`导入设置 → 导入结果 → 编辑条目 → 返回原导入结果`。
- 进入下一层前必须保留上一层的数据和滚动上下文。
- 保存、返回或关闭编辑层后恢复上一层，不得关闭整个流程。
- 只有用户主动关闭顶层流程时，才清理该流程的临时数据。
- 抽屉优先使用 shadcn/ui Sheet，不自行实现基础抽屉组件。

## 3. 右侧工作区 Tab

满足以下任一条件时，优先使用右侧工作区 Tab：

- 内容复杂，存在多个分区、预览、日志或辅助面板。
- 用户可能在多个对象间切换并继续工作。
- 编辑状态需要在离开后保留。
- 操作时间较长，不适合阻塞当前页面。
- 对象本身具有独立生命周期，例如任务详情、复杂配置、文档或执行结果。

打开 Tab 时必须同步更新路由、业务模式和导航选中态，不能只切换内容区域。

## 4. 状态与数据同步

- 生命周期相关的数据必须统一管理，不能分别散落在多个布尔状态中。
- 页面位置、业务模式、侧边栏选中态和工作区 Tab 应作为一次完整导航事务同步更新。
- 编辑保存后以后端返回的最新实体为准更新界面，不能假设表单输入就是最终结果。
- 列表、导入结果和编辑实体之间必须通过稳定 ID 关联。
- 禁止使用旧名称、数组位置或显示文本匹配实体。
- 局部更新时必须保留源路径、错误信息、兜底标记等不属于编辑实体的数据。
- 交互状态更新优先放在用户事件链中，不通过额外 `useEffect` 修补同步问题。

## 5. 尺寸自适应

组件尺寸必须根据实际可用空间调整，禁止只针对截图尺寸写固定宽度。

### 5.1 抽屉

- 可调整宽度的抽屉必须定义 `minSize`、`defaultSize` 和 `maxSize`。
- 最大宽度不能超过当前窗口安全范围。
- 用户主动调整后的宽度按稳定的 `resizeStorageKey` 记忆。
- 标题区和底部操作区固定，中间内容区作为唯一滚动区域。
- Flex/Grid 滚动容器必须正确设置 `min-h-0`、`min-w-0` 和必要的 `overflow-hidden`。

### 5.2 列表和表格

- 文本列使用 `minmax(0, 1fr)` 消化剩余空间。
- 操作列根据内容保持 `auto`，不能挤压主要内容。
- 窄宽度下操作按钮允许换行到下一行。
- 名称和普通文本使用安全断行；Windows 路径、ID 等连续字符串使用 `break-all`。
- 单条超长内容不能撑大抽屉、表格或页面，也不能制造横向滚动。
- 列宽根据容器宽度分配，不得只根据页面初始宽度计算一次。

### 5.3 响应式判断

- 优先根据组件实际容器宽度响应，必要时使用 `ResizeObserver`。
- Tailwind 断点只用于粗粒度布局切换，不得代替容器尺寸计算。
- 自动收起侧边栏时，必须区分用户期望的打开状态 `intent` 与当前空间允许的显示状态 `effective`。
- 因窗口变窄自动收起时，不得覆盖用户原本的打开意图。
- 窗口重新变宽后按确定优先级恢复布局：先恢复右侧工作区，再恢复左侧边栏。

## 6. 选择器与滚动组件

- 产品 UI 的选择控件必须复用项目已有的 shadcn/ui、prompt-kit 或共享封装；禁止直接使用原生 `<select>`，也不得自行实现已有基础控件的等价版本。
- 仅在共享组件无法提供所需平台能力或无障碍能力时允许例外；必须在同一改动中记录理由、保留键盘/焦点/读屏能力，并为全局契约测试增加范围最小且可审计的例外。
- 日期、时间、时区等选择器优先使用 shadcn/ui、Radix 或成熟组合组件。
- 选择器不能只支持滚轮或点击，必须保留键盘操作和直接输入能力。
- 选中态统一使用主题 `accent`，不得硬编码亮色、黑色或独立品牌色。
- 列表行高度和间距必须连续，不能出现 `00/01` 等视觉断层。
- 滚动期间不得因重新排序、动态 key、重复定位或受控值回写导致列表回跳。
- 不要为短列表引入不稳定的虚拟滚动；确需虚拟化时必须固定行高和滚动锚点。

## 7. 用户偏好记忆

只记忆跨会话仍有意义的用户偏好，不记忆临时业务输入。

应该记忆：

- 用户主动选择的时区。
- 抽屉宽度、侧边栏宽度等用户主动调整的布局。
- 明确属于用户偏好的模式或展示设置。

不应自动记忆：

- 当前表单的临时字段。
- 加载、错误、选中条目等瞬时状态。
- 仅属于单次创建流程的日期、时间和业务参数。

时区首次使用时默认读取用户电脑本地时区；用户修改后持久化，后续默认使用上一次选择。持久化数据必须有明确 schema、默认值和版本策略，禁止散落硬编码的 localStorage key。

## 8. 按钮与选中态

- 主按钮是否可用必须由当前输入是否满足提交条件决定。
- 没有有效输入时，“发送”和“创建定时任务”等提交动作统一使用禁用态。
- 禁止一个无效提交按钮保持高亮，而同类按钮显示禁用。
- 发送模式切换优先使用组合按钮：主操作区与箭头区使用相同背景；箭头区域保持紧凑；中间不使用突兀分割线；箭头只负责展开模式菜单；当前模式可以切换回其他模式。
- 导航选中态、文本选中态和选择器选中态统一使用主题 token，不写死具体颜色。

## 9. 图标语义与主题适配

- 选择图标颜色前必须先判断语义，不得把 `primary` 当作通用图标色：
  - 页面、功能、来源、区块等静态标识使用 `foreground`；弱化辅助标识可以使用 `muted-foreground`。
  - 运行中、成功、警告、失败、选中等状态标识使用对应语义 token，并与文案、背景和交互状态保持一致。
  - 品牌图标优先保留品牌色；单色图片或自定义 SVG 必须明确提供明暗主题适配策略，不能依赖偶然的背景对比。
- 静态图标需要弱底色时，底色与前景必须来自同一主题语义，例如 `bg-foreground/10 + text-foreground`；不得使用浅色模式看似正常、深色模式接近背景的硬编码颜色或强调色组合。
- 同一业务语义跨页面出现时必须共享颜色规则。例如定时任务标识在管理列表、会话侧栏、会话标题、配置面板和详情页中应保持一致，不能逐页自行决定颜色。
- 不得机械全局替换颜色类。修改前应审计每个命中的语义，保留链接、按钮、选中态、加载态和结果状态的必要强调色。
- 图标的视觉说明统一使用项目 Tooltip 组件；`aria-label` 负责无障碍名称，不替代视觉提示；不得使用浏览器原生 `title` 作为产品 Tooltip。

## 10. 异步操作中间态

- 预计或实测可能超过 300ms 的网络请求、外部命令、文件系统扫描、复杂渲染和写操作，必须在用户触发后 100ms 内显示可见中间态，不能让原界面保持无反馈后突然跳转。
- 列表进入详情时先提交选中 locator 并切换到详情 loading/skeleton；独立工作区 Tab 导航先激活目标 Tab，再由目标内容区加载数据。不得把慢请求作为导航事务的前置条件。
- 中间态应出现在结果最终呈现的位置，并说明正在加载的业务对象；不得用与当前操作无关的全局 loading 文案。
- 操作进行中必须根据语义禁用、合并或幂等处理重复触发；写操作显示目标级 spinner，并禁止会冲突的其他写入口。
- 已有可展示缓存时保留现有内容并做局部刷新，不退回全屏 loading。失败后在当前处理位置显示结构化原因、恢复动作或返回入口。
- 对中间态增加接口或 DOM 回归测试，至少固定“触发后立即可见、完成后收敛、失败后可恢复、重复触发不产生并发副作用”。

## 11. 验证与回归

涉及 UI、布局或交互修改时，至少完成：

1. 为状态机、数据同步或接口映射增加单元测试。
2. 为关键布局结构增加契约测试，固定滚动区、列宽和操作区规则。
3. 执行前端类型检查和生产构建。
4. 使用内置浏览器 deep link 到目标页面验证实际交互。
5. 分别验证正常宽度、窄窗口、重新拉宽和长文本场景。
6. 验证结束后关闭测试页面并清理本次启动的进程。
7. 同步维护产品设计文档与开发计划。

涉及图标、颜色或主题 token 时，还必须在浅色与深色主题下分别检查静态态、hover、选中和禁用状态；不能只以单张截图或单一主题验收。

禁止只验证某一张截图对应的固定尺寸。

## 12. 主题样式级联

- 主题 recipe 生成的展示声明必须位于 CSS `components` layer，作为主题 role 的组件默认值；不得使用未分层的高优先级选择器或 `!important` 越过组件显式 utility/variant。无障碍 `prefers-reduced-motion` 规则可以强制关闭动效。
- 组件覆盖只用于真实变体、交互状态和组件拓扑，例如 focus ring、单边 separator、joined control、透明 variant，以及显式声明的阴影、圆角和动效；禁止在组件中按 `themeId` 特判视觉样式。
- 迁移现有主题时，必须由各主题 recipe 明确声明需要保持的边框、圆角、阴影、颜色、材质、状态和动效，不得把旧主题外观硬编码回共享组件。
- Dialog、Sheet、AlertDialog 必须 Portal 到 `body` 的专用 overlay host；host 不得包含非 `none` 的 `transform`、`filter`、`backdrop-filter`、`contain`，也不得使用会裁剪后代的 `overflow`。
- Dropdown Menu、Context Menu 的 Radix Content/SubContent 定位节点只负责定位、焦点和外部交互事件；位移、缩放、淡入淡出、材质、圆角和内容裁剪必须放在其内部视觉层，禁止在定位节点上施加开合 transform 动画或 filter。
- 验收时必须检查生成 CSS 的 layer 与顺序，并至少在两个主题下通过 computed style 覆盖代表性静态态、hover/focus 态、outline 按钮、input 和 joined/split control，确认主题默认值生效且组件显式变体可覆盖。
