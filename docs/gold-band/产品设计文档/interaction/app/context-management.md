# 上下文管理与角色批量导入

## 1. 页面职责

上下文管理是桌面端管理可复用执行上下文的统一入口。当前 MVP 提供角色管理，角色分为客户端内置角色与用户级角色；工作流始终通过稳定 `profile id` 引用角色。

角色管理提供搜索、新增、查看、修改、删除和文件夹批量导入。所有写操作直接进入 Tauri command，浏览器实现只用于预览，不参与桌面端状态判断。

## 2. 批量导入数据模型

- `ImportProfilesInput`：用户选择的文件夹与本批次动态模板开关。
- `ImportProfilesResult`：扫描数量、成功记录、失败记录与截断标记。
- `ImportedProfileRecord`：源文件、导入状态、最终名称、兜底字段、生成的角色 id，以及可选结构化错误。
- `ImportProfileError`：只携带类型化 `code`；前端根据 code 提供中英文文案，后端不返回对客文案。

单文件错误码区分读取失败、front matter 无效、空文件、名称缺失与创建失败。文件夹级错误由 command error 返回，区分路径不存在、不是目录、无法完整遍历以及没有 Markdown 文件。

## 3. 发现与解析流程

1. 校验所选路径存在且为目录。
2. 使用行业成熟的 `walkdir` 遍历目录，关闭符号链接跟随并按文件名稳定排序。
3. 遍历必须在写入角色前完整完成；任何目录读取错误都终止本批次，避免将“漏扫文件”误报为成功。
4. 只接收扩展名大小写不敏感的 Markdown 文件，最多处理 5000 个；发现第 5001 个时返回截断标记。
5. 复用统一 front matter 解析和角色创建接口，不维护第二套写盘协议。

解析时兼容 `name/title` 与 `summary/description`。字段缺失时使用文件名和正文首个有效段落兜底；动态模板校验失败时降级为静态角色并在记录中标注，不覆盖任何已有角色。

## 4. 前端状态生命周期

文件选择、导入请求、结果展示和结果内编辑属于同一生命周期，由单一 reducer 管理：

```text
设置抽屉 -> 选择目录 -> 导入中
                ├─ 失败：保持设置抽屉并显示错误
                └─ 成功：同一右侧抽屉切换为导入结果
结果抽屉 -> 编辑角色抽屉
                ├─ 读取失败：返回结果抽屉并显示错误
                └─ 成功：保留批次结果并进入角色编辑层
角色编辑抽屉 -> 保存 / 返回 / 关闭 -> 恢复原导入结果
```

设置、结果和单项编辑共享右侧 Sheet 工作流，任何时刻只允许一个抽屉表面处于打开状态，禁止叠加焦点陷阱。取消原生目录选择只结束加载态，不关闭设置抽屉；只有在结果层主动关闭才清空本批次，编辑完成或退出必须返回原结果列表，以便连续修正其他角色。编辑保存成功时，以接口返回的最新角色实体为准，按稳定 `importedId` 回写本批次结果中对应记录的可见名称；不得按旧名称、源路径或数组位置猜测关联，也不得丢失源文件路径和兜底诊断。任何失败都必须出现在当前可见表面。

## 5. 验收约束

- 符号链接目录不会被递归进入，遍历错误不会静默忽略。
- 文件处理顺序稳定，超过上限时结果可预测。
- 每条失败记录使用类型化错误结构，前端覆盖全部本地化文案。
- 导入与结果内编辑失败均可见且可重试；编辑任意成功项后可返回同一批次继续修改下一项，结果行立即展示保存后的名称并保留导入诊断。
- Rust 单元测试固化遍历、解析、错误结构和写入语义；前端单元测试固化 Tauri 接口透传与 reducer 状态转换。
