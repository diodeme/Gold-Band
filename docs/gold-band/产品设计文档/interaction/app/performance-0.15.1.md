# 0.15.1 性能修复

## 根因与边界

- 诊断逐项完成是正确设计；全局失效事件没有同步缩小消费范围，导致无关目录重复扫描。
- 图片只读接口复用了整份 Timeline 索引解析路径；16 次定位读取随历史规模线性放大。
- v10 到 v11 仅增加图片投影，原有升级入口却同时全量加载、合并和重写 canonical timeline。

## 诊断与目录

- 诊断完成发布单个 Agent 的最新投影；前端只替换配置匹配且未过期的目标，保留其他条目和 catalog 的引用。
- 目录内容实际变化后发布 Agent ID、project ID 的定向事件。相同内容不重复写盘和广播；周期批次完成不额外发布全局失效。
- 变更比较分别覆盖 ACP 与 Skills 来源，包括被同名 ACP 命令遮住的 Skill 元数据。复用目录内既有 `skillCommands` 字段保存最后一次扫描的内存投影，落盘时移除；查询始终重新读取当前文件系统，目录缓存不成为 Skills 的权威来源。
- 命令消费者共享当前挂载作用域的一次进行中请求，重复触发最多合并一次后续刷新。最后一个消费者卸载后删除作用域；迟到响应不得发布到新作用域。
- Skills 扫描通过 Tauri blocking 执行器运行；后台刷新失败保留已有目录。

## Timeline 读取与升级

- 单条读取共享只含事件 ID、位置、revision 和工具顺序的派生只读索引，不保存事件正文。LRU 最多 4 个索引，驻留估算预算 32 MiB；超预算索引不驻留。
- 同文件读取复用既有文件锁合并冷加载；全局 LRU 锁不覆盖 I/O。追加使用有界尾部重放；替换、压缩通过文件签名及前缀校验失效。图片 blob 读取与解码继续使用原有双并发预算。
- v10 合法定位信息显式迁移为当前索引，generation 与 canonical timeline 保持不变；新增 `imageProjectionPending` 区分尚未投影和已确认空图片集合。
- 当前可见的旧过程段在后台分页读取图片引用，每页最多读取 32 个工具事件，最多返回 256 个引用；不 hydrate 图片 blob。查询携带完整 attempt/branch、范围和 generation，迟到结果不能跨范围发布。
- 图片引用查询最多 2 个执行中、总计 16 个已接收请求。不可见过程段不启动查询；滚离后停止后续分页。错误局部重试，图片引用列表与缩略资源分开加载。
- 旧图片按可见范围补齐，不启动全历史图片回填。同一挂载范围保留至多 256 个引用及分页游标，滚动返回继续未完成页；卸载、范围或 generation 变化后重新查询，不持久化第二套图片事实源。重复游标或跨 generation 响应失败并提供局部重试。

## 审视与验证

- 复用 serde、既有 Timeline locator、文件锁、generation、内容寻址 blob、Tokio semaphore 和现有图片组件；不新增数据库或 canonical 图片实体。
- 只读索引是重量明确的派生投影，其容量和生命周期独立于历史正文。基础首批仍需一次索引加载，成本随索引规模增长；本轮消除逐图重复解析和仅为图片升级而重写全历史。
- 发布构建基线：1,000 / 10,000 / 100,000 条历史各读取 16 次，分别 114 / 1,186 / 11,538 ms；索引大小分别 921,467 / 9,336,949 / 94,663,118 字节。该数据测量定位读取，不包含图片解码、浏览器渲染或整页耗时。
- 相同 release benchmark 修复后为 20 / 48 / 529 ms，10 万条样本约快 21.8 倍；包含首次冷加载。热读取复用定位投影，不重新解析完整索引。
- 32 MiB 是 LRU 中定位数据的驻留估算预算，不是进程峰值内存上限；冷加载时仍短暂解析完整索引，进行中的投影与单条工具正文也需要内存。损坏或更早的不兼容索引仍沿用原有恢复路径，本轮只消除合法 v10 图片升级带来的全历史改写。
- 验收要求：无关目录零请求；同作用域单飞；旧响应隔离；重复定位只加载一次索引；普通追加增量追平；升级前后 timeline 字节完全一致；旧图片引用按页补齐且 generation 不匹配时拒绝。
