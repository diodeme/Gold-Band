# Gold Band 官网产品方案

## 产品定位

建设一个面向开发者的 Gold Band 产品官网，用真实桌面界面的操作演示，说明如何配置 Agent、用工作流控制执行、审阅产物并定制应用。主要转化目标是下载桌面客户端与进入浏览器 Demo。

官网从独立项目开始设计、开发和部署；Demo 直接复用已实现的页面与运行入口，仅补充官网接入、指定完整会话数据及相应验收。首页为产品宣传体验，不承载真实任务执行，不依赖桌面进程或本机服务。

## 页面与功能范围

| 页面 | 内容与目标 |
| --- | --- |
| Home | 品牌介绍、四段产品演示、下载与 Demo 入口 |
| Documentation | 独立文档占位页，为后续文档内容保留路由 |
| Demo | 复用已实现的模拟客户端，补充指定会话完整历史；首页提供入口，支持独立部署 |

首页和 Demo 均属于交付范围，分别设计加载边界。首页自动播放预设素材；Demo 复用客户端页面提供受限交互，禁止真实消息发送、业务保存和 Git 执行。Documentation 保留占位页，Demo 必须交付可操作页面。

网站支持中文与英文。推荐同时提供深浅色主题，并让演示素材跟随网站有效主题；在视觉设计阶段确定主题范围。主题与语言切换保留当前页面和章节。

## 技术选型与架构

- 官网：Vite、React、TypeScript、Tailwind CSS、shadcn/ui，使用成熟组件完成导航、菜单与可访问交互。
- 录制：rrweb；录制源使用 Gold Band 客户端前端，包括 prompt-kit 会话组件、工作流编辑器与图、文件编辑器及源码管理。
- Demo：Vite、React、TypeScript，复用客户端应用壳、页面、Tailwind CSS、shadcn/ui 和 prompt-kit 组件；独立入口注入只读 API 适配器和静态演示数据，不连接 Tauri 或业务后端。
- 回放：rrweb 官方回放引擎，配合独立的镜头与配速配置。使用 CSS transform 和原生动画能力完成推拉，不开发通用播放器或视频剪辑工具。
- 部署：静态站点与指纹资源；页面路由、语言、主题和 Demo 地址集中配置。站点运行不需要数据库、账号系统或业务后端。
- 目录按职责组织为页面与文案、视觉样式、回放组件、场景与镜头配置、静态素材、录制工具及验收测试。录制工具与客户端代码不进入官网首屏依赖。
- 设计参考 pi.dev，并使用 ui-ux-pro-max、ckm:ui-styling 评审视觉层级、留白、对比度、组件使用和动效。

## 页面构图

- 首屏明确出现 Gold Band 品牌与真实产品画面，下载为主操作，Demo 为体验入口；文案简短。首屏保留下一段内容线索。
- 桌面左侧固定产品演示，右侧四段文案随滚动切换。建议初稿媒体与文案宽度约 60:40，最终根据同视口参考截图调整，不把比例当作验收结论。
- 产品画面直接融入页面；不添加重复品牌条、上下包裹栏、嵌套卡片或常驻播放器工具栏。保留产品自身必要的窗口结构。
- 手机自然纵向滚动，每段严格“演示在上、文案在下”。不劫持滚轮或触摸滚动，不要求访客操作缩成邮票的桌面 UI。
- 手机使用专门取景轨道，关键部分必须能读。优先为同一份录制配置移动取景；涉及工作流与会话同时对照而无法清楚表达时，单独录制对应短镜头，不另做手机版客户端。
- 章节标题与产品状态对应。滚动决定当前章节，章节内部按预设时间轴播放；不把滚动像素直接变成播放进度。

## 四段产品故事

四段使用同一个预设项目与任务，保证配置、执行、产物、文件及 Git 变更能够对应。时长是首版剪辑目标，最终以阅读与动效评审调整；单段不超过60 秒预算。

| 场景 | 首版时长 | 要让访客看见的结果 |
| --- | --- | --- |
| 配置你的 Harness | 25–35 秒 | Agent、角色、Skill 和运行模式可以组合 |
| 实时观测、控制你的对话 | 45–60 秒 | 工作流依据输出决定下一步，不是单纯播放多段聊天 |
| 审阅你的任务 | 30–40 秒 | 从会话产物到工作区文件、Diff 和提交形成闭环 |
| 定制化你的应用 | 20–30 秒 | 外观可定制，窗口收缩后布局自动适配 |

### 1. 配置你的 Harness

1. 全景建立客户端空间关系，进入快速对话。
2. 放大选择器，选择 Claude/Codex 等实际支持的 Agent，展示角色选择及 Skill 卡片。
3. Skill 保留多 Agent 图标与同步关系，突出同一份 Skill 的多 Agent 管理。
4. 演示 Direct、Workflow、AUTO 的真实配置入口；分别停留到能辨认模式差异，不把三个标签闪过当作展示完成。
5. 最终选择用于下一段的工作流，缩回全景。

镜头重点为 Agent、角色/Skill、模式切换。角色与 Skill 的界面位置以实际客户端为准，不为宣传片移动客户端功能。

### 2. 实时观测、控制你的对话

先展示规则，再展示执行结果。核心分镜：

1. 打开工作流设置，放大“节点结果判定方式”下拉菜单，清晰展示人工 check、AI 输出验证、不启用（不验证）。
2. 选择 AI 输出验证，展示最小输出约束和成功表达式，例如结果包含 result/reason，表达式为 $.result == true；实际字段与客户端模板一致。
3. 缩回会话与工作流图同屏，启动受控示例执行，出现流式文字、思考与工具调用。
4. 提问与权限申请分别短暂停留，展示用户回答/批准后继续。它们属于交互阻塞，不等同于人工 check，也不替代 AI 输出结果判定。
5. 关键输出出现时放大结果：展示结构化输出内容、结果判定与对应路径。优先录制一次 result=false 进入修正节点，再录制修正后 result=true 进入后续节点，以清晰表达内容控制分支。
6. 每次节点推进都回到能同时看到会话与图的取景：当前节点完成、对应边/下一节点状态改变、会话按客户端跟随模式进入下一节点；变化来自同一执行状态，不分别编排两套动画。
7. 留出短暂全景展示最终路径与任务状态。

人工 check 的定义为 ACP 会话结束后由用户选择成功/失败；AI 输出验证依据 JSON 约束与成功表达式判断，不能宣传为自动证明代码质量；不启用不代表忽略执行错误。三种判定方式互斥。

工作流图、输出和权限组件必须真实录制。内部判定细节通过客户端的输出查看入口展示，不伪造产品状态徽章。工作流 Tab 按客户端实际工作区位置录制，官网左侧承载整个产品画面。

### 3. 审阅你的任务

1. 延续第二段任务，在会话中出现附件卡片及文件变更卡片。
2. 放大附件并打开报告；随后悬浮变更卡片，展示真实 Diff 预览，停留到能读懂关键修改。
3. 打开工作空间文件树，查看执行后的最新文件，编辑并保存一处小修改。
4. 打开源码管理，对照会话变更与工作区修改，查看 Diff，演示暂存和本地提交，最后显示提交后状态。
5. 取景在会话、文件内容与源码管理之间平滑切换，始终保留当前对象的路径或身份线索。

录制专用场景可模拟写入后的状态投影；公开 Demo 禁止业务保存和 Git 执行。真实 Git 验收仅在隔离的临时仓库进行，不操作用户工作仓库或远程推送。模拟状态不能作为已运行真实 Git 的验证证据。

rrweb 是否能还原悬浮预览需专项验证，包括鼠标、CSS hover、Portal 和出现时序；只记录鼠标坐标不算通过。手机播放的是已录下的悬浮动作，无需访客具备 hover。

### 4. 定制化你的应用

1. 快速进入设置，局部放大主题选择，切换不同主题风格。
2. 展示字体切换与正文变化，再展示头像及其在会话中的实际效果。
3. 缩回全景，调整录制源的真实 viewport：三栏 → 双栏 → 单栏 → 双栏 → 三栏。
4. 栏位切换由客户端布局规则触发，录制真实尺寸变化，不用镜头缩放冒充窗口收缩。
5. 恢复开场尺寸与主题，便于循环衔接。

双主题方案分别录制对应明暗版本；每个版本可展示同一明暗模式下的主题风格变化。客户端外观演示只改变画面中的客户端，不应意外更改官网外层主题。

## 配速与镜头

这是预设宣传节奏，不提供访客可调倍速、进度条、跳空闲或全屏工具栏。内部按分镜配置变化的播放速率，访客无需操作。

| 阶段 | 初始剪辑参数 | 目的 |
| --- | --- | --- |
| 普通导航、重复操作 | 约 1.5–2 倍；纯等待尽量在脚本中去掉 | 快速交代过程 |
| 进入重点 | 约 350–600ms 平滑移近，逐步回到正常配速 | 先建立焦点 |
| 配置、结果、Diff | 约 0.8–1 倍，关键静态状态停留约 1.5–3 秒 | 留出阅读时间 |
| 离开重点 | 约 350–600ms 平滑缩回，再加快普通步骤 | 保持空间连续性 |

以上是制作起点，不是所有镜头硬套同一倍率。流式输出保留自然推进；不因加速把提问、权限或判定结果一闪而过。镜头通常放大约 1.3–1.8 倍，手机取景以实际可读性确定。

- 一个镜头只强调一个因果点；避免连续来回推拉、弹簧过冲、快速横扫。
- 变速是平滑调度的预设轨道，不在关键输出出现瞬间骤然切倍速；阅读停留优先在录制脚本中预留。
- 以 rrweb 回放时钟为唯一进度源，镜头/配速/章节内状态共享时间映射；暂停、恢复、重播、切主题都必须同步。不用独立 setTimeout 驱动镜头。
- 镜头数据仅包含片段/步骤标识、时间、目标矩形、缩放和缓动等必要字段。录制阶段按语义目标测量并保存归一化取景，不长期依赖易变的 DOM 文本选择器或 rrweb node ID。
- 缩放整个回放视口（包括光标、菜单与 Portal），仅在媒体舞台边界裁切。不得只缩放正文导致浮层错位。
- 自动播放内容保留可访问的最小暂停/继续入口以满足动效可控要求，但不呈现播放器面板。尊重 reduced-motion，默认海报/静态关键帧，关闭自动推拉。
- rrweb 的 DOM 文字通常适合缩放，但图片、头像、canvas 有分辨率限制；最终字号、图像和图都以回放截图验收。

## 深浅主题回放建议

可以让回放自动跟随官网有效主题，不能假定 rrweb 天生支持动态换肤。

推荐同一录制脚本分别生成深色、浅色素材，复用分镜与语义步骤。按 scene + language + theme 选择资产；四段 × 两语言 × 两主题共 16 份录制及海报。移动端优先复用这些素材，仅另存取景轨道。

主题由官网明确选择或系统偏好决定（用户选择优先）；不是无缘无故定时切换。切换时暂停旧回放、保留当前步骤及步骤内进度、加载目标主题、定位对应步骤，再继续。两次录制时长可能不同，不能直接以相同毫秒值或总时长百分比假设内容对应；配对素材必须拥有相同语义检查点。

等待主题资产期间展示目标主题同一步骤的静态画面；加载失败可重试，不闪白、不回片头、不同时运行两个回放实例。不会首屏下载所有主题与语言。

不推荐用 CSS invert/filter 全局反色，会破坏品牌图标、Diff 状态色和图片。直接覆盖回放 iframe 的主题变量仅能作为兼容性验证方案，必须证明内联样式、录制中的主题变更、编辑器、图片和浮层均正确后才可替代双份素材。

本功能不同于第四段录下“用户切换主题”的动作：前者是访客切换官网外观，后者是宣传片的产品操作。

## 录制与运行隔离

录制入口复用真实客户端 UI，使用专用的有界场景状态和客户端 API 事件契约。公开 Demo 使用只读边界，桌面 API 和后端不为宣传修改。

按客户端工作流数据结构与事件契约建立录制用场景数据，覆盖图、流式事件、提问、权限、输出判定和写入后的展示结果。一个场景状态统一派生 run/session/graph/files 投影，不新增完整 mock 后端或另写业务执行引擎。

每段最多 60 秒、12 MiB、12,000 events；单时刻最多一个活动回放。首屏先显示海报，只加载当前场景/语言/主题；非当前场景不运行客户端。离屏或页面隐藏暂停，切段销毁旧回放、监听器、RAF 并拒绝迟到请求。资源随站点分发，不依赖录制服务器。

### 架构与体验边界

复用范围包括现有 Demo 页面、模拟客户端外框、只读 API 适配器、路由、样例和偏好管理。下方页面清单用于明确保留范围与回归验收，不代表需要逐项重新实现。仅在接入官网或完整会话数据时，按实际缺口补充必要适配。

Demo 是可浏览、可探索配置的模拟客户端。页面结构、样式、菜单、浮层和响应式行为复用客户端组件，不另写一套简化客户端。独立浏览器入口装配客户端页面及 Demo 数据适配器；桌面端 API 契约、后端与默认运行行为保持不变。后续客户端前端更新后，重新构建并部署 Demo 即可同步共享页面改动，并通过适配器契约检查发现新增接口。

使用客户端 API 契约建立明确的读取白名单；未实现接口和业务写操作统一返回结构化不可用错误，不能回退调用桌面接口。界面禁用与接口拒绝分别生效。配置表单允许临时修改以体验控件，但不能保存业务数据；主题、语言、字体及布局偏好可存入版本化浏览器存储，表单草稿仅保留在当前交互生命周期中。没有真实 Agent 执行、MCP 请求、系统文件写入或 Git 操作。

## 验收门槛

### 必须打开前端并对照 pi.dev

1. 启动或打开实际前端，最终使用当前生产构建；同时打开 pi.dev，在相同视口截图对照首屏、各章稳定状态、重点镜头和手机布局。不能只读源码、看 DOM 或引用技能便宣告审美通过。
2. 每次记录参考日期、视口、主题和滚动位置；pi.dev 可能随演示改变外观，要区分页面基准与演示中的状态。浏览器扩展注入内容不作为设计参考或录制内容。
3. 对照评审构图比例、产品可读性、字体层级、中英文换行、留白节奏、边界强度、导航克制程度和动效连续性。目标是对齐参考的完成度与产品叙事，不照搬 Pi 的终端心智、命令安装框或品牌资产。
4. 输出成对截图及逐项“通过/待改/有意差异”的简短理由；设计不协调，即使无溢出和测试全绿也不得验收通过。
5. 至少覆盖 1440/1280px 桌面、768px 中间宽度、390/320px 手机；含触屏能力的桌面宽度、窄后拉宽、中英文、长文案。双主题方案启用后两主题分别评审。
6. 手机关键字无需捏合放大也能读，演示在上文案在下，不出现整台桌面客户端缩成小字的主要镜头。网页无横向溢出，焦点、浮层和标题无意外裁切。
7. 提问、授权、JSON 结果和下一节点关系清楚可见；镜头始终跟上焦点，切章不抖、循环不突兀。连续观看四段后评审节奏，不能只截静态图。

## 方案自评审

- 架构：将官网展示、录制源和可操作 Demo 分开，分别管理运行与加载生命周期，避免把桌面业务执行带入宣传页面。
- 过度设计：四段场景脚本与轻量镜头/节奏数据足以表达需求，优先使用成熟回放与组件；不做通用剪辑台。双主题增加资产而非复杂换肤引擎。
- Demo 范围：复用客户端页面、只读适配器及静态数据即可满足体验，不新增业务后端或模拟执行引擎；完整会话作为静态事实源，不复制客户端业务状态机。
- Demo 性能：真实历史规模以导出清单为准，采用摘要优先、历史分页、详情按需加载；导入后定义并实测首批呈现、翻页及内存预算，不能通过删减历史达标。
- 性能：固定场景规模、按需资源、一个活动实例、transform 驱动镜头；不每帧更新页面根 React 状态，不重复解析全部录制。以生产性能时间线检查关键镜头卡顿和长任务。
- 主要待验证风险：hover/Portal、工作流图还原、变速同步、主题语义对齐及手机可读性。先做高风险样片再扩展，不把未验证能力写成完成。

## 数据与接口设计

| 数据 | 内容 | 归属与生命周期 |
| --- | --- | --- |
| 页面内容 | 页面、章节标识，中英文标题、正文、入口 | 静态内容，随站点版本发布 |
| 场景数据 | 预设任务、工作流、会话、文件及状态变化 | 录制工具，单次录制结束释放 |
| 素材清单 | 场景、语言、主题、资源地址、尺寸、时长与版本 | 静态资产索引，按当前选择加载 |
| 镜头与节奏 | 语义步骤、原始时间区间、取景、配速与缓动 | 每段有界配置，播放时只读取当前轨道 |
| 回放位置 | 当前场景、步骤与步骤内进度、播放状态 | 单个回放会话，切换时同步定位 |
| 用户偏好 | 语言、主题选择 | 版本化浏览器存储；存储不可用时使用内存 |
| Demo 数据集 | 样例、真实会话导出、工作流快照、文件与引用清单 | 随 Demo 版本发布的只读事实源；摘要、分页和详情为派生投影 |
| Demo 导航与表单 | 完整 locator、Tab、临时配置 | 导航由路由管理；表单局部内存状态，关闭对应流程释放 |
| Demo 外观偏好 | 语言、主题、字体、字号与用户布局 | 独立版本化浏览器存储，不写入会话或客户端业务数据 |

录制工具输出 rrweb 事件文件、海报、语义检查点和素材清单。素材检查应校验文件存在、版本匹配、时间范围、取景边界以及同场景明暗素材的步骤对应关系。播放层只消费这些产物，不调用客户端业务 API。
