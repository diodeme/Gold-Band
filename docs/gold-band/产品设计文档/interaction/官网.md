## 内置精简 Demo 数据集（2026-09-11）

Demo 是官网宣传体验，只需要会话结构、消息正文、代码块、diff 和消息内图片，不需要承载可复现的运行现场。真实候选 `G:/Gold-Band/task-035/website-real-history-demo/dataset` 为 4.73 GiB / 308,117 文件，其中 `archive/`（3.12 GiB）是 run-001（2.00 GiB / 24,102 文件）的全量镜像，最大单项是 `attachments/` 下的发布压缩包（ji-host/ji-relay 二进制、Maven 输入、JDK、OCI 镜像），与演示无关。

发布数据改为经 `scripts/slim-demo-dataset.mjs` 投影后的精简数据集，内置在 `marketing/demo/data/ji-history`：2,997 文件、45.8 MiB 发布内容，另 0.6 MiB `manifest.json` 只作为构建期输入，不进入发布清单。保留 `dataset.json`、`run.json`、`task.json`、`workflow.json`、`resources.json`，以及每个会话的 `index.json`、`pages/`、`images/`、`changes/`、`comparisons/`；删除 `archive/`、`files/`、`directories/`、`raw/` 和逐条工具调用事件。

活动明细改为「标题投影」发布：37,708 行只保留 `id`、`kind`、`title`、`status`、`toolCallId`、`sessionId`、序号、`timestamp`、`durationMs` 和工具名，思考行另保留正文（否则该行不渲染），工具行不发 payload，并去掉未被列表使用的 `timing` 大对象。`index.json` 的 `eventRefs` 退化为指向活动页的定位索引，不再指向事件文件。实测各档体积：原样 85.2 MiB、仅标题 33.9 MiB、去掉 `timing` 后 20.1 MiB；带上 9 MiB 定位索引后，整个数据集由 18.3 MiB 增至 46.4 MiB，仍在既定 30–50 MB 预算内。

体验结果是会话列表、消息流、思考与工具卡片摘要、代码块、图片和单轮 diff 全部保留，工具卡片按“标题 + 状态 + 活动摘要”展示。原始帧面板与工作区文件树失去数据：前者提示“操作失败，请重试”，后者返回空列表，两者都不影响主流程。`index.json` 仍保留工具调用的定位元数据，需要带截断预览的本地探索可用 `--tool-detail preview --tool-output-chars <n>` 重新生成，代价是回到数十 MiB 级并产生约 2.8 万个事件文件。

数据格式没有新增业务概念，仍使用既有 `dataset.json`、`resources.json` 与会话资源契约，客户端读取路径不变；由于内置数据集没有缺失引用，构建不再需要 `DEMO_ALLOW_MISSING_REFERENCES`。原始候选与发布投影都没有随构建上传到服务器。

第一版裁剪把活动明细整段删除后，工具调用分组的展开区域没有内容也没有说明，用户会读成“功能坏了”。根因属于正确设计但实现不完整：UI 的活动分组只有加载、错误和列表三种分支，缺空态；适配器也无法区分“确实没有活动”和“本期不发布”。修复分两处：一是共享 UI 增加空态分支与 `acp.activityDetailUnavailable`，桌面端默认文案保持中性（“暂无可显示的活动明细。”），Demo 用既有 `i18n.addResourceBundle` 覆盖为“Demo 不展示具体工具调用明细。”，中英文各自维护；二是按上节把活动行以标题投影发布，让分组重新显示真实行。空态因此只作为无行场景的兜底。

裁剪脚本同时把工具卡片的 `toolDetailAvailable` 置为 false，卡片不再声称存在明细，点击不会去请求已裁掉的资源。验收：中文与英文内嵌 Demo 展开工具调用分组均显示真实行（命令标题、Grep/Read 标签、思考过程与“已完成”状态），控制台无错误，工具卡片点击不再出现加载失败。工具卡片自身展开正文仍为空是预期结果。

## 内嵌 Demo 的主题对齐与外框（2026-09-11）

官网与 Demo 的外观改为同源：站点把当前生效的 `light`/`dark` 通过 `theme` 查询参数传给 Demo，与既有的 `language` 参数同一条链路；`DemoPage` 在 `src` 变化时重置加载态，`iframe` 重新加载后由 `entryPreferences` 写入外观偏好。这样深浅色切换与语言切换行为一致，也不新增跨窗口消息协议。

Demo 的客户端按桌面端默认窗口尺寸呈现：`src-tauri/tauri.conf.json` 的窗口为 1280×720，渠道覆盖只改标题不改尺寸，因此舞台用网格轨道 `min(1346px, 100%)`（1280 ÷ 0.96 加上两个 6px 分隔条）与 `min(720px, 100%)` 限制，客户端实测 1281×720；视口更窄时按可用空间收缩，≤640px 回退为铺满整屏。此前客户端会被拉伸填满浏览器。

「舞台」底色是低对比而非反色：深色客户端配 `#2b2e2f`、浅色配 `#e4e7e3`（`--demo-stage-background` 按 `data-color-scheme` 取值），只与客户端拉开一档明度，边框与阴影可辨但不刺眼。此前该底色固定为 `#080909`，深色主题下与客户端几乎同色。

工具行展开不再显示 TOOL PARAMETERS：没有已发布明细时，`orderedInput` 不传给卡片，展开区域改为显示 `acp.activityDetailUnavailable`（Demo 覆盖为“Demo 不展示具体工具调用明细。”）。折叠态的一行摘要芯片（如 `Grep | head -300 …`）仍由 `toolSummary` 保留，因为摘要与参数面板虽然同源于 `queryBlocks`，但分别渲染。

## 配速与镜头

这是预设宣传节奏，不提供访客可调倍速、进度条、跳空闲或全屏工具栏。内部按分镜配置变化的播放速率，访客无需操作。

| 阶段 | 初始剪辑参数 | 目的 |
| --- | --- | --- |
| 普通导航、重复操作 | 约 1.5–2 倍；纯等待尽量在脚本中去掉 | 快速交代过程 |
| 进入重点 | 约 350–600ms 平滑移近，逐步回到正常配速 | 先建立焦点 |
| 配置、结果、Diff | 约 0.8–1 倍，关键静态状态停留约 1.5–3 秒 | 留出阅读时间 |
| 离开重点 | 约 350–600ms 平滑缩回，再加快普通步骤 | 保持空间连续性 |

以上是制作起点，不是所有镜头硬套同一倍率。流式输出保留自然推进；不因加速把提问、权限或判定结果一闪而过。镜头通常放大约 1.3–1.8 倍，手机取景以实际可读性确定。

- 一个镜头只强调一个因果点；避免连续来回推拉、弹簧过冲、快速横扫。
- 变速是平滑调度的预设轨道，不在关键输出出现瞬间骤然切倍速；阅读停留优先在录制脚本中预留。
- 以 rrweb 回放时钟为唯一进度源，镜头/配速/章节内状态共享时间映射；暂停、恢复、重播、切主题都必须同步。不用独立 setTimeout 驱动镜头。
- 镜头数据仅包含片段/步骤标识、时间、目标矩形、缩放和缓动等必要字段。录制阶段按语义目标测量并保存归一化取景，不长期依赖易变的 DOM 文本选择器或 rrweb node ID。
- 缩放整个回放视口（包括光标、菜单与 Portal），仅在媒体舞台边界裁切。不得只缩放正文导致浮层错位。
- 自动播放内容保留可访问的最小暂停/继续入口以满足动效可控要求，但不呈现播放器面板。尊重 reduced-motion，默认海报/静态关键帧，关闭自动推拉。
- rrweb 的 DOM 文字通常适合缩放，但图片、头像、canvas 有分辨率限制；最终字号、图像和图都以回放截图验收。

## 深浅主题回放建议

可以让回放自动跟随官网有效主题，不能假定 rrweb 天生支持动态换肤。

推荐同一录制脚本分别生成深色、浅色素材，复用分镜与语义步骤。按 scene + language + theme 选择资产；四段 × 两语言 × 两主题共 16 份录制及海报。移动端优先复用这些素材，仅另存取景轨道。

主题由官网明确选择或系统偏好决定（用户选择优先）；不是无缘无故定时切换。切换时暂停旧回放、保留当前步骤及步骤内进度、加载目标主题、定位对应步骤，再继续。两次录制时长可能不同，不能直接以相同毫秒值或总时长百分比假设内容对应；配对素材必须拥有相同语义检查点。

等待主题资产期间展示目标主题同一步骤的静态画面；加载失败可重试，不闪白、不回片头、不同时运行两个回放实例。不会首屏下载所有主题与语言。

不推荐用 CSS invert/filter 全局反色，会破坏品牌图标、Diff 状态色和图片。直接覆盖回放 iframe 的主题变量仅能作为兼容性验证方案，必须证明内联样式、录制中的主题变更、编辑器、图片和浮层均正确后才可替代双份素材。

本功能不同于第四段录下“用户切换主题”的动作：前者是访客切换官网外观，后者是宣传片的产品操作。

## Demo 页面复用与补充

### 真实历史读取契约实施（2026-09-09）

JSON与JSONL脱敏先解析结构，再脱敏字段和字符串，最后由JSON序列化器维护转义边界；不得直接在序列化JSON上替换凭据。归档必须另验可解析性，hash只能证明副本稳定，不能代替语义完整性。

首次导出与已有候选修复遵守同一文件解析边界；JSON按完整文档脱敏后压缩，JSONL按完整行处理，保留源hash与前后stat核查。真实文件/gzip失败回归覆盖带引号工具命令，不能只验证sanitize字符串函数。单文档内存成本只在离线导出发生，不扩大浏览器历史加载范围。

已有副本的结构恢复只沿manifest明确来源读取，并先匹配sourceSha256；区分源本来不可解析和导出引入的不可解析，不把源异常伪造为有效记录。

无扩展名blob按完整内容检测UTF-8及NUL；二进制保留原字节，文本遵守结构化脱敏边界。22517个已导出blob最大约1.54MB，此离线逐文件处理不增加无界缓存。二进制归档以源hash匹配和解压字节相等验收，禁止文本换行归一化改变其内容。

源文件后续不可取得但导出归档仍存在时，保留并核对既有副本hash及结构，单独记录其当前来源不可复核状态，不删除已取得历史或误报为新生成源数据。

生产复制只消费完整性检查生成的显式清单，拒绝路径穿越；未引用的旧候选文件不会进入发布目录。

复制逐文件核对清单hash/字节数并写入同一已核验buffer，防止检查与复制间文件变化。额外I/O只在离线构建执行，峰值内存受最大单文件限制，不引入浏览器预加载或缓存。

凭据扫描误报只按明确字段/格式及可复核上下文逐项分类；流式hash片段必须匹配同日志完整hash，工作流依赖必须处于dependsOn数组，不整体忽略generic-api-key规则。

结构恢复同时更新对应文件预览与Raw正文，重算父资源引用；发布图片的静态预览身份保留，源运行授权token不保留。恢复操作复用资源遍历器，避免重建无关二进制附件。

Raw完整性独立比较全部根会话每页正文、行号、计数及未截断标记与已核验归档逐行对应；该检查仅离线执行。

资源描述符可携带comparisonIndex等后续引用；脱敏与完整性检查均递归处理描述符的附加字段，不能只处理path对应正文后提前返回。

任务元数据与执行工作流快照必须由dataset/manifest显式引用，进入hash校验及发布闭包。真实项目调用authoring getWorkflow不得回退录制样例；无对应authoring快照时返回既有不可用错误，执行快照仍完整导出。该修复复用现有身份，不增加跨域模型或全量首屏读取。

2026-09-10续作：Raw帧沿用客户端page/pageSize、kind/direction/search/order接口及kind提取规则，离线生成50帧正文页。未打开Raw时不读取正文，默认分页仅取当前页，显式搜索逐页扫描并只保留命中身份。原始帧正文保留完整，不套用宣传片预算。根与子分支诊断计数来自同一Attempt原始日志。

- 架构：将官网展示、录制源和可操作 Demo 分开，分别管理运行与加载生命周期，避免把桌面业务执行带入宣传页面。

- Demo 性能：真实历史规模以导出清单为准，采用摘要优先、历史分页、详情按需加载；导入后定义并实测首批呈现、翻页及内存预算，不能通过删减历史达标。
- 性能：固定场景规模、按需资源、一个活动实例、transform 驱动镜头；不每帧更新页面根 React 状态，不重复解析全部录制。以生产性能时间线检查关键镜头卡顿和长任务。
- 主要待验证风险：hover/Portal、工作流图还原、变速同步、主题语义对齐及手机可读性。先做高风险样片再扩展，不把未验证能力写成完成。

## 数据与接口设计

### 独立回放控制器（2026-09-09）

`marketing/site/replay-controller.ts` 消费既有 SceneAsset 与 PlaybackPosition。引擎独占 raw 时间；控制器保存用户播放意图、可见性和当前加载请求，切换先释放旧引擎再加载，拒绝已取消请求的迟到成功及失败。语义位置以 stepId/fraction 映射；隐藏和离屏不改变用户暂停意图。镜头整体 transform 与配速仅由 raw 时间计算，最多一个可取消 RAF；reduced-motion 初始暂停，主动播放仍禁用平滑推拉。

控制器接口测试通过不等于生产回放验收。实际 UI 接入、配对文件、资源闭包、最终预算和源/回放同点可读性须分别完成并记录，不由单测或资源枚举替代。

录制源窄窗继续复用客户端布局：AppTitleBar 品牌文本在可用空间不足时收缩，小于容器 sm 断点时仅保留完整品牌图标与可访问名称，避免残字，窗口操作保留；ConversationRunHeader 根据实际容器宽度将任务标题换至独立行，会话选择器允许收缩并保留完整可访问名称。该修复不改变会话选中、工作流推进和自动跟随契约。
