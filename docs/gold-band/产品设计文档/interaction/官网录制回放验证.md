# 官网录制回放验证

## 目标与范围

验证 rrweb 2.1.1 对 Gold Band React 页面、会话、右侧工作区及三栏/双栏/单栏响应式变化的还原能力。作为官网素材技术验证，不新增官网、不改变客户端导航及运行时。

## 数据与生命周期

- 专用 capture HTML 启动现有 React App，使用 browser preview API 和已有 run-052 样例；不连接 Tauri、不调用真实 Agent。
- rrweb 在被录制 iframe 自己的 JavaScript 环境运行。录制初始 DOM、内联样式、增量 DOM、鼠标、输入、滚动和真实视口 resize。
- 使用官方 rrweb-player 提供暂停、重播、倍速、拖动进度。录制结束后卸载源页面，仅运行回放。
- 单次最多 60 秒、12 MiB、12,000 个事件，超过上限停止，不裁掉依赖的初始快照；停止幂等，拒绝迟到事件。
- 录制只驻留内存，用户可导出 JSON；无上传、无后台采集。只有专用 demo entry 引用录制器，正常桌面 entry 不导入。

## 响应式验证

调整源 iframe 的实际 viewport，依次 1440 → 900 → 600 → 900 → 1440 px，固定高度 800 px。由现有 WorkspaceShell 决定栏位显示与恢复，demo 不复制或修改其状态机。回放按记录的 viewport 重建并适配外层容器，不把录制解释为可交互客户端。

## 方案评审与限制

- 复用 rrweb、rrweb-player、现有 shadcn/ui 和现有浏览器样例，不增加事件总线、持久化服务或通用动画系统。
- 事件追加只序列化当前事件，复杂度按新增事件字节数增长；不在滚动时反复序列化全部记录。统计低频更新，页面隐藏时暂停播放。
- CSS、图片、字体的可移植性需要实际检查；当前版本只保证本地同源资源可用时的回放。
- 不验证 EXE/WebView2 注入、原生窗口/文件对话框、真实 ACP 流或 Canvas 录制。浏览器验证通过不等于以上能力通过。
- 录制还原当时语言/主题，切换 demo 主题后需重新录制。

- 手动录制验证中文输入“验证录制输入：三栏、双栏、单栏。”以及打开 `src/config.json` Diff，回放均还原；停止后源 iframe 数为 0。
- 390×844 手机容器无横向溢出，重新拉宽可恢复播放器尺寸。完整桌面录制在手机上字小，正式官网应另做取景或单独场景，不能将整体缩放等同于响应式网页体验。
- 单元测试 4 项通过：完整快照要求、事件数量上限、UTF-8 字节上限、停止幂等及迟到事件拒绝。
- `npm run demo:rrweb:build` 类型检查及构建通过。构建包含真实应用的重型模块，有现有大 chunk 提示；这是本地录制验证站点，不适合原样作为官网首屏。
- 审计脚本：`scripts/verify-rrweb-demo.mjs`，使用 agent-browser；`AGENT_BROWSER_BIN` 可指定 CLI 可执行文件，`RRWEB_DEMO_URL` 可指定生产预览 URL。
- 本地结果：`.codex-temp/rrweb-verification/report.json`、`light-recording.json`、`dark-recording.json`，报告包含截图路径。测试使用的 run-052 来自现有 browser fixture，其“错误阻塞预览/ACP 会话失败”和占位附件是原有测试内容，不是 rrweb 录制故障。

完成评审：复用现有布局和库足以满足本轮验证，未新增客户端状态或常驻采集；采集有界、回放释放源页面，无新增全量历史读取。仍未验收 EXE 原生环境、真实流式 ACP、原生对话框及工作流画布，不据此承诺这些场景已支持。
