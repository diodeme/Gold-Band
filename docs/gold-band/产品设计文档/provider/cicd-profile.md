# CI/CD 内置角色

## 目标与边界

WB 用户可在自行编排的工作流节点上绑定 `pf-builtin-cicd`。角色默认任务为构建 + 部署，构建后核实成功并推送物料，再部署至终态；具体范围由人类指令和节点 task / goal 确定。角色展示名为 `CI/CD`，加入 WB 专属 `wb-development-cicd` 模板的验收成功后节点并默认启用人工 check，普通模式不可见，不新增 CI/CD 节点类型、执行器或专用授权状态机。

部署支持按构建和按包名两种方式，默认向用户推荐按构建部署；两种方式都须交互确认，配置预填不能代替用户选择。按包名使用本次构建产物时，先构建与推送再核实真实包名；使用已有包时询问是否仍需新构建，只有明确指令才能省略构建。

CICD 在任何构建、物料 / 镜像推送或部署前检查业务仓库的本次需求相关提交与远端状态。相关范围依据原始需求、当前 task / goal、runtime 明确提供的前序产物和用户明确指认界定；无法判断时先澄清。发现相关未提交改动时，CICD 协助用户提交：仅检查相关路径状态与差异，说明变更并确认三行提交消息后，按具体路径执行 git add / git commit，再复查工作区；不使用 git add -A，不纳入无关改动，不修改业务代码内容。相关提交已存在但未推送时，核对当前分支、远端、待推送提交与远端分支实际将包含的内容，用户确认后执行普通 git push 并核实远端分支包含相关提交；禁止 force push 和推送未确认内容。用户未确认、提交或 push 失败、复查仍有相关未提交改动、远端分支缺少相关提交时停止。提交第二行使用标准 Conventional Commits 类型 token 与中文描述；需求 ID / 名称先从原始需求确认，缺失或冲突时询问用户，仍无法确认才使用默认值。代码 push 与后续物料 / 镜像推送是不同操作。

发布计划回归部署 / 审批、触发自测、查询自测和跑批均为选配，可询问用户是否追加，不主动执行。未选择时不发起、不查询、不等待，也不影响主任务完成；已选择执行自测时，必要的状态查询包含在该选择内。

复用现有 Profile 注册、按语言选择正文、稳定 ID 引用及 runtime 输出契约。角色属于 system prompt 中稳定执行方法；本次业务参数和目标属于 user prompt。正文以 `src/prompts/zh-CN/profile/cicd.md` 和 `src/prompts/en/profile/cicd.md` 为真源，作为静态角色关闭动态模板。

正文的“代码提交前置条件”与“CLI 与参数检查”分别成节；前者负责业务仓库提交与远端推送门禁，后者从 CLI 版本检查开始维护运行环境、配置和参数来源，避免两组编号被误读为同一流程。

## 能力与参数

基于用户提供的 wetest-cli skill 1.1.0 及其 CLI 0.2.9 命令参考，收录 build、deploy、weflow、batch 四域。角色正文自包含关键参数，不依赖外部 skill 的本机路径。CLI 安装、内网接入、鉴权和 Agent 命令能力均为实际运行前提，角色绑定本身不提供这些能力。

参数统一接入共享记忆领域服务，格式与边界以 [工作空间与任务记忆](../runtime/workspace-task-memory.md) 为准：

- 工作空间 `subSysId1`、`subSysId2` 等保存真实子系统 ID；任务选择单独使用 `cicd.<S>.selected`，不能默认执行全部成员。
- S 使用真实 ID 的 UTF-8 百分号编码，只保留 ASCII 字母、数字、连字符、下划线、波浪号，其他字节为大写 %HH（包括点号与百分号）；不使用可变清单序号或名称作为身份。CLI 使用解码后的真实 ID。
- 每子系统分别保存 `build.jobId/branch/appList` 和 `deploy.mode/templateId/templateName/deployType/env/ips/containers/pkgNames/inputParams`。完整 key 表见双语角色。列表为 JSON 数组序列化后的字符串，inputParams 为不含凭据的 JSON 对象字符串；不另建整份配置 JSON。
- 任务同 key 优先，任务空值不回退。selected 仅从任务作用域读取，且必须属于当前工作空间清单；已有明确选择和授权直接沿用，仅补问缺项、冲突或授权未覆盖的部分。
- 通过 `memory_read` 刷新，按目标作用域逐 key revision 调用 `memory_write`。新确认值默认写任务，项目范围复用需用户明确要求。冲突重新核对，不盲目覆盖；禁止直接创建或编辑记忆文件。
- 写入只保证逐 key 原子；全部修改成功后刷新并核实完整参数组再提交外部操作。容量超限或工具缺失明确阻塞，不能绕过服务。记忆只保存参数，不保存凭据、授权标记、执行 ID、运行状态或终态证据。

授权沿用同一范围内明确人类指令，默认值与角色绑定不代表部署授权。部署前核对有效环境、模板、实际主机或容器、物料来源、部署类型及授权覆盖；特别注意 env 对 ip/container 的覆盖。发布计划操作还核对审批含义和关联部署范围。所需授权缺失且无法交互时报告阻塞。

命令、子命令或参数有疑惑时，使用 `wetest <cmd> --help`，必要时继续查询子命令 help。动态发现仍遵循“查询自由、触发类确认”：按实际语义和副作用分类，触发作业或改变状态前需有覆盖有效参数的用户确认，不能仅凭命令名称判级，也不能试运行触发命令探测参数。已有同范围明确确认可沿用；选配范围、部署和审批的参数核对要求继续生效。

## 结果与恢复

- CLI 退出码和业务结果均成功只代表请求成功，构建、部署、自测需要另外验证远端终态。
- buildId、aompJobId、commandId 是各自平台操作的身份；附件保存执行证据，Gold Band runtime 继续管理节点 canonical state。
- 超时或响应丢失先查询核实，避免重复提交；恢复和新 Round 先检查前序操作。节点取消不等于远端作业取消。
- 轮询有间隔、总期限及剩余预算约束。Job 发现必须过滤分页；包列表仅必要时查询并提取目标证据。
- 未执行、运行中、未知或失败不能映射成成功；runtime 提供 artifact 契约时严格按其输出，未提供时不得自行推断或伪造控制结果。
- 正式角色已接入，删除无条件未配置失败。provider 仍只提交一次，错误使用人工恢复且清除自动重试策略，不进行自动产物补问或重放。WB 默认模板使用人工 check；自定义节点显式配置 AI 输出验证时仍保留既有产物与控制结果校验能力。

## 自评审与验收

现有 Profile 与共享记忆机制足够，此次修正两套契约未接通的实现，不新增执行器、状态、依赖、缓存或队列。读取仍为两个有界文件，按 key 线性合并；每作用域最多 100 条，有效数据上限 32 KiB，多子系统字段计入同一容量。参数配置无历史扫描或 N+1 读取，CLI 查询只针对所选子系统且有界。逐 key 锁不覆盖外部操作或交互，无需额外 benchmark。

验收通过 Profile list/show 接口核对双语参数契约及 WB 可见性，通过共享记忆接口验证子系统隔离、任务覆盖、空值与冲突，通过 provider 恢复测试验证真实成功保留及单次调用。测试固定交付给 Agent 的契约，不等同于真实 Agent 或 WeTest 平台端到端验收。
输出契约补充：CICD 的单次提交与普通节点的执行后产物补问不兼容。底层按内置角色身份选择单次行为，静态与动态节点在显式声明输出时于同次执行内使用 InlineControl；普通角色继续原输出流程。WB 默认模板不再声明输出，节点结果改由人工 check 判定；该底层能力保留给显式配置 AI 输出验证的自定义 CICD 节点。没有新增模型、状态或 I/O。
