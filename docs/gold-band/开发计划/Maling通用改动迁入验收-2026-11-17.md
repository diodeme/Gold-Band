# Maling 通用改动迁入验收（2026-11-17）

来源：[MalingWB/Maling @ 43b2e9a89c](https://github.com/MalingWB/Maling/commit/43b2e9a89c4f280628b540e39e12d17cd9a97370)。本地基线：d6ec717cf。按功能依赖顺序迁入 98 个非 merge 提交；不直接合并 fork 分支，避免混入渠道业务。以下 fork 原有文档中的历史验收记录不代表本次环境的验收，当前结果以本页为准。

## 范围

- 文件引用和产物导航：目录与会话来源、引用恢复、文件菜单、附件持久化和受控访问。
- 草稿与排队：先读取再确认删除、附件归属、编辑占用释放、自动分发与会话切换隔离。
- 首次启动：环境检查、Agent 发现与诊断、默认模型及工作流绑定、稍后设置和设置页重跑。
- Agent：DeepSeek Harness、Qoder、ZCode、WorkBuddy 展示，平台约束、来源与连接要求；ACP 认证共享和错误投影、CodeBuddy 多轮启动配置统一。
- Workflow：横纵布局、全屏、当前节点重试、失败节点 successor Run 重跑及恢复和所有权约束。
- 桌面交互：缩放、侧栏分页和定位、会话轮次导航、输入框高度、Meadow／Vista 主题和六张内置壁纸。
- 兼容修复：MCP tools/list、WebView 启动初始化、单个无效 Agent 配置隔离。

明确排除：Multica 角色／Workflow 资产分发、卸载、工单响应、新 Runtime 协议和 3 秒心跳（#11、#36）；WB WeAPM／渠道改动；独立营销网站与知识库。现有 Multica 实现和文案保留，仅测试夹具补齐通用 RunState 的可选 rerun 字段。项目共享 rules／AGENTS 不随 fork 改写。

## 整合调整

- 保留主线已有的 composer stack、草稿取用后焦点、MCP 冷启动超时及 orphaned turn 交互恢复。
- 引导的环境警告与 deferred 退出统一按实际 Agent 启动路径解释，补 npm 受限时稍后设置回归。
- 修复 fork 轮次导航的整段 timeline 重读、空结果不更新及加载期间丢失刷新；复用现有 locator LRU，64 条分页、256 条前端窗口，保留滚动锚点。
- 保留既有 Multica locale 真源；修正 resize 手柄的翻译路径并使用 Tooltip 组件；新主题遵守既有中性低对比滚动条契约。
- 壁纸偏好测试接受新 canonical 语义：切到不提供壁纸的主题时 theme 来源折叠为 none，调用方输入保持不变。

## 过度设计与性能评审

复用 prompt-kit、shadcn/ui、现有 ACP／Workflow 状态机、配置提交边界及 timeline locator 索引。cap-std 用于文件引用的目录能力边界，semver 用于 Node/npm 兼容判定；不为导航新增依赖或持久字段。

导航首屏与刷新读量有界，IPC 阻塞读取在 blocking worker；不带入 3 秒渠道心跳。130 轮后端接口用例验证每页最多 64 次 prompt 读取、最新轮类型更新 1 次读取且不读工具正文；10,000 轮前端模拟验证最多 256 个导航 DOM。文件引用、引导诊断、失败节点资产复制使用迁入实现的有界数量／大小与并发限制。主题资源只按已选主题／色系消费，资源总量约 11 MiB（六张 WebP），包体会相应增加。
