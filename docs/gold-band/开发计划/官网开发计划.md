# Gold Band 官网开发计划

## 目标与依据

从独立工程开始完成 Gold Band 官网的设计、录制、开发、验收与静态部署。产品范围和分镜以 [官网产品方案](../产品设计文档/interaction/官网.md) 为准。

交付 Home、Documentation 占位页、完整浏览器 Demo 及入口、中英文、四段产品宣传回放及配套录制工具。深浅色主题与素材联动按产品方案推荐，在视觉设计阶段确定范围。

官网按从零建设规划；Demo 复用已实现的页面、入口、只读适配器与样例，只补充接入、指定完整会话数据和必要适配。未勾选任务表示本次交付尚待实施或验证，不表示已有 Demo 能力需要重做。客户端前端同时作为录制源和 Demo 共享页面来源；桌面 API 契约、后端与默认运行行为保持不变。

- [ ] 定义字体、字号、间距、颜色、边界、图标及动画 token。
- [ ] 打开 pi.dev，在桌面与手机视口记录首屏、演示区、文案和导航的参考截图。
- [ ] 使用 ui-ux-pro-max、ckm:ui-styling 制定视觉规范，明确对齐的构图与节奏。
- [ ] 设计桌面左演示右文案、手机上演示下文案的页面结构；首屏体现品牌和产品，并露出下一段线索。
- [ ] 编写四场景中英文文案和分镜表，定义关键操作、取景、停留与配速。

出口条件：页面结构、视觉规范和分镜可直接指导实现，四段使用同一个预设任务，关键镜头有明确阅读目标。

## 第二阶段：建立工程与录制链路

- [ ] 创建 Vite、React、TypeScript 工程，配置 Tailwind CSS、shadcn/ui、资源路径与独立构建。
- [ ] 建立页面内容、素材清单、镜头、配速、语义检查点和回放状态的数据结构。
- [ ] 建立独立录制入口，装配客户端前端及受控场景数据，通过客户端事件契约驱动展示。
- [ ] 集成 rrweb 录制与回放引擎，生成事件文件和海报，校验资源可移植性。
- [ ] 设置每段 60 秒、12 MiB、12,000 events 的素材预算，超限报告错误。
- [ ] 将录制工具、客户端前端、官网回放和公开 Demo 的运行边界分开；官网首屏不加载客户端应用。

出口条件：能够重复生成一个独立于录制服务器运行的回放，文件、字体与样式正常加载。

## 第三阶段：完成工作流控制样片

先完成风险最高的第二段，验证录制技术和叙事，再批量制作四段素材。

- [ ] 放大工作流结果判定菜单，展示人工 check、AI 输出验证、不启用。
- [ ] 选择 AI 输出验证，展示 JSON 输出约束及成功表达式。
- [ ] 展示流式文字、思考、工具调用、提问及权限申请，清楚呈现等待和恢复。
- [ ] 录制输出决定分支：false 进入修正，修正后 true 进入后续节点；会话与工作流图由同一场景状态驱动。
- [ ] 在源页面与回放的对应时刻检查图、菜单、浮层、光标及状态推进，禁止仅靠装饰性节点动画表达执行结果。
- [ ] 打开实际前端观看样片，验证普通步骤快、关键结果慢、回到全景后能看懂路径关系。
- [ ] 验证平滑 zoom in/out、变速与回放时钟同步、暂停和继续。

出口条件：观众能看清“输出内容如何决定下一步”，回放与源页面一致，镜头和配速顺滑。

## 第四阶段：制作完整素材

- [ ] 配置 Harness：Agent、角色、Skill 多 Agent 管理，Direct、Workflow、AUTO 的配置体验。
- [ ] 实时观测与控制：将第三阶段样片完善为完整场景。
- [ ] 审阅任务：附件、悬浮 Diff、最新工作区文件编辑、源码 Diff、暂存和本地提交状态。
- [ ] 定制应用：主题、字体、头像，以及真实 viewport 的三栏 → 双栏 → 单栏 → 双栏 → 三栏变化。
- [ ] 校验悬浮与 Portal 在回放中的可见性；模拟状态与真实执行证据分别记录。
- [ ] 真实 Git 验证在隔离临时仓库进行，不操作用户工作仓库或远程推送。
- [ ] 为关键操作配置取景与节奏：普通步骤约 1.5–2 倍，重点约 0.8–1 倍，阅读停留约 1.5–3 秒，镜头约 350–600ms 进出。
- [ ] 制作手机取景轨道；同一素材无法保证可读性时单独录制局部镜头。
- [ ] 双主题范围确定后，生成四场景 × 两语言 × 两主题素材及海报；主题配对通过语义检查点对应。

出口条件：四段故事内容连贯、关键操作可读、素材符合预算，可由脚本重复生成。

## 第五阶段：实现官网页面与回放

- [ ] 实现 Home、Documentation 占位页与实际 Demo 应用入口，Demo 不以占位页替代交付。
- [ ] 实现中英文切换及选定的主题方案，保留当前页面与章节。
- [ ] 根据可用宽度决定左右或上下结构，pointer/hover 能力只影响对应交互。
- [ ] 实现桌面 sticky 演示与章节切换，手机自然纵向滚动；滚动不直接控制帧进度。
- [ ] 实现基于统一时间轴的取景与配速，不显示访客倍速、进度条或全屏播放器面板。
- [ ] 提供最小可访问暂停/继续入口，支持 reduced-motion，页面隐藏或演示离屏时暂停。
- [ ] 实现素材懒加载、海报、加载失败重试及版本校验，同一时刻最多一个活动回放。
- [ ] 双主题切换按语义步骤恢复进度，处理快速切换、加载失败和迟到响应。
- [ ] 切章、语言、主题或离开页面时清理回放、监听器、RAF 与请求。
- [ ] 通过 transform 更新镜头，不把每帧像素或时间写入页面根 React 状态。

出口条件：官网能独立运行，四场景在不同宽度和语言下完整呈现，回放状态和资源生命周期正确。

## 方案评审

- 架构：官网、录制源和 Demo 职责分离，展示层不拥有客户端业务执行状态。
- 过度设计：固定四场景、轻量镜头/节奏数据及静态素材即可满足需求，不开发通用剪辑台、完整 mock 后端或移动客户端。
- 性能：按当前场景/语言/主题加载，单个活动实例，固定素材上限；避免全量预加载、重复解析与高频全局重渲染。
- Demo：共享页面加只读适配器和静态数据，不增加完整模拟后端；完整会话按实际规模分页和懒加载，宣传片预算不适用于其历史数据。
- 数据依赖：指定会话必须从源电脑取得并核验，不能用虚构数据替代完整验收；该依赖不阻塞独立页面与其他样例建设。
- 风险：工作流图、hover/Portal 还原、变速时钟、双主题步骤对齐和手机可读性优先由样片验证。
