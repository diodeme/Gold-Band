# 用户交互后执行状态收敛计划

**目标：** 定时任务因 AskUserQuestion 或 Workflow 人工验收进入 `attention_required` 后，用户完成交互时让原 occurrence 立即恢复为 `running`，并在原 Run 结束后继续收敛为 `succeeded` 或 `failed`。

**架构：** occurrence 仍是唯一权威生命周期。AskUserQuestion 与 ManualCheck 共用统一恢复边界，在写入 durable elicitation response 或提交人工判定前，通过完整的 Task/Run/Round/Attempt locator 请求 scheduler 恢复原 occurrence；scheduler 完成数据库 claim、heartbeat 注册、definition 投影和 `running` 事件后返回原 occurrence ID。ManualCheck 将该 ID 注入后台 App，使后续 lifecycle 终结同一记录。普通非定时交互没有匹配 occurrence 时维持现有流程；已识别为定时恢复但 claim 失败时返回结构化错误，不推进业务状态。

**性能边界：** 每次交互仅增加现有复合 locator 的单行查询、单行 claim、既有 revision/CAS 投影更新和一次事件发布；不增加轮询、历史扫描、N+1、无界缓存或扩大的锁范围。
