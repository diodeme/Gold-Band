# Scheduler Schema Drift Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover a scheduler database marked as v2 while it still has the v1 occurrence table, preserving definitions and deleting unverifiable legacy occurrences.

**Architecture:** Keep `core_schema` as the version selector, but verify the v2 occurrence capability before running v2-to-v3. When the marker and physical schema disagree in the known v2/v1 shape, reuse the existing transactional v1-to-v2 rebuild and then the existing v2-to-v3 migration.

**Tech Stack:** Rust, rusqlite, SQLite transactional DDL, Cargo tests.

- [x] **Step 3: Implement the smallest schema capability check**

Add a private helper that reads `PRAGMA table_info(scheduled_occurrences)` and proves all v2-only columns exist. In the `Some(2)` branch, call `migrate_schema_v1_to_v2` only when that capability is missing, then always call `migrate_schema_v2_to_v3` and update the marker in the same transaction.

```rust
const SCHEDULER_V2_OCCURRENCE_COLUMNS: [&str; 4] = [
    "schedule_revision",
    "node_id",
    "accepted_at",
    "execution_snapshot_json",
];

fn occurrence_schema_has_v2_capability(transaction: &Transaction<'_>) -> Result<bool> {
    let mut statement = transaction.prepare("PRAGMA table_info(scheduled_occurrences)")?;
    let columns = statement.query_map([], |row| row.get::<_, String>(1))?;
    let columns = columns.collect::<std::result::Result<std::collections::HashSet<_>, _>>()?;
    Ok(SCHEDULER_V2_OCCURRENCE_COLUMNS
        .iter()
        .all(|column| columns.contains(*column)))
}
```
