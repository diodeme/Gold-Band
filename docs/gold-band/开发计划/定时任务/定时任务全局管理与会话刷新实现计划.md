# 定时任务全局管理与会话刷新实现计划

## 目标

管理页展示所有已登记工作区的定时任务；后台触发新 Task/Run 后，左侧会话列表自动刷新；Workflow/AUTO 重复执行复用同一 Task 并创建新的 Run。

## 数据与接口

- `ScheduledTaskVm` 增加 `workspaceName`，`projectId` 继续作为启停和筛选的稳定标识。
- `list_scheduled_tasks(projectId = null)` 聚合所有已登记工作区；传入 `projectId` 时保留局部查询能力。
- 创建、启停和调度状态保存后发布 `gold-band://scheduled-task-updated`，仅供定时任务列表和详情局部合并调度投影。
- App 根层只使用 `gold-band://conversation-run-state-updated` 维护会话侧栏。事件命中已加载 Run 时直接合并；已知 Task 出现新 Run 时读取该 Task 的首批 Run 摘要；当前工作区出现新 Task 时读取该工作区首批 Task 摘要。定时任务定义变化和置顶关系未变化时均不读取置顶分页。

## 实现状态

- [x] 多工作区聚合查询与工作区名称映射。
- [x] Workflow/AUTO 在同一 Task 下递增创建新的 Run。
- [x] Scheduler 成功、失败、跳过和重试状态保存后发布更新事件。
- [x] App 根层从通用调度事件刷新迁移到会话运行状态事件，按稳定 locator 定向发现新 Task/Run。
- [x] 启停等定义变化不再触发工作区或置顶会话分页；新 Run 只读取所属 Task，新 Task 只读取当前工作区首屏。
- [x] 管理页改为全局扁平列表，增加工作区筛选和行内工作区归属。
- [x] 任务标题下的副信息末尾展示工作空间名称，并与标题共用单行省略规则，避免长名称撑宽列表。
- [x] 管理页启停使用任务自身 `projectId`，避免跨工作区操作错误。
- [x] 浏览器 fallback 支持多个定时任务并发布本地更新事件。
- [x] Rust 与 Web 接口层回归测试。

## 验收

- 两个工作区创建的定时任务同时出现在“全部工作区”列表，筛选只改变可见行。
- 任务副信息按模式、Direct 会话策略、窄屏计划摘要、工作空间的顺序展示；工作空间位于末尾，超长副信息单行省略且不产生横向滚动。
- Workflow/AUTO 首次触发得到 `task-001/run-001`，下一次触发得到 `task-001/run-002`。
- 后台触发后无需切换页面，左侧会话列表出现新 Task 或新的 Run。
- 管理页的状态、下次执行时间和最近运行状态通过 CRUD 返回实体或调度事件局部合并。
- 切换启用开关不会令工作区会话或置顶会话进入 loading，也不会发起对应分页请求；真正的新 Task/Run 仍通过会话运行状态事件定向出现。
