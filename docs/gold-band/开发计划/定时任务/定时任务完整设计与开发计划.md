# Gold Band 定时任务开发计划

## 目标

为 Direct、Workflow、AUTO 增加统一的定时触发能力，复用现有 Task/Run/ACP 生命周期，并提供 composer 创建入口和左侧定时任务管理页。

## 已确认范围

- 定时任务是触发层，不是第四种运行模式。
- 支持 `At`、重复预设、固定间隔 `Every`、自定义 Cron。
- `Every` 只支持分钟和小时；首次启用记录 `anchorAt`，暂停不补跑，重新启用或修改间隔时重新起算。
- Workflow/AUTO 只能新会话；Direct 支持新会话和持续会话。
- 默认启用队列保护；关闭后按 30 秒间隔最多重试 3 次。
- 错过执行不补跑。
- 会话使用 AlarmClock 图标标注，不增加任务名称字段。

## 2026-08-03 可靠性与 Direct 对齐修订

本修订覆盖 AionUi 当前 Direct 定时任务能力，并修正上一版计划将“启动后台执行”误认为“执行完成”的问题。Direct 必须补齐立即执行、任务详情/执行历史、诊断字段、full-auto 校验、missed、崩溃恢复、lease/heartbeat、完成通知和保持唤醒；Workflow/AUTO 复用同一 occurrence 生命周期，但保留 Gold Band 自身的内容指纹、Task/Run、Workflow snapshot 和 AUTO authoring 规则。

定时任务不增加独立名称字段，展示标题取 instruction 第一条非空行。旧 JSON definition/trigger 只做一次性迁移，新的 scheduler source of truth 改为独立 SQLite 数据库；不保留双写和旧 runtime fallback。

无人值守处理固定为：permission request 以 `failed + SCHEDULED_PERMISSION_REQUIRED` 结束；`AskUserQuestion` 以 `attention_required + SCHEDULED_USER_INPUT_REQUIRED` 结束并保留可恢复 Run。两者都必须释放 scheduler lease，不能无限等待。

- [x] 实现 `scheduled-task.json` 校验：模式与 session policy 约束、IANA 时区、Every 正整数和分钟/小时枚举。

### 2. 调度计算器

- [ ] 调度器只创建/认领 occurrence 并调用 App 既有 Task/Run API；真实完成事件必须带 occurrence ID，不能把进程启动标记为成功。
