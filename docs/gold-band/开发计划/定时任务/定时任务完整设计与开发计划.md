# Gold Band 定时任务开发计划

## 目标

为 Direct、Workflow、AUTO 增加统一的定时触发能力，复用现有 Task/Run/ACP 生命周期，并提供 composer 创建入口和左侧定时任务管理页。

## 已确认范围

- 定时任务是触发层，不是第四种运行模式。
- 支持 `At`、重复预设、固定间隔 `Every`、自定义 Cron。
- `Every` 只支持分钟和小时；首次启用记录 `anchorAt`，暂停不补跑，重新启用或修改间隔时重新起算。
- Workflow/AUTO 只能新会话；Direct 支持新会话和持续会话。
- 默认启用队列保护；关闭后按 30 秒间隔最多重试 3 次。
- 错过执行不补跑。
- 会话使用 AlarmClock 图标标注，不增加任务名称字段。

## 2026-08-03 可靠性与 Direct 对齐修订

本修订覆盖 AionUi 当前 Direct 定时任务能力，并修正上一版计划将“启动后台执行”误认为“执行完成”的问题。Direct 必须补齐立即执行、任务详情/执行历史、诊断字段、full-auto 校验、missed、崩溃恢复、lease/heartbeat、完成通知、保持唤醒和定时任务 skill；Workflow/AUTO 复用同一 occurrence 生命周期，但保留 Gold Band 自身的内容指纹、Task/Run、Workflow snapshot 和 AUTO authoring 规则。

定时任务不增加独立名称字段，展示标题取 instruction 第一条非空行。旧 JSON definition/trigger 只做一次性迁移，新的 scheduler source of truth 改为独立 SQLite 数据库；不保留双写和旧 runtime fallback。

无人值守处理固定为：permission request 以 `failed + SCHEDULED_PERMISSION_REQUIRED` 结束；`AskUserQuestion` 以 `attention_required + SCHEDULED_USER_INPUT_REQUIRED` 结束并保留可恢复 Run。两者都必须释放 scheduler lease，不能无限等待。

## 实施任务

### 1. 领域模型与持久化

- [x] 在 Rust runtime 增加 `ScheduledTaskDefinition`、`ScheduleSpec`、`EverySpec`、`OverlapPolicy`、`ScheduledTrigger` 等类型。
- [ ] 将旧 per-project JSON definition/trigger 迁移到独立 SQLite scheduler store，使用 occurrence 唯一约束、原子认领、lease、heartbeat 和输入附件快照。
- [x] 实现 `scheduled-task.json` 校验：模式与 session policy 约束、IANA 时区、Every 正整数和分钟/小时枚举。
- [x] 为 task content 建立稳定指纹；Workflow/AUTO 的 Agent 身份、Agent 策略和可用 Agent 集合属于 authoring 并参与指纹，只有 model、thought level、permission 和 Direct session policy 不参与指纹。
- [x] 为 schema 添加 Rust 接口层单元测试，覆盖非法单位、非法模式、空指纹和重复启用。

### 2. 调度计算器

- [ ] 使用成熟 Cron 解析/计算库实现 `At`、真正的每个整点 Hourly、每天、工作日、每周多选和自定义 Cron。
- [x] 实现 `Every` 的 anchor 计算、暂停/重新启用重置和间隔编辑重置。
- [ ] 明确系统默认时区、DST wall-clock 计算；`Every` 使用绝对时间间隔。
- [ ] 实现 missed 记录和下一个未来时间点计算，不生成补跑 run。
- [ ] 为边界时间、周日跨周、多选星期、DST 和 Every 重置行为添加接口测试。

### 3. Scheduler 与队列保护

- [ ] 用每任务 timer 替换每秒全量轮询；启动和系统唤醒显式恢复 lease、标记 missed，并只安排未来时间点。
- [ ] 对 running、permission waiting、AskUserQuestion、waiting-for-user 和 resumable paused 统一识别 active，并通过 occurrence claim 防止跨进程重复执行。
- [ ] `skip_when_running` 和 `retry_when_busy` 作用于 occurrence；busy 重试有明确上限，错误执行不无限重试。
- [ ] 调度器只创建/认领 occurrence 并调用 App 既有 Task/Run API；真实完成事件必须带 occurrence ID，不能把进程启动标记为成功。
- [ ] 覆盖启动恢复、lease 到期、并发 claim、唤醒 missed、permission、AskUserQuestion、run-now 和进程关闭测试。

### 4. Task/Run/ACP 集成

- [x] 增加创建、更新、启用、暂停、删除和查询 scheduled task 的基础命令接口。
- [ ] 增加立即执行、occurrence 历史、诊断字段和 attention 状态的命令接口。
- [x] Workflow/AUTO 根据 content fingerprint 复用 task 或在下一触发物化新 task；每次内容不变的触发创建新 run。

- [x] 为 Direct Agent 不可修改、Direct workspace/content 变化、Workflow/AUTO Agent/authoring 变化和 model/thought level/permission 变化分别增加回归测试；验证 Workflow/AUTO Agent/authoring 变化后下一次触发创建新 Task，仅执行配置变化时复用 Task 并创建新 Run。
