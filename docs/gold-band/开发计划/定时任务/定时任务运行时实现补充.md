## 2026-08-06 Task 4：deadline coordinator

- [x] 引入 `tokio-util::time::DelayQueue`，同一 enabled job 只保留一个计时项；更新替换旧 deadline，暂停、删除和 workspace 移除取消 deadline。
- [x] CRUD/service 保持创建只持久化定义和输入快照；提交成功后只通知 coordinator 重排，不在创建动作中调用模型。
- [x] timer 注册和触发均重新读取 SQLite `revision`、`enabled` 与 `next_run_at`；陈旧 callback 不物化 occurrence。
- [x] `JobDisabled`/`JobDeleted` 只作为失效通知，命令循环重新读取 SQLite 最终状态；乱序到达的旧通知不会取消已经重新启用或重建的 job。
- [x] 首次到期使用事务型 `materialize_due_occurrence` 创建 scheduled occurrence；run-now 通过显式 `RunNow` 命令立即创建 manual occurrence，且不推进 `next_run_at`。成功执行后的 Task 关联、最近结果等元数据持久化允许推进 `revision`，coordinator 按最新记录刷新原 deadline。
- [x] workspace 启动注册执行 schema/幂等迁移、过期 lease 恢复和 reconcile；旧 JSON/共享数据库在读取或打开前先检查 durable marker，已完成迁移时忽略损坏的废弃源。
- [x] pending/retrying 通过 SQLite partial index 直接查询最老一条，不再受 10,000 条历史扫描上限影响，然后才处理后续计划点。
- [x] 早于 `LATE_FIRE_GRACE` 的时间点标记为 `missed`；单个 coordinator turn 最多处理 `MISSED_RECONCILE_BATCH_SIZE` 条后返回 command/deadline select，并以持久化的过去 `next_run_at` 立即续排下一批，grace 内近迟到点保持可执行。
- [x] coordinator 在 Tauri async runtime 中启动；系统 resume 触发 reconcile，退出触发 shutdown；删除全局一秒轮询。
- [x] paused-time 测试覆盖精确注册、替换、取消、stale revision、乱序 disable/delete、`SchedulerCoordinatorHandle::RunNow`、manual deadline 保持（不要求执行元数据写入后 revision 不变）和 missed/grace 边界。
- [x] 所有 runtime definition 回写统一携带 claim 时的 `ScheduledJobRecord.revision`，通过 `update_job_runtime_projection` CAS 持久化；并发 authoring 的 `Conflict` 与删除后的 `NotFound` 均按 stale no-op 处理，不覆盖也不复活 job。生命周期回写使用 `project_id + job_id` 精确查询，不扫描全表。
- [x] repository 增加 project-scoped recoverable-job 查询，合并 enabled job 与拥有 pending/retrying/running occurrence 的 job，并返回最早 running `lease_until`。coordinator 对 retry、lease 和业务 `next_run_at` 取最早唤醒时间，deadline 回调先执行 expired-lease recovery；disabled one-shot 的非终态 occurrence 同样可以恢复。
- [x] graceful `Shutdown` 将当前 owner 仍持有的 running occurrence 释放为 `retrying + SCHEDULED_LEASE_LOST`；Task 5 再把现有 process-level heartbeat 拆成 per-occurrence guard。
- [x] `RegisterWorkspace` 瞬时失败使用命名退避常量去重重试；新 registration 构建成功后才替换旧 registration，失败时保留旧 deadline。正常成功或 workspace 移除会使待到达的旧 retry 命令失效。
- [x] 使用命名 interval/tolerance 比较 process-level wall clock 与 monotonic clock，仅检测到跳变时消费 `ReconcileReason::TimerDrift` 做全量 reconcile，不恢复一秒 job polling。
- [x] 新增真实 paused-time command-loop 验收：`RegisterWorkspace/JobCreated -> Tokio advance + 可控 wall clock -> deadline -> SQLite materialize/process -> re-register`；同时覆盖 lease 精确到期、首次注册失败后成功、旧 registration 保留、TimerDrift 和 shutdown release。
- [x] 将 workspace refresh 收紧为 replace-on-success：候选 registration 在独立 reconcile 完整成功后才替换旧对象；open/migration/query/process 任一步失败都会按原 `revision + wake_at` 重建旧 deadline 集合，2 秒去重重试成功后才提交候选。
- [x] `SchedulerCoordinatorHandle::shutdown()` 增加 oneshot ack 并持有唯一 coordinator `JoinHandle`；真实 command loop 严格按 release owned leases -> ack -> exit 执行，调用方在 ack 后继续 join task。Tauri `ExitRequested` 使用原子 started/completed 状态防重入，完成前持续 `prevent_exit`，完成后只允许程序化重试退出。
- [x] manual run-now 与 missed recovery 全部切换到 project-scoped、require-existing-definition 的 occurrence 仓储接口；delete 竞态返回 not found，不允许 `ensure_job_row` 在活跃 runtime 中复活 job 或产生 ghost occurrence。placeholder helper 仅保留给核心仓储的隔离单测。
- [x] 新增接口级回归：候选 reconcile 中途失败保持旧 registration/deadline 且 2 秒重试后才替换；shutdown ack 返回前 release 已调用；due materialize 后 delete 再 missed、stale run-now record 后 delete 均不会重建任何 job/occurrence。
- [x] deadline 回调弹出注册项后保留原 `revision + scheduled_deadline`；DB、materialize、process 或 refresh 任一步失败都用 `DEADLINE_FAILURE_RETRY_DELAY` 自重装，下一次回调重新读取 SQLite，不依赖外部命令唤醒。
- [x] manual/scheduled claim 到真实执行接受之间统一使用 `ClaimToHandoffGuard`；任意早退错误自动移除 active 并释放为 retrying，即时终态显式 disarm，成功执行后 handoff 给 lifecycle。
- [x] `Shutdown` ack 升级为 `ScheduledServiceResult<()>`，release 失败返回结构化错误；handle 无论 ack 成功、失败或丢失都先 join coordinator task，再优先返回原 release/ack 错误。
- [x] `ClockDriftDetector` 改为累计 wall/monotonic residual，只有累计超过容差或墙钟倒退才触发 reconcile 并重置基线；正常单调推进不重复触发。
- [x] `TimerDrift` reconcile 使用 coordinator-owned pending 状态；失败时保留 pending 并在下一个 `CLOCK_DRIFT_CHECK_INTERVAL` 重试，只有完整成功才清除，不因 detector 已重置基线而丢失恢复机会。
- [x] coordinator 使用公平 `tokio::select!`，控制命令洪峰不会无限饿死 deadline、lease heartbeat 或 clock check；scheduled busy retry 改为唯一调用 `scheduler::queue::decide_queue`，不再复制重试次数或间隔。
- [x] 新增接口级回归：deadline process failure 无外部信号 2 秒后重试成功；manual/scheduled active probe 错误均释放 claim；shutdown release 与 join 双失败时仍完成 join 并优先返回 release/ack 错误；多段单次低于阈值但累计越界的漂移只在越界时触发；TimerDrift reconcile 首次失败后会在下一次时钟检查成功重试。
- [x] 新增响应性回归：600 个 missed 点的 reconcile 单轮不会穷尽 backlog；控制命令积压时到期 deadline 仍可执行。
