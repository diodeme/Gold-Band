# Direct / Workflow / AUTO 生命周期指标重构计划

## 1. 目标

按 `产品设计文档/runtime/metrics-collection.md` 将 `POST /api/client-report/metrics/batch` 从节点快照协议替换为生命周期事件协议。仅 wb 渠道启用，直接删除旧的前序节点补报、开始/结束哨兵和兼容消费路径。

## 2. 数据先行

先冻结 core 数据，再修改发布点：

- `SessionMode`：Direct / Workflow / Auto。
- `ExecutionKind`：Turn / Run / NodeAttempt / OuterRun / UnitAttempt。
- 生命周期事实：started、completed、paused、resumed、intervention、acceptance completed。
- `ExecutionOutcome`、`TerminalReason`：结构化 enum，不携带对客文案。
- usage/model snapshot：按实际 resolved provider/model 分段的 token 与 ACP 净处理时间。
- terminal counters：只保留 pause、resume、permission request、elicitation、manual continue 五项。
- execution relation：execution、parent、node/turn/outer/unit/child run ID；删除冗余 runId/roundId，增加 roundIndex。
- `eventRevision`：run/outer/turn 按 executionId 递增，node/unit attempt 按 attemptId 递增并持久化；eventId/executionId/attemptId 全部使用 UUID。
- 指标 attempt：服务端以 attemptId 留存 Usage。Direct 满足 attemptId 等于 executionId 且 attemptIndex 固定为 1；Workflow/AUTO 的 executionId 标识稳定逻辑 node/unit，attemptId 标识一次真实尝试，attemptIndex 在同一 executionId 内从 1 严格递增；重试同时更换 attemptId/attemptIndex 但保持 executionId，parentExecutionId 指向 run/outer-run。

HTTP DTO `MetricsEventItem` 只在 `src-tauri` 管理，core runtime 不依赖 HTTP 协议。

## 3. 实施阶段

### Phase 1：协议与纯映射

- 新增生命周期事件 DTO、字段 enum 和序列化测试。
- 实现三种模式领域事件到 DTO 的纯映射。
- 统一 `eventId`、时间、原始 `userId/workspace`、clientVersion 的生成和快照规则。
- `reportedAt` 入队冻结，重试复用；reporter 按月份拆批。
- 删除 `billableTokens`，只保留 provider 原始 token。
- 定义完整 enum 集合、`counters` 计算器和 `modelUsages[]` 聚合器。
- 定义 outcome/terminalReason 合法组合；Workflow node attempt 快照 roleName。

完成条件：三种模式示例与字段表一致，JSON contract 测试通过。

### Phase 2：补齐领域事实

- Direct：首轮与后续追问统一发布 turn start/terminal，消除内部 Workflow 重复指标。
- Workflow：发布 run、node attempt、pause/resume、intervention 完整生命周期。
- Workflow node attempt 上报 nodeId、roundIndex 和 resolved roleName，不上报 runId/roundId。
- AUTO：发布 outer run、所有 dynamic unit attempt、每次 acceptance，并补齐父子关系。
- 每次 ACP prompt 用 resolved provider/model 和 usage delta 形成 segment；模型切换后分别累计。
- counters、revision、request ID 去重集合和 model usage accumulator 由生命周期所有者统一管理。
- 独立 `observability.snapshot.json` 后台尽力持久化；失败不影响会话。

完成条件：每个执行单元有且仅有一个 start 和 terminal；覆盖 success/failure/cancel/kill/pause/resume。

### Phase 3：非阻塞上报

- setup 时仅 `channel == wb` 注册 `desktop.metrics`。
- subscriber 使用容量 2048 的 `tokio::mpsc` 和 `try_send`。
- reporter 按 100 条或 2 秒 flush，有限重试，退出最多等待 500 ms。
- 唯一 `metrics.log` 最大 20 MB；超限清空并写 reset。每次发送/重试记录 requestId、时间、完整请求体和响应/错误，认证头不落日志。
- 删除旧 `NodeMetricItem`、sentinel、前序补报和 node-start HTTP 路径。

完成条件：慢网、断网、5xx、队列满、subscriber panic 均不改变 runtime 结果。

### Phase 4：服务端与联调

- 服务端按 `eventId` 幂等接收 `events`。
- 固化七个价值维度的聚合口径，避免 parent/child 成本双计。
- wb 构建联调三种模式，确认原始 `userId/workspace` 到达服务端。
- 删除服务端旧 `metrics[]` 节点协议，不保留双写。

完成条件：七个价值维度均可由原子事件查询或聚合。

## 4. 必须固化的测试

### Core / Rust

- Direct 首轮与后续 turn 的 completed/failed/cancelled。
- Workflow run success/failure/killed、首轮/多轮、node retry provider/model。
- Workflow pause → resume、intervention 类型、node failure 定位。
- AUTO outer success/failure/killed，以及四种 `unitKind`。
- acceptance 首次通过与修复后通过；outer/leaf failure 关联。
- resolved model、token、cache、ACP 时间映射和可选字段缺失。
- A → B → A 模型切换的分模型 usage、最终模型与汇总 usage；不增加模型切换次数。
- 顶层 usage 等于非 null 已知段之和，并按确认口径视为完整总量。
- pause/resume、permission、elicitation、manual continue 的去重计数和零值序列化。
- counters 只出现在 Direct turn、Workflow run、AUTO outer-run 终态，node/unit 终态不得携带。
- 队列满不 panic、不等待；subscriber/reporter 失败不影响会话。
- default 不注册；wb 缺 endpoint/key 时不发送。
- 队列满直接丢弃新指标并记录 queue/capacity/eventKind；HTTP 队列额外记录 eventId/executionId。snapshot 队列满或断开时记录 path/revision；所有日志失败均不影响会话。

### HTTP contract

- 字段名、全部 enum 允许值、ISO-8601、批量上限和请求头快照。
- `userId/workspace` 保持原值，workspace 切换后已排队事件不串写。
- eventId 重放幂等；4xx 不重试；timeout/5xx 有限重试。
- `metrics.log` 对每次 attempt 记录日志时间和完整请求体，响应/异常完整可对照，且无 API Key。

### 端到端

- wb 构建分别执行 Direct、Workflow、AUTO 的成功与停止路径。
- Workflow 制造 pause/resume 和 node failure；AUTO 制造 acceptance repair 与 leaf failure。
- 对照 runtime 与服务端事件的父子关系、终态、counters、分模型 token、ACP 时间。
- 慢响应代理下验证 UI、ACP 流和 runtime 终态不受阻塞。

## 5. 预计修改范围

| 路径 | 方向 |
|---|---|
| `src/app/mod.rs` | 生命周期事实补充模式、关系、model usage、counters、terminal reason |
| `src/app/observability.rs` | 沿用 bus，增加隔离测试，不承载 HTTP |
| `src/app/orchestrator.rs` | 在真实状态转换处发布 Workflow/AUTO 事实 |
| ACP prompt dispatcher | 统一 Direct turn 生命周期与 usage 快照 |
| `src-tauri/src/metrics.rs` | 生命周期事件 DTO、wb gate、collector/reporter；删除旧协议 |
| `src-tauri/src/main.rs` / `state.rs` | wb setup 与 reporter 生命周期 |
| 服务端 client-report | 新协议接收、幂等与价值聚合 |

## 6. 非目标

- 不引入 OpenTelemetry、Kafka、本地数据库 outbox 或 schema registry。
- 不追求崩溃场景 exactly-once；先以 eventId 幂等和有界队列满足非阻塞。
- 不在客户端计算无干预率、全自动交付率等报表指标。
- 不保留新旧协议双写或旧哨兵兼容逻辑。
- 不改变三种会话的调度、暂停、恢复、停止与 ACP 行为。

## 7. 完成定义

- 产品设计、客户端 DTO、服务端 DTO、contract 测试一致。
- 七个价值维度可追溯，无 Direct 首轮和 AUTO child workflow 重复统计。
- 仅 wb 采集；每条事件包含产生时的原始 `userId/workspace`。
- Rust 单元测试、HTTP contract 与三模式端到端验收通过。
- 实现后回写本文进度、验证命令与结果，并同步维护产品设计文档。

## 10. 2026-08-01 影响性评估加固记录

- 修复 P0 门禁语义：是否创建 core 指标事实生产者由 `wb + endpoint + API key` 统一决定；默认渠道不再派生事实或写 observability snapshot。
- 将节点事实派生和 snapshot 持久化分别收敛为单个有界后台 worker，业务线程只做 `try_send`；snapshot 保持 revision 写入顺序。
- Direct executionId 改为 started 时生成的严格 UUID，并同时作为 attemptId；permission/elicitation 与 terminal 使用 attempt 上下文关联同一 UUID，不再发送冗余 turnId。
- 增加 attemptIndex contract 回归：缺失/0、Direct 非 1、delivery 携带均拒绝；started/terminal/acceptance 保持同一序号；DTO 固定输出 `attemptIndex`。
- terminal 后清理 Direct、run、acceptance、node 的内存状态，消除持续运行下的线性增长风险。
- reporter 退出 flush 延续单批最多 100 条约束，且整个退出发送窗口最多 500 ms；补充慢端点关闭测试。
- metrics subscriber 在映射前调用领域 `validate()`，结构非法的事件不会进入 HTTP 队列。

对应回归覆盖：默认关闭/显式开启门禁、snapshot 最新 revision、退出批量上限、500 ms 有界关闭，以及既有 DTO/月份拆批/重试/日志契约测试。
