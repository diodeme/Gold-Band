## 1. 开发目标

在不新增上报端点的前提下，破坏式升级：

- `POST /api/client-report/heartbeat`
- `POST /api/client-report/metrics/batch`

覆盖 Direct、Workflow、AUTO 三种模式，并保证：

1. Direct 按 turn 统计，内部单 Worker 壳不重复进入 Workflow 指标。
2. Workflow 按 runtime run 统计，node/attempt 用于下钻。
3. AUTO 按 outer run 统计，dynamic graph 与 child workflow 保留父子关系。
4. started 是分母、finished 是终局。
5. 指标事件本地持久化，网络失败和应用重启不丢失。
6. token 按 turn/attempt 增量上报，AUTO 容器与子节点不重复。

本计划不实现数据看板 UI；客户端、接口契约、服务端事实表和接口级测试属于范围。

---

## 2. 现状与根因

当前 `src-tauri/src/metrics.rs`：

- heartbeat 使用环境变量读取用户名并上传 workspace，且无条件每 15 分钟轮询；
- node metrics 在 NodeStarted/NodeCompleted 时直接发 HTTP；
- HTTP 失败只写日志；
- NodeStarted 产生前驱、RUNNING 和 sentinel 噪声；
- RunCompleted、RunPaused、InterventionRequested 被 `_ => {}` 丢弃；
- NodeMetricItem 无 attemptId、provider、model；
- node metrics 使用 UUID fallback，但 run lifecycle 使用展示 ID，服务端无法稳定 JOIN。

根因不是缺少三个 match 分支，而是分析领域仍以“节点快照”为中心，无法表达 Direct turn、run 分母和 AUTO 动态父子关系。V2 先统一数据结构，再改接口和实现。

## 3. 复用成熟能力

### 3.1 直接复用

- `RuntimeLifecycleBus`：继续作为进程内领域事件分发。
- `rusqlite`：实现 durable outbox，不引入新数据库依赖。
- `reqwest`：继续发送 heartbeat 与 batch。
- `uuid`：生成 heartbeat/event/attempt/turn canonical ID。
- `whoami`：按 Windows、macOS、Linux 对应系统能力读取用户名。
- 当前 `AcpTurnFinished`、RunStarted 持久化状态、RunPaused、InterventionRequested、RunCompleted 和 DynamicGraphState：作为事件事实来源。

### 3.2 不采用

- 不新增 `/events` 端点，metrics/batch 直接承载事件批次。
- 不新增第二套 analytics event bus，复用 RuntimeLifecycleBus 并在 recorder 层投影。
- 不引入重型 OpenTelemetry 业务事件链；它适合运行监控，不替代高基数业务事实。
- 不在客户端计算成功率/留存率。
- 不继续从 lifecycle subscriber 直接发 HTTP。

## 4. 数据结构改造

### 4.1 上报身份

heartbeat 与 metrics/batch 共享规范化 userId，但 workspace 边界不同：

```rust
struct HeartbeatIdentity {
    user_id: String,
}

struct EventIdentity {
    user_id: String,
    workspace: String,
}
```

- userId 使用 `whoami::username()` 跨平台读取，trim 后转为小写，最大 128 字符；失败、空值或 unknown 时禁止上报。
- 服务端再次执行相同规范化，数据库使用大小写不敏感、重音敏感排序规则。
- heartbeat 不上传 workspace；metrics/batch 的执行事件继续携带 workspace。
- 不生成 installationId、workspaceId、accountId 或 appSessionId。
- heartbeat 每个逻辑请求生成 heartbeatId；appStarted 和四类业务事实的有限重试复用同一 heartbeatId。

执行领域仍使用 canonical UUID：TaskState.uuid、RunState.uuid、RoundState.uuid、NodeState.uuid；NodeState 与 DynamicNodeState 对每次实际 attempt 增加 `attemptUuid`，Direct/manual prompt 在后端接受前必须有稳定 `turnId`。

analytics 层禁止 `uuid.unwrap_or(display_id)`；缺失执行 canonical ID 应在状态创建/迁移处修复。
### 4.2 analytics events

建议在 `src/analytics/` 新建纯 Rust 领域模块：

```text
src/analytics/
  mod.rs
  event.rs
  identity.rs
  projection.rs
```

主要结构：

```rust
enum ProcessingMode { Direct, Workflow, Auto }
enum ExecutionKind { Turn, Run }
enum ExecutionOrigin { InitialPrompt, FollowUp, NewRun, Rerun, RuntimeContinue }

struct AnalyticsEvent {
    event_id: String,
    idempotency_key: String,
    event_type: AnalyticsEventType,
    occurred_at: DateTime<Utc>,
    mode: ProcessingMode,
    user_id: String,
    workspace: String,
    task_id: String,
    execution: ExecutionRef,
    refs: AnalyticsRefs,
    payload: AnalyticsPayload,
}
```

实际代码使用 enum + tagged payload，禁止在一个大结构里堆互斥 Option。

事件枚举：ExecutionStarted、ExecutionPaused、ExecutionResumed、ExecutionFinished、UnitFinished、InterventionRequested。

### 4.3 usage

```rust
struct UsageDelta {
    usage_scope_id: String,
    input_tokens: u64,
    output_tokens: u64,
    cache_read_tokens: u64,
    total_tokens: u64,
}
```

Direct 同一 ACP session 每次 turn 开始保存 usage baseline，结束计算 delta。Workflow/AUTO attempt 同理。counter 回退或 session 更换时不得产生负数，记录结构化诊断码 `analytics.usage.counter-reset`。

resolvedModel 优先读取 provider/session 实际结果；requestedModel 只记录用户/runtime override，不把配置值冒充实际模型。

## 5. 生命周期接入

### 5.1 新增或扩展事件

- `RunStarted`：状态持久化后发出，带 mode 和 canonical UUID。
- `NodeCompleted`：补 canonical attemptId、provider、requestedModel、resolvedModel、usage delta。
- `RunPaused/RunCompleted`：补 canonical UUID、mode、duration、新轮次和 workflow snapshot 归因。
- `AcpTurnStarted`：每个 prompt 被后端接受后发出。
- `AcpTurnFinished`：补 mode、origin、usage delta、provider/resolvedModel 和 terminal reason code。
- dynamic 层级统一映射进 UnitFinished，避免把 HTTP schema 散落进 orchestrator。

### 5.2 Direct

首轮：

1. 创建 task/run/round/node 壳并持久化。
2. 获取 turnId。
3. 只记录 `AcpTurnStarted(mode=direct, origin=initialPrompt)`。
4. 内部 Node/Run lifecycle 对 analytics 标记 `internalShell`，不投影为 Workflow execution/unit。
5. 首轮自然结束由 turn finished 投影；内部 RunCompleted 仍服务 UI/通知。

后续追问：每个 prompt 新建 turnId，保存 usage baseline，AcpTurnFinished 生成本轮 delta；Cancelled 单独上报，不记 Failed。

### 5.3 Workflow

- run 状态创建完成后立即记录 RunStarted。
- 只在 node attempt 定局时记录 UnitFinished。
- retry 创建新的 attemptUuid，不能覆盖旧 attempt。
- new round 仍属于同一 run execution。
- run 完成后的手动追问投影成 turn，mode=workflow、origin=followUp。

### 5.4 AUTO

- outer run started/finished 是产品主 execution。
- AI-DYNAMIC outer node 是 container。
- dynamic worker/merge/acceptance/workflowInvocation 投影为 dynamicNodeAttempt。
- kind/depth/groupId/provider/model/workflowId/childRunId 进入结构字段，不上传 title/task/workspacePath。
- child workflow run 带 parentExecutionId/parentUnitId，并从 outer run 产品分母排除。
- billable usage 只能由唯一 usageScopeId 的真实执行单元承载。

## 6. 客户端持久化与上传

### 6.1 模块划分

```text
src-tauri/src/analytics/
  mod.rs
  recorder.rs
  outbox.rs
  uploader.rs
  response.rs
  identity.rs
  heartbeat.rs
  reconciliation.rs
```

原 `metrics.rs` 的 base URL、API key 与 endpoint 归一化抽到共享 `client_report.rs`，供 analytics 和 feedback 复用，不复制网络配置逻辑。

### 6.2 outbox

批量指标使用独立 `analytics.sqlite3`，不与可重建搜索索引共用数据库生命周期。完整 DDL 与 lease 规则见[批量指标上报开发方案](./批量指标上报开发方案.md)。

```sql
CREATE TABLE analytics_outbox (
  event_id TEXT PRIMARY KEY,
  idempotency_key TEXT NOT NULL UNIQUE,
  schema_version INTEGER NOT NULL,
  event_type TEXT NOT NULL,
  mode TEXT NOT NULL,
  occurred_at TEXT NOT NULL,
  payload_json TEXT NOT NULL,
  status TEXT NOT NULL,
  attempt_count INTEGER NOT NULL DEFAULT 0,
  next_attempt_at TEXT NOT NULL,
  lease_owner TEXT,
  lease_until TEXT,
  created_at TEXT NOT NULL,
  acked_at TEXT,
  last_error_code INTEGER
);
CREATE INDEX analytics_outbox_pending
ON analytics_outbox(status, next_attempt_at, created_at);
```

Recorder 同步插入 SQLite 后返回；Uploader 后台读取。HTTP 不运行在 runtime 热路径。

### 6.3 reconciliation

应用启动后扫描：

- 已存在 RunState 但无 started 幂等键；
- 已终局 RunState 但无 finished 幂等键；
- 已终局 attempt 但无 unit finished；
- timeline/prompt 中有 turnId 且 snapshot 已终局但无 turn finished。
- 持久化 lifecycle history 中有 pause/resume/intervention 但无对应幂等键。

补写事件复用确定性 idempotencyKey，禁止生成第二份领域事实。

### 6.4 uploader

- 每批最多 200 条、512 KiB。
- 单事件最多 64 KiB。
- pending/过期 in_flight 在 SQLite 事务内领取并设置 60 秒 lease。
- accepted/duplicate → acked。
- rejected → rejected + error code。
- 429/5xx/timeout → pending + full jitter；429 优先 Retry-After。
- 413 → 二分批次，单事件仍超限则 rejected。
- 401/403 → 暂停上传，等待配置变化。
- 崩溃留下 in_flight 时，lease 过期后恢复。

本功能不需要外部子进程，不使用 `std::process::Command`。

### 6.5 heartbeat

heartbeat 不进入 durable outbox，支持六类 reason：

- metrics 配置、endpoint 和 API Key 就绪后发送 `appStarted`，不依赖 workspace；
- 窗口回前台、pointerdown、keydown 和 Direct/Workflow/AUTO 业务命令发送 `activity`。
- 用户在当前 Conversation 新建或 rerun 顶层 run 并获得新 canonical runId 后，按 runMode 发送 `directStarted/workflowStarted/autoStarted`；
- 定时任务定义和输入快照 durable 创建后发送 `scheduledTaskCreated`。

请求固定为 heartbeatId、userId、reason、clientVersion、os 五个字段。删除 workspace、appSessionId、reportedAt、foregrounded、interval 和 execution 活跃跟踪。

六类信号统一发布到现有 `RuntimeLifecycleBus`，由异步 metrics subscriber 映射和发送，producer 不等待 HTTP 或感知结果。appStarted 和四类业务事实对网络错误、超时、429、5xx 和无效 2xx 响应在 30 秒、2 分钟后有限重试并复用同一 heartbeatId；400、401、413 不自动重试。appStarted/activity 成功后 activity 节流 15 分钟，activity 失败后退避 1 分钟并等待下一次真实操作；业务事实不改变 activity 状态。follow-up、continue、same-run retry、旧工作台、scheduled runtime 与 AUTO child run 不产生 Started。

## 7. 服务端接口与存储

服务端代码不在当前仓库，需由配套服务项目同步实现；本仓库先固化契约测试 JSON fixture。

### 7.1 metrics/batch

1. 校验 schemaVersion=2、batch 大小和公共字段。
2. 每个事件独立校验。
3. 按 eventId/idempotencyKey 幂等写 raw 表。
4. 返回 accepted/duplicate/rejected 明细。
5. 异步物化 execution_fact、unit_fact、execution_transition_fact、intervention_fact、usage_fact。

一个坏事件不能导致其余合法事件整批丢失。

### 7.2 heartbeat

控制台在同一事务内：

1. 校验 5 字段 DTO、API Key 和 userId 规范化结果。
2. 生成 UTC receivedAt，按 `Asia/Shanghai` 计算 statDate。
3. 按 heartbeatId 插入 `client_heartbeat_event`，重复时返回 duplicate。
4. 新事件按 `(statDate,userId)` upsert `heartbeat_daily`。
5. reason=appStarted 时 `app_start_count + 1`；latest version/OS 只允许更新事件覆盖。

只建设原始事件表和用户日聚合表。原始表保留 90 天；heartbeat_daily 长期保留并按 statDate 月度 RANGE 分区，提前创建未来 3 个月分区。统计包括周活跃回访率和只展示完整 cohort 的首次观测用户次周留存。
### 7.3 约束

- heartbeatId、eventId、idempotencyKey 各自在所属接口唯一。
- metrics/batch 事件公共身份为 userId + workspace。
- usageScopeId 唯一计费。
- child run 通过 parentExecutionId/parentUnitId 关联。
- heartbeat receivedAt 以 UTC 存储并按 Asia/Shanghai 物化 statDate；metrics 事件时间统一 UTC。
- heartbeat 不上传 workspace；metrics/batch 除结构化 workspace 外，不保存 prompt、回复、工具或附件正文。

## 8. 破坏式迁移

1. 服务端部署 V2 schema 与两个端点的新请求体。
2. 客户端合并 V2 serializer/outbox/uploader。
3. 删除 V1 NodeMetricItem、NodeMetricBatch、sentinel、predecessor 重复上报和直接 HTTP subscriber。
4. heartbeat 保持 5 字段并扩为六种 reason，经现有生命周期总线投影，删除 workspace、session、客户端时间与周期执行心跳。
5. 清理旧接口说明。

不双写 V1/V2，不保留 `metrics` 与 `events` 两套 payload，不用 404 fallback 回旧协议。历史 V1 数据可归档，但不与 V2 execution_fact 强行拼接趋势。

## 9. 单元测试与接口验收

### 9.1 serializer

- heartbeat JSON 严格包含 5 个字段和六种 reason。
- appStarted/业务事实有限重试复用 heartbeatId；activity 成功节流 15 分钟、失败退避 1 分钟且不受业务事实结果影响。
- 总线映射、Conversation 新 run/rerun、定时任务 durable create 与任务失败隔离均有接口回归测试。
- whoami 跨平台用户名获取、空值/unknown 拒绝和大小写规范化。
- 六类 event JSON snapshot。
- enum 非法值拒绝。
- batch 条数和大小边界。

### 9.2 Direct

- 首轮仅一个 Direct turn execution。
- 后续两 turn ID 不同、runId 上下文相同。
- 同 session usage 100→150、150→210 上报 50 和 60。
- completed/failed/cancelled 正确区分。
- completed run follow-up 不生成新 run started/finished。

### 9.3 Workflow

- run 状态落盘后立即有 started。
- 首节点未完成退出仍保留分母事件。
- 同 node 两个 attemptUuid 产生两条 unit fact。
- new round 仍关联同 run。
- pause/resume 顺序和不同 eventId 正确。

### 9.4 AUTO

- outer run 只有一个产品主 execution。
- dynamic worker/merge/acceptance kind 正确。
- workflowInvocation 关联 child run。
- child run 不进入 outer run 分母。
- outer container 与 dynamic billable usage 不重复。
- 并行 sibling leaf pause reason 不被错误归并。

### 9.5 可靠性与隐私

- 同 event 上传两次只保存一次。
- 部分 rejected 不影响 accepted。
- timeout/500/429 退避重试，401/403 暂停。
- `in_flight` lease 过期后恢复为 `pending`，同一时刻只允许一个批次在途。
- state/outbox 崩溃窗口由 reconciliation 补齐。
- heartbeat fixture 只允许规范化 userId，不含 workspace；metrics/batch fixture 可含 workspace，但禁止 task title、prompt、response、tool input/output 和 attachment path。

## 11. 风险控制

| 风险 | 控制 |
|---|---|
| 文件状态与 SQLite 无法原子提交 | 确定性幂等键 + reconciliation |
| Direct 首轮双计 | internalShell 规则 + 专项测试 |
| 同 session token 重复 | usage baseline/delta + usageScopeId |
| AUTO 容器/child run 重复 | parent 关系 + billable/container |
| canonical UUID 缺失 | 创建/迁移先补齐，analytics 禁止 fallback |
| 服务端未同步 | 合同 fixture + 协调发布，不做 V1 fallback |
| 数据被误读成业务成功 | 统一使用 turn/run 终局术语 |
| heartbeat 数据增长 | 原始表保留 90 天；heartbeat_daily 长期保留、按月分区并提前建未来分区 |
