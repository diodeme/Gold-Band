# Gold Band 主题引擎 v2 设计方案

> 状态：设计稿  
> 日期：2026-08-15  
> 范围：Theme Contract、Theme SDK、Web Runtime、Tauri 资源投影及共享组件消费层升级  
> 不包含：任何新增正式主题的具体视觉设计

## 1. 一句话结论

Theme Engine v2 在保留 `themeId × colorScheme × visualQuality + personalization` 现有权威模型的前提下，把 v1 只预留或部分实现的字体资源、组件状态 recipe、形状、动效、图标和壁纸补成封闭、可校验、可编译、可回退的正式能力；用户设置仍只选择主题、明暗、质量档、字体来源/字号和头像，不新增图标、壁纸或字体高级选项。

## 2. 背景与根因

v1 已经完成以下基础能力：

- 声明式内置主题包、DTCG token、Style Dictionary 构建和 Web/Rust Catalog。
- `themeId × colorScheme` 外观模型和按主题隔离的视觉质量选择。
- 语义颜色、材质 token、少量稳定 component role 和根 CSS variables。
- UI / 编辑器两套字体与字号继承，以及头像继承。
- Theme Package 不允许注入 JavaScript、HTML、任意 CSS 或远程 URL。

但当前实现与 v1 原设计之间仍有结构性缺口：

1. `fonts` capability 只有字体栈字符串，没有字体文件、字重、字符覆盖、授权和语言解析契约；内置 MiSans 的 `@font-face` 仍硬编码在全局 CSS。
2. `component-recipes` 实际只支持背景、前景、边框颜色和材质类型；v1 设计中已定义的 border width、radius、shadow、transition 和更多业务角色没有落地。
3. 当前只有单个全局 radius、shadow、duration 和 easing，无法让不同主题系统化表达控件、表面、弹层、滚动条和交互状态。
4. `icons` 与 `wallpapers` 只存在于 v1 设计文档，没有进入 capability 枚举、Schema、构建产物和运行时消费路径。
5. `assets/` 当前只生成文件 hash 清单，不复制到 Web 产物、不生成安全 URL，也没有按资源种类验证尺寸、字符范围或实际用途。
6. 部分共享组件仍直接使用硬编码圆角、阴影和动效 class；新增高差异主题会迫使业务组件出现主题特判。

根因不是缺少某一套主题 CSS，而是 Theme Contract 的“可表达范围”和 Asset Pipeline 没有完成。v2 必须补齐通用契约，不为某个具体主题增加旁路。

## 3. 目标与非目标

### 3.1 目标

1. 将 Theme Contract 升级到 v2，并由 JSON Schema、Theme SDK、Web Zod 和 Rust `serde` 共同维护同一封闭字段集合。
2. 建立完整主题资源模型：稳定 asset ID、类型、路径、授权、hash、尺寸、字符覆盖、构建 URL 和回退。
3. 让主题包能够声明并实际加载本地 WOFF2/WOFF 字体，支持 UI / 编辑器、字重和多语言字体栈。
4. 扩展结构 token 和 component recipe，使共享组件能够消费主题定义的形状、边框、阴影、滚动条、动效和交互状态。
5. 实现按语义槽覆盖的主题图标；缺失或损坏时回退 Gold Band 内置 Lucide 图标。
6. 实现按稳定表面槽声明的静态主题壁纸；缺失或损坏时回退语义背景色。
7. 主题切换仍只更新根属性、CSS variables 和轻量资源 locator，不重新请求业务数据、不重建 Markdown、不销毁 CodeMirror。
8. 内置主题资源编译进 Vite `frontendDist`，不为纯视觉资源新增 Tauri IPC、文件系统权限或长生命周期缓存。
9. v1 两个内置主题迁移到 v2 后保持既有视觉和用户偏好语义不变。
10. 通过非分发的 contract fixture 验证字体、图标、壁纸和高差异 recipe，无需新增正式主题。

### 3.2 非目标

- 本方案不定义、命名或实现任何新增正式主题。
- 不实现 `.gbtheme` 用户导入、主题市场、在线下载、主题签名网络和主题热更新。
- 不开放用户自定义图标包、壁纸、壁纸暗度、壁纸模糊、强调色或高级排版参数。
- 不允许主题改变布局结构、信息层级、组件尺寸、触控目标、焦点顺序、业务状态机或路由。
- 不允许主题提供任意 CSS selector、JavaScript、React、HTML、WASM、Canvas shader、视频壁纸或远程资源 URL。
- 不替换 EXE、任务栏、安装包或操作系统级应用图标。
- 不为主题资源建立数据库、后台下载队列或新 IPC 事件流。

## 4. 设计原则与权威事实源

### 4.1 三层 token 继续作为唯一视觉决策链

```text
Primitive
  原始颜色、尺寸、字重、阴影、时长
        ↓
Semantic
  foreground、surface、control-radius、overlay-shadow、motion-fast
        ↓
Component Recipe
  button、input、message、tool-card、dialog、workflow-node
```

- 业务组件不得直接消费 primitive。
- 主题作者只能引用 Contract 公开的 semantic token 和资源 ID。
- component recipe 不接受原始 selector 或任意声明字符串。
- shared shadcn/prompt-kit 组件负责把 component recipe 投影到 DOM。

### 4.2 权威事实源

| 领域 | 权威事实源 | 说明 |
| --- | --- | --- |
| 当前主题和明暗偏好 | 后端 `AppearancePreference` | v2 不新增字段 |
| 字体、字号和头像用户覆盖 | 后端 `PersonalizationPreference` | v2 不新增用户高级字体字段 |
| 可用主题身份与版本 | 生成的 Theme Catalog | 使用稳定 `themeId`，不按名称反查 |
| 主题视觉能力 | Theme Package v2 | token、recipe、font、icon、wallpaper 声明 |
| 物理资源完整性 | 生成的 Asset Manifest v2 | hash、类型、尺寸和输出 URL |
| 当前有效外观 | `EffectiveAppearanceV2` | 运行时投影，不持久化 |
| 图标可访问名称 | Gold Band 业务组件 | 主题只替换图形，不替换语义 |

### 4.3 运行时不读取源包

Style Dictionary、Ajv、源 token 和原始资源目录只存在于开发构建期。Web/Tauri 运行时只消费：

- 已验证的 Runtime Theme Package v2。
- 已生成的 CSS。
- 已生成的 Asset Manifest v2。
- 已复制并使用 content hash 命名的同源静态资源。

```text
│   ├── light.tokens.json
│   └── dark.tokens.json
├── recipes.json
├── presets.json
├── resources.json
├── fonts.json                 # 声明 fonts capability 时必需
├── icons.json                 # 声明 icons capability 时必需
├── wallpapers.json            # 声明 wallpapers capability 时必需
├── visual-quality/
│   └── performance.json       # 声明 visual-quality-profiles 时必需

│   ├── fonts/
│   ├── avatars/
```

只有与 capability 对应的声明文件才允许存在。声明 capability 但缺少文件、存在文件但未声明 capability，均构建失败。

### 5.2 Manifest v2

```ts
type ThemeCapabilityV2 =

```

v2 仍要求所有正式主题同时提供 light 和 dark，不允许 `system` 跨主题包回退。

## 6. 统一资源契约

### 6.1 Asset ID 与物理文件分离

主题 token、字体栈、图标槽、壁纸槽和头像只引用稳定 asset ID，不直接保存文件路径。

```ts
type ThemeAssetKind =
  | "font"
  | "avatar"
  | "icon"
  | "texture"
  | "wallpaper"
  | "preview";

interface ThemeAssetSourceV2 {
  id: string;
  kind: ThemeAssetKind;
  path: `assets/${string}`;
  licenseId: string;
  required?: boolean;
}
```

构建器从真实文件推导并生成：

```ts
interface ThemeAssetRecordV2 {
  id: string;
  kind: ThemeAssetKind;
  mediaType: string;
  bytes: number;
  sha256: string;
  outputUrl: string;
  width?: number;
  height?: number;
  fontMetadata?: ResolvedFontMetadata;
  required: boolean;
}
```

主题作者不得填写 `bytes`、`sha256`、`outputUrl`、图片尺寸或从字体文件可读取的真实元数据，避免声明与文件事实分裂。

### 6.2 支持格式

| 资源 | v2 格式 | 说明 |
| --- | --- | --- |
| 字体 | WOFF2、WOFF | 禁止 TTF/OTF 和远程 URL |
| 图标 | PNG、WebP | 单色图标使用 alpha mask；v2 不开放 SVG |
| 壁纸 | PNG、WebP | 仅静态图片 |
| 纹理 | PNG、WebP | 小尺寸、可平铺 |
| 头像 | PNG、WebP | 沿用主题头像能力 |
| 预览 | PNG、WebP | 设置页主题预览 |

v2 不开放 SVG，避免为未来不受信任主题引入 SVG 脚本、外链、滤镜和解析差异。单色可着色图标通过 PNG/WebP alpha mask + `currentColor` 实现。

### 6.3 路径与授权校验

- asset ID 在单个主题包内唯一，使用小写 kebab-case。
- 路径必须规范化后位于主题根目录下的 `assets/`。
- 拒绝绝对路径、`..`、符号链接、大小写冲突路径和重复物理文件映射。
- 每个 asset 必须关联 `LICENSES.json` 中存在的 `licenseId`。
- 同一物理文件可以被多个语义槽引用，但 Asset Manifest 只保留一份记录。
- 构建失败不得保留部分生成目录；使用临时目录完成后原子替换 `dist` 和 Web generated assets。

### 6.4 初始资源预算

沿用 v1 的 package 级上限作为 v2 初始硬边界：最多 128 个资源、源文件总计不超过 16 MiB。同时增加按类型校验：

- 单个 icon：最大 128×128、最大 256 KiB。
- 单个 texture：最大 1024×1024、最大 2 MiB。
- 单个 wallpaper / preview：最大 4096×4096、最大 16 MP、最大 4 MiB。
- 单个字体：最大 8 MiB；字体总量仍受 16 MiB package 上限约束。

这些数值作为 SDK 常量和构建测试固定。只有实际合规主题资源无法满足且完成包体、解码和内存测量后，才允许统一调整，不能由单个主题覆盖。

## 7. 字体资源与多语言排版

### 7.1 Font Face

```ts
type ScriptCode = string; // 校验为 ISO 15924 四字母代码

interface ThemeFontFaceV2 {
  id: string;
  family: string;
  assetId: string;
  weight: 400 | 500 | 600 | 700;
  style: "normal" | "italic";
  display: "swap";
  coverage: {
    scripts: ScriptCode[];
    locales?: string[];       // BCP 47
    unicodeRanges?: string[];
  };
  metrics?: {
    sizeAdjust?: string;
    ascentOverride?: string;
    descentOverride?: string;
    lineGapOverride?: string;
  };
}
```

SDK 校验：

- `assetId` 必须指向 `kind=font` 的 WOFF2/WOFF。
- `family + weight + style + coverage` 不得冲突。
- `unicodeRanges` 必须符合 CSS `U+...` 封闭语法，不接受任意描述符。
- `locales` 规范化为 BCP 47；`scripts` 校验 ISO 15924 格式。
- 字体声明的 weight 必须与读取到的字体元数据一致；不允许把同一个 Regular 文件伪装成多个字重。
- `font-display` 固定为 `swap`，主题作者不可修改。

### 7.2 Font Stack

```ts
interface ThemeFontStackV2 {
  id: string;
  displayName: LocalizedText;
  defaultFaces: string[];
  byScript?: Record<ScriptCode, string[]>;
  byLocale?: Record<string, string[]>;
  systemFallbacks: string[];
}

interface ThemeTypographyPresetV2 {
  uiStackId: string;
  uiSize: number;
  uiLineHeight: number;
  editorStackId: string;
  editorSize: number;
  editorLineHeight: number;
  weights: {
    read: 400 | 500;
    emphasize: 400 | 500 | 600;
    announce: 500 | 600 | 700;
  };
}
```

解析顺序：

```text
精确 locale
  -> language + script
  -> script
  -> stack defaultFaces
  -> builtin.gold-band 对应 UI / editor 安全字体栈
```

运行时使用 `Intl.Locale(locale).maximize()` 推导 script。对于共享相同 Unicode code point 但字形约定不同的简中、繁中、日文和韩文，必须按 locale/script 选择字体族，不能只依赖 `unicode-range`。

### 7.3 用户设置保持不变

`PersonalizationPreference` 继续只保存：

```ts
type FontPreference =
  | { source: "theme" }
  | { source: "local"; family: string };

type FontSizePreference =
  | { source: "theme" }
  | { source: "custom"; px: number };
```

设置页“默认字体”卡片显示 `ResolvedTypography.displayName`，例如：

```text
默认字体 · <当前主题解析出的字体名称>
```

不向用户开放 font face、语言字体、fallback、字重、行高、字距或资源包选择。用户显式本机字体覆盖继续优先于主题字体。

### 7.4 字体加载边界

- SDK 将 font face 编译为 `@font-face`，URL 指向同源 hash 资源。
- CSS 可以包含全部 face 声明，但 WebView 只请求当前 stack、weight 和字符范围实际命中的文件。
- 字体加载失败不阻塞应用壳；先使用安全 fallback，再由浏览器 swap。
- 语言切换只重新解析并写入根字体 CSS variables，不重建页面或持久化主题派生结果。
- 非当前主题字体不得被 CSS 实际引用，因此不请求、不解码。

## 8. 结构、材质、动效与滚动条 token

v2 将 v1 `material.radius/shadow/motion*` 拆分为职责明确的组，材质只描述光学效果。

```ts
interface ThemeShapeTokensV2 {
  radiusControl: string;
  radiusSurface: string;
  radiusOverlay: string;
  radiusAvatar: string;
  radiusPill: string;
  borderHairline: string;
  borderDefault: string;
  borderStrong: string;
}

interface ThemeElevationTokensV2 {
  none: string;
  surface: string;
  overlay: string;
  floating: string;
  pressed: string;
  pressOffset: 0 | 1 | 2;
}

interface ThemeMotionTokensV2 {
  mode: "smooth" | "stepped" | "none";
  durationFast: string;
  durationNormal: string;
  durationSlow: string;
  easingStandard: string;
  easingEnter: string;
  easingPress: string;
}

interface ThemeScrollbarTokensV2 {
  width: string;
  thumbRadius: string;
  thumbInset: string;
  minLength: string;
  buttons: "none" | "visible";
}
```

约束：

- dimension 使用受控单位和范围解析器，不把任意 CSS 字符串原样透传。
- shadow 限制层数、blur、spread 和总字符串长度。
- easing 只接受 `linear`、标准 cubic-bezier 或 `steps()`；拒绝任意函数。
- `mode=none` 只关闭装饰运动，不关闭业务 loading、进度和状态反馈。
- `prefers-reduced-motion` 始终具有更高优先级。
- scrollbar token 只控制视觉几何，不改变滚动行为和最小可操作性。

## 9. Component Recipe v2

### 9.1 Surface Recipe

```ts
type ThemeVisualState =
  | "default"
  | "hover"
  | "active"
  | "selected"
  | "focus"
  | "disabled";

interface ThemeStateRecipeV2 {
  background?: SemanticBackgroundRef;
  foreground?: SemanticForegroundRef;
  border?: SemanticBorderRef;
  elevation?: "none" | "surface" | "overlay" | "floating" | "pressed";
  opacity?: number;
  press?: boolean;
}

interface ThemeSurfaceRecipeV2 {
  background: SemanticBackgroundRef;
  foreground: SemanticForegroundRef;
  border: SemanticBorderRef;
  borderWidth: "none" | "hairline" | "default" | "strong";
  borderStyle: "solid" | "double" | "dashed";
  radius: "control" | "surface" | "overlay" | "avatar" | "pill";
  elevation: "none" | "surface" | "overlay" | "floating";
  material: "flat" | "subtle" | "elevated";
  motion: "none" | "color" | "surface" | "press";
  states?: Partial<Record<Exclude<ThemeVisualState, "default">, ThemeStateRecipeV2>>;
}
```

校验不变量：

- state 修改背景时必须同时给出合法前景，或显式继承已验证的前景配对。
- focus state 不能关闭 engine-owned focus ring，也不能把 ring 宽度降到最低要求以下。
- disabled 可以降低对比，但仍须满足 disabled 控件和文字最低要求。
- `press=true` 只允许使用 package 级 `pressOffset`，不能写任意 transform。
- theme state 不能改变 `display`、`visibility`、尺寸、padding、position 或 DOM 顺序。

v2 保留 v1 已存在角色并新增业务语义角色：

```text

navigation-item

popover
```

角色由共享组件标注。页面不得为了主题在局部添加另一个 selector，也不得读取 `themeId`。

### 9.3 共享组件消费

- shadcn Button/Input/Card/Dialog/Sheet/Popover/Select/Dropdown/Tooltip 等统一消费 role CSS variables。
- prompt-kit 消息、Markdown、Composer、tool card 和 activity 消费会话角色。
- Workflow 节点、边、controls 和 minimap 消费 workflow 角色。
- CodeMirror 只更新 theme extension 和 CSS variables，不销毁 `EditorView`。
- `rounded-full`、固定 shadow 和固定动效优先从共享组件移除；确为业务语义的圆形状态点和头像保留专用 role。

### 10.1 语义槽而不是组件名

```ts
type ThemeIconSlotV2 =

```

首批槽位只覆盖跨页面重复、具有稳定业务语义的图标。页面专属、低复用或第三方品牌图标继续由产品代码管理。

### 10.2 Icon Descriptor

```ts
interface ThemeIconDescriptorV2 {
  assetId: string;
  renderMode: "mask" | "image";
  nativeSize: 16 | 20 | 24 | 32;
  imageRendering: "auto" | "pixelated";
}

interface ThemeIconMapV2 {
  defaults: Partial<Record<ThemeIconSlotV2, ThemeIconDescriptorV2>>;
  schemes?: {
    light?: Partial<Record<ThemeIconSlotV2, ThemeIconDescriptorV2>>;
    dark?: Partial<Record<ThemeIconSlotV2, ThemeIconDescriptorV2>>;
  };
}
```

- `mask` 使用资源 alpha 通道并继承 `currentColor`，适用于单色主题图标。
- `image` 保留原图颜色；必须分别验证 light/dark 对比度。
- `imageRendering=pixelated` 只作用于主题自有图标，不作用于用户图片、附件、壁纸或业务资产。
- 主题不提供 `aria-label`、tooltip 或危险动作文案；这些仍由业务组件负责。

### 10.3 ThemeIcon 共享组件

```tsx
<ThemeIcon
  slot="navigation.search"
  fallback={Search}
  aria-hidden="true"
/>
```

`ThemeIcon` 只负责图形解析：

1. 当前 scheme override。
2. theme defaults。
3. Gold Band 代码内 Lucide fallback。

资源加载失败时同一次渲染降级 fallback，不清空按钮、不改变 accessible name，也不让整个主题失效。

### 10.4 图标运行时边界

- `ThemeAssetsContext` 只保存已解析的 icon descriptor map 和稳定 URL，不保存二进制。
- Context 仅在主题或 scheme 改变时更新，不跟随 composer、会话或工作区高频状态。
- 图标主题切换允许图标组件重渲染，但不得让消息正文、Markdown 或编辑器因 Context 订阅而重渲染。
- 可通过拆分 `ThemeIconContext` 与 `ThemeRuntimeCommandsContext` 保持最小订阅边界。

## 11. 壁纸能力

### 11.1 稳定表面槽

```ts
type ThemeWallpaperSlotV2 =
  | "app"
  | "conversation"
  | "workspace"
  | "settings";
```

每个可用 surface 在 DOM 上标记稳定 `data-theme-wallpaper-slot`。主题不能提供选择器。

### 11.2 Wallpaper Descriptor

```ts
interface ThemeWallpaperDescriptorV2 {
  assetId: string;
  fit: "cover" | "contain" | "tile";
  position:
    | "center"
    | "top"
    | "bottom"
    | "left"
    | "right"
    | "top-left"
    | "top-right"
    | "bottom-left"
    | "bottom-right";
  repeat: "no-repeat" | "repeat" | "repeat-x" | "repeat-y";
  opacity: number;
  overlayColor: SemanticBackgroundRef;
  overlayOpacity: number;
}

interface ThemeWallpaperMapV2 {
  light: Partial<Record<ThemeWallpaperSlotV2, ThemeWallpaperDescriptorV2>>;
  dark: Partial<Record<ThemeWallpaperSlotV2, ThemeWallpaperDescriptorV2>>;
}
```

v2 不允许自定义 blend mode、任意 filter、视频、GIF、Canvas 或 pointer-driven parallax。若未来确有需求，必须以新 Contract 版本和独立性能预算引入。

### 11.3 层级与回退

- 壁纸使用 surface 自身的 `::before` 背景层，业务内容位于同一 surface 的正常 stacking context。
- overlay 使用主题语义色，保证正文与控件对比度；不能依赖壁纸图像本身恰好较暗或较亮。
- 最具体的 surface 只绘制自己的壁纸；不得让 app、conversation、workspace 多层壁纸同时透叠。
- 当前槽缺失时直接使用该 surface 的语义背景色。
- 切换主题前只预加载当前可见槽的 wallpaper；失败时继续使用语义背景色并完成主题切换。
- Tauri 原生窗口背景仍同步 `windowSurface` 实色，不使用壁纸，避免 WebView 创建/resize 期间暴露透明或错误底色。

### 11.4 视觉质量档

`performance` 可以关闭 wallpaper 和 texture，但不能换成另一张表达不同内容的图片：

```ts
interface WallpaperPerformanceOverrideV2 {
  enabled: false;
}
```

关闭后回退该 surface 的语义背景色。设置页仍只有既有“完整效果 / 性能优先”，不增加壁纸开关。

## 12. Runtime Theme Package v2

```ts
interface RuntimeThemePackageV2 {
  schemaVersion: 2;
  contractVersion: 2;
  id: string;
  version: string;
  source: ThemeSource;
  name: LocalizedText;
  author: string;
  capabilities: ThemeCapabilityV2[];
  schemes: {
    light: ThemeSchemeV2;
    dark: ThemeSchemeV2;
  };
  recipes: ThemeRecipeMapV2;
  assets: ThemeAssetManifestSummaryV2;
  fonts?: ThemeFontRuntimeV2;
  icons?: ThemeIconMapV2;
  wallpapers?: ThemeWallpaperMapV2;
  visualQualityProfiles?: ThemeVisualQualityProfilesV2;

```

`ThemeSchemeV2` 包含：

- `windowSurface` 与 preview palette。
- semantic colors。
- material optical tokens。
- shape、elevation、motion、scrollbar。
- typography preset 与 avatar preset。

Runtime Package 只包含 locator 和已解析值，不内嵌字体或图片字节。

## 13. Theme SDK v2 编译链路

### 13.1 构建顺序

```text
发现 themes/*/manifest.json
  -> 校验 Manifest v2 与 capability/file 一致性
  -> 解析 DTCG token 与 alias
  -> 校验 recipes / fonts / icons / wallpapers
  -> 扫描物理资源并校验路径、签名、MIME、尺寸、字体元数据与授权
  -> 生成 content hash 资源名
  -> 生成 Runtime Theme Package v2
  -> 生成 Asset Manifest v2
  -> 生成 @font-face、token、recipe、wallpaper CSS
  -> 原子写入 theme dist
  -> 原子重建 Web generated catalog/CSS/assets
  -> 生成 Rust builtin catalog
```

任一步失败都不覆盖上一次完整生成产物。

### 13.2 Web 输出目录

```text
web/public/theme-assets/<theme-id>/
  <sha256-prefix>-<safe-name>.<ext>

web/src/themes/generated/
  catalog.json
  builtin-themes.css
  asset-catalog.json
```

- `web/public/theme-assets` 是构建生成目录，每次 `themes:build` 原子清理并重建。
- Vite 将其作为同源静态文件复制进 `frontendDist`。
- CSS 和 runtime JSON 只引用 `/theme-assets/...`，不引用源码目录或绝对文件路径。
- URL 文件名包含 hash，主题升级不会命中旧资源内容。

### 13.3 Tauri 资源边界

内置主题字体、图标和壁纸属于 Web 前端资源，应进入 `frontendDist`，不进入 Tauri `bundle.resources`：

- 不需要 `resolveResource`。
- 不需要 fs plugin scope。
- 不需要新增 IPC command。
- 不向 WebView 暴露任意本地文件路径。
- 原生 Core 只继续消费生成的 Rust Catalog 和 `windowSurface`。

未来实现用户 `.gbtheme` 导入时，再单独设计安装目录、原子激活、asset protocol 和 scoped permission；本方案不提前建立两套资源路径。

### 13.4 依赖选择

- 继续使用 Style Dictionary、Ajv、Zod 和 Rust `serde`。
- Node 构建期使用成熟的图片尺寸/MIME 解析库校验 PNG/WebP，不自行实现图片解码器。
- 字体元数据读取优先选择纯构建期、无网络、支持 WOFF/WOFF2 的成熟库。
- 新依赖不得进入 Web 运行时 bundle；Theme SDK 依赖只作为 devDependency。

## 14. Web Runtime 解析与应用

### 14.1 EffectiveAppearanceV2

```ts
interface EffectiveAppearanceV2 {
  themeId: string;
  themeVersion: string;
  colorScheme: "light" | "dark";
  visualQuality?: "full" | "performance";
  material: ResolvedMaterialTokensV2;
  shape: ResolvedShapeTokensV2;
  elevation: ResolvedElevationTokensV2;
  motion: ResolvedMotionTokensV2;
  scrollbar: ResolvedScrollbarTokensV2;
  semantic: ResolvedSemanticTokensV2;
  recipes: ResolvedRecipeMapV2;
  typography: {
    ui: ResolvedTypographyV2;
    editor: ResolvedTypographyV2;
  };
  avatars: ResolvedAvatarMap;
  icons: ResolvedThemeIconMapV2;
  wallpapers: ResolvedThemeWallpaperMapV2;
}
```

解析输入增加当前 app locale，但 locale 只是投影输入，不写入 Appearance Preference：

```text
Theme Package + scheme + quality + personalization + app locale
  -> EffectiveAppearanceV2
```

### 14.2 原子应用顺序

1. 解析目标 package、scheme、quality 和 locale。
2. 解析并校验当前可见 wallpaper URL；失败标记为无 wallpaper。
3. 在同一提交中更新根 `data-theme`、`data-color-scheme`、`data-visual-quality`、`data-material-model` 和 CSS variables。
4. 更新低频 `ThemeIconContext` 值。
5. 同步 Tauri 原生窗口 `windowSurface`。
6. 设置页使用同一 `EffectiveAppearanceV2` 更新字体显示名称和主题摘要。

主题切换不等待字体完成下载；字体由 `font-display: swap` 渐进生效。壁纸只做可见槽的有界预加载，不阻塞其他 UI。

### 14.3 React 更新边界

- semantic、shape、motion、scrollbar、wallpaper 主要通过根 CSS variables 和稳定 DOM role 生效。
- 只有 ThemeIcon 需要读取 descriptor map；Context 不包含 Theme Package 完整对象。
- 当前不可见页面不订阅 wallpaper 状态。
- 主题切换不得触发会话、文件、Git、Agent 或 Runtime 数据刷新。
- 已完成 Markdown、历史消息、CodeMirror 文档和右侧 workspace resource identity 保持不变。

## 15. 设置页行为

### 15.1 不新增用户入口

v2 不增加以下设置：

- 图标包选择。
- 壁纸选择、暗度、模糊和开关。
- 中文/英文/其他语言字体分别选择。
- 字重、行高、fallback、字体加载策略。
- 形状、圆角、阴影或动效风格。

这些均由当前主题包和 visual quality 决定。

### 15.2 现有字体卡动态化

当前“默认字体 · MiSans”改为读取 `ResolvedTypography.displayName`：

```text
默认字体 · <当前主题与语言解析出的字体名称>
```

- 预览使用当前有效字体栈。
- 用户选择本机字体时继续显示本机字体选中态。
- 恢复按钮只把来源改回 `theme`，不写具体主题字体名称。
- 主题或应用语言改变时动态更新名称，不写入用户偏好。

### 15.3 主题预览

主题抽屉继续只展示名称、选中态和 light/dark 视觉预览。预览图由主题包资源提供，可以包含该主题的字体、图标和壁纸效果，但设置页不拆分展示这些内部能力。

## 16. v1 到 v2 的迁移策略

项目仍处于开发阶段，采用破坏式 Contract 升级，不维护 v1/v2 双运行时。

### 16.1 需要迁移

- 新建 `theme-manifest-v2.schema.json` 和 `theme-package-v2.schema.json`。
- `theme-sdk/src/contract.mjs`、Web Zod 和 Rust `serde` 一次性切换到 v2。
- `builtin.gold-band` 与 `builtin.tech-neutral` manifest 改为 `schemaVersion=2 / contractVersion=2`。
- v1 `material.radius/shadow/motion*` 映射到 v2 shape/elevation/motion。
- v1 简化 recipes 映射为 v2 显式字段，视觉值保持一致。
- MiSans 从全局硬编码字体迁入 Gold Band 主题资源契约；技术中性可以引用同一官方资源定义或拥有受构建器去重的独立 asset 记录。
- 现有滚动条固定几何迁入两个主题的 scrollbar token。
- Catalog、生成 CSS、Asset Manifest 和测试期望全部升级到 v2。

### 16.2 不需要迁移

- `AppearancePreference` schema 不变。
- `PersonalizationPreference` schema 不变。
- `themeId` 不变，用户已选主题继续有效。
- `colorScheme`、`visualQualityByTheme`、字体来源、字号来源和头像来源不变。
- 不新增数据库字段或 localStorage key。

### 16.3 删除旧路径

升级完成后删除：

- v1 Schema 和 v1 runtime parser。
- `styles.css` 中硬编码的主题字体 `@font-face`。
- v1 material 中已迁移到 shape/elevation/motion 的重复字段。
- 共享组件中被 role token 替代的固定圆角、阴影和动效 class。
- 只为两个旧主题存在的字体名称硬编码和测试断言。

v1 用户主题导入尚未开放，因此不提供 v1 package 兼容层。若磁盘上出现未知 v1 包，Catalog 将其标为 unsupported，并返回结构化错误，不尝试猜测转换。

## 18. 安全评审

### 18.1 信任边界

- v2 当前只构建仓库内官方主题，但所有输入仍按未来不受信任包的标准校验。
- 主题资源不执行；PNG/WebP 作为图片或 mask，WOFF/WOFF2 仅作为字体。
- 不接受远程 URL、SVG、GIF、视频、CSS、HTML、JavaScript 或 WASM。
- 生成 URL 必须为当前应用同源 `/theme-assets/...`。
- Web Runtime 不接触原始文件系统路径。

### 18.2 Tauri 边界

- 内置主题资源进入 Vite `frontendDist`，不扩大 Tauri capability。
- Core 不接收主题资源字节，不解析图标或壁纸，不增加长任务。
- 原生窗口只接收已校验的 `windowSurface` 颜色。
- 当前 `csp: null` 不因本方案新增远程 origin；后续单独启用 CSP 时必须允许同源 `font-src` 和 `img-src`。CSP 改造不与本次主题升级耦合，避免扩大变更面。

## 19. 性能影响评审

### 19.1 数据规模与算法

- 内置主题预计个位数，Catalog 仍为线性小集合。
- Theme SDK 构建扫描单包最多 128 个资源，复杂度为 O(theme + asset bytes)。
- Runtime resolver 只解析当前主题，font/icon/wallpaper map 使用稳定 ID Map，查找 O(1)。
- 不增加会话、文件、Markdown 或编辑器数据读取。

### 19.2 包体与加载

- 字体、图标和壁纸会增加安装包体积，必须受 16 MiB/主题预算约束并在发布构建记录差异。
- `@font-face` 使用 `unicode-range` 和实际字体栈懒加载；未使用 face 不请求。
- 主题图标由可见 `ThemeIcon` 按需加载；同一 hash URL 复用浏览器缓存。
- 壁纸只预加载当前可见槽；非当前主题、不可见页面壁纸不请求和不解码。
- Asset Catalog 只包含 metadata 和 URL，不把二进制放入 React state。

### 19.3 渲染与合成

- 静态壁纸只占一个 surface 背景层，不在消息、列表行或工具步骤重复创建图层。
- wallpaper overlay 与内容共享稳定 stacking context，不使用持续动画。
- icon mask 使用固定尺寸，不在运行时缩放超大资源。
- stepped/smooth motion 都只消费预定义 keyframe 和有限 CSS 属性；禁止 `transition: all`。
- visual quality 可以关闭 wallpaper/texture 和重材质效果，但不能改变业务语义。

### 19.4 验收基线

- 主题切换不新增数据请求。
- 已完成历史消息和 Markdown render 次数保持不变。
- CodeMirror `EditorView` identity 保持不变。
- 非当前主题字体、图标和壁纸没有网络/asset request。
- 当前壁纸解码后不产生超出文件尺寸预算的图片内存。
- 生产构建记录主题资源总字节、Vite 输出增量和应用安装包增量。
- 壁纸主题 fixture 在正常窗口、最大化窗口和快速切换主题时不得出现持续长帧或无界 GPU memory 增长。

## 20. 过度设计评审

### 20.1 本方案为何不过度设计

- 字体文件、图标和壁纸都是 v1 已声明但未完成的真实能力，不是为假设主题新增通用页面 DSL。
- shape/elevation/motion/scrollbar 是当前硬编码样式无法被主题包表达的最小结构集合。
- 图标按有限语义槽覆盖，不建立任意组件替换系统。
- 壁纸只支持四个稳定 surface、静态图片和有限布局参数，不建设背景场景引擎。
- 运行时复用 CSS variables、Vite static assets 和低频 Context，不新增数据库、队列、缓存服务或 IPC。
- 多语言字体只定义 face、coverage 和 stack；不实现下载式语言包，等出现真实包体问题再扩展。

### 20.2 明确不引入的抽象

- 任意 CSS AST 或 selector DSL。
- 主题级 React component registry。
- 图标脚本、SVG sanitizer 或远程 icon service。
- 动态壁纸播放器、shader、粒子系统和帧调度器。
- 用户级壁纸/图标偏好和覆盖优先级。
- v1/v2 双解析器和长期兼容桥。

- capability/file 严格一致。
- token alias 循环、缺失引用和非法值失败。
- recipe 任意字段、未知 role/state 和非法前景背景组合失败。
- asset 路径逃逸、符号链接、大小写冲突和重复 ID 失败。
- MIME/签名不一致、尺寸/体积/数量超限失败。
- font metadata、weight、coverage、locale/script 和 stack 引用失败。
- icon slot、renderMode、nativeSize 和 asset kind 失败。
- wallpaper slot、fit、position、opacity 和 asset kind 失败。
- 失败构建不破坏上一次完整生成产物。

### 22.2 Web Runtime

- `themeId + scheme + quality + locale + personalization` 解析稳定。
- UI / editor 字体域不串值。
- 主题字体显示名称随主题和语言变化。
- 本机字体与自定义字号继续覆盖主题值。
- 图标按 scheme override -> default -> Lucide 回退。
- 图标错误不删除按钮和 accessible name。
- wallpaper 按 visible slot 加载并在失败时回退语义背景。
- performance 关闭 wallpaper 后不改变其他主题语义。
- 主题切换不重建 timeline、Markdown 和 CodeMirror。
- Icon Context 更新不让非图标重型子树重渲染。

### 22.3 Rust/Tauri

- Rust Catalog 只接受 Contract v2。
- 内置主题 ID 与用户 Appearance Preference 保持一致。
- 未知/损坏主题仍回退 `builtin.gold-band`。
- 原生窗口背景只使用 `windowSurface`。
- 主题资源全部来自 `frontendDist`，无需新增 fs/capability。
- release bundle 包含所有 Asset Manifest 记录文件且 hash 对应。

### 22.4 视觉与交互

- 两个内置主题 light/dark/system 无视觉回归。
- default、hover、active、selected、focus、disabled、loading 状态前景背景配对正确。
- focus ring 始终可见，键盘导航和危险操作语义不变。
- 正常宽度、窄窗口、重新拉宽、最大化和长文本无溢出或重叠。
- 会话、Markdown、工具卡、权限卡、工作流、右侧文件、Diff 和设置页 role 覆盖完整。
- 图标尺寸不改变按钮和触控目标。
- 壁纸 surface overlay 保持正文 4.5:1、UI 边界 3:1。
- 用户图片、附件缩略图和业务预览保持原始渲染方式。

## 24. 完成定义

Theme Engine v2 只有同时满足以下条件才算完成：

1. Theme Contract、JSON Schema、Web Zod、Rust `serde` 和 SDK 构建器全部切换到 v2。
2. v1 parser、Schema、硬编码字体和重复消费路径已删除，不存在双版本运行时。
3. 两个现有内置主题迁移完成，视觉与用户偏好语义无回归。
4. 字体文件、字重、覆盖范围、locale/script 和 fallback 通过主题包声明并实际生效。
5. 设置页默认字体名称来自当前有效主题投影，不新增高级字体设置。
6. shape、elevation、motion、scrollbar 和 state recipe 被共享组件实际消费。
7. icons capability、首批语义槽、ThemeIcon 和 Lucide fallback 完整可用。
8. wallpapers capability、四个 surface slot、overlay、预加载和失败回退完整可用。
9. 图标和壁纸不新增用户设置，不改变业务可访问名称、布局或交互语义。
10. 所有主题资产通过 hash、类型、尺寸、授权和路径校验并进入 Vite `frontendDist`。
11. 主题切换不新增数据请求、不重建历史 Markdown、不销毁 CodeMirror、不扩大 Tauri 权限。
12. SDK、Web、Rust、生产构建、浏览器、EXE、视觉、性能和包体验收全部通过。
13. 仅使用非分发 fixture 即可证明 v2 能表达字体、图标、壁纸和高差异组件视觉，而不引入任何新增正式主题设计。
