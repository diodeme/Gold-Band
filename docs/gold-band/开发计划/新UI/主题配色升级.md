# Gold Band 主题配色升级计划

## 1. 问题与目标

旧主题的主要问题不是单个色值不好看，而是背景、内容面、侧栏、边框和交互强调之间缺少稳定的语义层级：默认浅色被冷蓝大面积染色，旧深色则由香槟金同时承担品牌、操作、选中和焦点语义。

本轮目标：

- 四套主题继续共享 Tailwind CSS + shadcn/ui semantic token 接口，禁止页面级配色分支和硬编码。
- 浅色以中性 surface 为主体；品牌色只用于操作、焦点、选中和状态。
- 深色参考成熟桌面 AI 工具的中性灰阶最佳实践，保证背景、内容面、浮层和边界清楚可辨。
- 设置页主题预览与 CSS runtime 色板保持一致，主要文字和状态色满足 WCAG AA。

## 2. 色板方向

### 2.1 瓷白

- 瓷白主面、雾灰工作区、石墨文字与低饱和矿物靛蓝强调。
- 蓝色不得大面积铺入页面底、侧栏和边框。

### 2.2 科技灰

- 参考成熟桌面 AI 工具的浅色工作区：`#ffffff` 主内容、`#f3f3f3` 侧栏、`#e7e7e7` 选中面、`#e5e5e5` 边界和 `#3f3f3f` 石墨正文。
- 主操作、焦点和普通交互同样使用无彩石墨灰；冷蓝只用于运行状态，避免文字、图标与 surface 被蓝灰统一染色后显得偏脏。
- 文字采用四级层次：`#171717` 深黑标题、`#2b2b2b` 正文、`#666666` 辅助文字、更浅的禁用/占位态；侧栏导航、分组和任务标题统一使用 `sidebar-foreground = #171717`，时间、空状态等元信息才使用 `#666666`。大面积灰色只服务于侧栏和必要的交互 surface，不能侵蚀标题与阅读正文的对比度。

### 2.3 石墨深色

- 按 Codex 桌面端截图取样，以 `#181818` 主内容、`#202020` 侧栏/标题栏、`#242424` 内容面、`#2d2d2d` composer/高层 surface、`#313131` 选中面建立无彩炭灰层级。
- 选中、按钮和焦点不再使用品牌蓝；冷蓝只承载运行状态，暖橙只承载权限/警告。

### 2.4 终端黑

- 与石墨深色共享无彩层级逻辑，但整体压暗为 `#111111 / #191919 / #1b1b1b / #252525 / #2d2d2d`。
- 作为比石墨深色更安静的沉浸选项，不使用蓝色或灰紫铺满背景与选中态。

## 3. 实现范围

- 更新 `web/src/styles.css` 中四套主题的 semantic CSS variables。
- 更新 `web/src/theme.ts` 中设置页主题预览色板。
- 默认浅色名称调整为“瓷白”，原暖色浅色以“科技灰”和新的 `light-gray` 持久化 ID 完整替换。
- 主题选项只保留名称，从主题数据模型、设置页和中英文 i18n 中删除说明字段与说明文案。
- 侧栏所有选中态必须使用 `sidebar-accent` / `sidebar-accent-foreground` 成对语义 token，覆盖主导航、运行项和会话切换器。
- 共享 shadcn `TabsList` 默认 track 使用 `secondary` surface + `border` 内描边，避免默认浅色的 `muted` 与 workspace 同色；`line`、Agent 图标和自带边界的透明变体不改。
- 新增全局 `text-selection` / `text-selection-foreground` 成对 token，并移除基础 Input 的局部 selection 配色，统一普通文本、Markdown、输入框与 composer 的选区层级。
- 新增 `message-user` / `message-user-foreground` 成对 token，由 prompt-kit `MessageContent` 的 user 变体统一消费；移除用户气泡对 `primary` 的动态混色、边框和投影。
- 新增 `content-header` 语义 token：两套浅色的运行标题栏与 ACP session header 使用纯白，两套深色使用各自的低层 surface；不再通过 `gold-surface-high/60` 在主内容顶部制造连续灰带。
- prompt-kit `MessageContent` 的 assistant 变体改为透明背景、实色正文、无边框和无投影，使 AI 阅读内容直接落在页面白底上；卡片只保留给工具、思考、代码和真正独立的结构化对象。
- 主题抽屉从“左侧分组标签 + 全宽单列大卡”改为“顶部小标题 + 容器响应式样本网格”；默认抽屉宽度下每组两列，窄抽屉单列。主题卡收紧为空间匹配的横向预览卡，并用对勾状态胶囊表达当前主题。
- 共享 Tabs 增加 `bare` 变体：胶囊选项自身拥有边界或容器显式提供边界时清除默认 track、padding 和 ring，避免双重描边。
- 不修改页面布局，不新增组件；开发阶段直接删除旧 `light-warm` 入口，不增加兼容层或 fallback。

## 4. 验收

- Vitest 固化 CSS runtime 色板、设置页预览色板和主要前景色 WCAG AA 对比度。
- 源码契约测试固化侧栏选中背景与前景的语义配对，禁止回退为 `text-sidebar-primary`。
- 源码契约测试固化默认 Tabs track 的 `secondary` / `border` 语义，覆盖所有复用默认变体的页面。
- 色板测试固化四套文本选区 token 及选区文字 WCAG AA 对比度，禁止回退到 `primary/30`。
- Tabs 源码契约测试覆盖 `bare` 变体及 Agent 选择器、Round 详情两个消费点，禁止透明覆盖后继续遗留默认 ring。
- Web 生产构建通过。
- 实际启动前端验证设置页、会话首页、侧栏、标题栏、composer 和配置区域。
- 瓷白、科技灰、石墨深色和终端黑具有可辨识的独立气质，同时保持统一的信息层级。
- 契约测试固化主题卡片只展示名称、`light-gray` 枚举与科技灰 runtime/preview/window surface 同源，并拒绝旧 `light-warm` 值。
- 科技灰契约额外固定无彩侧栏、选中面、深黑 `sidebar-foreground` 和石墨主色，禁止回退到旧蓝灰 `primary`、把主要标题降级为 `muted-foreground`，或使用带蓝通道偏移的中性 surface。
- 欢迎语与页面级标题必须消费 `title` token，禁止再次使用 `foreground` 透明度制造灰雾感。
- 用户气泡色板测试固化四套主题的背景/文字对比度；源码契约禁止恢复 `primary` 混色，并确保 hidden runtime context 不在浅灰气泡内嵌套白色卡片。
- hidden runtime context 尺寸契约固定标题始终 `w-full`，折叠态通过 inline-size containment 排除隐藏区的 intrinsic width 贡献，展开态解除 containment 并由 `w-max + max-w-full` 的隐藏正文按需扩展整个用户气泡。
- 内容层契约固定浅色 `content-header = #ffffff`、assistant 正文透明背景和无投影，禁止重新形成灰色 header 带或白卡片堆叠。
- 主题抽屉源码契约固定 `@2xl/theme-drawer:grid-cols-2`、移除旧 `72px + 1fr` 分栏与 `min-h-32` 全宽卡，并保证 effective theme 同时覆盖手动选择和跟随系统解析结果。
