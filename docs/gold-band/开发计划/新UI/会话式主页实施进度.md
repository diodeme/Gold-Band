## 2026-07-23 Direct 配置边界与创建失败修复

- 产品边界：Direct 的 Agent、模型和权限全部在快速会话 composer 内完成，运行模式管理页删除 Direct tab 和配置区，只保留工作流与 AUTO；Direct 校验错误不再提供跳转运行模式管理的“去配置 / 修复”按钮。
- 根因修复：Direct 内部 worker 使用 `raw-agent` prompt envelope，本应完全绕过 Gold Band 角色层，但 workflow profile resolver 仍对所有 worker 强制解析 profile，导致创建时报 `direct-agent is not associated with role`。
- 数据规则：profile resolver 按 prompt envelope 分流；`runtime-managed` worker 继续强制有效 profile，`raw-agent` worker 不解析 profile 且禁止绑定非空 profile，确保 Direct 的空 system prompt 不被角色内容污染。
- 验收固化：新增 resolver 正反例单测与 Direct task 创建接口回归测试；运行模式管理 toolbar 测试明确断言不包含 Direct。

## 2026-07-10 工作流编辑器输入画布闪烁修复

- 问题：运行模式管理页编辑工作流模板时，右侧 Inspector 输入框每输入一个字符，左侧 ReactFlow 画布会闪烁，尤其是目标、prompt、schema 等长文本字段。
- 根因：`WorkflowEditor` 用完整 `workflow` 对象同时驱动画布投影和右侧表单；配置字段逐键更新时也会触发 `workflowToFlow()` 重算全部 nodes/edges。
- 方案：新增作者态工作流画布签名，只包含 entry、节点 id/type/provider 与边 from/to/on 等影响画布结构或呈现的字段；ReactFlow 投影依赖该签名、选中态、校验高亮和终点显隐。右侧配置字段仍更新完整草稿，保证保存正确，但不再逐键刷新画布。
- 验收固化：`web/tests/workflow-editor-graph-signature.test.ts` 覆盖 Inspector-only 配置不改变画布签名，provider/edge 等画布字段改变时签名必须变化。

## 2026-07-10 旧 UI 工作空间选择页与新 UI 切换边界修复

- 问题：旧 UI 打开“选择工作空间”覆盖页后切换到新 UI，会话模式仍被旧 UI 选择页占住；只有打开一个旧 UI workspace 后才恢复正常。同时旧 UI 最近工作空间列表只能打开，不能移除历史项。
- 根因：`workspacePickerOpen` 是 App 级状态，`renderConversationContent()` 也优先渲染它，导致旧 UI 的覆盖层跨越了新旧 UI 状态边界；最近 workspace 只有 `choose_workspace` / `select_recent_workspace` 写入和选择接口，缺少“移除最近记录但不切换 workspace”的命令。
- 方案：将 workspace picker 明确定义为工作台模式覆盖层，启动自动打开仅限 `uiMode=workbench && needsWorkspace=true`；切到会话模式时关闭该覆盖层，并且在旧 UI 尚未选择 workspace 时不把占位 cwd 同步到新 UI。新增 `remove_recent_workspace` 命令和前端 API，最近列表行使用 shadcn Button + Tooltip 与 Trash2 图标提供移除操作；当前 workspace 与唯一有效 recent 项禁用移除，命令层返回结构化错误兜底。
- 验收固化：后端新增最近 workspace 删除持久化单测；前端新增 workspace picker scope 单测覆盖工作台 picker 边界、当前/最后一个 recent 禁删规则，并补齐 API facade / desktopApi / browserApi 对 `remove_recent_workspace` 的透传与拒绝测试。

## 2026-07-09 运行模式管理新增工作流模板草稿修复

- 问题：新 UI 的运行模式管理页点击“新增模板”后只显示居中空态文案，没有进入工作流编辑器；旧 UI 创建任务抽屉同流程正常。
- 根因：新 UI 的新增模板分支把 `wfEditWorkflow` 置为 `null`，而页面用 `wfEditWorkflow` 作为是否渲染 `WorkflowEditor` 的条件，导致新增模板被当成无草稿空态。

- 验收固化：`web/tests/run-mode-management-page.test.ts` 覆盖运行模式管理页新增模板入口必须创建可编辑 workflow 草稿，防止回退为 `null` 空态。

## 2026-07-04 AUTO 全局 Goal 输入空格修复

- 问题：会话主页新建会话使用 AUTO 模式时，全局 Goal 输入框输入空格后会立即消失，导致无法输入包含空格的目标文本。
- 根因：`ConversationComposer` 的 AUTO 会话级配置在每次 `onChange` 时立刻 `trim()` 后保存到父级 `runMode`，随后 `useEffect` 又把父级配置反灌回输入框，导致正在编辑中的尾随空格被删除。
- 方案：区分编辑态与有效性判定。编辑态通过 `optionalRunModeText` 保留原始字符串；创建会话 payload 边界通过 `normalizeConversationAutoConfigForSubmit` 保留非空文本原样，仅把纯空白值折叠为未设置。
- 横向检查：前端显式拦截空格的输入相关位置主要是可键盘激活的按钮/列表项；普通 `Input` / `Textarea` 未发现同类每按键 trim 反灌问题。运行模式管理页的全局 Goal 是表单保存模式，不存在会话主页这种逐键同步链路。
- 验收固化：`web/tests/conversation-run-mode-config.test.ts` 覆盖编辑态保留空格、提交态不裁剪非空文本、以及受控输入反灌不吞尾随空格。

## 2026-06-30 首页 composer 草稿跨页面保留

- 问题：在会话主页输入未发送正文（及附件）后，离开会话主页再返回时，正文与附件不应丢失；离开路径包括跳转运行模式管理（去配置 / 修改 AUTO / 修改工作流）、打开其他会话窗口、进入设置等普通跨页面导航。
- 根因：`ConversationComposer` 的 `content` 与 `attachments` 原为组件本地 `useState`，组件卸载会销毁草稿；附件图片的 `previewUrl` 也不能由短生命周期 hook 在普通卸载时释放。
- 方案：沿用「创建任务草稿跨页面保留」同一心智，`web/src/lib/conversation-composer-draft.ts` 由 App 层 owner 统一持有正文与附件，经 `ConversationComposerDraftProvider` 下发；`ConversationComposer` 受控消费草稿，`useAttachmentPicker` 支持外部附件状态注入。
- 生命周期：普通跨页面导航不清空草稿，也不释放图片 preview URL；仅显式移除/清空附件、创建会话成功、切换目标工作空间或应用卸载时释放附件资源并清空对应草稿。
- 验收固化：`web/tests/conversation-composer-draft.test.ts` 覆盖正文/附件跨页面保留、普通保留不释放 preview URL、owner 清理路径释放 preview URL 与 reset 语义。
