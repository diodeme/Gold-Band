## 2. 可行性与工作量结论

这两个改动可以实现，但不能只按两个前端组件改动估算。

- “把文件放进右侧工作区查看”较直接：现有 `RightWorkspaceResource`、文件 Tab、CodeMirror、图片预览和安全 preview grant 都可以复用。
- “准确展示每一轮 prompt turn 的工具文件变化”仍是运行时能力：需要把 ACP diff 按稳定 turnId 持久化、折叠同路径的多次修改，并保存不可变前后版本。它不扫描或比较 live workspace，因此不会把用户或其他并发 session 的磁盘变化算入当前 turn。
- 完整质量版本预计 **7～10 个开发日**，主要成本在 ACP diff 持久化、同路径 mutation 链折叠、不可变版本存储、右栏 Diff Viewer 和接口级测试。

用户附件和 artifact 的消息内展示不与文件变更卡合并：前者表达 prompt 输入，后者表达 Agent 结构化输出；两者只复用右侧文件查看能力。

## 3. 问题判断

### 3.1 不是右侧工作区设计缺陷

当前通用右侧工作区已经具备：

- 按资源 kind 注册 renderer / close resolver。
- 多 Tab、会话 scope、LRU 和响应式 Dock / Sheet。
- `file` 资源、CodeMirror 6、文本/Markdown/图片/不支持格式的读取与预览。
- 会话 Markdown 本地文件链接打开、Tab 复用和行列定位。

因此不新建“附件侧栏”或“产物查看器”，继续扩展通用文件资源与 Diff 资源即可。

### 3.2 根因是资源领域和 turn 生命周期缺失

现有实现存在以下结构性问题：

1. `AssetItemVm` 只包含名称和 attempt locator，不包含真实文件版本，无法保证历史内容稳定。
2. `ConversationRunVm.artifacts / attachments` 是当前选中 session 的 attempt 级聚合，适合旧展开栏，不适合生成 prompt-turn 文件变化。
3. `AcpSessionAssetsPanel + ACPArtifactsDialog` 把文件当成 composer 上方的 session 附属信息，而不是可复用的工作区资源。
4. 用户消息附件和 artifact 已拥有正确的消息归属，但其点击查看尚未统一进入右侧工作区。
5. 当前文件 Tab 指向 live workspace path；旧 turn 的 diff 若继续读取 live path，会被后续修改覆盖。

正确方向是新增只由 ACP tool diff 驱动的 **turn-scoped file change set** 和 **immutable file version**。用户附件与 artifact 保持现有消息生命周期，不进入 change set；三者只在右侧查看器层复用通用文件资源能力。

## 4. 目标与非目标

### 4.1 目标

1. 一个可见用户 prompt 到对应 Agent 处理终止，形成一个稳定 `PromptTurn`。
2. 每个 turn 只记录 ACP tool call 返回的 diff，并按返回顺序合成为本轮工具报告的净效果；不读取当前磁盘或 live workspace 作为最终状态。
3. tool diff 中的文件使用统一不可变版本协议；用户附件与 artifact 使用各自现有消息 locator 打开右侧工作区。
4. 卡片和右栏只读取持久化版本，不根据当前目录重新猜测历史。
5. 根会话与 Agent branch 各自只展示归属于本 branch 的 change set。
6. 完成、失败、取消的 turn 都要结算已发生的文件变化。
7. hidden repair 属于触发它的可见 turn，不单独生成用户可见卡片。
8. 未来 commit/tree/blob 比较接入时不替换前端卡片和 Diff Viewer。

### 4.2 非目标

- 本期不实现 Git 初始化、提交、暂存、撤销、Review、commit 列表或多 commit 选择器。
- 本期不在卡片中提供截图示例里的“撤销”“审核”按钮；没有后端语义的按钮不进入 UI。
- 不把 Round 详情页现有 artifact / attachment 排障入口一并删除；本期只替换 Conversation / ACP 会话详情主路径。
- 不把右侧工作区改造成 IDE，也不增加 terminal / command bar 心智。
- 不宣称共享 main workspace 中的变化一定由当前 Agent 因果产生；该场景只能表达“本 turn 观察窗口内的净变化”。

## 5. 领域模型

### 5.1 生命周期归属

```text
AcpAttempt
└── PromptTurn (turnId / promptId)
    ├── user message
    ├── user attachments（消息自有，不进入 change set）
    ├── agent messages / artifact（消息自有，不进入 change set）
    ├── tools / hidden repair
    └── TurnFileChangeSet
        └── FileChange[]
            ├── beforeVersion?
            └── afterVersion?
```

- `AcpAttempt` 是长会话容器。
- `PromptTurn` 是本需求的最小归属单位。
- `TurnFileChangeSet` 与 `turnId`、branch 和 attempt locator 一一绑定。
- 文件版本属于历史快照生命周期，不属于 React Tab 生命周期，也不依赖文件当前是否仍存在。

### 5.2 后端持久化模型

建议在 Rust 领域层新增以下结构，序列化时使用 camelCase：

```rust
struct TurnFileChangeSet {
    id: String,
    turn_id: String,
    prompt_event_id: String,
    branch_id: String,
    locator: AcpAttemptLocator,
    status: TurnFileChangeSetStatus, // capturing | finalized | partial
    started_at: String,
    finished_at: Option<String>,
    summary: TurnFileChangeSummary,
    changes: Vec<TurnFileChange>,
    limitation_codes: Vec<String>,
}

struct TurnFileChange {
    id: String,
    change_kind: FileChangeKind, // added | modified | deleted | renamed
    logical_path: String,
    previous_logical_path: Option<String>,
    mime_type: Option<String>,
    text: bool,
    added_lines: Option<u64>,
    deleted_lines: Option<u64>,
    before_version: Option<FileVersionRef>,
    after_version: Option<FileVersionRef>,
    limitation_code: Option<String>,
}

struct FileVersionRef {
    id: String,
    storage_kind: FileVersionStorageKind, // captured_blob；以后可增加 git_blob
    content_hash: String,
    byte_length: u64,
    encoding: Option<String>,
    line_ending: Option<String>,
}
```

约束：

- `added` 只有 `afterVersion`。
- `deleted` 只有 `beforeVersion`。
- `modified` 同时拥有 before / after。
- `renamed` 先预留枚举与 `previousLogicalPath`，本期采集器可保守投影为 delete + add，不做相似度猜测。
- 行数统计只用于文本；二进制使用 `null`，不能伪造 `0`。
- change set 不保存 `sourceKind`；其中所有条目都来自 ACP tool diff。用户附件和 artifact 不通过伪造文件 mutation 接入。

### 5.3 通用文件资源 locator

将现有只覆盖 workspace / external 的 `WorkspaceFileLocatorVm` 提升为带 tag 的 `FileResourceLocatorVm`：

```ts
type FileResourceLocatorVm =
  | { kind: 'workspace'; projectId: string; canonicalPath: string; relativePath: string | null }
  | { kind: 'external'; projectId: string; canonicalPath: string; grantId: string }
  | { kind: 'conversation-asset'; projectId: string; locator: AcpAttemptLocatorVm; assetKind: 'user-attachment' | 'artifact'; name: string }
  | { kind: 'conversation-version'; projectId: string; changeSetId: string; versionId: string };
```

- `conversation-asset` 由现有用户消息附件或 artifact 消息提供，只负责将既有消息资源打开到右栏，不进入 turn change set。
- `conversation-version` 对应 ACP tool diff 持久化的不可变前后版本；两类 locator 都不向前端暴露 runtime 绝对路径。
- 后端通过 locator 解析到受控的 attempt blob / asset root，并继续执行 canonicalize、symlink 和 preview grant 校验。
- 历史版本一律只读；现有 live workspace 文件继续保持原自动保存语义。

### 5.4 右侧工作区资源

新增一种资源，不把 Diff 塞进普通文件 Tab 的局部状态：

```ts
type FileDiffWorkspaceResource = {
  kind: 'file-diff';
  key: string;
  scopeKey: string;
  title: string;
  changeSetId: string;
  changeId: string;
  beforeVersionId: string;
  afterVersionId: string;
};
```

- 新增文件：打开现有 `file` 资源，locator 指向 `conversation-version` 的 after version。
- 修改文件：打开 `file-diff` 资源。
- 删除文件：行保持非交互，不创建右栏资源。
- live 文件 key 继续按 canonical path 复用；历史文件 key 按 version ID；diff key 按 before + after version ID。这样同一路径在不同 turn 的内容不会串 Tab。

### 6.1 选型结论

1. 文本 diff 使用官方 `@codemirror/merge`，不引入独立 diff UI。
2. tool diff 的 old / new 正文使用 blake3 CAS + 原子文件持久化；Rust `similar` 只比较这两份正文并计算 `+N/-N`。未来 commit/tree/blob 的枚举和内容读取使用 Git CLI。
3. 文件变更卡只组合现有 shadcn/ui copy-in 与 Lucide icon。
4. 用户附件和 artifact 消息点击继续复用当前文件 renderer，不进入文件变更卡，也不新建专用查看器。

## 7. Turn 文件采集方案

### 7.1 稳定 turnId

- 用户点击发送前即生成稳定 `turnId`，继续沿用当前 command 传入的 `promptId`。
- runtime 自动首轮也必须生成稳定 `turnId`，不能依赖 UI 是否传入。
- `user_prompt_event.raw.promptId`、通知去重、usage journal 和文件 change set 使用同一个业务 turn identity；现有 timeline event ID 可保留为事件 ID，不再兼任业务 turn ID。
- hidden output repair 继承原可见 `turnId`，不得生成第二张文件卡。

### 7.2 唯一采集来源

```text
生成 turnId
  → record user prompt event
  → session/prompt
  → 收到 ACP toolCall / toolCallUpdate 的结构化 diff
  → 按 toolCallId + eventSeq + contentIndex 持久化 mutation
  → hidden repair 继续写入同一 turnId
  → turn 终止时折叠 mutation chain
  → 原子写入 change set
  → timeline 追加 fileChangeSet 指针事件
```

change set 在当前可见 turn 的 prompt 调用及其 hidden repair 全部终止后关闭。它不读取 `git status`、不扫描目录、不监听文件系统，也不根据工具名称猜测写入；没有 ACP diff 的 execute / shell / MCP 操作不进入卡片。

### 7.3 ACP diff 归一化

ACP 已经完成 provider 差异转换，本层只消费标准结构化 diff，不增加 Claude / Codex / Gemini 等 provider adapter。每个合法 diff 至少需要：

- `path`；
- 完整 `oldText` / `newText` 中至少一个存在；
- 所属 `toolCallId`、timeline `eventSeq` 和 content item index。

Gold Band 只做协议校验、路径规范化和安全边界判断，不把 raw tool name 作为采集条件。diff 缺字段或历史内容被截断时不伪造统计，记录结构化 limitation code。

### 7.4 Mutation 折叠

同一 turn 内按规范化 logical path 分组，再按 `eventSeq + contentIndex` 排序：

1. 第一条 mutation 的 `oldText` 作为本轮 tool-reported before。
2. 最后一条 mutation 的 `newText` 作为本轮 tool-reported after。
3. 相邻 mutation 校验 `previous.afterHash == next.beforeHash`；不一致时保留证据并将该文件标记为 non-linear，不静默拼接错误链。
4. before / after hash 相同表示本轮工具最终报告已恢复原内容，不进入卡片。
5. `None → blob` 为 added，`blob → blob` 为 modified，`blob → None` 为 deleted，`None → None` 不展示。
6. added / deleted / modified 的行数统计根据合成后的 tool-reported before / after 重新计算，不能累加各 tool call 的 `+/-`。

示例：

```text
Write:  不存在 → B
Edit:   B → C
卡片:   added，打开内容 C

Write:  A → B
Edit:   B → C
卡片:   modified，展示 A → C
```

这里的 `C` 是最后一次 tool call 当时返回并持久化的内容，不是用户稍后点击卡片时磁盘上的最新内容。后续 tool call、用户编辑、其他 session 或 Git 操作改变 live 文件，都不能改变已经 finalized 的卡片。

### 7.5 明确排除项

- 用户上传附件继续绑定用户消息；点击消息中的图片或文件 chip 打开右侧工作区，不写入 change set。
- canonical artifact 继续由 Agent 消息的现有特殊样式承载；点击该消息打开右侧工作区，不写入 change set。
- ACP tool diff 若修改了任意普通路径，包括运行时 `attachments/` 下由文件工具创建的文件，都按普通 tool file change 处理；本期不按目录增加“附件 / 产物”标签或第二条记录。
- 不从 attempt `attachments/` / `artifacts/` 目录扫描、补录或推断文件变化。

### 7.6 并发与 branch 归属

- mutation 由当前 ACP prompt 的 tool call 直接报告，并绑定稳定 turnId，不受共享 workspace 中其他 session 的磁盘写入影响。
- 根会话与 Agent branch 根据持久化 timeline / branch ownership 归属 change set，不根据路径或自然语言推断。
- UI 可直接使用“本轮文件变化”，无需 shared-workspace attribution 降级标记。

### 7.7 持久化与崩溃恢复

建议目录：

```text
attempt/
├── acp.timeline.jsonl
├── acp.turn-file-mutations.jsonl
├── turn-file-change-sets/
│   └── <turn-id>.json
└── acp.file-blobs/<hash-prefix>/<blake3>
```

- 每个 ACP diff 的 old / new 全文先原子写入 blake3 CAS，再把 mutation journal 持久化并 `sync_data`；幂等键由 `turnId + toolCallId + eventSeq + contentIndex + beforeHash + afterHash` 构成。
- finalized change set 使用临时文件 + rename 原子写入；重复 finalize 同一 turnId 必须幂等。
- `fileChangeSet` timeline item 只保存 summary 和 `changeSetId`，详情点击/展开时懒加载，避免会话分页携带大清单和正文。
- runtime 重建发现 mutation journal 已存在但 change set 未 finalized 时，只重放该 turn 已持久化的 mutation；不读取当前 workspace 猜测缺失内容。若 turn 已确定终止则恢复 finalize，否则等待原 prompt 生命周期继续处理。
- CAS 以 blake3 去重，写入使用原子文件；同一 attempt 的多个 turn 不重复保存相同内容。

## 8. 后端接口方案

### 8.1 查询接口

```text
get_turn_file_change_set(locator, branchId, changeSetId)
read_file_resource(locator: FileResourceLocatorVm, preferSource?)
get_file_comparison(changeSetId, changeId)
issue_file_version_preview(versionId)
```

`get_file_comparison` 返回：

```ts
interface FileComparisonVm {
  changeSetId: string;
  changeId: string;
  path: string;
  renderKind: 'text' | 'image' | 'unsupported';
  language: string | null;
  stats: { addedLines: number | null; deletedLines: number | null };
  before: WorkspaceFileSnapshotVm | null;
  after: WorkspaceFileSnapshotVm | null;
  limitationCode: string | null;
}
```

- 卡片列表不预加载 file comparison。
- text comparison 在打开 Tab 后才加载 before / after 正文。
- image comparison 返回两个短期 preview grant，不返回任意本地 URL。
- deleted 行没有点击行为，因此正常 UI 不调用 comparison；接口仍允许内部诊断读取 before version。

### 8.2 timeline 投影

新增 `AcpUiEvent.kind = "fileChangeSet"`：

- stable ID：`turn-file-change-set:{turnId}`。
- seq 位于该 turn 所有普通消息、tool、repair 和 runtime output 落盘之后。
- 一个 change set 在 branch 分页中计为一个稳定语义块。
- live update 只在 finalized 后发布一次；不在流式过程中反复改变卡片位置。
- branch projection 使用持久化 branch ownership，不根据路径或文本推断归属。

## 9. 前端实现方案

### 9.1 文件变更卡

新增组合组件 `TurnFileChangesCard`，使用现有 shadcn/ui：

- 外层：`Card`。
- 文件列表展开：`Collapsible`。
- 长列表：卡内有限高度 `ScrollArea`，不占用整个消息流。
- 行操作：`Button variant="ghost"` 与 `Tooltip`。
- 图标：Lucide `FileDiff / FilePlus2 / FileMinus2`。

布局：

```text
┌ 本轮变化 23 个文件               +361  -108 ┐
├ src/.../mod.rs                    +10    -3 ┤
├ src/.../models.rs                  +2    -0 ┤
├ docs/plan.md                       +8    -0 ┤
└ 再显示 20 个文件                         ┘
```

交互规则：

- 默认展示条数来自统一配置 `turnFileCardPreviewLimit`，不在组件内散落硬编码。
- 修改行可点击，打开或激活 `file-diff`。
- 新增行可点击，打开该 turn 的 after version 原文；文本/代码/Markdown 使用现有 CodeMirror/Markdown renderer，图片使用现有图片 renderer。
- 删除行展示路径和删除统计，但使用非交互行，不设置伪按钮、hover 或焦点。
- 卡片不显示“附件 / 产物”等来源标签；所有条目都表示 ACP tool call 明确报告的文件变化。
- 卡片作为 ACP 结构化行，不显示头像，但与 tool / thought 保持相同横向位置。
- 无文件变化的 turn 不渲染空卡片。
- partial change set 在标题区显示一个可聚焦告警 icon，Tooltip 通过 i18n 解释未捕获原因；不把内部实现说明常驻在消息流。

### 9.2 Diff Viewer

新增 `FileDiffWorkspacePanel`：

- 本期默认使用 `@codemirror/merge` 的单栏 `unifiedMergeView`，视觉和交互对齐评审截图：删除行在上、插入行在下、上下文行保持单列连续阅读。
- 不根据右栏宽度自动切换 side-by-side，避免用户阅读位置跳变；双栏 `MergeView` 只作为后续可选视图模式预留，不进入本期默认入口。
- 配置 `EditorState.readOnly`、`EditorView.editable.of(false)` 与 `mergeControls: false`；本期无 accept / reject / apply / revert controls。
- 复用 `WorkspaceFileEditor` 的语言识别、字体、主题 token、搜索和行号 extension 工厂，不复制一套 CodeMirror 主题。
- 开启 `highlightChanges`、diff gutter 和 `collapseUnchanged`；长段未修改内容折叠为类似“55 行未修改”的整行浅色圆角入口，点击或键盘操作后展开。
- 顶部标题固定为“本轮修改 Diff”，表示当前 Prompt Turn 的首个 oldText 与最后 newText 之间的比较；上一处/下一处变化按钮只在官方 changed chunk 至少为两处时显示。导航只改变 CodeMirror selection / scroll，不重建编辑器。
- 大文本超过配置上限时不挂载完整 merge view，返回 limitation code 并提供“分别查看前后版本”的只读入口。

视觉结构：

```text
┌ 本轮修改 Diff                       +26  -10 ┐
├ M  docs/.../方案.md                +26  -10 ┤
├ 55 行未修改                                  ┤
│ 58  上下文行                                  │
│ 59- 删除内容                                  │
│ 59+ 新增内容                                  │
│ 60  上下文行                                  │
├ 131 行未修改                                 ┤
│ ...                                           │
└───────────────────────────────────────────────┘
```

- 顶部比较工具栏和当前文件栏使用 sticky 布局；滚动正文时仍能看到版本语义、文件名和 `+N/-N`。
- “本轮修改 Diff”比较第一条 tool diff 持久化的 old version 与最后一条 tool diff 持久化的 new version；不能使用“当前文件”等会让用户误以为读取 live workspace 的文案。
- 文件状态 `A / M / D`、增删统计和折叠入口使用语义 token；浅色/深色主题均避免大面积高饱和红绿背景，只强调行 gutter、行号和实际变化文本。
- 折叠入口、版本选择和变化导航必须可聚焦，并提供中文/英文 aria-label；不能只依赖红绿区分状态。
- 本期一个 `file-diff` Tab 只挂载当前文件的一份 CodeMirror 实例。变更卡中的文件行负责切换/打开对应文件，不在一个长页面中为每个文件重复挂载编辑器。

图片与二进制：

- 新增图片直接使用现有图片预览。
- 修改图片第一版可使用前后并排预览；若视觉验收要求拖动比较，再引入 `react-compare-slider`。
- 不支持二进制 diff 时仍可打开 `file-diff` 展示名称、MIME、before / after 大小与 hash；前端根据 `turn-files.binary-diff-unsupported` 显示文案。

## 10. 配置、性能与安全

所有阈值进入 `WorkspaceFileConfig` 或独立 `TurnFileCaptureConfig`，至少包括：

- `cardPreviewLimit`
- `captureMaxEntries`
- `captureMaxFileBytes`
- `captureMaxTotalBytes`
- `diffTextMaxBytes`
- `diffTextMaxLines`
- `blobCacheMaxBytes`
- `blobRetentionPolicy`

性能规则：

- 会话快照只带 change set summary，不带完整 change list 和正文。
- 卡片展开时拉 change list，打开 Tab 时再拉正文。
- tool diff 到达时只对其携带的 old / new 正文做 CAS 去重和 mutation journal 追加，不访问工作区、不执行 Git、不枚举目录。
- turn finalize 只折叠当前 turn 的 mutation 元数据，并使用 `similar` 计算合成后 tool-reported before / after 的 `+N/-N`；成本与 tool diff 数量和正文大小相关，而不是与仓库大小相关。
- 文件列表使用稳定 change ID；展开/收起不重建会话全部 Markdown 或 CodeMirror。

安全规则：

- 前端不能提交任意 blob path 或 runtime absolute path，只提交后端签发的 changeSetId / versionId。
- resolver 必须校验 project、attempt、branch ownership 和 version 所属关系。
- CAS 路径由 hash 生成，不拼接用户文件名。
- 图片继续通过短期 preview grant；禁止 WebView 直接加载本地路径。
- symlink、路径穿越、Windows 大小写与 UNC 路径继续复用 workspace file 领域的权威校验。

## 11. 错误模型与 i18n

后端只返回结构化 code + params，不返回对客文案：

| code | 含义 |
| --- | --- |
| `turn-files.change-set-not-found` | change set 不存在或不属于 locator |
| `turn-files.version-not-found` | 不可变版本不存在 |
| `turn-files.version-access-denied` | project / branch / attempt 归属校验失败 |
| `turn-files.capture-partial` | 捕获因上限、截断、崩溃或 mutation 链不连续而降级 |
| `turn-files.capture-limit-exceeded` | 单文件、总量或条目数超限 |
| `turn-files.invalid-tool-diff` | ACP diff 缺少路径或完整前后文本，不能形成可信版本 |
| `turn-files.non-linear-mutation` | 同一路径相邻 mutation 的 after / before hash 不连续 |
| `turn-files.diff-too-large` | 文本 diff 超出渲染阈值 |
| `turn-files.binary-diff-unsupported` | 当前格式不支持内容差异 |
| `turn-files.blob-corrupted` | CAS blob hash 校验失败 |

中英文文案统一维护在前端 i18n；若实现中需要新增 runtime prompt 上下文或 repair 指令，必须同步放入 `src/prompts/zh-CN/...` 与 `src/prompts/en/...`，不能在代码中硬编码长 prompt。本方案预计不需要修改提示词。

## 12. 后续 Git 管理兼容设计

本期就把“文件比较”定义为两个版本端点，而不是“当前文件 + 一段 patch”：

```rust
enum VersionEndpoint {
    CapturedVersion { version_id: String },
    // 后续新增
    GitBlob { repository_id: String, oid: String },
    GitTreePath { repository_id: String, tree_oid: String, path: String },
}
```

未来 Git 功能可增加：

```text
list_git_changes(baseEndpoint, targetEndpoint)
get_git_file_comparison(baseEndpoint, targetEndpoint, path)
```

这样可以覆盖：

- commit A 与 commit B。
- merge-base 与目标 commit。
- 某组 commit 解析后的首尾 tree。
- commit 与当前 worktree。
- 两个 blob。

前端仍消费 `FileChange[]` 和 `FileComparisonVm`，继续使用同一文件卡与 CodeMirror merge viewer。`react-diff-view` 这类“只消费 unified patch 文本”的组件不作为主选，正是为了避免未来多端点时重新设计 UI 数据模型。

## 14. 接口级测试与验收矩阵

### 14.1 Rust 单元/集成测试

- 标准 ACP diff 的新增、修改、删除分别生成正确 before / after。
- 同一 tool call 多文件、同一文件多个 tool call、同一 tool call 多次 update 均按稳定键幂等持久化。
- 同一路径多次修改按 mutation chain 折叠；`Write A→B` 后 `Edit B→C` 必须持久化并展示 `A→C`，不读取磁盘当前内容。
- 新文件 `Write None→B` 后 `Edit B→C` 必须保持 added，点击打开已捕获版本 C。
- 工具最终报告恢复首个 old hash 时不进入卡片。
- mutation 链 hash 不连续时返回 `turn-files.non-linear-mutation`，不伪造连续链。

- 文件名含空格、中文、换行和 Windows 大小写差异。
- hidden repair 合并到原 turn；取消/失败仍结算。
- mutation journal 崩溃恢复幂等，不重复生成 change set。
- 大文件、二进制、总量和条目上限返回结构化 limitation code。
- versionId 路径穿越、跨 project、跨 attempt、跨 branch 访问被拒绝。
- 历史 version 在 live workspace 后续变化/删除后仍可读取。

### 14.3 真实 UI 验收

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 单轮混合变化 | 同一 turn 的 tool call 报告新增、修改、删除多个文件 | turn 末尾只有一张汇总卡，统计与列表一致 |

## 15. 风险与处理

| 风险 | 错误做法 | 方案 |
| --- | --- | --- |
| 旧 turn 读取 live path | 后续修改使历史 diff 变化 | before / after 物化为不可变 CAS version |
| 扫描 workspace 推断本轮变化 | 把用户或并发 session 的写入算入当前 turn | 只消费绑定当前 turnId 的 ACP tool diff |
| 累加每次 tool diff 的行数 | 文件恢复原状仍显示变化，统计失真 | 折叠为最早 tool-reported before / 最后 tool-reported after，再用 `similar` 计算净统计 |
| mutation 更新重复到达 | 同一个 tool call 重复计数 | 使用稳定幂等键并按 tool update revision 合并 |
| 在 timeline 内嵌正文 | 会话分页和 live refresh 变重 | timeline 只存 summary + changeSetId，详情懒加载 |
| 把用户附件或 artifact 塞进 diff 卡 | 破坏消息归属并产生重复入口 | 保持消息内展示，只统一右栏查看器 |
| 为 Git 未来选择 patch-only UI | commit/tree/blob 接入时重写前端 | 使用版本端点 + CodeMirror before/after viewer |
| 保留旧聚合栏 fallback | 两个入口状态和数量不一致 | 开发阶段破坏式删除旧消费路径 |

## 16. 一句话结论

> 用户附件和 artifact 保持消息归属并统一在右栏查看；文件变更卡只持久化当前 turn 的 ACP tool diff，以不可变 before / after 版本和 CodeMirror merge 展示，后续 Git commit diff 只需增加新的版本 provider。

### 17.2 实际数据与接口边界

- ACP 标准 diff 的 `oldText/newText` 可能是完整内容，也可能只是一次 Edit 的上下文 hunk。同一 tool call 的流式 update 必须取最后 revision，不能将不同上下文范围误串成两次编辑；若后续 update 错把 unified diff 的 `No newline at end of file` 元数据混进文本字段，捕获层按 diff 元数据处理并恢复真实末尾换行，不得写入版本正文。用户附件中的图片继续使用现有安全图片查看链路，ACP diff 的二进制/image endpoint 留给后续协议或 Git provider。
- Conversation 主 DTO 已删除旧 session 聚合 `artifacts/attachments`；Round/节点排障 DTO、`AssetItemVm` 和按名读取 command 保留。
- 普通 live workspace 文件仍使用原 `file` 资源与自动保存；历史 captured version 一律只读，二者不共享内容状态。
- 后续 Git 管理继续以 `FileChange/FileComparison` 为前端契约，新增 Git 版本 provider 即可复用卡片和 unified viewer；本期未调用 Git CLI，也未增加 commit UI。
