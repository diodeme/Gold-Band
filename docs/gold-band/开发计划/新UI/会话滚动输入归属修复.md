# 会话滚动输入归属修复

日期：2026-09-08。

## 原始意图与根因

- `a157cdda` 为避免布局变化打断贴底，建立独立于滚动几何的用户跟随意图；`94ef9471` 保护历史阅读窗口，正文冻结而控制状态继续收敛。这些设计继续保留。
- 实现把容器空白处 pointerdown 当成滚动条拖动，没有按 pointerId 管理释放，也没有处理失焦。后续布局造成 scrollTop 减小即可误报 user-scrollbar-up。
- 捕获的滚轮和键盘事件未判断内部滚动区域、编辑控件、缩放与已取消事件的输入归属，可误报主动阅读历史。正文冻结不依赖分页阈值，因此单页也受影响。
- 分类：正确设计下的输入识别和手势生命周期实现不完整。此证据不证明 task-341 的实际触发操作。

- [x] 新增单容器 DOM 复现：12 项中修复前 9 项失败，空白/失焦报告 false + user-scrollbar-up，内部滚动及编辑/缩放/取消事件错误报告脱离跟随，其他指针释放错误结束拖动。

- [x] 不修改正文冻结、canonical head 恢复、分页和发送逻辑；旧测试的无坐标 pointerdown 不再算滚动条输入，真实拖动由新增测试覆盖。

## 自评审

- 过度设计：复用 prompt-kit/use-stick-to-bottom，不新增依赖或跟随状态机；以 pointerId 替换原布尔值，仍只有一个临时手势事实源。
- 性能：滚轮/键盘只遍历目标到当前 viewport 的祖先，复杂度 O(DOM 深度)，与历史消息总量无关；滚动条几何只在按下时读取。没有增加 I/O、正文解析、轮询或持久状态。
- 经验：既有 bug-fix-verification、状态生命周期和输入意图规则已覆盖通用原则，不新增规则。
