# 单页会话发送跟随修复

日期：2026-09-07。

## 原始意图与根因

- 用户报告的场景没有达到前端分页阈值，不能以历史分页请求解释全部现象。
- `9a67ca24`（2026-07-31）在发送时直接执行 `scrollToBottom({ animation: instant, ignoreEscapes: true })`，表达用户发送后查看最新内容的意图，但执行发生在 optimistic prompt 的 DOM 提交之前。
- `94ef9471`（2026-08-31）将主动阅读历史时的正文窗口冻结，状态与准入仍独立收敛；这是阅读位置与有界窗口保护，不能整体删除。该条件不要求达到分页阈值。
- `3d16e77`（2026-09-07）区分工具展开和主动阅读历史；跟随回调刻意排除 external-scroll-to-bottom 自动追平，防止程序恢复滚动反复发起 canonical 请求。发送入口仍沿用旧的纯滚动调用，未接入新的正文交接契约。
- 分类：正确设计下的发送集成不完整。正文积压与新 DOM 尚未提交分别造成发送后仍显示旧正文，以及定位依赖后续动画帧。测试不证明用户全部随机跳动现场都来自这两点。

## 实施

- [x] 在消息数为 1～2、没有 beforeSeq/afterSeq 分页请求的条件下建立失败测试。
- [x] 发送写入 optimistic prompt 后复用现有“回到最新”入口；显式查看最新取消旧的待恢复阅读位置。
- [x] 有积压时复用 canonical-head coordinator 的 single-flight、owner、水位与有界窗口；无积压时复用 pendingLatestLayoutCommit，在新 DOM paint 前贴底。
- [x] 保留历史冻结、工具展开、后续用户逃逸、分页锚点和 queue-prompt 分支。
- [x] 更新原“发送后仍保留历史窗口”的测试，改为 canonical prompt 收敛且无重复气泡；其他历史阅读回归保持原断言。

## 验证证据

- 修复前新增 3 个测试全部失败：积压回复未进入 DOM；冻结 RAF 时已贴底发送的 scrollTop 为 900、历史位置发送为 500，均未达到新内容底部 1300。
- 修复后相同 3 个测试全部通过：积压只新增一次 canonical head 查询，未产生 beforeSeq/afterSeq 请求；无积压不新增查询，冻结 RAF 时已完成同步定位。
- 相关回归覆盖 re-entry reconciliation、chat-container-stick-to-bottom、acp-chat-events。首次全组检查除与发送新契约冲突的旧测试外，170 项通过；更新该测试后，定向 4 项通过，最终完整重跑 3 个文件共 171 项全部通过。
- `npx tsc -p web/tsconfig.build.json --noEmit` 通过。
- Chrome 真实页面使用 8 条初始回复，分页阈值 96。上翻后发布最终回复，正文保持阅读窗口；发送后最终回复与新 prompt 可见，回到最新按钮消失且截图确认贴底；底部再次发送仍贴底，后续上翻能恢复阅读状态。内置 iab 不可用，使用现有 Chrome 验证；临时夹具、测试 tab 与本次 Vite 进程验证后清理。
- 本次不声称修复“离开前始终跟随，切回后仍显示旧正文”的未复现现场，也未验证 EXE 原生窗口切换。

## 自评审

- 过度设计：仅修复既有命令入口与 layout commit 的集成，无新增组件、依赖、状态机、持久字段、缓存或轮询。
- 性能：正常发送新增一次有界 DOM 几何读取/定位，不增加 I/O；积压恢复使用现有 page/window 上限和单请求合并，不全量读取历史、不逐项补渲染积压、不扩大 React 订阅。没有引入需要额外 benchmark 的规模或频率变化。
- 经验复盘：现有 bug-fix-verification、状态生命周期和 UI 意图规则已覆盖此次问题的通用约束，不新增重复规则。
