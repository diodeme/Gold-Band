# Gold Band 可扩展主题引擎与主题包技术方案

## 1. 背景与结论

Gold Band 当前桌面主题模型把“具体色板”直接作为 `desktopTheme` 保存，支持 `system`、`light`、`light-gray`、`dark`、`black`。前端通过根节点 `data-theme`、`.dark` 和 `web/src/styles.css` 中的语义颜色变量完成切换；字体、UI 字号、编辑器字号和头像则作为独立用户偏好保存。

这套设计足以支持同一设计语言下的换色，但不能稳定承载 Glassmorphism、Editorial、Neo-Brutalist、Neumorphism、Bento、Pixel Adventure 等整体设计风格。问题根因不是缺少更多颜色变量，而是当前模型没有明确区分：

- 设计风格与明暗模式。
- 主题提供的默认预设与用户显式覆盖。
- 业务组件语义与组件视觉 recipe。
- 主题数据、主题静态资源与可执行代码。
- 内置主题与未来用户导入主题的共同契约。

本方案决定建设“主题引擎 + 声明式主题包”架构：

```text
最终外观
= 主题包 Theme Package
+ 明暗模式 Color Scheme
+ 当前主题的视觉质量档 Visual Quality Profile
+ 用户显式个性化覆盖 Personalization Override
```

其中第一阶段只开放当前已经存在产品入口的覆盖能力：

- 界面 UI 字体与字号。
- 编辑器字体与字号。
- Agent 头像、个人头像及头像形状。

壁纸、图标包、强调色、壁纸暗度和模糊度等个人覆盖不进入第一阶段偏好模型；主题包契约保留版本化扩展位置，待产品提供对应设置入口后再实现，避免为假设性需求提前增加状态、存储和 UI。

## 2. 目标与非目标

### 2.1 目标

1. 将桌面外观拆为稳定的 `themeId × colorScheme` 两个维度。
2. 一个正式主题包必须同时提供浅色与深色方案，`system` 只解析明暗，不改变设计风格。
3. 内置主题与未来导入主题使用相同的 Theme Contract、解析器、回退规则和运行时消费路径。
4. 业务组件保持单一实现；主题不得复制会话、ACP、工作区或设置页业务组件。
5. 主题可以通过 token、受控组件 recipe 和静态资源形成明显不同的设计语言，而不改变业务结构和交互语义。
6. 界面 UI 与编辑器成为两个独立排版领域，分别拥有字体族和基准字号。
7. 主题包提供字体、字号和默认头像预设；用户设置只保存显式覆盖，不保存主题解析后的结果。
8. 主题切换以根节点属性和 CSS variables 为主，不让会话历史、Markdown、编辑器或右侧工作区因 React Context 变化而整体重渲染。
9. 为后续 `.gbtheme` 本地导入、图标槽、壁纸、纹理和主题市场建立清晰的安全边界与版本策略。
10. 先迁移现有主题并证明无回归，再实现 Glass 浅色/深色主题，最后用高差异风格验证契约不存在 Glass 特化。
11. 允许主题包按需提供“完整效果 / 性能优先”两个视觉质量档；用户选择按主题隔离，未声明该能力的主题不显示此设置。

### 2.2 非目标

- 不允许主题包注入 JavaScript、React、HTML 或任意 CSS。
- 不允许主题改变路由、导航层级、ACP 消息顺序、工具调用语义、按钮行为、焦点管理或数据请求。
- 不为不同主题复制一套会话组件或页面组件。
- 第一阶段不实现用户自定义壁纸、用户图标包、用户强调色和主题市场。
- 第一阶段不允许主题替换 EXE 文件图标、任务栏身份或操作系统级应用品牌。
- 不迁移到 daisyUI、Panda CSS、vanilla-extract 或 CSS-in-JS ThemeProvider；继续使用 Tailwind CSS v4、shadcn/ui copy-in 组件与 prompt-kit。

## 3. 开源组件与行业实践选型

本方案不自创 design token 基础格式和通用转换器，采用以下成熟能力：

### 3.1 DTCG Design Tokens Format

主题源 token 遵循 Design Tokens Community Group 格式，使用 `$type`、`$value`、group、alias 和 composite token 表达颜色、尺寸、字体、阴影、渐变、边框和动效。Gold Band 自有字段放在命名空间明确的 `$extensions` 中，不污染标准 token 语义。

DTCG 负责可交换的设计决策，不负责 Gold Band 的组件角色、图标槽、壁纸槽、主题安装和安全规则。

### 3.2 Style Dictionary

使用 Style Dictionary 作为主题开发期编译器：

- 解析 DTCG token 和 alias。
- 检测循环引用、缺失引用和类型错误。
- 通过 Gold Band transforms 生成 CSS variables、运行时 JSON 和 TypeScript 契约测试输入。
- 为官方主题和第三方主题作者提供一致的构建、检查和预览流程。

Style Dictionary 不进入桌面应用主题切换热路径。运行时只加载已经校验和编译的轻量产物；未来导入未经信任的用户主题时，由 Gold Band 自己的受控编译/解析层生成允许的变量，不能直接执行包内 CSS。

### 3.3 Zod、Rust 强类型与 JSON Schema

- Web 端复用现有 Zod，校验 Theme Contract、运行时 VM 和前端边界。
- Tauri/Rust 端使用 `serde` 强类型反序列化，并为导入、安装、发现和持久化定义结构化错误。
- 主题 SDK 导出 JSON Schema，供主题作者在编辑器中获得补全和错误提示。

### 3.4 CSS Variables 与根节点属性

运行时继续使用浏览器原生 CSS variables 和根节点属性：

```html
<html data-theme="builtin.gold-band" data-color-scheme="dark" data-visual-quality="full" class="dark">
```

- `data-theme` 选择设计风格。
- `data-color-scheme` 表示解析后的 `light | dark`。
- `data-visual-quality` 只表示当前主题解析后的 `full | performance`；未声明视觉质量能力的主题固定为 `full`，组件不得据此写业务分支。
- `.dark` 继续服务 Tailwind `dark:` 变体和现有第三方组件。
- `system` 仅存在于用户偏好，解析后不会作为组件消费值。

不引入 `next-themes`：Gold Band 是 Vite/Tauri 桌面应用，当前已经具备系统明暗监听、偏好持久化和根属性切换能力；引入 Next.js 专用抽象没有收益。

## 4. 领域划分与权威事实源

### 4.1 Theme Catalog 领域

管理可用主题包的稳定身份、版本、来源和安装状态。

```ts
type ThemeSource = "builtin" | "user";

interface ThemePackageSummary {
  id: string;
  version: string;
  contractVersion: number;
  source: ThemeSource;
  name: LocalizedText;
  author?: string;
  preview: {
    light: AssetRef;
    dark: AssetRef;
  };
  capabilities: ThemeCapability[];
}
```

`id` 是持久化和关联的稳定身份，显示名称不能参与查找。内置主题使用 `builtin.*` 命名空间；用户主题使用清单声明且经过冲突校验的全局 ID。

### 4.2 Appearance Preference 领域

管理用户选择了哪个主题、怎样解析明暗，以及每个主题明确选择的视觉质量档：

```ts
type ColorSchemePreference = "system" | "light" | "dark";
type VisualQuality = "full" | "performance";

interface AppearancePreference {
  schemaVersion: 2;
  themeId: string;
  colorScheme: ColorSchemePreference;
  visualQualityByTheme: Record<string, VisualQuality>;
}
```

`visualQualityByTheme` 必须按稳定 `themeId` 隔离，不能保存成跨主题全局单值。同一台设备上，Glass 可能需要“性能优先”，而 Pixel 或 Gold Band 的“完整效果”本身已经足够轻量；全局单值无法表达这一事实。

该 Map 的权威事实源在后端用户设置文件，并按已安装主题集合保持有界：

- 只有用户对声明 `visual-quality-profiles` 能力的主题作出选择时才写入。
- 卸载用户主题时，在同一卸载事务中删除对应条目；内置主题条目随设置长期保留。
- 当前主题没有该能力时忽略 Map 中的值，不显示设置项，也不制造伪“性能档”。
- 当前主题支持该能力但没有已保存选择时，使用 manifest 的 `default`，不把默认值提前写入偏好。
- 主题升级取消该能力时忽略并清理失效条目；不得让已失效偏好影响其他主题。

权威事实源在后端用户设置文件。前端只消费 `AppearancePreferenceVm` 和当前解析结果，不另建 localStorage 旁路。系统明暗变化只改变 `resolvedColorScheme`，不写回用户的 `colorScheme: "system"`。

### 4.3 Personalization Preference 领域

第一阶段只覆盖当前已有设置入口的字体、字号和头像：

```ts
type ThemeInherited = { source: "theme" };

type FontPreference =
  | ThemeInherited
  | { source: "local"; family: string };

type FontSizePreference =
  | ThemeInherited
  | { source: "custom"; px: number };

type AvatarPreference =
  | ThemeInherited
  | { source: "user"; assetId: string };

type AvatarShapePreference =
  | ThemeInherited
  | { source: "custom"; value: "circle" | "square" };

interface PersonalizationPreference {
  schemaVersion: 1;
  typography: {
    ui: {
      font: FontPreference;
      fontSize: FontSizePreference;
    };
    editor: {
      font: FontPreference;
      fontSize: FontSizePreference;
    };
  };
  avatars: {
    agent: {
      image: AvatarPreference;
      shape: AvatarShapePreference;
    };
    user: {
      image: AvatarPreference;
      shape: AvatarShapePreference;
    };
  };
}
```

必须保留以下语义：

- `source: "theme"` 表示持续继承当前主题，不把当前主题的具体值固化到用户设置。
- 本机字体暂时不可用时，保留用户选择并使用主题字体作为运行时回退；字体恢复后自动重新生效。
- 用户头像资源独立于主题资源。切换、更新或卸载主题不得删除用户头像。
- 清除当前自定义头像只把选择恢复为 `source: "theme"`，不删除最近头像列表；删除资源必须是独立、明确的用户动作。

### 4.4 Theme Runtime 领域

Theme Runtime 负责把包、明暗模式和用户覆盖解析成唯一的 `EffectiveAppearance`：

```ts
interface EffectiveAppearance {
  themeId: string;
  themeVersion: string;
  colorScheme: "light" | "dark";
  visualQuality?: VisualQuality;
  tokens: ResolvedThemeTokens;
  recipes: ResolvedComponentRecipes;
  typography: {
    ui: ResolvedTypography;
    editor: ResolvedTypography;
  };
  avatars: {
    agent: ResolvedAvatar;
    user: ResolvedAvatar;
  };
}
```

解析优先级统一为：

```text
用户显式覆盖
  -> 当前主题对应明暗方案的预设
  -> builtin.gold-band 对应明暗方案的安全默认值
```

`EffectiveAppearance` 是投影，不持久化，不反向成为偏好事实源。

## 5. 界面 UI 与编辑器排版边界

字体必须严格分成两个独立领域，设置页、数据模型、token 和组件消费路径均使用一致术语。

### 5.1 界面 UI

覆盖：

- 标题栏、侧栏、设置页、管理页和所有普通控件。
- 会话正文、用户消息、Assistant 消息、Activity 摘要和普通 Markdown。
- 表单、Dialog、Sheet、Popover、菜单、Tooltip、状态栏和导航。

核心变量：

```css
--gb-font-ui-family;
--gb-font-ui-size;
```

Tailwind 的 `font-sans` 和 UI 字号比例从这两个变量派生。主题可以提供基准字号，但不得为每个页面写独立字号分支。

### 5.2 编辑器

覆盖：

- 文件查看与编辑。
- 运行产物查看。
- 本轮文件修改 Diff、Git Diff、版本对比及所有差异视图。
- CodeMirror 内容、行号、gutter、内联代码编辑区域和源码模式。

核心变量：

```css
--gb-font-editor-family;
--gb-font-editor-size;
```

编辑器字体不等于“所有代码片段字体”。聊天正文中的短 inline code 仍属于界面 UI 的排版流，但可以使用主题定义的 UI monospace fallback；只有上述独立编辑/查看与 Diff 载体消费完整编辑器字体设置。若产品后续希望 inline code 也跟随编辑器字体，必须作为明确规则调整，不通过偶然继承实现。

### 5.3 主题预设示例

```text
builtin.gold-band
  界面 UI：MiSans / 14px
  编辑器：JetBrains Mono / 12px

builtin.glass
  界面 UI：主题无衬线字体栈 / 14px
  编辑器：主题等宽字体栈 / 12px

builtin.pixel-adventure（后续验证主题）
  界面 UI：像素 UI 字体 + 中文 fallback / 15px
  编辑器：像素等宽字体 + CJK 等宽 fallback / 13px
```

字体资源只允许本地 WOFF2/WOFF，禁止远程 URL；主题必须声明字体授权信息、字重、覆盖范围和 fallback。字体加载失败不能阻塞应用壳显示。

## 6. Theme Contract

### 6.1 三层 token

主题 token 使用 Primitive -> Semantic -> Component 三层结构：

```text
Primitive
  原始颜色、尺寸、透明度、阴影、字体、动效
        ↓
Semantic
  background、foreground、surface、border、status、selection
        ↓
Component
  composer、message、tool-card、dialog、sidebar、editor 等角色
```

组件不得直接消费主题 primitive。现有 shadcn token 保留为兼容语义接口，并逐步映射到 `--gb-*` contract；业务代码不得根据 `themeId` 写条件分支。

### 6.2 必填语义 token

第一阶段至少覆盖：

- 应用壳：window、workspace、sidebar、titlebar、content-header、divider。
- 通用表面：background、card、popover、muted、overlay、input。
- 前景：title、foreground、muted-foreground、disabled、link。
- 操作：primary、secondary、accent、focus-ring、selection。
- 状态：running、success、warning、danger、permission。
- 会话：conversation-background、message-user、message-assistant、composer、activity、tool-card、permission-card。
- 工作区：workspace-tab、resource-header、file-tree、editor、diff-added、diff-removed、diff-modified。
- 材质：surface opacity、border highlight、shadow、blur、saturate、noise、motion duration/easing。

每个颜色 token 必须明确前景/背景配对，不能让主题作者只提供单个状态色后由组件猜测可读前景。

### 6.3 组件 recipe

主题 recipe 只允许组合引擎公开的视觉属性，不提供任意选择器：

```ts
interface SurfaceRecipe {
  background: TokenRef;
  foreground: TokenRef;
  borderColor: TokenRef;
  borderWidth: TokenRef;
  radius: TokenRef;
  shadow: TokenRef;
  backdropBlur?: TokenRef;
  backdropSaturate?: TokenRef;
  texture?: AssetRef;
  transition?: TokenRef;
}
```

首批稳定组件角色：

- `app.shell`
- `app.titlebar`
- `navigation.sidebar`
- `navigation.item`
- `workspace.panel`
- `conversation.viewport`
- `conversation.message.user`
- `conversation.message.assistant`
- `conversation.activity`
- `conversation.tool-card`
- `conversation.permission-card`
- `conversation.composer`
- `overlay.dialog`
- `overlay.sheet`
- `overlay.popover`
- `control.button.primary`
- `control.button.secondary`
- `control.input`
- `editor.surface`
- `editor.diff`

共享 shadcn/ui 与 prompt-kit copy-in 组件负责消费 recipe；页面只表达业务角色和状态。Glass 可以使用半透明、模糊和受光边缘，Neo-Brutalist 可以使用粗边框和硬阴影，Editorial 可以使用细分隔线和排版层级，但所有主题共享同一 DOM、状态机和可访问性约束。

### 6.4 主题能力声明

manifest 显式声明能力，运行时不得通过扫描文件猜测：

```ts
type ThemeCapability =
  | "tokens"
  | "component-recipes"
  | "fonts"
  | "avatars"
  | "textures"
  | "icons"
  | "wallpapers"
  | "visual-quality-profiles";
```

第一阶段运行时启用 `tokens`、`component-recipes`、`fonts`、`avatars`、`textures`。`icons` 与 `wallpapers` 进入契约保留区但不开放个人设置；只有引擎实现对应版本后才能启用能力。

### 6.5 视觉质量档是封闭的效果覆盖层

主题包不需要复制两份主题。基础 token、recipe 和资源表达“完整效果”，`performance` 只提供一份受限差异覆盖：

```ts
type VisualQuality = "full" | "performance";

interface ThemeVisualQualityProfiles {
  default: VisualQuality;
  supported: ["full", "performance"];
  performance: VisualPerformanceOverrides;
}

interface VisualPerformanceOverrides {
  filters?: FilterQualityOverrides;
  shadows?: ShadowQualityOverrides;
  textures?: TextureQualityOverrides;
  backgrounds?: BackgroundQualityOverrides;
  transparency?: TransparencyQualityOverrides;
  compositing?: CompositingQualityOverrides;
  motion?: MotionQualityOverrides;
  decorativeEffects?: DecorativeEffectQualityOverrides;
}
```

这些 DTO 不是任意 token Map。Theme SDK、JSON Schema、Rust `serde` 和前端 Zod 共同维护允许字段的封闭集合，并对 `performance` 与 `full` 的解析结果执行路径级 diff。只要差异触及字体、字号、头像、布局、业务颜色、焦点或内容，主题包就无法通过构建或导入校验。

设置页只有在当前主题声明该能力、两个档位均有效且解析结果确有差异时，才显示：

```text
视觉效果
● 完整效果
○ 性能优先
```

该控件是外观设置中的短选项，使用现有 shadcn/ui Radio Group copy-in 组件。切换只替换当前主题的效果变量和资源 locator，不卸载业务组件，不重新读取会话数据。

## 7. 主题包格式

### 7.1 源包与运行时包分离

官方主题开发目录可以包含 DTCG 源文件和构建配置，应用分发包只包含运行时需要的产物。

```text
themes/glass/
├── manifest.json
├── tokens/
│   ├── primitives.tokens.json
│   ├── semantic.tokens.json
│   ├── light.tokens.json
│   └── dark.tokens.json
├── recipes.json
├── assets/
│   ├── fonts/
│   ├── avatars/
│   ├── textures/
│   └── previews/
├── LICENSES.json
└── dist/
    ├── runtime-theme.json
    ├── builtin-theme.css
    └── asset-manifest.json
```

未来 `.gbtheme` 是压缩后的声明式分发包，不是 npm 包、Tauri 插件或可执行扩展。

### 7.2 manifest

```json
{
  "schemaVersion": 1,
  "contractVersion": 1,
  "id": "builtin.glass",
  "version": "1.0.0",
  "name": {
    "zh-CN": "玻璃拟态",
    "en": "Glass"
  },
  "author": "Gold Band",
  "schemes": ["light", "dark"],
  "capabilities": [
    "tokens",
    "component-recipes",
    "fonts",
    "avatars",
    "textures",
    "visual-quality-profiles"
  ],
  "visualQualityProfiles": {
    "default": "full",
    "supported": ["full", "performance"],
    "performance": "visual-quality/performance.json"
  }
}
```

正式可选主题缺少 light 或 dark 时安装失败，不能在系统切换明暗时回退到另一种设计风格。

### 7.3 内置主题与用户主题

- 内置主题随应用发布，构建期由 Style Dictionary 编译并进入只读资源目录。
- 用户主题未来安装到用户级主题目录，使用原子临时目录校验后再重命名生效。
- 两者进入同一 Theme Catalog，运行时解析规则一致。
- `builtin.gold-band` 永远存在，作为主题缺失、损坏、版本不兼容时的安全回退。

## 8. 静态资源、头像、图标与壁纸

### 8.1 头像

主题可以为 `avatar.agent.default` 和 `avatar.user.default` 提供资源及默认形状。主题头像只是视觉默认值，不是用户身份资产。

- 用户未选择头像时显示当前主题头像。
- 用户选择历史头像后，主题切换不改变头像。
- “恢复主题头像”只清除当前选择，不删除历史头像。
- 主题卸载不影响用户头像目录。
- 主题头像损坏时回退到 `builtin.gold-band` 默认头像。

### 8.2 图标

后续图标能力按语义槽覆盖，不按 React 组件名或内部 class 覆盖：

```text
navigation.search
navigation.settings
entity.agent
conversation.thought
tool.read
tool.write
status.running
status.success
status.warning
status.error
action.send
action.continue
```

缺失槽位回退内置 Lucide 图标。图标包不能隐藏状态、改变可访问名称或替换危险操作语义。

### 8.3 壁纸

后续壁纸能力通过稳定表面槽位声明，例如 `wallpaper.app`、`wallpaper.conversation`、`wallpaper.settings`，并附带受控的 size、position、repeat、opacity 和遮罩 token。第一阶段不提供用户壁纸设置，也不在偏好模型增加壁纸字段。

## 9. 安全与资源信任边界

未来用户导入主题必须执行以下约束：

1. 不接受任意 CSS、JS、HTML、React、WASM 或远程 URL。
2. 只接受 schema 允许的 token、recipe 属性和静态资源类型。
3. 所有相对资源路径规范化后必须位于主题安装目录内，拒绝绝对路径、`..` 穿越、符号链接逃逸和重复冲突路径。
4. 压缩包限制文件数量、单文件大小、解压后总大小和压缩比，防止 zip bomb。
5. 图片校验 MIME、文件签名、像素上限和解码结果；SVG 若开放必须经过严格净化，第一阶段优先只允许 PNG/WebP。
6. 字体只允许 WOFF2/WOFF，限制文件数量和总大小，禁止字体加载阻塞首屏。
7. recipe 中 blur、shadow、纹理、背景资源、混合与动画必须受性能预算限制；视觉质量覆盖只能修改 6.5 与 14.3 定义的封闭字段。
8. 安装采用 `validate -> stage -> atomic activate`；失败不改变当前主题。
9. 启用主题后若运行时解析失败，原子回退 `builtin.gold-band` 并返回结构化错误。

错误接口至少包含：

```ts
interface ThemeErrorVm {
  code: string;
  params: Record<string, unknown>;
}
```

后端只返回错误码和参数，用户文案由前端 i18n 映射。建议错误码：

- `theme.package-invalid`
- `theme.contract-version-unsupported`
- `theme.scheme-incomplete`
- `theme.token-missing`
- `theme.token-type-invalid`
- `theme.reference-cycle`
- `theme.asset-invalid`
- `theme.asset-limit-exceeded`
- `theme.path-outside-package`
- `theme.install-failed`
- `theme.active-package-missing`

## 10. 运行时流程

### 10.1 启动

```text
读取 AppearancePreference 与 PersonalizationPreference
  -> 发现 Theme Catalog
  -> 按稳定 ID 解析主题包
  -> 解析 system 明暗
  -> 按 themeId 解析视觉质量选择或主题默认值
  -> 解析主题预设与用户覆盖
  -> 应用根属性、CSS variables、字体与主题资源
  -> 同步 Tauri 原生窗口安全底色
  -> 渲染应用壳
```

首屏必须内置 `builtin.gold-band` 的最小同步变量，避免异步发现主题时白屏或闪烁。用户主题可在应用壳显示后加载；加载期间先使用对应明暗的安全主题，完成后原子替换变量。

### 10.2 切换主题

1. 用户在设置页选择主题、明暗偏好或当前主题提供的视觉质量档。
2. 前端提交完整 `AppearancePreference`。
3. 后端校验目标主题存在且兼容，原子持久化后返回最新偏好与解析摘要。
4. 前端在同一用户事件链中应用根属性和变量。
5. 仅当主题资源需要异步加载时显示设置区局部处理中状态；现有内容保持可用。
6. 字体和头像的 `source: "theme"` 跟随新主题重算，用户显式覆盖保持不变。
7. 切换主题时读取目标 `themeId` 对应的视觉质量选择；没有记录时使用目标主题默认值，不能沿用上一个主题的选择。

主题状态不能拆成多个互相修补的 `useEffect` 布尔值；一次切换是包含主题 ID、明暗解析、窗口底色和有效预设的完整事务。

### 10.3 React 边界

- 主题 token 不放入包含完整对象的大型 React Context。
- 普通视觉变化直接更新根 CSS variables。
- 只有必须选择资源 URL 的少量组件订阅稳定的 `ThemeAssetsContext`，value 只包含解析后的有限 asset locator。
- Composer 输入、流式消息、右侧 Tab 和主题状态保持独立更新频率。
- 切换主题可以触发样式重算，但不能重新请求会话、重建 timeline、重播 Markdown 或销毁 CodeMirror `EditorView`。

## 11. 设置页交互

个性化页保持“外观 / 字体 / 头像”的产品范围，但调整为继承语义。

### 11.1 外观

- 先选择设计风格主题卡。
- 再选择 `跟随系统 / 浅色 / 深色`。
- `跟随系统` 始终在同一主题包的 light/dark 之间切换。
- 主题预览卡使用包内 light/dark 预览图，不通过前端临时猜测色板。

### 11.2 字体

字体分成两个可展开区域：

```text
界面 UI
  侧栏、设置、聊天正文和普通 Markdown

编辑器
  文件查看与编辑、运行产物及所有 Diff 视图
```

每个区域分别提供：

- “跟随主题 · 当前有效字体”预设卡。
- 本机字体选择。
- 当前有效字号输入。
- “恢复主题值”按钮。
- `跟随主题` 或 `已自定义` 状态说明。

重置字号不是恢复固定 `14px / 12px`，而是把来源改为 `theme`。输入框继续展示当前主题解析出的有效值。

### 11.3 头像

- 默认展示当前主题头像。
- 继续支持上传、最近头像和圆形/方形选择。
- 形状也具有 `跟随主题 / 自定义` 来源。
- “恢复主题头像”不删除历史资源。

设置页只展示帮助用户做决定的文案，不展示 Theme Contract、包目录、token 层级或实现说明。

## 12. 现有数据迁移

### 12.1 现有四套主题

现有色板配对迁移为两个内置主题包：

| 旧值 | 新主题包 | 新明暗偏好 |
| --- | --- | --- |
| `light` | `builtin.gold-band` | `light` |
| `dark` | `builtin.gold-band` | `dark` |
| `light-gray` | `builtin.tech-neutral` | `light` |
| `black` | `builtin.tech-neutral` | `dark` |
| `system` | 按迁移时当前有效具体主题确定主题包 | `system` |

当前系统允许浅色和深色分别记住不同具体主题，可能形成跨设计包组合。新模型要求 `system` 在同一设计风格内切换，因此迁移时以当下解析出的具体主题确定 `themeId`，保证升级瞬间视觉不变；下一次操作系统切换后使用该主题包的对应方案。开发阶段不保留旧双偏好兼容层。

### 12.2 字体和字号

- 旧 `font = app-default` 迁移为界面 UI 字体 `source: theme`。
- 旧本机字体字符串迁移为界面 UI 字体 `source: local`。
- 当前实现尚无独立编辑器字体选择；编辑器字体初始迁移为 `source: theme`。
- 旧 UI 字号等于旧默认值 `14` 时迁移为 `source: theme`；其他合法值迁移为 `source: custom`。
- 旧代码/编辑器字号等于旧默认值 `12` 时迁移为 `source: theme`；其他合法值迁移为 `source: custom`。

这里接受一个开发期语义收敛：用户恰好手动选择 14/12 无法与旧默认事实区分，统一迁移为跟随主题。迁移后新模型会显式保存来源，不再有歧义。

### 12.3 头像

- `selectedAvatarId = null` 迁移为图片 `source: theme`。
- 已选择头像迁移为 `source: user`，稳定引用原资源 ID。
- 当前保存的圆形/方形无法判断是否为主动覆盖；为避免视觉改变，迁移为 `source: custom`。
- 用户可在新设置页主动恢复主题形状。

迁移必须一次性写入带版本的新 schema；成功后删除旧字段和旧消费路径，不长期双写。

## 13. 组件改造范围

### 13.1 必须改造

- `web/src/theme.ts` 与根主题应用流程。
- `PreferencesVm`、Tauri command、Rust config 和设置持久化。
- Shell、标题栏、侧栏、主工作区边界。
- shadcn/ui Button、Input、Dialog、AlertDialog、Sheet、Popover、Select、Dropdown、Tooltip、Card 等 copy-in 组件。
- prompt-kit Composer、消息和 Markdown 基础呈现。
- ACP Activity、工具调用卡、权限卡、文件变更卡及会话状态区域。
- 右侧工作区 Header、Tabs、文件树、CodeMirror 与所有 Diff viewer。
- 设置页主题、字体、字号和头像交互。
- 原生窗口背景色同步与主题预览。

### 13.2 不改变

- ACP、任务、运行和会话领域模型。
- 会话分页、流式缓冲、Markdown 解析和历史锚点。
- CodeMirror 文档、撤销栈、保存队列和文件生命周期。
- 工作区导航事务、Sheet/Tab 载体选择和响应式状态机。
- 权限、错误、成功、运行中等业务语义。

### 13.3 改造原则

1. 先为组件标定业务角色，再映射 token/recipe，禁止机械替换 class。
2. 优先修改共享 shadcn/ui 与 prompt-kit copy-in 组件，页面只保留业务差异。
3. 高密度会话和列表不为每一行创建独立模糊层或重型纹理。
4. 标题、消息、工具卡和编辑器的 DOM 身份不得因主题变化改变。
5. 不允许 `if (themeId === "glass")` 等主题特判进入业务组件。

## 14. 性能影响与不过度设计评审

### 14.1 数据规模

主题目录规模预计远小于会话和文件数据：内置主题个位数，用户主题初期按几十个以内设计。Catalog 只读取 manifest 与预览 locator，不在列表阶段加载完整 token、字体和壁纸。

### 14.2 加载与缓存

- 启动只同步加载当前主题的最小运行时 token。
- 主题列表只加载 summary；打开预览或启用主题时再读取完整资源。
- 非当前主题字体、纹理和壁纸不加载。
- 解析缓存以 `themeId + version + scheme + visualQuality` 为 key，采用有界条目数；主题更新、质量切换或卸载时原子失效。
- 不建立无界主题资源缓存，不把二进制资源放入全局 React 状态。

### 14.3 渲染、GPU 与视觉质量变量边界

- 普通主题切换只更新根属性和一组 CSS variables。
- Glass 的 `backdrop-filter` 仅用于应用壳、Composer、弹层等少量连续大表面，禁止在消息行、列表行和每个工具步骤创建独立合成层。
- 噪点使用小型预生成静态纹理，禁止运行时 SVG `feTurbulence` 覆盖全窗口。
- blur、shadow、纹理和动画受包校验预算约束，并提供不支持 filter 与 `prefers-reduced-motion` 降级。
- 壁纸后续必须限制解码像素和显存规模，默认提供遮罩以保持文本对比度。

无法对不同 GPU、驱动、WebView 版本、窗口尺寸和页面内容量造成的全部性能差异作绝对穷举；可以且必须穷举的是“主题包被允许控制的性能变量”。Theme Contract v1 将其封闭为以下八类：

| 类别 | `performance` 允许降低或关闭的因素 | 主要成本 |
| --- | --- | --- |
| Filter | `backdrop-filter` 的 blur、saturate、brightness、contrast；普通 `filter` 的 blur、drop-shadow；滤镜启用状态与静态 fallback | 离屏采样、重绘、合成和显存带宽 |
| Shadow | 阴影层数、模糊半径、扩散半径、透明度、inset、发光与动态阴影；可切换为单层或无阴影 | 大面积绘制、离屏缓冲和动画重绘 |
| Texture | noise/grain/scanline 等纹理启用状态、资源档位、解码尺寸、平铺密度、透明度和更新方式 | 图片解码、显存、填充率和持续重绘 |
| Background | 壁纸的静态/动态资源档、解码像素上限、帧率、视差、渐变层数及静态占位；第一阶段只接受静态图片，动态资源待独立能力版本开放 | 解码、上传、显存、持续合成和功耗 |
| Transparency | 表面透明度、叠层数量预算、玻璃嵌套深度和不透明 fallback；性能档可把半透明材质解析为主题提供的实色表面 | overdraw、背景重采样和合成层数量 |
| Compositing | `mix-blend-mode`、`background-blend-mode`、mask、复杂 clip-path、反射/高光叠层的启用状态与静态 fallback | 离屏缓冲、裁剪、混合及合成层膨胀 |
| Motion | 装饰动画、过渡和动态背景的启用状态、并发数量、持续时间、帧率档、循环、弹性/视差强度；禁止 `transition: all`，优先 transform/opacity | 主线程样式计算、绘制、合成和持续功耗 |
| Decorative effects | 光斑、辉光、反射、粒子、光标跟随、hover 光照等纯装饰效果的数量、刷新频率和静态替代 | 事件热路径、逐帧计算、绘制和图层合成 |

“完整效果”也必须满足包级硬预算，不能把性能档当作超限主题的免责入口。无论选择哪个档位，以下因素都由校验器固定限制：资源文件数与字节数、图片解码总像素、单表面滤镜上限、连续全屏效果数量、阴影层数、背景层数、动画并发数与无限循环、合成层角色数量。具体数值必须在 Glass 样板的 Windows WebView2、macOS WKWebView 和 Linux WebKitGTK 生产构建测量后固化，不能凭感觉填写。

以下虽然也影响性能，但不属于视觉质量档的可写范围：

- DOM 数量、组件布局、消息数量、虚拟化、Markdown 解析、React 状态与重渲染范围。
- 字体文件、字体族、字号、头像和图标语义；它们分别由主题预设、个人覆盖和资源预算管理。
- 网络、IPC、文件读取、CodeMirror 文档、会话流式合并和业务数据缓存。
- `will-change`、`contain`、`content-visibility`、图层提升策略和事件调度；这些是引擎实现细节，只能由 Gold Band 根据测量统一管理，不能交给主题作者。
- Canvas、WebGL、自定义 shader、运行时 SVG filter、视频壁纸和任意脚本动画；Theme Contract v1 直接禁止，不作为可调档位。

视觉质量档明确不得修改：

- 信息结构、组件布局、间距、尺寸、显隐和功能入口。
- 界面 UI / 编辑器字体、字号、头像和头像形状。
- 业务状态颜色语义、消息内容、图标的可访问名称和危险操作语义。
- 键盘行为、焦点顺序、focus ring、文本对比度和其他可访问性要求。

`prefers-reduced-motion` 是独立的可访问性约束，优先级高于用户选择的“完整效果”；它只能进一步减少运动，不能反向开启主题已关闭的效果。

### 14.4 复杂度判断

本方案只新增解决真实扩展需求所需的抽象：Theme Contract、Catalog、Resolver 和包校验。第一阶段不实现 Marketplace、在线下载、主题签名网络、个人壁纸覆盖或任意布局 DSL。组件 recipe 使用固定角色和属性白名单，不建设通用 UI 渲染器。

## 16. 测试与验收

### 16.1 单元测试

- Theme Contract 完整性、类型、alias 解析和循环引用。
- `themeId + colorScheme + system` 解析。
- `visualQualityByTheme` 按主题隔离、主题默认值解析、卸载清理和能力取消收敛。
- 视觉质量覆盖只接受白名单路径，越界修改字体、布局、业务颜色或可访问性时拒绝。
- 用户覆盖 -> 主题预设 -> 安全默认的优先级。
- 本机字体不可用与恢复。
- 用户头像选择、恢复主题头像和主题卸载不删除用户资源。
- 旧主题、字体、字号和头像数据一次性迁移。
- 主题缺失、损坏和版本不兼容回退。

### 16.2 接口测试

- 保存偏好以后端返回的 canonical VM 更新界面。
- 同一写入事务中主题、明暗和窗口底色收敛。
- 切换视觉质量只写当前 `themeId`，切换主题恢复各自选择且不会形成跨主题串值。
- 未来导入覆盖路径逃逸、重复 ID、zip bomb、错误 MIME、超限图片和非法字体。
- 错误只返回结构化 code/params，前端 i18n 映射中英文文案。

### 16.3 前端契约测试

- 共享组件消费稳定 component role，不读取具体主题 ID。
- 切换主题不会重新请求会话或重建 timeline。
- Composer 输入不会因 ThemeAssetsContext 更新而重渲染历史消息。
- CodeMirror `EditorView`、文档和撤销历史在主题切换后保持身份。
- UI 字体只覆盖界面 UI 范围；编辑器字体覆盖文件、产物和全部 Diff。
- 主题默认字号更新不会覆盖用户显式字号。
- 切换视觉质量不改变 DOM 身份、字体、字号、头像、布局、业务状态语义和 focus ring。

### 16.4 视觉与交互验收

每个正式主题必须检查：

- light、dark 和 system 切换。
- 声明视觉质量能力的主题分别检查完整效果、性能优先、重新进入应用后的按主题恢复；未声明主题不显示控件。
- 正常宽度、窄窗口、重新拉宽和长文本。
- 应用壳、设置页、会话首页、长 ACP 会话、右侧文件、源码管理和 Diff。
- default、hover、active、focus、disabled、loading、running、success、warning、danger、permission。
- 键盘导航、焦点可见性、文本选区和 WCAG AA 对比度。
- 主题字体加载失败、主题资源损坏和系统字体卸载。

使用内置浏览器 deep link 到目标页面验证 Web 页面；只有验证 EXE 原生窗口底色、标题栏和客户端级切换时使用 computer-use。验证结束后关闭测试页面并清理本次启动的进程。

### 16.5 性能验收

- 主题切换不触发数据请求，不重新解析已完成 Markdown，不销毁编辑器。
- React Profiler 中已完成历史消息 render 次数保持不变。
- 非当前主题资源不加载。
- Catalog 扫描只读取 manifest，不读取完整字体或图片正文。
- Glass 在目标窗口尺寸和长会话下无持续掉帧；滚动期间不为每个消息块新增合成层。
- 对 Glass 两个质量档分别记录生产构建下的帧时间、长帧、合成层数量、GPU/图片内存和静止功耗；性能档必须在至少一项已识别瓶颈上有可复现改善，不能只是名称不同。
- 主题缓存、字体缓存和图片缓存均有明确上限。

## 18. 完成定义

主题引擎第一轮完成必须同时满足：

1. 现有色板已迁入主题包，旧字段和旧消费路径删除。
2. 设置页以设计风格和明暗模式选择外观。
3. 界面 UI 与编辑器分别拥有主题字体、主题字号和本机/自定义覆盖。
4. 主题默认头像、用户头像和头像形状继承关系正确。
5. Glass 同时提供完整浅色与深色方案，并覆盖会话和右侧工作区关键组件。
6. 业务组件中不存在具体 `themeId` 分支。
7. 主题切换不破坏会话、Markdown、编辑器、路由和用户资产生命周期。
8. 单元测试、接口测试、类型检查、生产构建、视觉验证和性能评审全部通过。
9. 仅新增一个合规主题包而不修改业务组件，即可得到明显不同的完整设计风格。
10. 支持该能力的主题可独立记忆完整效果或性能优先；覆盖字段全部通过 schema 白名单和路径级 diff 校验，不能越界改变业务或可访问性。
