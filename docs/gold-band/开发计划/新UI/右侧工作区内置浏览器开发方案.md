# 右侧工作区内置浏览器开发方案

## 1. 文档状态

- 状态：阶段 A–D 已实现。空白页与无标签统一为门户页；书签按 origin 落盘，图标复用 favicon 缓存且不写入访问记录。地址栏补全最近 200 条访问记录和 origin 图标。普通左键 `http(s)` 在到达 `NewWindowRequested` 之前改成当前页跳转；电脑/移动版切换在同一活 WebView 上改 UA 并 reload。
- 编制日期：2026-09-16。
- 目标版本：MVP 增量能力。
- 产品设计真源：[右侧工作区内置浏览器](../../产品设计文档/interaction/app/in-app-browser.md)。
- 前置能力：通用右侧工作区 Tab、文件链接 resolver、`gold-band-preview` grant、`BrandLoadingState`、Shell 布局帧。

实现必须同步维护产品设计文档与本方案。未获产品设计变更前，不得把 URL 做成工作区 Tab、按工作空间复制浏览会话，或从本机浏览器导入 Cookie。

## 2. 设计方向

问题不是文件 canonical state 缺陷，而是缺少「应用内浏览」这一工作对象。宿主必须是零权限子 WebView，不能用 iframe。布局同步抄 Tauri #14588 的占位 div 范式，但要接到 Gold Band Shell（位移、Sheet、Dialog、自动收起），不能只观察 width/height。

## 3. 实施阶段

### 阶段 A：宿主骨架

- capability 绑定 `webviews: ["main"]`，不按 window 授权；浏览子 WebView 从 Rust `Window::add_child` 创建，前端不调用 JS `createWebview`，子页零 IPC。
- `NativeBrowserViewport`：占位 div、逻辑像素 bounds、rAF 合并最新矩形、DPI。create 完成与 `live` 翻转后必须再对齐一次，避免网页按第一帧小矩形排版。
- 接到 `WorkspaceShell` 已有布局帧：左栏折叠、右栏尺寸、Sheet、scaleFactor、激活资源变化。
- Dialog / Sheet overlay 打开时 hide；对话栏菜单以对话栏为 collision boundary 并标记约束，不走 hide。未受约束且与网页占位盒相交的菜单仍 hide。关闭后若浏览器仍是可见激活资源则按占位盒 show。
- 模块与 WebView 环境仅在首次真正打开浏览器时加载/创建。

### 阶段 B：全局会话与工作区投影

- 进程内 `BrowserSession` 单例：`pages[]`（上限 32）、`activePageId`、活 WebView LRU（上限 5）。
- 工作区资源 `kind: 'browser'`，当前 scope 内 key 为 `browser`，只作投影。
- × 投影 Tab、关右栏或离开拥有浏览器的 `WorkspaceShell`：丢弃全部活 WebView，保留 `pages`。Shell owner 卸载必须 close/discard，不能只依赖占位组件异步 hide。
- 窗口自动收起且 Sheet 未开：只 hide，不丢弃。
- 内部关闭所有页：清空 `pages`，投影 Tab 仍在，空态 `+`。
- Cookie 目录：`{appData}/browser-profile/`，与主 WebView 隔离，退出不清空。

### 阶段 C：导航与链接

- 工具栏：后退、前进、加载中停止、地址栏、电脑/移动版切换、带 Tooltip 的「用系统浏览器打开」。电脑/移动切换走 `browser_set_view_mode`：同一实例改 UA 后 reload，不 close。
- 地址解析先识别显式 scheme、域名、IP、localhost 和本地 HTML；其他输入按设置的百度 / Google / Bing 搜索。空白逻辑页首次提交走 create，活页走 navigate。
- 访问记录与打开的页签分开：`load-finish` 写入规范化 `http(s)` URL，最多 200 条，落在 `browser-profile/history.json`。地址栏聚焦未改字时浮层展示最近 8 条；输入后过滤；普通词加「搜索网页」。悬停/选中访问项显示 ×，按 URL 删除该条并落盘，origin 下没有剩余访问时删掉图标文件。回车提交当前输入并关闭浮层，方向键才选中建议。桌面端浮层是独立、受限、可复用的 child WebView，只拥有自身矩形与 choose/remove 事件权限；网页子 WebView 的位置和尺寸始终不变。普通 Web 预览保留 DOM `absolute` 回退。origin 图标后台拉 `/favicon.ico|png|svg`，32px PNG 缓存，失败用 Globe；内部页签复用同一 origin 图标。不进 Settings，不做历史管理页。
- “设置 → 通用 → 浏览器”持久化搜索引擎、localhost 内部打开、普通网站内部打开三个偏好；默认分别为百度、开启、开启。缺少普通网页偏好字段时按开启处理，已显式保存的开关值保持不变。对客标题为“打开 localhost / 打开网站”，不使用“本地链接”，以免被理解成本地 HTML。
- 页内导航按手势补完，而不是给 `Deny` 加回退：普通左键 `http(s)` 链接由文档创建脚本在捕获阶段 `location.assign` 到当前页（零 IPC）；Ctrl+点击、右键「新窗口」、以及仍到达 `on_new_window` 的 `window.open` 才开内部新页并 `Deny` 系统窗口。Windows External 上 `_blank` 锚点经常根本不会触发 `on_new_window`，因此不能把左键没反应当成 Deny 忘了 navigate。
- 统一 `openWebTarget`：`http(s)` 按浏览器偏好路由；会话和 Markdown 中的本地 `.html/.htm` 进浏览器；工作空间与运行目录树中的 `.html/.htm` 打开文件工作区源码，由右上角浮层按钮再 `openWebTarget`；其它本地文件仍走文件工作区；`mailto:`/`tel:` 走系统 opener。Agent 管理诊断帮助中的 ACP Registry 始终走 `openWebTarget`，Agent 管理页复用 draft 右侧工作区投影。
- 替换 Markdown / 文件预览 / 源码管理 Markdown 中对 `http(s)` 的 `openExternalUrl`。
- 本地 HTML 经现有文件链接 resolver 得到 canonical path 后，以 `file://` 加载，并用该文件父目录作为导航白名单；相对 CSS/JS/图片可打开。不开放任意 `file://`，也不用 `gold-band-preview` 的图片 CSP 承载可执行 HTML。
- 内部页上限 32：拒绝新建并返回 `browser.page.limit_reached`。
- 门户页：无内部页和 `about:blank` 都渲染同一 React 门户，不创建白色子 WebView。空白内部页仍保留占位盒只为测量 bounds，点书签/提交地址时按该尺寸创建原生页。书签按 origin 去重，上限 32，落在 `browser-profile/bookmarks.json`，不进 Settings。渠道目录 `configs/browser-bookmarks.json` 只做首次种子；`wb` 内置码灵官网、CI 平台、DPMS、AOMP、WeAPM、Pace+、CMDB，图标运行时拉取。图标 `ensure_origin_favicon`，不 upsert 访问记录。拖拽复用 `@dnd-kit/sortable`。工具栏已加入态用 `accent-foreground` 实心 + `accent` 浅底；`accent` 是选中底色，不能拿来填图标。

### 阶段 D：页签交互与下载、加载

- 内部页签：origin 图标（与访问记录同一缓存）、最小宽度、横向滚动、`gold-themed-scrollbar`、溢出菜单、右侧钉住的 `+`、hover ×。
- shadcn ContextMenu：关闭 / 关闭其他 / 关闭左 / 关闭右 / 关闭所有。
- 下载：拦截后系统另存为；失败返回 `browser.download.unsupported`。
- 原生实例创建前由占位盒显示 `BrandLoadingState`；创建成功立即 show 并让 WebView 渐进渲染，不把 `load-finish` 作为可见性门槛。
- load-start 启动 15 秒有界恢复；load-finish、停止、关闭、丢弃清理 timer。loading 只控制工具栏的停止/刷新状态，站点长期 loading 也不得被 Logo 遮住。

### 现场二次缺陷与红绿证据

- 长期加载根因：`NativeBrowserViewport` 曾以 `visible && !page.loading` 调用 `ensurePage`，并只在 `!page.loading` 时同步 bounds；因此收到 `load-start` 后原生页面被隐藏，必须等 `load-finish` 才能看见。最小失败测试实际收到 `ensurePage(..., false)`，预期为 `true`。
- 透明命中根因：浏览器占位组件卸载只异步 `hideAll`，`WorkspaceShell` 作为 child WebView 最终 owner 卸载时没有 `discardAll`；切到设置页后原生图层仍可能位于顶层并截获原浏览器矩形内的点击。最小失败测试中 owner 卸载后 `discardAll` 调用次数为 0，预期为 1。
- 修复：原生实例创建成功即显示；loading 不再参与页面显隐。`BrowserNativeLifecycle` 在真正的 Shell owner 卸载时 `discardAll`，并以本地 generation fence 取消 React StrictMode 模拟卸载产生的迟到 cleanup，不增加全局 owner registry 或第二套生命周期状态机。

### 现场四次复测后的切页白屏与侧栏闪烁

- 切会话详情 / 快速会话 / 会话内设置再回来，工具栏和 URL 还在、网页全白：浏览会话是进程单例，React 常复用面板。scope-change close resolver 异步 `suppress()` 后，复用面板不会再 `resume()`；`resume` 即使执行也只清标志、不通知占位盒 `show`。会话内设置让 `scopeKey=null`，`available=false` 会 discard；回来后迟到 discard 或 suppress 中的 `ensurePage` 把重建实例再次 hide。
- 设置里改浏览器选项时左侧会话列表闪一下：`onSavePreferences` 只应补丁 `bootstrap.preferences`，但 App 把整个 `bootstrap` 对象当作会话侧栏加载触发器，每次开关都 `beginConversationSidebarBootstrap` 把已 ready 的列表打回 loading。
- 修复：`resume` / overlay 关闭走统一 visibility 通知，占位组件订阅后重新 `ensurePage`；deactivate/scope-change 不再 suppress 全局浏览器；`available=false` discard 带 generation fence。会话侧栏只在 `conversationShellReady` 时加载，ready 后台刷新不降级 loading。最小失败测试覆盖 resume 通知与 show、viewport 再同步、短暂 unavailable 不 discard、ready 不降级，以及 App 不以 bootstrap 对象身份触发侧栏加载。

### 现场复测后的原生层根因

- 复测仍只显示 Logo 的直接原因：Rust `on_page_load` 在 `Started` 时调用 `webview.hide()`，覆盖前端刚完成的 show。新增原生契约测试先稳定失败于 `Started` 不可见，修复后 load callback 只发事件和日志，不再改变显隐。
- 透明命中无法可靠收敛的直接原因：close/discard/eviction 先从 `BrowserHostInner` 删除或 drain，再调用 native close；`close_labels` 又只 warn 不返回错误。close 失败时 registry 已丢失句柄，后续 owner cleanup 无法重试。新增事务顺序测试先证明 close 失败前已经 mark closed；修复为先 best-effort hide、再 native close，成功后才按 `pageId + label` 删除，失败返回 `browser.webview.operation_failed` 并保留 registry。即使 close 失败，也先尽力让图层退出命中区域。
- 诊断：`gold_band::browser` 结构化记录 create/reuse、show、hide/hide-all、navigate、load-start/load-finish、close/discard-all、registry remaining 与错误。远程目标只记录 origin，本地目标只记录 `file://<local>`；bounds 成功热路径不逐帧写日志。

### LRU 与紧凑 Sheet 生命周期收敛

- LRU 偏差根因：Rust registry 已维护真实访问顺序，但前端又按内部页数组顺序提前选择淘汰页，形成两套事实源。修复为只由 `BrowserHostInner` 淘汰；旧实例成功关闭后立即发送 `discarded { pageId }` 事件，前端只收敛对应页的 `live` 投影。最小失败测试固定“淘汰后即使替代 WebView 创建失败，被淘汰页仍必须变为非 live，其他页不受影响”。
- 紧凑 Sheet 偏差根因：Radix Sheet 的 overlay 与 content 是 Portal 兄弟节点，按 content 子树排除无法识别自身 overlay。shadcn Sheet copy-in 增加通用 `overlayProps`，右侧工作区给自身 overlay 写稳定 owner 标记；浏览器忽略该 overlay，其他 sheet overlay 仍阻塞。DOM 红测同时覆盖 owner 标记存在与移除两种结果。

### 隐藏保留与资源终止分离

- 根因：浏览会话与原生 registry 本来就是应用级单例，但 `BrowserNativeLifecycle` 与 `registerResourceCloseResolver('browser')` 把 React / Shell 的临时生命周期当成资源生命周期，用 `discardAll` 表达「暂时不可见」，于是收起右栏、切会话、进设置页都会销毁全部活实例。这是生命周期边界不一致，不是单场景漏判。
- 修复：抽出 `resolveBrowserResourceTransition(reason)` 作为唯一映射——`close` → `discardAll`，`deactivate` / `workspace-close` → `suppress`，`scope-change` → no-op。`scope-change` 必须是 no-op：它由 `BrowserNativeLifecycle` 统一驱动，子级 effect 先于父级执行；父级 resolver 再 suppress 会覆盖子级刚做的结果。`BrowserNativeLifecycle` 增加 `scopeKey` 入参与展示布尔量一起求值；`suppress` 改为返回 Promise 的幂等操作，`resume` 幂等且重复调用不产生额外 IPC。
- 最小失败测试：持续 `available=false` 改判 suppress 且不 discard；Shell 卸载改判 suppress 保留实例；`scopeKey` 变化但展示布尔量完全相同时不得 suppress / discard（只允许重新求值）；显式 `close` 仍走 discardAll 且不 suppress。
- 语义按 Tauri 子 WebView 定义，不绑定 WebView2：`show/hide`、bounds、`close`、registry 与 LRU 对所有平台一致，WebView2 / WKWebView / WebKitGTK 只作为平台实现细节。代价是保留实例继续占内存并可能后台跑定时器、网络或音频，由 5 个活实例上限兜底；第一版不引入平台专属 suspend / 冻结状态机。
- 本条取代上一条「deactivate/scope-change 不再 suppress 全局浏览器」的旧结论：现在 deactivate / workspace-close 明确 suppress，只有 scope-change 保持 no-op。

### 切会话闪屏收敛

- 症状：保留生效后，每次切回会话原浏览器页会闪一下。
- 根因一（本次引入）：`BrowserNativeLifecycle` 在 `scopeKey` 变化时强制 `suppress()` 再 `resume()`，对同一个可见页执行了一次多余 hide → show。浏览会话是进程单例，切会话时可见页没有变化，这次 hide 没有任何收敛价值，只制造闪屏。修复为删除该强制分支，`scopeKey` 只参与重新求值。
- 根因二（结构性）：切到未展示浏览器的会话或设置页时必须 hide（原生层盖在 HTML 之上），回来必须 show；中间露出的 HTML 空白即闪屏。原实现把首次测量与 `show` 排进 `requestAnimationFrame`，等于等空白帧画完才发 IPC。修复为 `NativeBrowserViewport` 挂载时在 layout 阶段直接测量并 `ensurePage`，resize / observer 后续同步仍走 rAF 合并；`live` 翻转单独补一次同步，避免挂载时重复同步。
- 最小失败测试：先把 `requestAnimationFrame` 换成不执行的桩，断言挂载后 `ensurePage` 已被调用且没有任何 rAF 回调入队；修复前稳定失败，修复后通过。
- 未采纳：用离屏停靠代替 hide、或引入平台 suspend / 冻结。前者收益未经验证且改变命中与渲染语义，后者存在平台差异，均需实测证据后再单独设计。

### 现场三次复测后的 Windows 线程根因

- 网页一直 loading、切设置页后原矩形不可点：`runtime.log` 在 `operation="create"` started 后没有任何 completed / page-load / show / hide / discard 记录。同步 `browser_create_page` 在主 WebView2 IPC 回调线程上调用 `Window::add_child`，wry 的 `wait_with_pump` 等待新 controller 完成，而 WebView2 回调不可重入，命令死锁。此时 HWND 可能已经挂上但未初始化，前端 `markLive` 永不执行，后续 hide/discard IPC 全部排队。
- 修复：全部会创建、关闭或操作子 WebView 的命令改为 `async fn`，让 Tauri 在 tokio worker 上执行，由事件循环完成创建。这是 Tauri 官方对 Windows 创建 WebView 的约束，不是新状态机。
- 伴随实现缺陷：`NativeBrowserViewport` 曾依赖整个 `page` 对象，title / load 事件会 cleanup `hideAll`。改为只按 `pageId` 与可见性绑定生命周期，投影字段走 ref。`openUrl` 新建远程页即挂 15 秒 stall timer；`createPage` 失败时 `markLoading(false)`。
- 死锁依赖真实 WebView2，cargo test 无法复现。替代证据是 `gold_band::browser` 日志中 create started/completed 必须成对出现；前端用 3 项失败测试钉住 viewport 身份、openUrl timer 与 create 失败 loading 清零。
- 网页不随栏宽/高度排版：create 进行中 `ensurePage` 会更新 `lastBounds` 但 in-flight create 仍按第一帧 `add_child`；`live` 翻转后占位组件不再同步。修复为 create 成功后应用最新 `lastBounds`，rAF 读取该帧最后矩形，`live` 后再同步一次且不 hide。

### Windows 无边框缩放 overlay 在 unstable 多 WebView 下缺失

- 冷启动未打开浏览器页就不能拖窗口边缘：`tauri/unstable` 把主 WebView 建成 `WindowChild`，runtime 跳过 `TAURI_DRAG_RESIZE_WINDOW`。Win10 关闭 native shadow 后没有 DWM 外侧框，客户区边缘全部打进主 WebView。属于宿主挂钩缺口，不是 2026-07-28 阴影策略错误。
- 修复：窗口就绪后重新断言 `resizable` 走 Tauri 同一 attach 路径；`add_child` 与地址建议 `HWND_TOP` 之后再把 overlay 抬到最前。overlay 客户区有孔洞，建议浮层仍可点击。
- HWND z-order 无法在 cargo mock / jsdom 中复现；契约测试固定 `unstable`、overlay 类名、`set_resizable(true)` 与调用点。Win10 EXE 验收：冷启动拖边，打开贴边浏览页后右边缘仍可拖。

### 现场复测后的本地 HTML 打开失败与重复点击卡死

- 本地 HTML 打不开：地址栏已显示 `file:///E:/Projects/Code/AI/Test/pelican-bike.html`，但同一时段 `gold_band::browser` 没有任何 `create` / `navigate` / `page-load` 记录，页面停在白屏。根因是原设计把「已授权目录 + `file://` 导航」当成可用方案，而 Windows WebView2 对子 WebView 不保证 `file://` 导航及相对资源加载；`wry` 只在初始 URL 上做自定义协议改写，`navigate` 不会改写，因此必须显式选择平台可加载的协议形态。
- 连续点击导致应用无响应：`commitNavigation` 先写权威 URL、再 fire-and-forget 下发原生命令，失败既不回滚也不结构化上报；同一 page 允许并发导航，点击次数会线性放大原生调用，最终阻塞 WebView 消息循环。
- 修复方向（根因层，不是补丁）：
  1. 本地 HTML 改走 `gold-band-browser-file` 自定义协议。Rust 只按「当前页已授权目录」逐段解析路径，拒绝越界、编码分隔符与非 GET/HEAD，响应 `no-store` / `nosniff` / 推断 `Content-Type`；Windows 生成 `http://<scheme>.localhost/<path>`，其他平台生成 `<scheme>://localhost/<path>`，处理器同时接受两种形态。
  2. 授权目录只来自「打开本地 HTML 时解析出的文件父目录」，页面跳到 `http(s)` 即清空该页授权，协议请求随之为 404（fail closed）。重新输入已授权协议地址时保留原目录而不是丢授权。
  3. 前端导航收敛为每页单一在途事务：同目标重复提交复用在途 Promise，不同目标只保留最后一个排队目标；权威 URL 只在原生命令成功后写入，失败时结束 loading、保留上一次确认 URL，并把结构化错误码投到该页 notice。
  4. 本地 HTML 解析改为浏览器专属轻量解析，不再借用文件编辑器链路签发外部访问令牌、启动文件监听，避免连续点击堆积 grant 与 watcher。
- 红绿证据：`web/tests/browser-webview-host.test.ts` 先新增 2 项失败测试（「同目标连续提交只下发一次导航」实际调用 2 次；「原生导航失败后仍停留在失败 URL 且 loading 未收敛」），修复后转绿。Rust 侧新增 4 项接口级测试：协议路径越界拒绝（含 `..%5C`、`%2F`、空路径）、协议响应只服务授权目录内文件（含 MIME、HEAD、缺失文件 404、非 GET/HEAD 405）、导航使用平台可加载 scheme、重复导航不丢授权目录。
- 验证边界：协议与授权目录的端到端行为已由接口级测试固定；WebView2 真实渲染仍需 EXE 人工验收（用内置浏览器打开 `E:\Projects\Code\AI\Test\pelican-bike.html`，观察是否出现 `create`/`navigate` started 与 completed 配对、随后 `page-load` started/finished，页面显示动画且连续点击不再堆积）。

## 4. 接口草案

前端只提交意图，Rust 解析 URL、本地 HTML 路径和下载落盘。

- `browser_create_page { url, viewMode }` / `browser_set_view_mode { pageId, viewMode }` / `browser_navigate { pageId, url }`；原生 LRU 淘汰通过 `discarded { pageId }` 事件收敛
- `browser_resolve_local_html { projectId, rawHref } -> { canonicalPath }`：浏览器专属轻量解析，只返回 canonical 路径，不签发外部访问令牌、不启动文件监听；越界或非 HTML 直接返回 `workspace-file.*` / `browser.navigation.invalid`
- `browser_close_page { pageId }`（前端也可只改会话再 close native）
- 下载由 WebView 回调触发，Rust 调系统保存对话框并写入。
- 错误一律 `CommandErrorVm`。code 见产品设计第 13 节。

Native 实例 registry 放 Rust 或与窗口绑定的前端 ref 仓库均可，但 **句柄不得进工作区 Tab reducer**。推荐：前端 session store 只持有页摘要；viewport 模块持有 `pageId → Webview`。

内部页超过 32：拒绝新建并返回结构化错误，或淘汰最旧非当前页摘要并丢掉其 WebView。实现时选一种并用测试钉死。

## 6. 方案审视

过度设计：不新增跨层 identity，不把浏览会话写入 `core.db` 或 conversation preference。5 个活 WebView 与 32 个页摘要是有界常量，不是新状态机。继续复用唯一 `BrowserHostInner` registry；命令只把同步 IPC 改成 async，不增加队列、全局 owner 或第二套生命周期。本地 HTML 协议不引入本地 HTTP 服务、临时目录或独立缓存：它复用 Tauri 异步自定义协议与页面已持有的授权目录，读文件是单次有界读取（64MB 上限），请求间无共享状态。导航收敛使用既有的 `page.url` 与 `loading`，不新增状态字段，每页只多一个在途 Promise 与一个「最后一个排队目标」字符串。

性能：未打开零成本，宿主模块不得被 WorkspaceShell 静态导入。可见时 bounds 每帧最多一次 IPC，且不得发布 React 根 state；挂载首帧在 layout 阶段直接测量一次，不排队等帧，后续 rAF 只发送该帧最后一次矩形。占位组件不再因 title/load 投影反复 hide/show，也不在挂载时重复同步。收起右栏、切会话或离开 Shell 只 hide + suppress，隐藏热路径最多一次 hide-all，仍是 O(5) 有界操作，不增加轮询；真正销毁只发生在明确关闭、LRU 淘汰与应用退出。保留实例的内存与后台活动由 5 个活实例上限兜底，第一版不引入冻结或超时回收机制。页摘要 O(页数) 且 ≤32；每个 loading 页最多一个 15 秒 timer，结束即释放。生命周期日志为低频常数条目并受既有 8 MiB × 4 轮转限制。async 命令只在 create/navigate/close 等低频路径多一次线程切换，不改变热路径。create 完成后多一次 setBounds 是 O(1) 收敛，不是逐帧补偿循环。本地 HTML 协议每次请求只 stat + 读一个文件，不扫目录；同一目标连续提交不产生额外原生调用，因此耗时与点击次数无关。
