# 右侧工作区内置浏览器开发方案

## 1. 文档状态

- 状态：阶段 A–D 已实现。空白页与无标签统一为门户页；书签按 origin 落盘，图标复用 favicon 缓存且不写入访问记录。地址栏补全最近 200 条访问记录和 origin 图标。普通左键 `http(s)` 在到达 `NewWindowRequested` 之前改成当前页跳转；电脑/移动版切换在同一活 WebView 上改 UA 并 reload。
- 编制日期：2026-09-16。
- 目标版本：MVP 增量能力。
- 产品设计真源：[右侧工作区内置浏览器](../../产品设计文档/interaction/app/in-app-browser.md)。
- 前置能力：通用右侧工作区 Tab、文件链接 resolver、`gold-band-preview` grant、`BrandLoadingState`、Shell 布局帧。

实现必须同步维护产品设计文档与本方案。未获产品设计变更前，不得把 URL 做成工作区 Tab、按工作空间复制浏览会话，或从本机浏览器导入 Cookie。

## 2. 设计方向

问题不是文件 canonical state 缺陷，而是缺少「应用内浏览」这一工作对象。宿主必须是零权限子 WebView，不能用 iframe。布局同步抄 Tauri #14588 的占位 div 范式，但要接到 Gold Band Shell（位移、Sheet、Dialog、自动收起），不能只观察 width/height。

## 3. 实施阶段

### 阶段 A：宿主骨架

- capability 绑定 `webviews: ["main"]`，不按 window 授权；浏览子 WebView 从 Rust `Window::add_child` 创建，前端不调用 JS `createWebview`，子页零 IPC。
- `NativeBrowserViewport`：占位 div、逻辑像素 bounds、rAF 合并最新矩形、DPI。create 完成与 `live` 翻转后必须再对齐一次，避免网页按第一帧小矩形排版。
- 接到 `WorkspaceShell` 已有布局帧：左栏折叠、右栏尺寸、Sheet、scaleFactor、激活资源变化。
- Dialog / Sheet overlay 打开时 hide，关闭后若浏览器仍是可见激活资源则按占位盒 show。
- 模块与 WebView 环境仅在首次真正打开浏览器时加载/创建。

### 阶段 B：全局会话与工作区投影

- 进程内 `BrowserSession` 单例：`pages[]`（上限 32）、`activePageId`、活 WebView LRU（上限 5）。
- 工作区资源 `kind: 'browser'`，当前 scope 内 key 为 `browser`，只作投影。
- × 投影 Tab、关右栏或离开拥有浏览器的 `WorkspaceShell`：丢弃全部活 WebView，保留 `pages`。Shell owner 卸载必须 close/discard，不能只依赖占位组件异步 hide。
- 窗口自动收起且 Sheet 未开：只 hide，不丢弃。
- 内部关闭所有页：清空 `pages`，投影 Tab 仍在，空态 `+`。
- Cookie 目录：`{appData}/browser-profile/`，与主 WebView 隔离，退出不清空。

### 阶段 C：导航与链接

- 工具栏：后退、前进、加载中停止、地址栏、电脑/移动版切换、带 Tooltip 的「用系统浏览器打开」。电脑/移动切换走 `browser_set_view_mode`：同一实例改 UA 后 reload，不 close。
- 地址解析先识别显式 scheme、域名、IP、localhost 和本地 HTML；其他输入按设置的百度 / Google / Bing 搜索。空白逻辑页首次提交走 create，活页走 navigate。
- 访问记录与打开的页签分开：`load-finish` 写入规范化 `http(s)` URL，最多 200 条，落在 `browser-profile/history.json`。地址栏聚焦未改字时浮层展示最近 8 条；输入后过滤；普通词加「搜索网页」。悬停/选中访问项显示 ×，按 URL 删除该条并落盘，origin 下没有剩余访问时删掉图标文件。回车提交当前输入并关闭浮层，方向键才选中建议。浮层不占工具栏布局；与网页重叠时只下移子 WebView 顶边。origin 图标后台拉 `/favicon.ico|png|svg`，32px PNG 缓存，失败用 Globe；内部页签复用同一 origin 图标。不进 Settings，不做历史管理页。
- “设置 → 通用 → 浏览器”持久化搜索引擎、localhost 内部打开、普通网页内部打开三个偏好；默认分别为百度、开启、关闭。
- 页内导航按手势补完，而不是给 `Deny` 加回退：普通左键 `http(s)` 链接由文档创建脚本在捕获阶段 `location.assign` 到当前页（零 IPC）；Ctrl+点击、右键「新窗口」、以及仍到达 `on_new_window` 的 `window.open` 才开内部新页并 `Deny` 系统窗口。Windows External 上 `_blank` 锚点经常根本不会触发 `on_new_window`，因此不能把左键没反应当成 Deny 忘了 navigate。
- 统一 `openWebTarget`：`http(s)` 按浏览器偏好路由，本地 `.html/.htm` 进浏览器；其它本地文件仍走文件工作区；`mailto:`/`tel:` 走系统 opener。
- 替换 Markdown / 文件预览 / 源码管理 Markdown 中对 `http(s)` 的 `openExternalUrl`。
- 本地 HTML 经现有文件链接 resolver 得到 canonical path 后，以 `file://` 加载，并用该文件父目录作为导航白名单；相对 CSS/JS/图片可打开。不开放任意 `file://`，也不用 `gold-band-preview` 的图片 CSP 承载可执行 HTML。
- 内部页上限 32：拒绝新建并返回 `browser.page.limit_reached`。
- 门户页：无内部页和 `about:blank` 都渲染同一 React 门户，不创建白色子 WebView。空白内部页仍保留占位盒只为测量 bounds，点书签/提交地址时按该尺寸创建原生页。书签按 origin 去重，上限 32，落在 `browser-profile/bookmarks.json`，不进 Settings。渠道目录 `configs/browser-bookmarks.json` 只做首次种子；`wb` 内置码灵官网、CI 平台、DPMS、AOMP、WeAPM、Pace+、CMDB，图标运行时拉取。图标 `ensure_origin_favicon`，不 upsert 访问记录。拖拽复用 `@dnd-kit/sortable`。工具栏已加入态用 `accent-foreground` 实心 + `accent` 浅底；`accent` 是选中底色，不能拿来填图标。

### 阶段 D：页签交互与下载、加载

- 内部页签：origin 图标（与访问记录同一缓存）、最小宽度、横向滚动、`gold-themed-scrollbar`、溢出菜单、右侧钉住的 `+`、hover ×。
- shadcn ContextMenu：关闭 / 关闭其他 / 关闭左 / 关闭右 / 关闭所有。
- 下载：拦截后系统另存为；失败返回 `browser.download.unsupported`。
- 原生实例创建前由占位盒显示 `BrandLoadingState`；创建成功立即 show 并让 WebView 渐进渲染，不把 `load-finish` 作为可见性门槛。
- load-start 启动 15 秒有界恢复；load-finish、停止、关闭、丢弃清理 timer。loading 只控制工具栏的停止/刷新状态，站点长期 loading 也不得被 Logo 遮住。

### 现场二次缺陷与红绿证据

- 长期加载根因：`NativeBrowserViewport` 曾以 `visible && !page.loading` 调用 `ensurePage`，并只在 `!page.loading` 时同步 bounds；因此收到 `load-start` 后原生页面被隐藏，必须等 `load-finish` 才能看见。最小失败测试实际收到 `ensurePage(..., false)`，预期为 `true`。
- 透明命中根因：浏览器占位组件卸载只异步 `hideAll`，`WorkspaceShell` 作为 child WebView 最终 owner 卸载时没有 `discardAll`；切到设置页后原生图层仍可能位于顶层并截获原浏览器矩形内的点击。最小失败测试中 owner 卸载后 `discardAll` 调用次数为 0，预期为 1。
- 修复：原生实例创建成功即显示；loading 不再参与页面显隐。`BrowserNativeLifecycle` 在真正的 Shell owner 卸载时 `discardAll`，并以本地 generation fence 取消 React StrictMode 模拟卸载产生的迟到 cleanup，不增加全局 owner registry 或第二套生命周期状态机。

### 现场四次复测后的切页白屏与侧栏闪烁

- 切会话详情 / 快速会话 / 会话内设置再回来，工具栏和 URL 还在、网页全白：浏览会话是进程单例，React 常复用面板。scope-change close resolver 异步 `suppress()` 后，复用面板不会再 `resume()`；`resume` 即使执行也只清标志、不通知占位盒 `show`。会话内设置让 `scopeKey=null`，`available=false` 会 discard；回来后迟到 discard 或 suppress 中的 `ensurePage` 把重建实例再次 hide。
- 设置里改浏览器选项时左侧会话列表闪一下：`onSavePreferences` 只应补丁 `bootstrap.preferences`，但 App 把整个 `bootstrap` 对象当作会话侧栏加载触发器，每次开关都 `beginConversationSidebarBootstrap` 把已 ready 的列表打回 loading。
- 修复：`resume` / overlay 关闭走统一 visibility 通知，占位组件订阅后重新 `ensurePage`；deactivate/scope-change 不再 suppress 全局浏览器；`available=false` discard 带 generation fence。会话侧栏只在 `conversationShellReady` 时加载，ready 后台刷新不降级 loading。最小失败测试覆盖 resume 通知与 show、viewport 再同步、短暂 unavailable 不 discard、ready 不降级，以及 App 不以 bootstrap 对象身份触发侧栏加载。

### 现场复测后的原生层根因

- 复测仍只显示 Logo 的直接原因：Rust `on_page_load` 在 `Started` 时调用 `webview.hide()`，覆盖前端刚完成的 show。新增原生契约测试先稳定失败于 `Started` 不可见，修复后 load callback 只发事件和日志，不再改变显隐。
- 透明命中无法可靠收敛的直接原因：close/discard/eviction 先从 `BrowserHostInner` 删除或 drain，再调用 native close；`close_labels` 又只 warn 不返回错误。close 失败时 registry 已丢失句柄，后续 owner cleanup 无法重试。新增事务顺序测试先证明 close 失败前已经 mark closed；修复为先 best-effort hide、再 native close，成功后才按 `pageId + label` 删除，失败返回 `browser.webview.operation_failed` 并保留 registry。即使 close 失败，也先尽力让图层退出命中区域。
- 诊断：`gold_band::browser` 结构化记录 create/reuse、show、hide/hide-all、navigate、load-start/load-finish、close/discard-all、registry remaining 与错误。远程目标只记录 origin，本地目标只记录 `file://<local>`；bounds 成功热路径不逐帧写日志。

### 现场三次复测后的 Windows 线程根因

- 网页一直 loading、切设置页后原矩形不可点：`runtime.log` 在 `operation="create"` started 后没有任何 completed / page-load / show / hide / discard 记录。同步 `browser_create_page` 在主 WebView2 IPC 回调线程上调用 `Window::add_child`，wry 的 `wait_with_pump` 等待新 controller 完成，而 WebView2 回调不可重入，命令死锁。此时 HWND 可能已经挂上但未初始化，前端 `markLive` 永不执行，后续 hide/discard IPC 全部排队。
- 修复：全部会创建、关闭或操作子 WebView 的命令改为 `async fn`，让 Tauri 在 tokio worker 上执行，由事件循环完成创建。这是 Tauri 官方对 Windows 创建 WebView 的约束，不是新状态机。
- 伴随实现缺陷：`NativeBrowserViewport` 曾依赖整个 `page` 对象，title / load 事件会 cleanup `hideAll`。改为只按 `pageId` 与可见性绑定生命周期，投影字段走 ref。`openUrl` 新建远程页即挂 15 秒 stall timer；`createPage` 失败时 `markLoading(false)`。
- 死锁依赖真实 WebView2，cargo test 无法复现。替代证据是 `gold_band::browser` 日志中 create started/completed 必须成对出现；前端用 3 项失败测试钉住 viewport 身份、openUrl timer 与 create 失败 loading 清零。
- 网页不随栏宽/高度排版：create 进行中 `ensurePage` 会更新 `lastBounds` 但 in-flight create 仍按第一帧 `add_child`；`live` 翻转后占位组件不再同步。修复为 create 成功后应用最新 `lastBounds`，rAF 读取该帧最后矩形，`live` 后再同步一次且不 hide。

## 4. 接口草案

前端只提交意图，Rust 解析 URL、本地 HTML 路径和下载落盘。

- `browser_create_page { url, viewMode }` / `browser_set_view_mode { pageId, viewMode }` / `browser_navigate { pageId, url }`
- `browser_close_page { pageId }`（前端也可只改会话再 close native）
- 下载由 WebView 回调触发，Rust 调系统保存对话框并写入。
- 错误一律 `CommandErrorVm`。code 见产品设计第 13 节。

Native 实例 registry 放 Rust 或与窗口绑定的前端 ref 仓库均可，但 **句柄不得进工作区 Tab reducer**。推荐：前端 session store 只持有页摘要；viewport 模块持有 `pageId → Webview`。

内部页超过 32：拒绝新建并返回结构化错误，或淘汰最旧非当前页摘要并丢掉其 WebView。实现时选一种并用测试钉死。

## 5. 验收

2026-09-16 自动化结果：首轮浏览器聚焦 Vitest 6 文件 21 项、浏览器 API 3 文件 22 项、右侧工作区 DOM 13 项全部通过；现场二次前端测试由 2 项失败转为 3 项通过，但用户实测证明仍未穿透原生回调。补充原生层两条红测与日志脱敏测试后，Rust browser 测试通过。现场三次将根因收敛到同步 IPC 死锁：viewport / session / host 3 项失败测试先复现「title 变更 hideAll」「openUrl 无 stall timer」「create 失败 loading 不清」，修复后转绿。EXE 复核看 `create` started/completed 配对与设置页原矩形可点。

接口 / 状态：

- 未打开浏览器时不创建子 WebView、不挂同步观察器。
- 两个工作空间打开浏览器看到同一 `pages` 与同一 `activePageId`。
- × 工作区浏览器 Tab 后 `pages` 仍在；再打开投影回到原当前页。
- 关右栏丢弃活 WebView；再打开只重建当前页。
- 自动收起不丢弃活 WebView，但必须 hide，不得盖住中间会话。
- 活 WebView 不超过 5；第 6 个后台页被淘汰后再次点开会重新 navigate。
- 内部关闭所有页后投影 Tab 仍在且可 `+`。
- `http(s)` 点击按 localhost / 普通网页两个持久偏好路由，不再由各消费端自行决定。
- 裸词输入按所选百度 / Google / Bing 搜索；显式域名仍按 URL 打开。
- 空白页输入地址后创建 native WebView；关闭内部页、关闭工作区投影再重开后仍可导航。
- 原生实例创建后，即使仍在 loading 也可见、可渐进渲染和交互；缺少 finish 事件时 15 秒内恢复工具栏状态。新建远程页在 create 返回前也受同一 timer 约束；create 失败后 loading 立即结束。
- 外部打开按钮有 Tooltip，并对未提交搜索词遵循当前搜索引擎。
- 当前页可在电脑版 / 移动版之间切换；默认电脑版，图标表示下一步动作；切换在同一活 WebView 上更换 User-Agent 并 reload，不 close、不改栏宽、不落盘，前进后退历史保留。
- 关闭浏览器工作区或离开会话 Shell 后，原生图层完成 discard；设置页及导航页在原浏览器矩形范围内可立即点击。
- Windows 上打开网页时 `runtime.log` 必须出现 `create` started 与 completed 配对，随后有 show / page-load；命令不得停在 started。
- 浏览器偏好保存并在应用重启后恢复；localhost 与普通网页链接按两个独立开关路由。
- 本地 `.html` 不创建文件编辑 Tab。

UI：

- 浅色/深色、右栏拖宽、左栏收起、三栏变一栏、Sheet、权限 Dialog 盖住时网页必须让出。
- 页签滚动、溢出菜单、右键五项、空态 `+`。
- 原生实例创建前呼吸 logo 可见，实例创建后立即让位给渐进渲染的页面；`prefers-reduced-motion` 关闭动效。

平台：Windows 与 macOS 为交付门槛；Linux 走同一路径，Wayland 错位不阻塞合并，但 hide/show 与零 IPC 仍必须成立。

## 6. 方案审视

过度设计：不新增跨层 identity，不把浏览会话写入 `core.db` 或 conversation preference。5 个活 WebView 与 32 个页摘要是有界常量，不是新状态机。继续复用唯一 `BrowserHostInner` registry；命令只把同步 IPC 改成 async，不增加队列、全局 owner 或第二套生命周期。日志复用 tracing/runtime.log。

性能：未打开零成本，宿主模块不得被 WorkspaceShell 静态导入。可见时 bounds 每帧最多一次 IPC，且不得发布 React 根 state；rAF 只发送该帧最后一次矩形。占位组件不再因 title/load 投影反复 hide/show。关右栏或离开 Shell 时最多串行关闭 5 个实例，避免后台 WebView 常驻和透明命中；这是低频 O(5) owner cleanup，不增加轮询。页摘要 O(页数) 且 ≤32；每个 loading 页最多一个 15 秒 timer，结束即释放。生命周期日志为低频常数条目并受既有 8 MiB × 4 轮转限制。async 命令只在 create/navigate/close 等低频路径多一次线程切换，不改变热路径。create 完成后多一次 setBounds 是 O(1) 收敛，不是逐帧补偿循环。
