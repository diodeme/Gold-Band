### 1.1.1 2026-08-05 会话目录入口与文件管理器定位

- 已发起会话的右侧工作区入口页和固定“新建 Tab”菜单提供两个并列入口：“工作空间”对应 `file-browser` 的项目根目录，“运行目录”对应 `conversation-directory` 的当前 attempt 产物。快速对话 draft 或尚未选择运行节点时不展示运行目录，且会话标题栏不再重复入口。两者均采用左侧文件详情、右侧目录树，文件查看复用 CodeMirror/安全图片预览，但运行产物默认只读。
- `FileWorkspaceSplitLayout` 已从文件面板抽出，运行目录与项目文件共用同一 shadcn `Button` 紧凑切换、响应式单双栏和可调整目录分栏，禁止为运行目录维护第二套布局。
- 项目文件也不再创建文件级右侧 Tab；`file-browser:<projectId>` 持有当前选中文件，树点击、搜索和文件链接都仅替换该选择与定位 revision，与运行目录的 Tab 内切换模型统一。
- 共享单栏切换不能只依赖 `hasFile` 布尔值：选择已存在文件后的另一文件时，必须以 `selectedFileKey` 变化切回详情。用户附件查看器的只读 CodeMirror 使用 `EditorView.lineWrapping` 和最小宽度约束，保证任意长行适配工作区宽度。
- 目录树节点和筛选结果文件均复用 shadcn/Radix `ContextMenu`。项目工作空间与运行目录树节点复用同一目录操作组件，均按“复制绝对路径、复制相对路径、在文件管理器中打开”的顺序提供操作；复制绝对路径规范化 Windows 扩展长度前缀，复制相对路径统一使用 `/` 分隔符。菜单操作不改变当前选择、Tab 或树布局。
- 新增运行目录列表与定位接口，均只接受 attempt locator 与相对路径，Rust 重新计算 attempt 根目录并拒绝越界；工作空间树的 `open_workspace_path_in_file_manager` 保持仅接受 `projectId + relativePath`。Windows 以 `process::background_command("explorer.exe")` 的隐藏进程和 `/select,` 参数定位目录或文件，满足无黑色终端窗口约束。
- 本轮按需求不启动前端做人工验证；以 TypeScript 构建、Vitest 与 Rust 定向测试作为回归验收。

### 1.1.3 2026-08-12 运行目录响应式重挂载修复

- 根因位于前端 DOM 生命周期而非目录接口：右侧工作区重新打开时先以 0 宽度挂载单栏，恢复偏好宽度后切换双栏；运行目录高度 hook 曾位于跨分支存活的父组件中，`ResizeObserver` 因而继续观察已卸载的单栏节点，新双栏树沿用 1px 高度并表现为空白。
- 保留现有 `react-arborist`、`react-resizable-panels`、响应式状态机和目录接口，把运行目录树及高度测量收进独立子组件。该组件在单栏与双栏分支之间移动时按 React 生命周期重新挂载，观察器自然绑定当前 DOM，不增加 store、兼容层、额外 IPC 或目录扫描。
- 新增真实 DOM 回归：面板初始宽度与树高度均为 0，随后只触发外层文件面板的响应式观察器恢复至 760px 双栏，断言新目录树 DOM 重新测得 800px 高度、文件仍可见且目录接口只调用一次。
- 性能评审：每个已挂载运行目录仍只有一个高度观察器；仅跨单双栏断点时发生一次预期目录树重挂载，同一布局区间不增加 React 更新、I/O、缓存或全量遍历。

### 1.1.4 2026-08-15 左右栏偏好恢复与单一宽度事实源

- 左栏重启后回到默认宽度的根因不是持久化失败，而是会话侧栏 VM 先以空 preferences 挂载，`react-resizable-panels` 已用 256px 完成首次注册；异步返回的 `sidebar.width` 只更新 `defaultSize` 属性不会改变现有 Panel。左栏改为与右栏一致的本地偏好投影：用户尚未操作时接收异步持久化宽度，并通过 Group canonical layout 事务恢复；用户开始拖动后不再被迟到 hydrate 覆盖。
- `sidebar.width` 与 `rightWorkspace.width` 分别是左右栏唯一持久化事实源。Group 级 `onLayoutChanged` 以 `meta.isUserInteraction` 判断用户完成动作，并比较相邻两次完成布局中左右外侧 Panel 的差量识别对应 separator，避免调整另一侧或自动布局时串写偏好；连续 pointermove 仍完全交给 `react-resizable-panels`，只在完成事件提交一次 React 状态和存储写入。
- 删除文件布局的 `preferredWidth` 配置、Rust/VM/TypeScript 投影及 `FileWorkspaceSplitLayout` 挂载时的主动扩宽 effect。工作空间和运行目录只根据实际容器宽度在单栏/双栏间响应，打开资源只改变 Tab 状态，不改变外层右栏宽度。
- 回归验收固定两个接口边界：Panel 以 256px 注册后，异步到达的最小偏好 176px 必须通过同一 Group 布局事务恢复；在 397px 右栏中打开运行目录后 `rightWorkspace.width` 必须保持 397px。方案没有新增依赖、store、缓存或后端命令；性能影响仅为 hydrate/拖拽完成时一次离散状态更新，无全量扫描、额外 I/O、无界状态或热路径写入。

### 1.1.5 2026-08-15 运行目录流式更新期间的右键菜单稳定性

- 根因不是 Radix 菜单或文件持续写入：会话流式快照会重建 selected session leaf，运行目录入口曾依赖完整 leaf 对象并反复更新工作区 Context；同时运行目录把 react-arborist 节点 renderer 写成 render 内联组件，父级更新会把每一行视为新组件并卸载，连带关闭菜单。
- 运行目录入口依赖收窄为 project/task/run/attempt locator 与展示 code 等 primitive 语义字段；目录行改为模块级稳定 renderer，并通过局部 Context 读取选择和命令。保留现有 react-arborist、shadcn/Radix ContextMenu 与目录接口，不新增 store、缓存、事件队列或后端调用。
- DOM 回归固定同一节点在无关父级更新前后保持相同元素 identity，目录接口不重复请求；因此菜单内部状态继续归属于同一行生命周期。本轮按用户要求不执行页面、编译、测试或其他验证；新增回归用例留待后续统一测试时执行。
- 性能评审：流式事件不再把语义未变的运行目录入口发布到工作区，目录行只在其消费字段变化时更新；比较成本为固定数量 primitive 的 O(1) 检查，不增加 I/O、全量扫描、缓存、队列或内存增长。

### 1.1.6 2026-08-17 运行目录跟随 selected attempt

- 根因：会话页已经从 canonical `sessionTree.selectedSessionKey` 投影出当前 attempt locator，但右侧工作区仅更新“新建 Tab”入口；已打开运行目录把 attempt locator 同时作为 Tab key 和数据身份保存，切换 session 后仍持有旧 locator。这不是后端目录解析或 session canonical state 缺陷，而是前端资源模型没有区分 run 级 Tab 生命周期与 selected-attempt 数据绑定域。
- 实现：运行目录改为 run 内唯一稳定 key `conversation-directory:<projectId>:<taskId>:<runId>`。`setConversationDirectoryEntry` 在当前 scope 内只同步已经存在的运行目录资源，不自动打开或激活；工作空间和其他固定 locator 资源保持不变。目录面板用完整 project/task/run/round/outer/node/attempt 数据身份驱动重挂载与加载，切换时清空旧树、文件选择和预览，并用取消标记与文件读取 generation 阻止旧 attempt 的迟到响应覆盖新内容。
- 接口与 DOM 回归：固定不同 attempt 生成相同运行目录 Tab key、同步后 Tab 数量和当前活动 Tab 不变、工作空间资源 identity 不变；实际 Provider 中切换 attempt 后已打开 Tab 原位获得新 locator；目录请求严格携带新 locator，旧根目录响应晚到后不能覆盖新树。定向 3 个 Vitest 文件共 30 项测试通过。
- 过度设计评审：复用现有 `ConversationWorkspaceStore`、reducer、React Context 和目录接口，仅新增 store 内已存在资源的同步动作与 attempt 数据 key；不增加全局刷新总线、持久字段、缓存、状态机或第三方依赖。上下文绑定域只用于描述既有资源差异，不把系统提示、附件和 Diff 等历史资源错误地统一跟随 selected attempt。
- 性能评审：attempt 切换只对当前 run 的有界 Tab 数组执行一次 O(Tabs) 原位替换；运行目录未激活时不挂载面板、不发起 I/O，激活时只懒加载新 attempt 根目录。相同 locator 的流式事件不重复同步或请求，不刷新项目工作空间、完整 run、会话历史或其他资源；没有 N+1、全量扫描、无界缓存、队列或额外并发锁。

### 1.1.6 2026-08-16 三栏宽度恢复与跨页面右栏记忆

- 根因包含三个 canonical 边界错误：早期实现按右栏当前实际宽度反馈式交换 resize behavior；改成两侧固定像素后，受窄窗约束的临时右栏宽度又成为面板库后续基线，窗口恢复时不再追赶偏好；从运行模式返回时，独立右 Panel 展开发生在旧的 640px 中区下限过渡期，会为了容纳右栏把左栏折叠。另一个独立问题是右栏 `requestedOpen` 与资源 scope 一起存储，无法让快速对话和会话详情共享用户的开关意图。
- 继续使用现有 shadcn Resizable 与 `react-resizable-panels`。最终方案不读取 Panel 当前宽度决定 owner：当窗口不足以容纳完整左右偏好和中区下限时，中区保持像素、右栏吸收窗口增减；达到完整偏好后切回右栏像素、中区吸收。owner 只在 canonical 宽度阈值变化时提交。页面 profile、有效显隐和偏好变化统一通过官方 Group `setLayout()` 原子提交三栏目标，删除左右 Panel 独立 `collapse/expand/resize`。右侧分隔条始终使用配置范围，完成事件才提交并持久化偏好。
- 会话工作区数据按生命周期拆分：`ConversationWorkspaceStore` 的 Shell state 统一持有 `requestedOpen/openRevision/width`，快速对话和会话详情共享；资源 LRU 只持有各 scope 的 `tabs/activeTabKey`。运行模式等无右栏页面仅取消有效呈现，不调用关闭；从 draft 创建会话只删除 draft 资源，不迁移 Shell 意图。
- 接口与 DOM 回归覆盖 Shell state hydrate/用户宽度优先级、资源 scope 隔离、无右栏页面返回快速对话及切到会话详情后开关和宽度不变；布局回归固定进入 640px profile 的运行模式再返回时，Group 原子目标仍同时包含左栏与右栏偏好。1px 连续扫描验证压缩区间不发布逐像素 React state，只在右栏完全恢复偏好的阈值切换一次 owner；owner 只能依赖 canonical 输入，禁止恢复实际宽度反馈字段。
- 过度设计评审：复用已有 Store、Provider、Resizable 和偏好接口，没有新增 aggregate、持久字段、依赖、兼容层或状态机。性能评审：窗口连续缩放热路径减少 `onResize` 布尔发布和 React 重渲染，只保留既有 rAF 折叠判断；无新增 I/O、扫描、缓存、队列、锁或阻塞行为。

### 1.1.7 2026-08-16 真实客户端三栏布局诊断

- 浏览器在 1800→500→1800px 和“快速对话→运行模式→快速对话”路径均恢复正确，但 Windows Tauri 客户端仍复现相同异常，说明现有模拟缺少原生窗口 resize、Panel 约束重新注册或实际事件顺序中的关键事实。停止继续按截图推断，先采集同一时间轴的 canonical 意图和物理 Panel 状态。

## 2. 背景与问题判断

Gold Band 已经完成通用右侧工作区与 Agent 分支会话的主体重构，当前具备：

- 左侧导航、中间主工作区、右侧辅助工作区三段式布局。
- 右侧工作区多 Tab 资源模型。
- draft / conversation scope 隔离与 24 项运行期 LRU。
- 全局宽度记忆、自动响应式收起与紧凑窗口 Sheet 降级。
- 只挂载激活 Tab 内容，非激活资源只保留轻量定位状态。
- `RightWorkspaceResource` 已预留 `file` 资源类型。

因此，本需求不是根本性的布局设计缺陷，也不应另建一套文件侧栏。正确方向是沿用通用右侧资源模型，补齐文件领域、文件服务、编辑器生命周期和 Markdown 文件链接协议。

现有实现有三处不足需要在本期一起完善，不能通过页面局部状态打补丁：

1. 右侧资源 renderer 与关闭拦截器当前是单例注册，文件资源与工作流编辑资源并存后可能互相覆盖，必须升级为按资源类型注册的 registry。
2. 现有文件资源仅保存 `path`，不能表达所属项目、工作区内外分类、规范化路径、目标行列和访问策略。
3. 文件内容、图片预览授权、编辑器状态和保存队列属于文件内容生命周期，不能放进轻量 Tab 状态，必须由独立 `FileContentStore` 统一管理。

## 3. 设计目标

1. 打开右侧工作区且没有资源 Tab 时，入口页提供“工作空间”选项；已发起会话且已选中运行节点时额外提供“运行目录”，快速对话不展示该项。
2. 点击“文件”后进入当前项目的文件目录，不弹出终端或命令输入界面。
3. 文件树支持按需展开、文件搜索、单击查看，以及右键复制绝对路径、工作区相对路径或在系统文件管理器中定位当前目录/文件。
4. 未选择文件时，左侧展示“从工作区目录树中选择文件”的空状态，右侧展示当前项目文件树。
5. 选择文本或代码文件后，左侧使用成熟代码编辑器查看和编辑；选择图片后，左侧使用图片预览器查看，右侧文件树始终保持可用。
6. 文件编辑采用近实时自动保存，不把正常编辑建模为长期未保存状态。
7. `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` 或平台等价重做快捷键由编辑器原生历史处理，撤销或重做后的内容继续自动写回磁盘。
8. 会话 Markdown 中的本地文件链接点击后，在右侧工作区打开或激活对应文件，并定位到目标行列。
9. 工作区外文件仅在用户显式点击后打开；文本、代码和配置文件允许编辑及自动保存，图片只读预览。文件详情显示不可点击的绝对路径，右侧仍展示当前项目文件树。
10. 用户编辑、Agent 写文件和外部程序写文件并发时，不静默覆盖任何一方的新版本。
11. 大仓库、大目录和大文件不能阻塞 WebView 主线程，也不能拖慢会话首屏。
12. 所有错误使用结构化错误码，后端不返回对客文案，前端通过 i18n 映射。

## 4. 非目标

- 文件拖拽排序、目录拖拽移动和批量文件操作。
- Git 状态装饰、Diff 编辑、冲突三方合并。

PDF、Office、音视频、压缩包、字体、数据库和其他通用二进制格式可在后续按右侧资源类型扩展；本期只返回明确的不支持状态并提供“使用系统应用打开”，不临时拼装低质量预览。

- 原生支持撤销/重做、行号、搜索、折叠、选区、目标位置滚动和只读模式。
- React 19 兼容路径已有成熟项目验证。
- 可以按文件大小关闭语法高亮和折叠，避免大文件编辑卡顿。
- 能直接使用应用语义色 token，不需要维护一套 IDE 主题系统。

`@uiw/react-codemirror` 默认安装固定浅色背景，因此适配层必须显式关闭其内置主题；编辑器表面和 `HighlightStyle` 统一引用 Gold Band 的 `foreground`、`muted-foreground`、`primary` 与语义状态 token。这样浅色、深色及后续主题均沿用应用主题事实，不在文件领域复制主题状态。

不自研文本编辑器、行号系统、撤销栈或代码搜索控件。

### 5.2 文件树

首选 `react-arborist`，实现前必须完成 React 19、键盘导航、受控展开和懒加载兼容性验证。若兼容性不满足，则使用 `@headless-tree/react + @tanstack/react-virtual` 组合，不允许退回手写树虚拟化、键盘导航和焦点管理。

文件树外观使用 Tailwind CSS utilities；搜索框、右键菜单、按钮、Tooltip、空状态和内部可调整分栏优先使用 shadcn/ui copy-in 组件：

- `ContextMenu`
- `Input`
- `Button`
- `Tooltip`
- `Resizable`
- `ScrollArea`（仅组件行为确有需要时使用，普通树滚动优先原生滚动容器）

图标继续使用项目现有 Lucide，不引入第二套结构性图标语言。

文件树筛选属于工具栏密度，不应直接套用表单输入的 3px 强焦点环。`Input` copy-in 组件统一提供 `toolbar` 外观变体：低对比度背景和边界、聚焦时 1px `ring` 与轻量表面变化；标准表单保持原焦点强度。两者均使用语义 token，不在文件树局部硬编码颜色，也不移除键盘可见焦点。

### 5.3 Rust 文件能力

优先采用成熟 crate：

- `ignore`：执行 gitignore-aware 文件搜索和目录遍历。
- `nucleo-matcher`：执行 Unicode-aware 文件名与相对路径模糊评分；复用 Helix/FZF 类工具验证过的匹配算法，不自研模糊搜索评分器。
- `notify`：监听工作区文件变化。
- `encoding_rs`：处理 BOM 与受支持文本编码。
- `blake3`：在读取文件时生成内容版本，支持并发写冲突判断。
- `infer`：根据文件签名辅助识别图片和其他二进制类型，不能只信任扩展名或前端传入的 MIME。
- `imagesize`：在完整解码前读取图片尺寸，执行像素上限保护。
- `resvg`：将 SVG 安全栅格化后预览，避免把潜在活动内容注入 WebView DOM。

文件读取、搜索、哈希、图片元数据解析、SVG 栅格化和其他阻塞操作必须离开 Tauri 主线程，沿用项目 `spawn_blocking_command`/Tokio 文件 I/O 规范。

### 5.4 行业实践结论

1. 使用 CodeMirror 6 统一文本和代码查看、编辑、撤销、重做及目标行列定位。
2. 文件树按目录懒加载，刷新时保留展开状态，并按工作区保存有限容量的树快照。
3. 所有异步读取和搜索使用请求序号或取消信号丢弃过期响应。
4. 本地文件链接统一支持 Windows 绝对路径、`file:///`、`:line`、`:line:column`、`#Lx` 与 URL 编码。
5. 文本和图片都按文件大小及内容复杂度分级，超过阈值时关闭高成本能力、切换只读或交给系统应用。
6. 编辑采用合并自动保存、串行 latest-wins 队列和 expected revision，不使用手动保存生命周期或时间窗口猜测自身写入。
7. 文件变化使用 Rust `notify` 事件，搜索在 Rust 后台执行并限制结果，不轮询活动文件、不把完整文件树传给前端搜索。
8. 工作区内文件由前端提交 `projectId + locator`，工作区外文件额外提交单路径 access token；Rust 权威解析根目录、规范化路径并判断访问范围，前端不能自行扩大权限。

### 5.5 文件查看格式与能力边界

文件类型必须采用“文件签名/BOM/内容探测优先，扩展名和声明 MIME 辅助”的统一识别器。扩展名列表仅用于选择语言高亮和展示图标，不能作为安全边界，也不能把支持能力实现成散落在组件里的硬编码白名单。

首期支持矩阵：

| 类别 | 保证支持的格式 | 查看能力 | 编辑能力 |
|---|---|---|---|
| 纯文本与文档源文件 | `.txt`、`.md`、`.mdx`、`.rst`、`.log` | CodeMirror 文本查看、查找、行号与自动换行 | 工作区内可编辑；用户显式打开的工作区外文件也可编辑 |
| 常用代码 | Rust、JavaScript/TypeScript、JSX/TSX、Python、Go、Java/Kotlin、C/C++、C#、Swift、PHP、Ruby、Shell、PowerShell、Batch、SQL、GraphQL、Protobuf 等常见源码 | CodeMirror 语法高亮、查找、折叠与行列定位；没有语言包时回退纯文本 | 工作区内可编辑；用户显式打开的工作区外文件也可编辑 |
| 配置与结构化文本 | JSON/JSONC、YAML、TOML、XML、HTML、CSS/SCSS/Less、INI、Properties、CSV/TSV、`.env`、Dockerfile、Makefile、`.gitignore` 等 | 按语言能力高亮；未知但可安全解码的文本回退纯文本 | 工作区内可编辑；用户显式打开的工作区外文件也可编辑 |
| 位图图片 | PNG、JPEG、WebP、GIF、BMP、ICO | 原始比例、适应窗口、缩放、拖拽查看、透明背景提示和基础元数据；GIF 保留动画 | 只读，不提供像素编辑 |
| 矢量图片 | SVG | 默认经 Rust 安全栅格化后预览；可切换“查看源码”进入 CodeMirror | 工作区内可编辑源码；用户显式打开的工作区外 SVG 也可编辑源码 |
| 其他文件 | PDF、Office、音视频、压缩包、字体、数据库、可执行文件及无法安全识别的二进制 | 显示类型、大小和路径，提供“使用系统应用打开” | 不支持 |

文本编码首期保证 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE/BE。其他编码不得进行有损猜测后自动写回；无法可靠解码时返回结构化不支持状态，后续通过显式“选择编码”能力扩展。

图片预览不使用 `file://`，也不向 WebView 暴露任意本地路径。Rust 在完成路径授权、签名识别、字节数和像素数检查后签发与 `projectId + canonicalPath + revision` 绑定的短期 preview token；前端通过受限自定义协议把 token 交给 `<img>`。协议响应必须限制 MIME、禁止嗅探并支持 token 失效。SVG 由 `resvg` 栅格化，不能使用 `dangerouslySetInnerHTML` 或直接挂载原始 SVG DOM。

## 6. 总体架构

```text
会话 Markdown 文件链接 ─┐
                       ├─> FileWorkspaceController
工作区文件树选择 ───────┘          │
                                  ├─> RightWorkspaceResource(file-browser / file)
                                  ├─> FileContentStore
                                  └─> Tauri WorkspaceFileService
                                             │
                                             ├─ 路径解析与权限分类
                                             ├─ 目录懒加载与搜索
                                             ├─ 文件识别、文本读取与版本生成
                                             ├─ 图片预览授权与安全输出
                                             ├─ 版本化自动保存
                                             └─ 文件变化监听与失效通知
```

职责边界：

- `RightWorkspaceState`：资源 scope 只负责 Tab 与激活项；会话 Shell state 负责开关、打开 revision 和运行期宽度投影，不保存文件内容。
- `FileExplorerStore`：负责项目级树快照、展开目录、搜索状态和目录缓存。
- `FileContentStore`：按文件类型统一负责文本内容、CodeMirror 状态、图片 preview token、LRU、保存队列和冲突状态。
- `WorkspaceFileService`：负责路径权威解析、文件 I/O、版本检查、搜索和变化事件。
- Markdown renderer：只识别链接并发出打开意图，不自行读取文件。

## 7. 领域模型

### 7.1 文件资源定位

```ts
type WorkspaceFileScope = "workspace" | "external";

interface WorkspaceFileLocator {
  projectId: string;
  canonicalPath: string;
  relativePath: string | null;
  scope: WorkspaceFileScope;
}

interface ExternalFileAccessGrantVm {
  token: string;
  permissions: Array<"read" | "write">;
  expiresAtMs: string;
}

interface FileTargetLocation {
  line: number | null;      // 1-based
  column: number | null;    // 1-based
  endLine: number | null;
}
```

`scope`、`canonicalPath` 和 `relativePath` 必须由 Rust 解析结果产生，前端不能仅根据字符串前缀自行判断文件是否属于工作区。工作区外文件由用户显式点击本地文件链接时签发 `ExternalFileAccessGrantVm`；token 只绑定该 canonical path 和读写权限，不写入 Tab 资源、持久化存储、日志或 URL。

### 7.2 右侧资源

```ts
type FileBrowserWorkspaceResource = RightWorkspaceResourceBase & {
  kind: "file-browser";
  projectId: string;
};

type FileWorkspaceResource = RightWorkspaceResourceBase & {
  kind: "file";
  projectId: string;
  locator: WorkspaceFileLocator;
  target: FileTargetLocation | null;
};
```

规则：

- `file-browser` 表示尚未选择文件的文件入口 Tab。
- `file` 资源 key 使用 `projectId + canonicalPath` 的稳定、平台感知规范化结果。
- 同一文件点击不同目标行时更新已有资源的 `target` 并激活，不创建重复 Tab。
- Windows 路径 key 比较必须处理盘符与大小写语义，显示路径不得被 key 规范化结果污染。
- 文件 Tab 只保存 locator 和目标位置，不保存内容、树或编辑器对象。
- 工作区外 access grant 只保存在 `FileContentStore`，关闭 Tab 时主动释放；应用异常退出时由后端 TTL 回收。

### 7.3 文件快照与版本

```ts
interface FileRevisionVm {
  byteLength: number;
  modifiedAtNs: string;
  contentHash: string;
}

interface WorkspaceFileSnapshotBaseVm {
  locator: WorkspaceFileLocator;
  name: string;
  revision: FileRevisionVm;
}

interface TextFileSnapshotVm extends WorkspaceFileSnapshotBaseVm {
  kind: "text";
  content: string;
  encoding: string;
  language: string | null;
  lineEnding: "lf" | "crlf" | "mixed";
  editable: boolean;
  limitationCode: string | null;
}

interface ImageFileSnapshotVm extends WorkspaceFileSnapshotBaseVm {
  kind: "image";
  mimeType: string;
  width: number;
  height: number;
  animated: boolean;
  previewGrant: { token: string; expiresAtMs: string };
  sourceEditable: boolean; // SVG 位于工作区内，或外部 access grant 含 write 权限时为 true
}

interface UnsupportedFileSnapshotVm extends WorkspaceFileSnapshotBaseVm {
  kind: "unsupported";
  mimeType: string | null;
  limitationCode: string;
}

type WorkspaceFileSnapshotVm =
  | TextFileSnapshotVm
  | ImageFileSnapshotVm
  | UnsupportedFileSnapshotVm;
```

使用判别联合避免以 `content: null` 同时表达图片、文件过大、编码失败和不支持格式。`contentHash` 在读取内容的同一次数据流中计算，不为哈希额外完整读取一次文件。`previewGrant` 是携带真实 `expiresAtMs`、限定单文件 revision 的读取授权，不是本地路径；文件变化或资源释放后立即失效，前端在到期前轮换。

### 7.4 文件内容生命周期

```ts
type FileSaveState =
  | { kind: "clean" }
  | { kind: "scheduled"; localRevision: number }
  | { kind: "saving"; localRevision: number; operationId: string }
  | { kind: "error"; localRevision: number; errorCode: string }
  | { kind: "conflict"; localRevision: number; diskRevision: FileRevisionVm };

interface TextFileDocumentState {
  kind: "text";
  locator: WorkspaceFileLocator;
  externalAccessGrant: ExternalFileAccessGrantVm | null;
  editorState: EditorState;
  diskRevision: FileRevisionVm;
  localRevision: number;
  saveState: FileSaveState;
  lastTarget: FileTargetLocation | null;
}

interface ImageFilePreviewState {
  kind: "image";
  locator: WorkspaceFileLocator;
  externalAccessGrant: ExternalFileAccessGrantVm | null;
  diskRevision: FileRevisionVm;
  previewGrant: { token: string; expiresAtMs: string };
  zoom: number;
  offset: { x: number; y: number };
}

type FileContentState = TextFileDocumentState | ImageFilePreviewState;
```

文本内容和撤销历史由 CodeMirror `EditorState` 管理，图片只保留轻量预览状态和有期限 token。`FileContentStore` 使用统一的独立 LRU：

- 干净文档和图片预览可按数量和总字节上限淘汰；淘汰图片时必须撤销 preview token。
- `scheduled`、`saving`、`error`、`conflict` 文档不得自动淘汰。
- 关闭文件后可以释放其编辑历史；本期不保证重新打开后继续撤销。
- 删除项目或移除工作区时清理对应文件树和内容缓存，并撤销关联的全部 preview token。

## 8. 用户界面与交互

### 8.1 右侧工作区入口页

右侧工作区没有激活资源时展示轻量入口页：

```text
工作空间
浏览和编辑当前工作区文件

运行目录（仅已发起会话）
浏览当前会话的运行文件
```

入口使用 Lucide 文件夹图标和 shadcn `Button`/可点击行，不使用大面积嵌套卡片，不展示实现方式、性能策略或未来规划文案。

点击后打开稳定的 `file-browser:<projectId>` Tab。

### 8.2 文件浏览布局

未选择文件：

```text
┌──────────────────────────────┬──────────────────┐
│                              │ 筛选文件…        │
│                              ├──────────────────┤
│          打开文件             │ 当前工作区目录树  │
│     从目录树中选择文件         │                  │
│                              │                  │
└──────────────────────────────┴──────────────────┘
```

选择文件：

```text
┌──────────────────────────────┬──────────────────┐
│ 路径 / 文件状态               │ 筛选文件…        │
├──────────────────────────────┼──────────────────┤

│                              │                  │
└──────────────────────────────┴──────────────────┘
```

内部左右分栏继续使用 shadcn `Resizable`，目录树宽度单独记忆，但不进入会话 scope。

### 8.3 文件树交互

- 单击目录：展开或收起；展开时若当前目录只有一个目录子项，则继续加载并展开，直到出现分叉、文件、空目录或安全深度上限。
- 搜索框右侧图标按钮：在紧凑目录和树形目录间切换；紧凑行的上下文菜单只操作链尾目录，中间目录通过树形目录访问。
- 单击文件：在当前文件/运行目录 Tab 内切换详情。
- Enter：打开当前键盘选中文件。
- 左右方向键：按标准树控件语义展开、收起和移动层级。
- `Shift+F10` 或系统上下文菜单键：打开当前节点右键菜单。
- 文件与目录共用紧凑右键菜单，LTR 下优先从点击点向右展开，窗口空间不足时允许 Radix collision adjustment：
  - 复制绝对路径。
  - 复制工作区相对路径。
- 相对路径统一使用 `/`，便于粘贴进对话和代码；绝对路径使用当前平台原生显示格式。Windows canonical path 在 Rust VM 边界和前端剪贴板边界统一移除 `\\?\`，`\\?\UNC\server\share` 转为 `\\server\share`。
- 复制菜单事件不得传播到树的文件激活逻辑，菜单打开及关闭同一帧内禁止 `onActivate`；成功不提示，失败使用绝对定位浮层，不插入树文档流或改变虚拟列表高度。
- 文件树保留可见 focus ring，不依赖 hover 表达可操作性；共享行状态投影和契约测试必须覆盖 idle/hover/selected/focused，禁止恢复 `gold-running` 选中面或 `node.isFocused` 的第二块背景。

### 8.4 文件 Tab

- 文件 Tab 标题显示文件名。
- 正常自动保存期间不显示未保存圆点。
- 短暂 `scheduled/saving` 状态不在消息流或大卡片中展示，最多在文件详情工具区显示低干扰状态。
- 只有 `error` 或 `conflict` 在 Tab 显示 attention 标记，并在编辑器顶部提供可恢复操作。
- 关闭 clean Tab：立即关闭。
- 关闭 scheduled/saving Tab：先冲刷保存队列，保存成功后关闭。
- 保存失败或冲突：保持 Tab 打开，禁止静默丢弃内容。

### 8.5 图片预览

- 图片沿用同一个文件 Tab 和左右分栏，左侧为预览画布，右侧仍是当前工作区文件树。
- 工具区只提供适应窗口、原始尺寸、放大、缩小、重置和使用系统应用打开；不展示与查看无关的说明文案。
- 图片大于视口时支持拖拽平移；缩放和平移状态按文件保存在运行期，关闭或 LRU 淘汰后可释放。
- PNG/WebP/GIF 的透明区域使用跟随主题的棋盘格表达；动画 GIF 默认播放，尊重系统 reduced motion 设置并允许暂停。
- SVG 默认展示安全栅格化结果，并提供“预览 / 源码”切换；工作区内 SVG 和具有 write grant 的工作区外 SVG 源码均可编辑和自动保存。
- 图片变化事件使旧 preview token 失效；若当前正在查看，则取得新 revision 后刷新，失败时保留 Tab 并展示恢复操作。

### 8.6 工作区外文件

- 只在用户显式点击本地文件链接后读取，不在 Markdown 渲染、hover 或预取阶段读取。
- 左侧按识别结果显示文本编辑器或图片预览，并展示不可点击的完整绝对路径。
- 右侧仍显示当前 `projectId` 对应工作区目录树。
- 不提供相对路径复制。
- 安全识别且位于文本大小阈值内的文本、代码、配置文件和 SVG 源码允许编辑，复用同一自动保存、撤销、expected revision 与冲突恢复流程。
- 位图图片保持只读；不支持格式继续提供“使用系统应用打开”。
- access grant 无法续期或已失效时立即暂停自动保存，保持内存内容和 Tab，不得降级成无授权路径写入；用户重新点击原链接授权后才能继续保存。
- 文件不存在、无权限或类型不支持时，仍保留文件 Tab，展示错误码映射后的恢复界面。

## 9. 近实时自动保存与撤销

### 9.1 保存语义

“实时修改”定义为近实时自动保存，而不是每次按键同步阻塞写盘：

1. CodeMirror 每次用户编辑产生本地事务，`localRevision` 递增。
2. 进入 `scheduled`，重置统一的自动保存定时器。
3. 用户停止输入 `autoSaveDelayMs` 后，将当前最新内容加入串行保存队列。
4. 同一文件同一时刻最多一个写请求在途；写入期间产生的新编辑只保留最新 pending revision。
5. 当前写入完成后，如果存在更新的 local revision，立即继续保存最新版本，不回放中间版本。
6. 只有服务端确认成功且返回新 revision 后，文档才进入 `clean`。

初始建议：`autoSaveDelayMs = 300`，最终值由统一配置下发，不在组件中硬编码。

### 9.2 强制冲刷时机

以下场景不等待自动保存延迟：

- `Ctrl/Cmd+S`。
- 编辑器失焦。
- 切换文件 Tab。
- 关闭文件 Tab。
- 收起右侧工作区但文档仍有 scheduled 内容。
- 应用窗口正常关闭。
- 页面 scope 被删除或项目被移除。

应用异常崩溃时仍可能丢失最后一个自动保存延迟窗口内的输入，本期接受最多约 300ms 的风险；不为此引入完整草稿数据库。

### 9.3 撤销与重做

- 撤销/重做完全使用 CodeMirror 原生历史，不自研命令栈。
- `Ctrl/Cmd+Z` 产生新的编辑器状态和 local revision，按同一自动保存流程写回撤销后的内容。
- `Ctrl/Cmd+Shift+Z` 或平台等价快捷键同理。
- 保存成功不清空 CodeMirror 撤销历史。
- 外部文件重新加载时建立新的历史边界，避免用户撤销跨过 Agent/外部程序写入并意外覆盖新内容。
- 文件 Tab 关闭或文档 LRU 淘汰后可释放历史；重新打开从磁盘最新内容开始。

### 9.4 保存失败

- IPC/磁盘写失败：进入 `error`，停止自动重试风暴。
- UI 提供“重试保存”和“重新加载”动作。
- 在错误恢复前继续允许编辑，新的 local revision 替换旧 pending 内容，但不丢失编辑器状态。
- 恢复网络无关；这是本地文件错误，文案必须给出权限、文件消失或磁盘不可用等恢复方向。

## 10. 并发修改与冲突处理

Gold Band 中用户、Agent、MCP/ACP 工具和外部编辑器可能同时修改文件，不能使用最后写入者静默覆盖策略。

### 10.1 乐观并发控制

保存请求必须携带读取时的 `expectedRevision`：

```ts
interface WriteFileResourceInput {
  projectId: string;
  canonicalPath: string;
  externalAccessToken: string | null;
  content: string;
  expectedRevision: FileRevisionVm;
  operationId: string;
  force: boolean;
}
```

默认 `force = false`。Rust 写入前重新校验文件 revision：

- 一致：执行原子写入并返回新 revision。
- 不一致：返回 `workspace-file.changed-on-disk`，不得写入。
- 文件消失：返回 `workspace-file.not-found`。
- 工作区内文件：必须再次验证 canonical path 仍位于项目根目录下。
- 工作区外文件：必须验证 `externalAccessToken` 有效、包含 write 权限且绑定同一 canonical path；缺失、过期或不匹配时返回 `workspace-file.external-access-denied`，不得写入。

`force = true` 只能由用户在冲突界面显式选择“覆盖磁盘版本”后使用，不提供隐式 fallback；工作区外文件即使强制覆盖也不能绕过 access grant 校验。

### 10.2 文件变化事件

Rust 文件服务按项目监听并对事件去抖、合并，前端收到：

```ts
interface WorkspaceFileChangedEvent {
  projectId: string;
  canonicalPath: string;
  kind: "created" | "modified" | "removed" | "renamed";
  revision: FileRevisionVm | null;
  operationId: string | null;
}
```

处理规则：

- 事件 revision 等于当前保存响应 revision，或 operationId 等于自身写入：确认自身保存，不触发重复加载。
- 文档为 clean 且外部 revision 更新：后台读取并无历史地替换内容，建立新的撤销历史边界。
- 文档为 scheduled/saving/error 且外部 revision 更新：进入 conflict，暂停自动保存。
- 文件被删除：保留内存内容，进入错误状态，允许用户复制内容或在工作区内显式重新创建（重新创建不属于本期文件树操作，可在冲突恢复动作中单独设计）。
- watcher 的原始 `kind` 不是目录结构变化的充分条件：原子保存会产生临时文件及目标路径的 `created/removed/renamed` 组合。前端先用 `operationId`、revision 是否存在和当前树路径身份做结构对账；已知且仍存在的路径属于内容替换，未知且重命名后不存在的临时路径直接忽略。只有节点身份确实新增、消失或改名时才失效受影响父目录，不全量重新扫描项目。

## 11. Tauri/Rust 文件服务

### 11.1 模块划分

建议新增独立模块，不把文件系统逻辑继续堆入 `commands_conversation.rs`：

```text
src-tauri/src/workspace_files/
├─ mod.rs
├─ commands.rs
├─ models.rs
├─ paths.rs
├─ reader.rs
├─ preview.rs
├─ writer.rs
├─ search.rs
└─ watcher.rs
```

如目录结构与项目文件数量约束冲突，应按职责合并小文件，但不能把路径解析、写入冲突和 watcher 混成一个巨型命令文件。

### 11.2 命令接口

```text
list_workspace_directory(project_id, relative_path)
search_workspace_files(project_id, query, request_id, limit)
resolve_workspace_file_link(project_id, raw_href)
read_file_resource(project_id, canonical_path, external_access_token)
release_workspace_file_preview(preview_token)
renew_external_file_access(external_access_token)
release_external_file_access(external_access_token)
write_file_resource(input)
start_workspace_file_watch(project_id)
stop_workspace_file_watch(project_id)
```

接口约束：

- 工作区文件树只提交 `projectId + relativePath`。
- `projectId` 必须通过现有 conversation workspace state 解析为权威根目录。
- Markdown 链接解析可以接收原始 href，但最终必须经过 Rust canonicalize 和 scope 分类。
- `resolve_workspace_file_link` 只在用户点击处理链中调用；目标位于工作区外时一并返回绑定单路径的 external access grant。
- `read_file_resource` 返回判别联合：文本返回内容，图片返回受限 preview token，不支持格式返回 limitation code；工作区外读取必须携带匹配的 access token。
- 图片自定义协议只接受后端签发的 token，不接受路径参数；token 到期、文件 revision 变化、Tab 关闭或 LRU 淘汰后失效。
- external access grant 仅在对应 Tab 仍打开时于到期前续期；续期返回轮换后的 token，旧 token 立即失效，关闭 Tab 必须主动 release。
- 前端不能调用通用 fs plugin 绕过领域命令。
- watcher 生命周期由当前打开项目和文件资源引用计数管理；工作区外 access grant 存活期间只监听对应单文件，不为历史项目或已关闭外部文件保留监听器。

### 11.3 路径安全

1. 解析工作区根目录并 canonicalize。
2. 解析目标路径，兼容 Windows 分隔符、盘符、UNC 和 `file:///`。
3. 工作区相对路径禁止绝对路径、空字节和 `..` 越界。
4. 目标 canonical path 与 workspace root 比较，后端产生 `workspace/external` 分类。
5. 目录符号链接不默认递归跟随到工作区外。
6. 外部文件只能通过用户显式点击本地文件链接获得 access grant；读取、写入、监听、刷新和冲突覆盖都必须校验同一个 grant，不允许由树搜索、预加载或普通 workspace 命令访问。
7. grant 绑定 canonical path、权限和到期时间；前端不能扩大路径范围，关闭 Tab 时主动释放，后端对异常退出依靠 TTL 回收。
8. 所有路径错误返回结构化错误码，日志可以记录技术详情，但不得把内部错误字符串、access token 或内部授权状态直接作为 UI 文案。

### 11.4 写入可靠性

- 在目标同目录创建临时文件。
- 保持原文件权限和受支持的 BOM/EOL 语义。
- 写入并 flush 后执行平台安全替换。
- Windows 上不得通过外部 shell、`cmd.exe` 或 `std::process::Command::new()` 完成替换。
- 文件写入不需要外部用户交互，不得启动可见终端。
- 失败时清理临时文件并保留原文件。

## 12. 文件树、搜索与缓存

### 12.1 目录懒加载

- 首次只加载工作区根目录直接子项。
- 展开目录时加载该目录直接子项；若结果仍是唯一目录子项，则继续按依赖顺序加载该子目录，直到目录链结束，不能并行猜测尚未返回的子路径。
- 展开只更新对应目录节点并保持当前滚动锚点；“定位到选中文件”是由文件选择/链接定位建立并消费一次的任务，后续 loading、展开和 watcher 快照变化不能重复滚动到旧文件。
- 目录条目按“目录优先、名称自然排序”返回。
- 后端只返回渲染所需的轻量元数据：name、relativePath、kind、hasChildren、size（文件可选）、modifiedAt（可选）。
- 不在初次打开时递归计算整个工作区大小或文件数量。

### 12.2 项目级树缓存

`FileExplorerStore` 按 projectId 保存：

- 已加载目录与子项。
- expanded paths。
- compact / tree 展示模式。
- 目录树滚动位置。
- 内部左右分栏宽度。
- 最近搜索词仅在当前运行期保存。

建议最多缓存 20～24 个项目，与现有 Conversation Workspace LRU 规模保持一致。写缓存时不得在每次展开/收起时深拷贝整棵大树；采用按目录 map 的规范化存储。

### 12.3 搜索

- 输入 200ms 防抖。
- Rust 使用 `ignore::WalkBuilder` 执行 gitignore-aware 搜索。
- Rust 使用 `nucleo-matcher` 对文件名和相对路径执行不区分大小写、支持 Unicode 规范化的模糊匹配，不搜索文件内容；查询按普通文本处理，不向 UI 暴露匹配语法。
- 排序领域契约依次为：文件名完全匹配、文件名前缀、文件名模糊匹配、仅相对路径模糊匹配；同层按 Nucleo 分数降序、路径深度升序和相对路径自然排序。语义层级使用结构化比较，不通过不可解释的加权魔法数字混合。
- 每次请求携带 requestId；新请求使旧请求结果失效。
- 默认最大返回 500 项，超过时返回 `truncated=true`。遍历期间使用固定容量 Top-K 保留全局最高相关度候选，结果上限不再提前中断遍历，也不受文件系统枚举顺序影响。
- 搜索结果以扁平列表展示，附带相对路径；选择结果后恢复原树展开状态并定位节点。
- `.git` 永远不递归；`node_modules`、`target` 等是否搜索遵循项目 ignore 规则和统一配置，不在组件中硬编码多份排除列表。

## 13. 会话 Markdown 文件链接

### 13.1 支持格式

```text
D:/repo/src/client.rs
D:/repo/src/client.rs:2727
D:/repo/src/client.rs:2727:8
file:///D:/repo/src/client.rs#L2727
/Users/name/repo/src/client.rs#L10-L20
```

会话消息允许工作区相对链接，例如 `src/client.rs:2727`，相对基准为当前 project workspace root。文件详情中的 Markdown 链接额外携带当前文档 canonical path，`LICENSE`、`../LICENSE` 等目标以文档所在目录解析；两类入口最终仍进入同一个 Rust canonicalize、scope 分类和 Tab 定位协议。

### 13.2 Markdown 组件改造

当前 prompt-kit `Markdown` 的 `<a>` 组件统一使用外部链接行为。本期增加本地资源链接协议：

```ts
interface MarkdownResourceLinkHandler {
  openLocalFile(rawHref: string): Promise<void>;
}
```

推荐通过会话级 Context 或稳定 memoized component factory 注入处理器，不能在每次 streaming 更新时创建新的 Markdown components 对象，否则会导致链接、代码块等子树反复卸载。

处理顺序：

1. HTTP/HTTPS/mailto 保持现有外部链接行为。
2. 本地候选链接点击时 `preventDefault`，不设置 `_blank`。
3. 调用 Rust `resolve_workspace_file_link`。
4. 返回 workspace 文件：打开或激活文件 Tab。
5. 返回 external 文件：携带单文件 access grant 打开文件 Tab；文本类按格式能力允许编辑，图片保持只读。
6. 返回 unsupported/not-found：仍创建错误态 Tab，保留路径上下文和恢复操作。

### 13.3 行列定位

- 行列统一使用 1-based 输入。
- 文件加载并创建 CodeMirror view 后执行定位。
- 目标列超过行长度时钳制到行末。
- 目标行超过文件行数时打开文件并返回结构化 adjusted location，前端提示已定位到最后一行，不把整次打开判为失败。
- 再次点击已打开文件的不同位置时更新 `targetRevision`，确保相同 target 重复点击也能重新定位。

## 14. 性能与配置

### 14.1 懒加载边界

- 文件入口、文件树和 CodeMirror 作为独立前端 chunk 动态加载。
- 未打开文件功能时，不加载编辑器语言包、文件树依赖和相关 CSS。
- 只有激活文件 Tab 挂载 CodeMirror DOM；非激活文件保留有限 `EditorState`，不保留 DOM。
- 语言支持按文件类型动态导入。
- CodeMirror 的语言、模式、编辑策略 Compartment 与图片 StateField 配置必须记录已应用 profile；初始化 extension 已包含的 profile 不在挂载 effect 中重复 dispatch，后续只在领域状态真实变化时 reconfigure/update，避免大型 Atomic widget 创建后被冗余 transaction 强制同步测量。

### 14.2 大文件与图片分级

所有阈值由 `configs/app-config.toml` 解析、校验并下发，禁止散落魔法数字。初始建议：

```toml
[workspaceFiles]
autoSaveDelayMs = 300
searchDebounceMs = 200
searchResultLimit = 500
textEditableMaxBytes = 2097152
textHighlightMaxChars = 120000
textReadOnlyMaxBytes = 10485760
imagePreviewMaxBytes = 20971520
imagePreviewMaxPixels = 40000000
contentCacheEntries = 12
contentCacheMaxBytes = 16777216
watchDebounceMs = 150
previewTokenTtlSeconds = 300
externalAccessGrantTtlSeconds = 1800
```

分级策略：

- 文本 `<= textEditableMaxBytes`：允许编辑。
- 超过语法阈值：保留编辑能力，但关闭高亮、折叠和高成本 decoration。
- `textEditableMaxBytes < size <= textReadOnlyMaxBytes`：只读文本查看。
- 文本 `> textReadOnlyMaxBytes`：不读取完整内容，显示“使用系统应用打开”。后续可扩展按行窗口读取。
- 图片同时满足 `imagePreviewMaxBytes` 和 `imagePreviewMaxPixels`：允许预览；任一超限则不送入 WebView 解码，显示元数据与“使用系统应用打开”。
- SVG 在栅格化前同时检查源文件字节数、画布尺寸和渲染预算，超限时不生成预览，但仍可在文本大小阈值允许时查看源码。
- 检测为图片以外的二进制：不进入 CodeMirror，按不支持格式降级。

### 14.3 右侧宽度配置

文件资源需要编辑器和文件树并排，现有固定右栏宽度上限需要升级为配置驱动的资源 profile。建议统一配置：

```toml
[workspaceLayout.rightWorkspace]
minWidth = 288
defaultWidth = 440
maxWidth = 960

[workspaceLayout.rightWorkspace.file]
splitMinWidth = 500
treeDefaultWidth = 280
treeMinWidth = 200
treeMaxWidth = 420
```

文件资源不得请求或写入外层右栏宽度；`rightWorkspace.width` 是所有资源共享的唯一用户偏好。空间不足时沿用现有紧凑 Sheet。自动布局压缩不能覆盖用户最后一次拖动右侧分隔条形成的偏好宽度。窗口不足以容纳完整偏好时，中区保持下限并由右栏连续吸收窗口增减；重新达到偏好后中区恢复为增量 owner。文件区已经跨过配置化 500px 双栏阈值后，左侧导航的恢复门槛必须按 `centerMinWidth + sidebarWidth + file.splitMinWidth + hysteresis` 计算，确保左栏出现不会把右侧重新挤回单栏。缩小时仍使用右栏通用最小宽度判断，保留单栏文件区的正常降级阶段。极窄 Sheet 中允许通过可见按钮在编辑器与目录树之间切换，不能把两栏压缩到不可操作宽度。

连续窗口拖拽采用“面板库管连续几何、React 管离散展示”的边界：Shell 的 ResizeObserver 只调度一个 rAF 计算自动折叠与 canonical owner，左栏、右栏或 owner 跨过各自断点时才发布；连续热路径不得调用 `panel.getSize()`、`panel.resize()` 或通过 `ResizablePanel.onResize` 发布逐像素状态。navigation 始终为像素 owner；窗口不足以容纳完整偏好时 center 为像素、right 为相对，达到偏好后 center 为相对、right 为像素。该切换只依赖 `availableWidth + centerMinWidth + sidebarWidth + rightWorkspace.width`，禁止读取实际 Panel 宽度形成反馈环，也不得动态收紧 `maxSize`。页面/显隐/偏好/owner 离散变化通过 Group `setLayout()` 原子收敛；separator pointer/keyboard 完成后通过 `onLayoutChanged` 保存新偏好。文件面板 ResizeObserver 同样只调度一个 rAF，并在回调帧重新读取最终 `clientWidth`，不能直接使用面板拓扑重组期间的中间尺寸。最终实际宽度写入 ref，仅当 `width >= splitMinWidth` 的结果变化时发布一次 React state。文件响应式 reducer 还必须接收 shell 宽度方向：growing 只允许 compact→split，shrinking 只允许 split→compact；同一次窗口 resize 引发的后续面板回调在 `FILE_WORKSPACE_RESIZE_DIRECTION_HOLD_MS` 内沿用最后方向，settle 后才进入 stationary，使用户直接拖动 separator 可以双向变化。内部目录栏 `onLayoutChanged` 只有 `meta.isUserInteraction` 为 true 时才更新树宽偏好。标签栏只观察 strip 容器并合并到下一动画帧，禁止窗口每变化一个像素就重渲染 FileContent、Atomic/CodeMirror 或 WorkspaceFileTree。

navigation/right Panel 及其 separator 必须始终保留在外层 Group 中；内容可以按展示态挂载，separator 折叠时保持 disabled、透明且不可命中。自动折叠、页面能力变化和偏好 hydrate 都通过同一 Group layout 事务把目标栏设为 0 或偏好宽度，不分别调用 Panel imperative API。不得在宽度断点条件卸载 Panel 或 separator，否则 `react-resizable-panels` 会按旧的双栏或三栏 topology layout 恢复百分比快照。right 进入紧凑模式时外层 Panel 只保留空壳，实际内容仅在 Sheet 挂载，不能重复创建编辑器。

## 15. 错误模型与 i18n

继续复用 `CommandErrorVm { code, params }`，后端不返回对客 msg。建议错误码：

| code | 含义 | 关键 params |
|---|---|---|
| `workspace-file.project-not-found` | 项目不存在或已移除 | `projectId` |
| `workspace-file.path-invalid` | 路径格式无效 | `path` |
| `workspace-file.path-outside-workspace` | 相对路径越界 | `path` |
| `workspace-file.not-found` | 文件不存在 | `path` |
| `workspace-file.not-a-file` | 目标不是普通文件 | `path` |
| `workspace-file.permission-denied` | 文件无访问权限 | `path`, `operation` |
| `workspace-file.format-unsupported` | 文件格式不支持内置查看 | `path`, `mimeType` |
| `workspace-file.encoding-unsupported` | 编码不支持 | `path`, `encoding` |
| `workspace-file.too-large` | 超过读取或编辑阈值 | `path`, `actualBytes`, `limitBytes` |
| `workspace-file.image-dimensions-too-large` | 图片像素数超过安全预览阈值 | `path`, `width`, `height`, `limitPixels` |
| `workspace-file.image-decode-failed` | 图片损坏或无法安全解码 | `path`, `mimeType` |
| `workspace-file.preview-token-invalid` | 图片预览授权失效 | `path`, `reason` |
| `workspace-file.changed-on-disk` | 磁盘版本冲突 | `path`, `expectedRevision`, `actualRevision` |
| `workspace-file.external-access-denied` | 工作区外文件授权缺失、过期或不匹配 | `path`, `operation`, `reason` |
| `workspace-file.read-failed` | 读取失败 | `path` |
| `workspace-file.write-failed` | 写入失败 | `path` |

## 18. 测试方案

### 18.1 Rust 单元测试

路径与安全：

- Windows 盘符、正反斜杠、URL 编码、`file:///`。
- 相对路径、`..` 越界、空路径、非法 UTF-8/空字节边界。
- 工作区内、工作区外、符号链接指向外部。
- external access grant 只能访问绑定路径，不能通过大小写、分隔符、符号链接或 `..` 扩大范围。
- grant 过期、释放、权限不匹配和路径不匹配均拒绝读取、写入与监听。
- Windows 大小写和规范化 key 行为。

目录与搜索：

- 根目录和子目录只返回一层。
- 目录优先与自然排序。
- `.gitignore`、隐藏目录、请求失效与结果上限。
- 文件名完全匹配、前缀、文件名模糊和仅路径模糊的稳定相关度顺序；非连续缩写可命中文件名。
- 结果超过上限时仍从全部有效候选中保留全局 Top-K，低相关度的早期遍历结果不能挤掉后续高相关度文件。
- watcher 创建、修改、删除、重命名事件合并。
- Markdown 自动保存的原子写入事件序列不发起目录请求，树根数组引用、展开状态和滚动位置保持不变；真实新增与删除仍刷新受影响目录。
- 内容修改不发起目录重新加载；创建、删除和重命名才进入父目录结构失效链。

读取与写入：

- UTF-8、BOM、受支持编码、文本/图片/不支持格式识别与大文件分级。
- 图片文件签名与扩展名冲突时以安全探测结果为准。
- PNG/JPEG/WebP/GIF/BMP/ICO 尺寸读取、字节/像素上限和损坏文件处理。
- SVG 只能输出安全栅格化预览，preview token 越权、到期和 revision 变化后均不可读取。
- 读取同时生成 revision。
- expected revision 一致时保存成功并返回新 revision。
- revision 不一致时绝不修改磁盘。
- 临时文件写失败时原文件保持不变。
- 工作区外文本携带有效 write grant 时可以保存并返回新 revision。
- 工作区外写入缺少 grant、grant 过期或路径不匹配时绝不修改磁盘。

## 20. 风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 每次按键直接写盘 | IPC、磁盘和 watcher 风暴 | 300ms 合并、串行 latest-wins 保存 |
| 异步写响应乱序 | 新内容被旧内容覆盖 | 单文件单在途写入 + localRevision 校验 |
| Agent 与用户并发写 | 静默丢失一方修改 | expectedRevision + conflict 状态 |
| watcher 把自身写当外部写 | 重复刷新、清空撤销历史 | operationId/revision 匹配 |
| 原子保存的 `created/removed/renamed` 被误当目录变化 | 每次自动保存都刷新树并破坏滚动锚点 | 结合 operationId、revision 与已有路径身份做结构对账，不按 watcher 原始 kind 直接刷新 |
| 初次递归扫描大仓库 | 打开右栏卡顿 | 目录懒加载，搜索才后台遍历 |
| 前端全量搜索 | IPC 与内存过高 | Rust ignore walker、取消和结果上限 |
| CodeMirror 增加首屏体积 | 会话启动变慢 | 文件功能独立动态 chunk |
| 大文件高亮 | 输入和滚动掉帧 | 配置化阈值、关闭高亮/折叠、只读降级 |
| 图片体积小但解压后像素巨大 | WebView 内存激增或崩溃 | 解码前检查字节与像素双阈值，超限不送入 WebView |
| SVG 包含脚本或外部资源 | 本地数据泄露或 WebView 注入 | Rust `resvg` 栅格化，禁止原始 SVG DOM 注入 |
| 图片预览协议接受路径 | 绕过工作区授权读取任意文件 | 只接受短期 token，并绑定 project、canonical path 与 revision |
| 外部文件链接扩大读写范围 | 本地文件隐私或完整性风险 | 仅在显式点击后签发单路径 grant，禁止预取，所有写入继续执行 revision 校验 |
| external access token 泄露或被复用 | 越权读取、写入其他文件 | token 不持久化、不进日志/URL，绑定 canonical path、权限与 TTL，关闭 Tab 主动释放 |
| singleton renderer/resolver | 文件与工作流资源互相覆盖 | 按 resource kind 的 registry |
| 紧凑宽度强行双栏 | 编辑器和树均不可用 | 按实际容器宽度使用 Sheet/单栏降级，不改写全局右栏偏好 |
| 窗口压缩、实际宽度反馈式交换 owner、独立 Panel 命令或条件重建拓扑 | 重新拉宽后右栏停留在压缩宽度，或页面返回时左栏变 0 | 仅右侧分隔条 intent 可以写偏好；固定 Panel 拓扑，owner 只由 canonical 阈值决定，页面与显隐变化使用 Group `setLayout()` 原子收敛三栏 |
| 连续展开时应用逐帧读取/写回面板尺寸，或把恢复推迟到松手 | 展开比收缩更卡、整页边界横向抖动，或已经越过阈值却迟迟不显示双栏 | 热路径不执行 `getSize/resize/onResize` 像素跟踪，单双栏仅由实际宽度即时决定；离散折叠恢复时才应用偏好宽度 |
