# 2026-09-18 工作空间文件引用到 Composer 设计与实施计划

## 1. 目标与结论

用户在右侧工作空间文件树或搜索结果中右键文件，可以将该文件作为结构化上下文引用到当前对话框 Composer。发送后 Agent 收到 ACP 标准 `ResourceLink`，Gold Band 不复制文件、不读取全文、不把路径拼接进用户正文。

本需求补齐的是文件树领域与 Composer prompt 输入领域之间缺少的显式命令链，而不是重构工作空间或附件模型：

- 保留文件树、`projectId`、canonical path resolver、右 workspace 资源和 prompt-kit Composer 的现有边界。
- 新增轻量 `workspaceFiles` prompt 字段与前端跨面板命令桥。
- 复用 ACP `ResourceLink` 与既有 prompt admission / queue / timeline 生命周期，不新增文件身份、缓存、队列或 watcher。

## 2. 根因与方案边界

### 2.1 现状

- `WorkspaceFileTree` 与搜索结果已使用 shadcn/Radix ContextMenu，但菜单只有复制绝对路径、复制相对路径和在文件管理器中打开。
- Composer 已有 quote、附件、草稿隔离和 prompt submission 生命周期。
- 普通附件链路面向上传快照，会在发送后物化到 `task-inputs` 或 `user-inputs`；这适合用户从系统选择器上传的文件，不适合工作空间内可由 Agent 按路径读取的代码、文档和配置。
- 直接向 textarea 插入路径会破坏结构化语义，用户编辑后无法可靠恢复，也无法做 scope 校验和消息回放。

### 2.2 判断

问题属于“正确设计下的能力缺口”：文件树和 Composer 的分域是必要的，缺少的是一条受控引用命令和结构化 prompt 字段。修复方向不是把两者状态合并，而是新增领域间 DTO。

## 3. 数据与接口设计

### 3.1 前端草稿模型

```ts
interface ComposerWorkspaceFileRef {
  id: string;                 // React key 与删除操作，不提交后端
  projectId: string;
  relativePath: string;
  name: string;
  byteLength: number | null;
  mimeType: string;
  canonicalPath?: string;     // 仅用于当前工作区打开文件，不作为提交身份
}
```

- 去重身份：规范化后的 `projectId + relativePath`。
- 草稿只保存轻量摘要，不保存正文、revision、preview grant 或 `File`。
- 引用与普通附件共享 Composer 上下文数量上限，当前为 10。

### 3.2 Prompt DTO

```ts
interface ConversationPromptInput {
  displayText: string;
  quotes: UserPromptQuote[];
  role?: UserPromptRole | null;
  workspaceFiles: Array<{
    projectId: string;
    relativePath: string;
  }>;
}
```

- 首页创建、会话详情追问、runtime continue、prompt queue 与定时创建入口统一消费该字段。已有会话追问和定时任务继续同一会话必须把该字段投影成 ResourceLink，不能在执行前丢掉。
- 空正文 + 非空 `workspaceFiles` 视为有效 prompt payload。
- 后端按每条引用自己的 `projectId` 解析已注册工作空间。另一工作空间的文件可以引用，ResourceLink 使用该文件的绝对 `file://` 路径；未注册的 project 拒绝。
- prompt queue 的自动 dispatch、手动 use 和 terminal recovery 共用同一个 `QueuedPrompt -> ConversationPromptInput` 投影，不在单条消费路径手写不完整字段。
- 定时任务 create / update 在持久化前校验生效后的引用集合；update 中 `workspaceFiles == null` 沿用当前集合，空数组表示清空，非空数组表示替换。

### 3.3 Rust 运行时解析结果

```rust
struct ResolvedWorkspaceFileRef {
    project_id: String,
    relative_path: String,
    canonical_path: PathBuf,
    name: String,
    mime_type: String,
    size: u64,
}
```

准入与 dispatch 前各解析一次：

1. 根据该引用自己的 `projectId` 在已注册工作空间中取根目录。另一工作空间允许引用，ResourceLink 使用解析后的绝对 `file://` 路径；未注册的 project 拒绝。
2. 拒绝 `..`、根路径、盘符前缀、空路径与非法 UTF-8。
3. canonicalize candidate。
4. 校验 canonical path 仍在同一 workspace root 内。
5. 校验为普通文件，拒绝目录与 symlink escape。
6. metadata 读取文件名、大小与 MIME。
7. 按规范化 locator 去重，并检查引用数加附件数不超过上限。
8. provider 去重使用解析后的 canonical locator；scheduled fingerprint 使用统一 authoring key，先处理分隔符、Windows 大小写、重复项和顺序，再参与哈希。

### 3.4 Provider 投影

每个解析成功的引用生成一个 ACP `ResourceLink`：

```json
{
  "type": "resource_link",
  "name": "WorkspaceFileTree.tsx",
  "uri": "file:///D:/workspaces/demo/web/src/components/workspace/files/WorkspaceFileTree.tsx",
  "mimeType": "text/typescript",
  "size": 18342
}
```

- 不进入 `task_input_attachment_paths` / `user_input_attachment_paths`。
- 不复制到 `authoring/inputs` 或 `user-inputs`。
- Agent capability 缺少 `embeddedContext` 或 `image` 时仍使用 ResourceLink，不展开正文。

## 4. 前端交互与状态边界

- 文件树与搜索结果仅对 `kind=file` 显示“引用到对话”；目录、symlink、other 与只读演示隐藏。
- 点击动作从当前 `WorkspaceDirectoryEntryVm` 生成 `ComposerWorkspaceFileRef`，立即进入当前 Composer 上下文区，不做右键 I/O。
- chip 与 quote / attachment 共用上下文区；文件名为主文案，Tooltip 展示相对路径和大小。
- 点击未发送 chip 打开既有 `file-browser:<projectId>` Tab 并选中文件；删除 chip 不关闭该 Tab。
- 点击 chip 时先用既有工作空间 resolver 取得 canonical locator，再创建 file-browser selected file；resolver 失败在当前位置显示结构化错误，不伪造 canonical path。
- 重复引用去重；宽屏 dock 模式聚焦 Composer，窄屏 Sheet 模式不抢焦点。
- 快速对话切换 workspace 时，旧 project 的文件引用随选择事件移除；正文和普通附件继续遵循既有跨页面草稿保留规则。
- 首页与 ACP Composer 通过 right workspace scope 注册命令；文件树只消费命令，不订阅草稿。
- 命令桥内部使用稳定 callback/ref，注册与注销只影响文件树局部，不重渲染页面壳、历史消息或 Markdown。

## 6. 测试与验收

### 6.1 Rust / 接口

- 合法项目内文件解析成功，返回正确名称、大小、MIME 和 canonical path。
- `..`、绝对路径、盘符前缀、未注册 project、目录、缺失、权限失败、symlink escape 全部返回稳定错误码。已注册的其他工作空间引用解析为绝对 ResourceLink。
- Windows 分隔符、大小写和重复 locator 去重符合预期。
- 引用数 + 附件数超过上限时拒绝或按既有 Composer 契约处理。
- prompt queue 保存并恢复轻量引用；排队后文件缺失时 dispatch 结算结构化失败。
- 队列 DTO 投影保留正文、quote、role、workspace file 和附件路径；纯文件引用自动 dispatch 不再被判为空 prompt。
- 定时任务 create / update 对未注册 project、非法路径、缺失文件和目录在持久化前返回结构化错误；update 的 None / 空 / 非空集合语义固定。继续同一会话时发送完整 `workspaceFiles`，不能只传正文。
- scheduler fingerprint 对引用顺序、重复项、路径分隔符和 Windows 大小写变体保持稳定。

### 6.2 Provider / ACP

- workspace 引用生成 `ResourceLink`，不调用 `resolve_user_input_attachments`，不创建 `user-inputs` 文件。
- Agent capability 缺失时仍投影 ResourceLink。
- Timeline 用户事件保存 `raw.workspaceFiles`，不把路径写入 `display_text`。

### 6.3 前端

- 文件树与搜索结果仅文件条目显示引用动作；目录和只读态不可用。
- 引用进入正确 right workspace scope，切换会话后不串数据；重复引用去重。
- chip 可删除、可打开工作空间文件；删除不关闭文件 Tab。
- 队列恢复后的 chip 只有轻量引用时，点击也必须先 resolver；无 Composer、只读或非文件条目不显示引用 action。
- 队列行展示 workspace file 数量；纯文件引用队列项不显示为空行。
- 首页草稿与 ACP 草稿分别保留引用；发送失败或 admission 前停止时完整回填。
- 添加引用、输入正文、流式更新和历史 Markdown 的渲染边界互不扩大。

### 6.4 UI 验证

- 使用内置浏览器 deep link 验证首页与会话详情。
- 覆盖宽屏 dock、窄屏 Sheet、浅色 / 深色主题、长路径、搜索结果右键和发送后的消息 chip。
- 验证结束后关闭测试页面并清理开发进程。

## 8. 性能与过度设计评审

- 右键添加是 O(1) 内存操作，不发起 I/O；准入与 dispatch 每个引用只做路径 canonicalize 与 metadata 读取。
- 不读取正文、不计算 BLAKE3、不生成 preview grant、不复制文件、不启动 watcher。
- 前端新增状态仅限当前 Composer 草稿的轻量引用数组和 right workspace scope 命令桥；不把草稿提升到页面壳，不复制 canonical state。
- 不新增文件 ID、revision、缓存、队列、并发机制或第二 prompt 状态机；新增 DTO 用于表达“引用”和“上传附件”的真实语义差异，复杂度与需求匹配。
- 定时任务前置校验复用最多 10 个引用的 canonicalize/metadata 读取，不读正文；队列摘要新增 O(1) 数量投影；chip 打开 resolver 只在用户点击时执行一次。
