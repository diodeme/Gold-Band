# 工作流本机模型绑定实施方案（内置与自定义）

## 1. 背景与根因

当前作者态 `WorkflowDsl` 同时保存节点逻辑和本机 Agent、模型、权限配置。内置工作流又会在应用加载时按稳定模板 ID 被新版本定义覆盖，因此系统无法同时满足以下目标：

1. 内置工作流定义随应用升级。
2. 用户本机不存在预设 Agent 时仍能使用内置工作流。
3. 用户配置不被内置模板 upsert 覆盖。
4. 自定义模板、Task、定时任务和 Run 使用一致的数据边界。

这是工作流定义与本机执行资源绑定耦合的设计缺陷，不能通过默认 Agent、运行时 fallback 或放宽内置模板写保护修补。本方案对所有普通 Worker 工作流统一拆分“工作流 DSL”和“本机模型绑定”，AI-DYNAMIC 维持现有运行时统一配置，不进入本方案。

## 2. 目标与非目标

### 2.1 目标

- 所有内置和自定义工作流使用同一套模型绑定规则。
- 内置定义继续由应用维护；用户可以保存完整有效的本机模型配置。
- 自定义模板和 Task 允许保存不完整或失效绑定，但不能启动新 Run。
- 新安装用户不获得硬编码默认 Agent；升级用户继承旧 Worker 配置。
- 模板、Task、定时任务和 Run 具有明确复制与冻结边界。
- 模型、权限和 Agent config options 按最新权威能力严格校验。
- 作者态与运行态复用现有 `WorkflowDsl` 类型，避免重写 runtime。

### 2.2 非目标

- 不改变 AI-DYNAMIC 的 fixed、bootstrap、merge、acceptance 或动态 candidate 配置机制。
- 不为同一模板提供 workspace 级模型配置覆盖。
- 不实现首次运行向导、保存后自动继续运行或启动意图恢复。
- 不实现多窗口编辑冲突合并；Gold Band 当前不存在该产品场景。
- 不在普通工作流导入导出中携带模型绑定。

## 3. 组件与最佳实践评审

本需求核心是领域拆分、迁移和保存状态机，没有可直接替代业务模型的开源组件。前端继续复用：

- shadcn/ui `Tabs`、`Button`、`AlertDialog`、`Select` / `DropdownMenu`。
- 现有 ACP 模型复合选择器和能力目录。
- 现有 `WorkflowEditor` 与 ReactFlow 画布。

实现采用配置定义与环境绑定分离、稳定实体 ID、不可变运行快照、原子写入、结构化错误和派生校验状态等通用实践，不自研基础表单控件。

## 4. 数据归属

### 4.1 作者态 WorkflowDsl

模板和 Task authoring 继续使用现有 `WorkflowDsl` 类型，不新增一套平行的 `WorkflowDefinition` 类型。作者态 Worker 中：

- 保留 `id`、profile、goal、output、success condition、manual check、prompt envelope、edges 和 control 等工作流语义。
- 新增内部持久化字段 `executionSlotId`。
- `provider`、`model`、`permission_mode`、Agent capability config options 保持为空，不再作为作者态权威事实源。

Profile 与 `promptEnvelope` 属于工作流定义，不属于模型配置。

### 4.2 WorkerModelBinding

本机模型绑定只覆盖普通 `worker` 节点：

```ts
interface WorkerModelBinding {
  executionSlotId: string;
  agentId: string;
  modelId?: string;
  permissionModeId?: string;
  configOptions?: Record<string, string>;
}

interface WorkflowModelBindings {
  definitionRevision: string;
  bindingRevision: number;
  bindings: WorkerModelBinding[];
}
```

语义：

- `agentId` 保存具体 `ManagedAgentId`。当前旧 Worker `provider` 就是该 ID 的字符串形式，迁移不按名称或 Catalog 反查。
- `modelId` 为空表示使用 Agent 默认模型，不表示未配置。
- `permissionModeId` 为空表示使用 Agent 默认权限，不表示未配置。
- `configOptions` 保存所有由 Agent capability 声明、用于 session 初始化的显式 option overrides，不硬编码 provider 专用字段。
- 绑定只保存稳定 ID和值，不保存 Agent、模型、权限或 option 的显示名称。
- 模型绑定属于用户级模板配置，跨 workspace 复用；同一模板只有一套绑定。

### 4.3 AI-DYNAMIC 边界

AI-DYNAMIC 及其内部动态节点完全排除：

- 不增加 `executionSlotId` 模型槽位。
- 不进入普通 Worker 配置完成统计和同步范围。
- 不从旧 AI-DYNAMIC 字段迁移 `WorkerModelBinding`。
- 继续使用现有 AUTO / AI-DYNAMIC 运行时统一配置与解析路径。

## 5. executionSlotId

`executionSlotId` 是普通 Worker 的内部稳定身份，与可编辑 `nodeId` 分工：

- `nodeId` 用于 DSL 拓扑和可读引用。
- `executionSlotId` 用于关联模型绑定，不在普通 UI 中展示或编辑。
- 修改 `nodeId` 时保留原 `executionSlotId` 和模型绑定。
- 内置 Worker 使用代码中显式声明且跨版本稳定的固定 ID。
- 自定义 Worker 新建时生成随机 UUID。
- 同一工作流内复制 Worker 时生成新 ID，同时复制完整模型配置；两个节点之后独立修改。
- 另存整个工作流时保留各 Worker 的 ID；新模板 ID提供绑定作用域隔离。
- 真正替换内置节点职责时分配新 ID；删除后的 ID不得复用于其他节点。
- 编辑草稿删除 Worker 时暂时保留绑定以支持撤销，正式保存时清理孤立绑定。

JSON 视图只编辑工作流定义，不包含模型绑定。内部 DSL 可以展示 `executionSlotId`，但已有节点不得随意修改；JSON 中缺失槽位的既有 Worker按相同 nodeId复用当前草稿槽位，真正新增的 Worker只生成一次 UUID。非空重复 ID不自动改写，继续由校验阻断保存并定位节点。

普通导出文件不包含 `executionSlotId`；导入时为每个 Worker重新生成，因此导入结果不会继承来源模板的绑定身份。

## 6. Revision 与时间

- `definitionRevision` 使用规范化工作流逻辑内容的 SHA-256。
- 根据已确认的产品约束，`executionSlotId` 不参与 `definitionRevision`，也不新增独立 binding schema revision。
- 槽位 ID意外变化时，系统按当前 ID直接关联；旧绑定成为孤立数据，新槽位显示未配置。该风险通过内置固定常量、唯一性测试和升级回归测试预防。
- `bindingRevision` 在模型绑定实际保存或迁移时递增，用于标识绑定版本；当前不设计多窗口 CAS 交互。
- 模板继续共用一个 `updatedAt`。定义、模型绑定或迁移实际改写持久化内容时更新；普通启动、读取、重复 upsert 和动态校验不更新时间。

## 7. 动态校验

`configured`、`valid`、`invalid` 等状态不持久化，每次从 Worker、绑定和当前 Agent 能力派生：

```text
unconfigured
valid
agent-unavailable
model-unsupported
permission-unsupported
config-option-unsupported
binding-duplicate
```

校验规则：

1. Worker 必须绑定存在且最近一次 doctor 成功的 Managed Agent。
2. 显式模型必须存在于最新 `supportedModels`。
3. 显式权限必须存在于最新 `supportedModes`。
4. 显式 config option ID和值必须存在于最新 Agent capability 目录。
5. 模型、权限或 config option 选择“不指定”时不要求目录中存在具体默认值。
6. Agent未返回模型或权限目录时，“不指定”仍有效。
7. 旧值失效时保留原始 ID用于展示和修复，不自动清空、替换或传给 Agent试错。

运行前使用现有权威诊断缓存，不为每次运行重复执行 doctor：

- 缓存缺失或因 Agent配置变更失效时触发诊断并在结果可用前阻断新 Run。
- Agent配置变更但 ID不变时，绑定继续关联；新诊断完成后重新校验。
- 诊断明确不可用或暂时无法确认能力时都阻断新 Run，但保留绑定。

## 8. Inspector 与同步

普通 Worker Inspector 拆为：

- **模型配置**：Agent、模型、全部 Agent config option overrides、权限模式、“同步至其他节点”。
- **节点配置**：node id、profile、goal、output、success condition、manual check、prompt envelope。

界面使用三个同级带边界分区，顺序固定为“模型配置 → 工作流控制 → 节点配置”；分区标题旁不显示 `worker` 等实现类型标识。

模型字段变化只更新 Inspector 最小草稿边界，不触发 ReactFlow 拓扑重算。

“同步至其他节点”规则：

- 作用域仅限当前工作流，确认弹窗必须明确展示该限制。
- 只同步其他普通 Worker，不包括 AI-DYNAMIC。
- 默认只填充未配置 Worker。
- 提供“覆盖已配置节点”选项。
- 同步完整 Agent、模型、权限和 config options，不提供拆分同步选项。
- 确认界面展示实际 Agent、模型、显式权限、config options，以及将填充和覆盖的节点数量。
- 同步写入当前编辑草稿；无需逐节点再次打开确认，最终保存时统一校验。
- 后端或领域命令一次生成并提交整份绑定快照，不逐节点持久化。

## 9. 保存规则

### 9.1 内置模板

内置模板只有全部普通 Worker绑定有效时才能点击“保存修改”。部分配置只存在于当前编辑会话：

- 页面内切换节点或管理页 Tab保留草稿。
- 离开页面或切换模板时提示“继续配置 / 放弃修改”。
- 未完成草稿不写入正式绑定，应用重启后不恢复。
- 升级迁移可以保留部分旧绑定；迁移不等价于用户保存。

内置模板状态矩阵：

| 定义变化 | 绑定变化 | 行为 |
| --- | --- | --- |
| 否 | 否 | 无需保存 |
| 否 | 是 | 全部 Worker有效时启用“保存修改” |
| 是 | 否 | 禁用“保存修改”，显示“还原其他修改”和另存入口 |
| 是 | 是 | 禁用“保存修改”，显示“还原其他修改”和另存入口 |

“还原其他修改”恢复全部工作流定义字段和拓扑，保留仍属于系统定义 Worker 的模型配置草稿；草稿新增后又被还原删除的 Worker绑定一并丢弃。

### 9.2 自定义模板

- `保存修改`一次原子保存当前 WorkflowDsl 和整份模型绑定。
- 工作流定义必须合法。
- 模型绑定允许未配置、Agent 不可用、模型失效、权限失效或 option 失效；模板明确标记为不可运行。
- 保存时保留无效原始 ID，不自动清理用户信息。
- 重命名只修改展示名称，保留 template ID、槽位和绑定。

### 9.3 另存为新工作流

- 内置或自定义模板都可以另存当前定义和模型绑定。
- 另存生成新的 template ID 与 workflow ID，结果为 `isBuiltIn=false`，剥离 `optionalEntryStage` 等内置元数据。
- 槽位 ID与模型配置随工作流保留；新 template ID隔离来源模板。
- 自定义结果允许保存不完整或无效绑定，但不能运行。

## 10. 运行阻断与定位

用户尝试运行配置不完整或无效的工作流时：

1. 阻断创建新 Run。
2. deep link 到该工作流编辑页并选中第一个问题 Worker。
3. 在对应模型字段展示普通内联校验错误和修复动作。
4. 不进入首次运行向导，不显示步骤进度，不保留启动意图。
5. 用户保存后自行再次发起运行。

模型配置有效性只统计普通 Worker，不统计 AI-DYNAMIC。

## 11. 模板、Task、定时任务与 Run

生命周期边界：

```text
模板 WorkflowDsl + 模板模型绑定
  -> 创建 Task
Task authoring WorkflowDsl + Task 模型绑定
  -> 创建 Run
注入 provider/model/permission/config_options 的完整 WorkflowDsl snapshot
```

规则：

- 创建 Task时复制模板定义和绑定；之后两者互不回写。
- Task authoring 继续复用 `WorkflowDsl`，Worker执行字段为空，模型配置保存在 Task独立绑定中。
- Task允许保存不完整或失效模型配置，但不能新建 Run。
- 用户可把 Task当前定义和绑定显式另存为模板，不隐式回写来源模板。
- 创建 Run前将 Task绑定注入同一 `WorkflowDsl` 类型，生成完整 `workflow.snapshot.json`。
- Run快照冻结本次 provider、model、permission 和 config options，不受模板或 Task后续修改影响。
- ACP session建立后的模型或权限 override 只属于该 session，不回写 Task或模板绑定。

定时任务在创建或编辑时冻结定义和模型绑定：

- 应用升级不自动切换到最新内置定义。
- 只有用户编辑并保存定时任务时才采用新的选择。
- 未来 occurrence 使用冻结数据生成完整 Run快照。
- 已有 occurrence 和历史 Run保持不变。

冻结快照不复制 Agent环境变量等敏感启动配置，未来启动 Worker仍需对应 Managed Agent存在。Agent被删除后：

- 已持有活动 session 的 Run可以继续当前 session。
- 尚未启动的新 Worker、停止后恢复和未来定时触发无法解析 Agent时进入结构化 `error-blocked`。

## 12. Agent 删除

允许删除仍被绑定引用的 Managed Agent，但必须二次确认并展示受影响的模板、Task和定时任务数量：

- 删除不级联清理绑定。
- 绑定保留原 `ManagedAgentId` 并动态显示“Agent 不可用”。
- 影响统计按实体去重，除普通 Worker 模型绑定外，还必须覆盖历史 Worker `provider`、AI-DYNAMIC 固定/引导/可选 Agent、Direct 定时快照和 AUTO 定时快照，避免向用户漏报受影响对象。
- 内置模板必须修复全部 Worker后才能重新保存。
- 自定义模板和 Task可以继续保存不可运行状态。
- 历史 Run快照不修改，未来执行遵守第 11 节边界。

## 13. 导入导出

- 普通导出只包含可移植工作流定义，不包含模型绑定，也不包含内部 `executionSlotId`。
- 导入时为每个普通 Worker生成新的 `executionSlotId`，所有 Worker进入未配置状态。
- 导入旧格式时忽略并移除旧 `provider/model/permission/config_options`，不把来源机器配置迁入当前用户环境。
- 导入后提示用户已导入定义，需要重新选择本机模型配置。
- Profile ID和 prompt envelope属于定义，继续导出；Profile缺失按定义错误修复。
- 首期不提供“备份定义与本机模型绑定”的另一种导出格式。

## 14. 存量迁移

### 14.1 模板

迁移覆盖所有内置和自定义模板，且必须发生在内置模板 upsert之前：

1. 读取旧 store和迁移版本。
2. 为普通 Worker补充 `executionSlotId`；内置 Worker使用代码固定 ID，自定义 Worker生成并持久化 UUID。
3. 从旧 Worker `provider/model/permission_mode/config_options` 提取绑定。
4. 旧 provider可解析为 ManagedAgentId时直接保存；不可解析或不存在时保留原字符串作为失效引用。
5. 从作者态 Worker删除旧本机执行字段。
6. 原子写入新 schema和迁移版本。
7. 再 upsert新版本内置定义，并按固定槽位保留旧绑定。

内置旧数据不完整时允许迁移部分绑定；新版本新增 Worker保持未配置，删除 Worker的绑定在成功写入后清理。迁移幂等，已有新格式绑定时不覆盖。

### 14.2 Task

- 已有 Task authoring workflow迁移为作者态 `WorkflowDsl + Task模型绑定`。
- 新建 Run只消费迁移后的新结构。
- 单个 Task迁移失败时标记需要修复，不阻断其他 Task和模板。

### 14.3 定时任务

- 已有定时任务迁移为冻结 `WorkflowDsl + 模型绑定`，保留原定义版本和执行选择。
- 单个定时任务迁移失败时标记配置错误并停止后续触发，不能使用半迁移数据运行。

### 14.4 历史数据

- 已有 Run、Round和 occurrence快照保持原格式，不迁移、不改写历史执行证据。
- 可编辑模板、Task和定时任务迁移成功后删除旧字段和旧消费路径，不双写，不在核心 runtime保留长期 fallback。
- 旧格式导入只在导入边界转换一次。

## 15. 运行解析

作者态与运行态复用同一 `WorkflowDsl` 类型：

```text
authoring WorkflowDsl
  + WorkerModelBindings
  + 当前 Agent capability
  -> 完整 executable WorkflowDsl snapshot
```

统一解析器负责：

- 按 `executionSlotId` 找到每个普通 Worker绑定。
- 严格校验 Agent、显式模型、显式权限和全部 config options。
- 将绑定写入现有 Worker `provider/model/permission_mode/config_options` 字段。
- 保持 AI-DYNAMIC 现有配置和解析逻辑不变。
- 返回完整快照或结构化错误，不产生部分 Run。

校验生命周期固定拆分为两层：

- `validate_authoring_workflow` 只校验定义结构、拓扑、可达性、输出契约、profile 形状、AI-DYNAMIC 配置和 control；普通 Worker 的 provider/model/permission/config 属于本机绑定，不作为 authoring definition 的必填字段。`session=continue` 在此阶段只校验目标是实际节点。
- `validate_workflow` 只用于绑定注入后的 executable workflow 与 Run snapshot，严格校验普通 Worker provider/model/permission，并校验 `session=continue` 的 provider capability。
- 模板保存、Task 创建/保存、AI-DYNAMIC 引用定义检查以及 authoring 图投影使用 definition 校验；创建 Run 与快照恢复继续使用 executable 校验。
- Task 可运行性投影依次执行 definition 校验、绑定注入和 executable 校验，保证编辑状态与实际启动边界一致。

## 16. 接口与错误

建议命令边界：

- 内置模板 `保存修改`：只接受当前模板整份 Worker模型绑定；后端重新校验全部普通 Worker，不接受定义写入。
- 自定义模板 `保存修改`：接受当前 WorkflowDsl和整份绑定，一次原子保存。
- `另存为新工作流`：接受定义、整份绑定和名称，一次原子创建。
- Task保存：接受 Task作者态 WorkflowDsl和整份 Task绑定，一次原子保存。
- 批量同步：只修改当前草稿；最终通过上述整份保存接口提交。
- 运行解析：接受完整业务 locator，生成并返回完整 executable WorkflowDsl snapshot。

建议结构化错误码：

| code | params | 语义 |
| --- | --- | --- |
| `workflow-model-binding.agent-required` | `executionSlotId`, `nodeId` | Worker未选择 Agent |
| `workflow-model-binding.agent-unavailable` | `executionSlotId`, `agentId` | Managed Agent不存在或诊断不可用 |
| `workflow-model-binding.model-unsupported` | `executionSlotId`, `agentId`, `modelId` | 显式模型不受支持 |
| `workflow-model-binding.permission-unsupported` | `executionSlotId`, `agentId`, `permissionModeId` | 显式权限不受支持 |
| `workflow-model-binding.option-unsupported` | `executionSlotId`, `agentId`, `optionId`, `value` | 显式 option或值不受支持 |
| `workflow-model-binding.slot-required` | `nodeId` | Worker缺少内部槽位 ID |
| `workflow-model-binding.slot-duplicate` | `executionSlotId`, `nodeIds` | 同一工作流存在重复槽位 ID |
| `workflow-model-binding.slot-not-found` | `executionSlotId` | 绑定引用当前定义不存在的 Worker |
| `workflow-template.readonly-built-in` | `templateId` | 尝试覆盖内置定义 |

后端只返回稳定 code和 params；前端负责中英文文案、字段定位和恢复动作。

## 17. 物理存储实现

物理存储已按父实体生命周期确定并落地：

- 模板：`WorkflowModelBindings` 嵌入每个 `WorkflowTemplate`，与定义一起保存在用户级 `~/.gold-band/context/workflows.json`；模板保存是一次 store 原子替换。
- Task：`TaskAuthoringWorkflow { workflow, modelBindings }` 聚合写入 Task 的 `authoring/workflow.json`；定义与绑定没有双写文件。
- 定时任务：创建或编辑时把同一 `TaskAuthoringWorkflow` 聚合冻结到计划 content snapshot；未来 occurrence 只读取该冻结聚合。
- Run：创建前严格校验 Task/计划绑定并注入普通 Worker，随后只把完整可执行 `WorkflowDsl` 写入 `runs/<run>/workflow.snapshot.json`。

读取边界负责一次性迁移旧格式并规范化 revision；无名称反查、N+1 文件读取或运行时跨目录全量扫描。写操作使用既有原子文件替换或数据库事务，校验失败不会创建部分 Run。

## 18. 性能影响评审

单个工作流普通 Worker按个位数到几十个评审，本次实现无明显性能风险：

- 投影、校验、同步和注入均为 O(n)。
- 绑定按 `executionSlotId` 建立 Map，不按 nodeId或名称反查。
- 使用现有诊断缓存，不在每次输入或运行时重复启动 doctor。
- 模型配置草稿位于 Inspector最小状态边界；Agent 图标由绑定单独投影，绑定变化不重算 ReactFlow拓扑或布局。
- Inspector 分区顺序、容器样式和同步提示只调整静态 DOM 与文案，不新增状态订阅、数据请求或布局计算。
- 同步一次更新草稿、保存一次提交整份快照，不产生 N+1 IPC。
- Store和缓存保持有界；原子写入临界区不包含 Agent诊断、网络调用或 provider执行。
- 空绑定快照保持显式 `bindings: []`，前端入口的边界规范化为 O(1)，不新增请求、扫描、订阅或渲染范围。
- 两层校验不引入跨实体扫描：模板/Task 保存和创建各执行一次 O(nodes + edges) definition 校验；Run 创建执行一次 O(nodes) 绑定注入和一次 O(nodes + edges) executable 校验；可运行性投影按同样顺序执行两次线性遍历，不新增文件 I/O、网络调用、缓存、队列或渲染订阅。
- Agent删除统计保持 O(Task + Schedule)：Task目录和定时定义各扫描一次，损坏项只累加有界 unknown计数；不重试、不缓存、不增加并行队列，也不进入保存、运行或调度触发热路径。

迁移使用有序 Map/排序保证确定性，最坏约为 O(n log n)；显式删除 Agent 时的影响统计会扫描 Task authoring 文件，但不在输入、保存、创建 Run 或调度触发热路径执行。运行与保存临界区不发起 doctor、网络调用或 provider 执行，也未新增无界缓存、队列或大范围 Context 订阅。生产构建通过；Vite 仍报告项目既有的 >500 kB chunk 警告，本功能未新增网络请求或独立重型依赖。当前规模无需额外 benchmark；未来单工作流达到数百 Worker时再用 React Profiler和保存耗时决定是否优化。

## 20. 自动化验收

### 数据与迁移

- 空模型绑定经 Rust 接口序列化后必须保留 `bindings: []`；前端收到历史省略字段 payload 时规范化为空数组，进入工作流修改态不得白屏。
- 新安装内置模板没有默认 Agent绑定。
- 所有内置和自定义模板、已有 Task和定时任务正确迁移。
- 内置模板迁移先于 upsert，部分旧绑定不丢失。
- AI-DYNAMIC 字段不进入 Worker模型绑定迁移。
- 重复迁移不覆盖新格式绑定。
- 重复绑定在迁移、运行注入和 Task保存接口边界均返回结构化错误，且失败不写入 authoring文件。
- 历史 Run和 occurrence快照不改写。
- 可编辑数据保存后不再产生旧 Worker执行字段。

### 身份与编辑

- nodeId改名保留槽位与绑定。
- 复制 Worker生成新槽位并复制完整模型配置。
- 另存保留槽位与配置，但生成新模板和 workflow ID。
- 草稿删除可撤销，正式保存清理孤立绑定。
- 内置固定槽位跨版本稳定且不重复。
- 导出不含绑定和槽位；导入生成新槽位并保持未配置。
- JSON缺失槽位的既有 Worker保持原槽位，新 Worker只生成一次槽位，显式重复槽位不被自动隐藏。

### 校验与保存

- 普通 Worker 的 authoring definition 不包含 provider 时仍可通过定义校验；同一数据未经绑定注入必须被 executable 校验拒绝。
- 默认轻量工作流配置全部 Worker 模型绑定后可成功创建 Task，持久化 authoring workflow 中 `grill` 等 Worker 的 provider/model 仍为空。
- authoring definition 缺少 `$end`、包含不可达节点等结构错误时仍必须被阻断。
- 模型、权限和 config options显式失效时严格阻断运行。
- Agent doctor成功且模型/权限“不指定”时配置有效。
- 内置模板不完整或无效时不能保存。
- 自定义模板和 Task可保存不完整或无效绑定，但不能运行。
- 会话 Run 中编辑或修复 Task 工作流时，前端保存链路必须把编辑器产出的整份模型绑定与 WorkflowDsl 一并传给 Task 原子保存接口。
- 内置四种改动组合符合状态矩阵。
- “还原其他修改”保留仍有归属的模型草稿。
- 自定义定义与绑定任一保存失败时都不产生部分写入。

### 同步与运行

- 同步只处理普通 Worker，默认跳过已配置节点。
- 覆盖同步复制 Agent、模型、显式权限和全部 config options。
- 同步确认展示实际配置和覆盖数量。
- Task创建复制模板绑定，后续互不回写。
- Run快照包含注入后的完整执行字段且不受后续模板/Task修改。
- 删除 Agent后绑定保留失效引用，未来执行按生命周期边界阻断。
- 单个损坏 Task、定时定义或 Workflow快照不影响其他引用计数；unknown数量在删除确认中可见，整体统计成功后仍允许显式删除。

### UI 与性能

- 运行阻断 deep link到第一个问题 Worker，不进入向导或自动续跑。
- 未完成内置草稿离开时确认，应用重启后不恢复。
- 模型字段变化不触发画布布局重算。
- 正常宽度、窄窗口、重新拉宽、键盘、明暗主题均可完成配置和修复。
