# 后台检测重复登录修复验收

## 问题与证据（2026-11-17）

最新版启动后 Cursor 与 Gemini CLI 反复出现登录界面。本机 `.maling/doctor/acp/` 的诊断协议帧显示：Cursor 在 session/new 返回 AuthRequired 后收到 authenticate(cursor_login)，Gemini 收到 authenticate(oauth-personal)。两者的 initialize.authMethods 均未声明 type。脱敏帧摘要保存在工作目录同级 `Gold-Band-integration-review/auth-login-evidence.json`。

根因是迁入的自动认证选择器将非 terminal/env_var 的未知方法视为可自动执行；周期 Doctor 与首次引导、会话创建共享这条路径。周期检测重复执行放大了登录副作用。这属于自动认证能力边界缺陷，不能通过按 Agent 名称禁用、延长轮询或缓存一次失败修复。

## 修复契约与评审

- 自动 authenticate 只选择显式声明 env_var 且全部必填变量已经配置的方法。optional 变量继续允许缺省。
- 未标明类型、agent/browser/terminal 或未知未来类型均不得自动执行；返回已有 provider.auth-required 结构化错误，保留方法 ID 和缺失变量信息。
- 规则在共用认证选择器生效，覆盖周期 Doctor、引导、模型探测和普通会话。既有配置凭据认证、single-flight 及一次 session/new 重试保持不变。
- 不增加依赖、状态、持久字段或 Agent 特例。方法扫描仍为 O(方法数)，减少不必要的认证 RPC 与等待；无新增加载或渲染成本。

## 验收

先增加选择器和 Doctor 协议接口的失败测试：模拟 Cursor、Gemini 无 type 的方法及显式 agent 方法，断言 authenticate 调用次数为零、session/new 只调用一次，最终返回 provider.auth-required。同时复跑已有凭据认证、可选变量、连接复用和并发认证测试。

- 修复前：选择器测试在 cursor_login 上失败；Doctor 接口实际记录 initialize → session/new → authenticate → session/new → session/delete，authenticate 次数为 1，稳定违反预期的 0 次。对应日志为同级审计目录中的 auth-red.log、auth-doctor-red.log。
- 修复后：认证相关测试 69 passed / 1 ignored，覆盖新用例、已有环境凭据认证、optional 变量及共享连接 single-flight；Doctor 相邻测试 23 passed / 1 ignored。日志为 auth-green.log、auth-doctor-direct-green.log。
- 本次 client.rs 的 rustfmt 检查与 git diff --check 通过；全 workspace 格式检查发现并行修改中的 src-tauri/src/main.rs 存在缩进差异，未改写该无关变更。测试使用受控 ACP 子进程，无需打开真实 OAuth 页面，也未修改用户供应商凭据或停止正在运行的客户端。

源代码修复不会自动替换已经运行的已安装客户端，应用端生效需要构建并运行包含修复的版本。此次未重新打包或替换已安装 EXE。
