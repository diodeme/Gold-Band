# 头像系统开发方案与实施记录

## 1. 方案判断

原系统只有会话内硬编码 Bot / User 图标，没有头像领域模型与持久化，因此需求来源于能力模型缺失，而不是单个页面样式不完善。本次建立统一头像偏好、存储和接口，再由设置页与会话详情共同消费，不采用页面 localStorage 或针对消息组件的路径补丁。

复用方案：

- shadcn/ui Avatar、DropdownMenu、Dialog、Button、Slider。
- `react-easy-crop` 负责拖动、缩放和圆形/方形取景框。
- 浏览器原生 file input 打开系统文件选择器。
- 既有 Preferences / Bootstrap 数据流负责跨页面同步。

## 4. 回归边界

- 修改 `PreferencesVm` 时必须保留 `avatars`，浏览器 preview clone 必须深拷贝最近头像。
- 头像文件仅存用户目录，不写入 task/run/session 文件，不随工作空间删除。
- 最近列表裁剪后必须同步清理淘汰图片文件，避免无界增长。
- 新增图片格式时必须同时补前端 accept、裁剪输出策略、后端 MIME 白名单与文件签名校验。
