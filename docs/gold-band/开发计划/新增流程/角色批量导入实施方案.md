# 角色批量导入实施方案

## 目标

让用户能把现成的角色 Markdown 文件批量导入平台，而不必逐个手动填写。用户选择一个文件夹后，客户端递归解析其中所有 `.md`，按宽松兜底策略导入为用户级角色，并以结果报告呈现。

## 设计结论

这是 profile 导入能力缺失导致的功能缺口。复用现有 front matter 解析（`parse_optional_frontmatter_document`）和单角色创建（`create_profile`）能力，不引入新解析库或目录遍历依赖（递归遍历自写，基于 `std::fs::read_dir`）。

数据与生命周期：

- 新增 `ImportProfilesInput`（`folder_path`、`dynamic_template`）、`ImportProfilesResult`、`ImportedProfileRecord`、`ImportRecordStatus`、`ProfileFieldFallback`。
- 导入一律创建 `User` scope 角色，id 由 `next_profile_id` 保证全局唯一，文件名由 `sanitize_profile_name`-id 生成；因此冲突只发生在显示名层面，用自动重命名解决，不会覆盖内置角色。
- 批量导入忽略文件自身声明的 `dynamicTemplate`，统一由导入开关决定；开启时复用 `profile_template_validation_contexts` + `render` 做模板校验，失败则降级为静态并标注。

解析与兜底：

- 用 `parse_optional_frontmatter_document` 取 fields 与 body；front matter 缺失时标 `frontmatter-missing`。
- `name = fields.name ?? fields.title ?? file_stem`；兜底标 `name`，仍空则失败。
- `summary = fields.summary ?? fields.description ?? 正文首段`；兜底标 `summary`，仍空用 name 兜底，确保通过 `ensure_profile_input`。
- 动态模板开关开启且校验失败标 `dynamic-template-downgraded`。
- 空文件或读取失败标记为失败，返回结构化错误码。

接口：

- Tauri 命令 `import_profiles_from_folder`（async + `spawn_blocking_command`），经 app facade 转发到 `profiles::import_profiles_from_folder`。
- 前端三层 API：`RuntimeApi.importProfilesFromFolder`、`desktopApi` 实现、`api.ts` 导出；浏览器预览提供空结果 stub 以满足接口。
- 错误码统一在 `profile.import.*`（`read-failed`、`empty-file`、`folder-not-found`、`folder-not-directory`、`no-markdown-files`），前端按码本地化，后端不拼客案。

## 验收矩阵

| 场景 | 验证 | 预期 |
| --- | --- | --- |
| 完整合规文件 | 导入有 front matter 且含 name+summary 的 md | Imported，无兜底标注 |
| 缺失 front matter | 导入纯 Markdown 文件 | 导入成功，标注 frontmatter-missing/name/summary |
| 缺 name / 缺 summary | 导入缺字段文件 | 分别用文件名 / 正文首段兜底 |
| 外部字段名 | 文件用 title/description | 正确读为 name/summary |
| 同名冲突 | 导入与已有角色同名文件 | 自动改名 -2/-3，不覆盖内置 |
| 动态开关关闭 | 正文含模板语法 | 按静态导入，不校验 |
| 动态开关开启 | 正文为合法模板 | dynamic_template=true |
| 动态开关开启 | 正文含未知变量 | 降级 false 并标注 |
| 空文件 | 导入空 md | 失败，error_code=empty-file |
| 文件夹无效 | 选择不存在/非目录/无 md 文件夹 | 返回 profile.import.* 错误码 |
