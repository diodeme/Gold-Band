# 桌面生命周期与跨平台集成重构

## 1. 目标与根因

本次不是分别修补 macOS Dock、Finder、通知和残留进程，而是修复桌面宿主缺少统一生命周期所有者的问题：窗口关闭曾等同于应用退出，外部进程只按父 PID 管理，通知导航只依赖瞬时事件，文件 reveal 由业务代码拼接平台命令，macOS 发布也缺少可验证的无凭证路径。

统一边界如下：

- Tauri 管理窗口、Dock 重开、官方 opener 和 bundle 签名。
- `DesktopLifecycleCoordinator` 管理关闭窗口、请求退出、清理和最终退出。
- `ManagedProcessGroup` 管理完整外部进程树。
- `PendingInterventionNavigations` 管理通知点击产生的可靠导航事实；Tauri event 只负责唤醒。
- 正常生命周期不使用崩溃恢复 PID/PGID 路径。

## 2. 数据与状态

### 2.1 桌面生命周期

`DesktopLifecycleState` 固定为：

| 状态 | 含义 |
| --- | --- |
| `Running` | 可接受窗口关闭或应用退出请求 |
| `ClosingMainWindow` | macOS 正在销毁主窗口，但应用不退出 |
| `AwaitingFrontend` | 宿主等待前端完成保存事务 |
| `Cleaning` | 后端清理 runtime、诊断进程和待安装更新 |
| `ReadyToExit` | 清理已结束，允许唯一一次宿主退出 |

每个原生退出请求创建唯一 `requestId`。只有当前 `AwaitingFrontend` 的 request 可以被 `resolve_app_exit` 解析；陈旧、重复或不匹配的响应返回结构化错误。

### 2.2 受管进程组

`ManagedProcessGroup` 独占 `command_group::GroupChild`、标准输入输出句柄和注册表 identity：

- Windows：Job Object + `CREATE_NO_WINDOW`，终止和等待覆盖 Job 中的后代。
- macOS/Linux：独立 PGID，正常终止先发 SIGTERM，统一宽限期后 SIGKILL。
- `Drop`、超时、解析失败和提前返回都终止并回收 group。
- 全局 live group 注册表只服务应用清理超时后的紧急终止。
- `recover_persisted_process_group` 只处理上次崩溃留下的持久化 PID/PGID。

### 2.3 待导航队列

队列元素为完整 `ViewActionPayload`，按 FIFO 保存并按 `dedupKey` 去重。生产者先入队再恢复窗口；消费者通过 `take_pending_intervention_navigations()` 一次性 drain，因此窗口构建与前端监听注册的先后顺序不会丢失业务事实。

## 3. 接口

| 接口 | 方向 | 契约 |
| --- | --- | --- |
| `complete_main_window_close()` | Web → Rust | 保存完成后关闭主窗口；macOS 仅销毁窗口，Windows/Linux 开始退出清理 |
| `resolve_app_exit({ requestId, decision })` | Web → Rust | `Proceed` 开始清理，`Cancel` 返回 Running |
| `gold-band://app-exit-requested` | Rust → Web | 请求同一个保存事务处理原生退出 |
| `take_pending_intervention_navigations()` | Web → Rust | 原子取出全部待导航 payload |
| `gold-band://intervention-navigate` | Rust → Web | 仅表示队列中可能有新数据 |

错误继续使用 `{ code, params }`，Rust 不返回对客文案。

## 4. 窗口与退出流程

### macOS 红色关闭

1. Web 拦截 close-requested 并冲刷 `FileContentStore` 全部保存队列。
2. 保存失败继续使用重试、取消、放弃三种决策。
3. 允许关闭后调用 `complete_main_window_close()`。
4. Rust 销毁 `main`，状态回到 `Running`；runtime、ACP/MCP 和 Dock 应用继续运行。

### Dock 重开与通知唤醒

`RunEvent::Reopen` 与通知导航共用 `ensure_main_window()`。存在 `main` 时 show/unminimize/focus；不存在时使用 `WebviewWindowBuilder::from_config` 读取权威窗口配置重建。新窗口仍由现有 bootstrap 完成主题、窗口约束和首帧显示。

### 真正退出

Cmd+Q、系统菜单、Windows/Linux 最后窗口关闭和 updater 退出统一进入协调器。窗口存在时先发退出请求，前端异常或 15 秒未响应则取消退出。窗口不存在时直接清理。后端清理总上限为 `APP_EXIT_CLEANUP_TIMEOUT = 15s`；超时记录结构化 warning，终止全部受管进程组后进入 `ReadyToExit`，只调用一次 `app.exit(0)`。

## 5. 跨平台集成

### Finder / 文件管理器

工作空间和会话运行目录都先在 Rust 中解析 root、canonicalize 并校验授权，再调用 `tauri_plugin_opener::OpenerExt::reveal_item_in_dir`。删除 Explorer 参数拼接与 `xdg-open` 分支。

### 系统通知

Windows 保留 `tauri-winrt-notification` 的 Toast、AUMID、按钮和展示策略；正文点击和 View 按钮改走待导航队列。macOS/Linux 继续使用 `notify-rust 4.18`，后台等待 typed `NotificationResponse`：`Default` 和 `Action("view")` 入队并恢复窗口，其他 action、reply 和 closed 只清 dedup。

### macOS 发布

- `tauri.conf.json` 默认 `bundle.macOS.signingIdentity = "-"`，由 bundler 完成 ad-hoc 签名。
- release-please 与手动 fallback 继续各自产出 arm64/x64 DMG，不增加 workflow、产品分支和文件名后缀。
- 凭证全空时只导出 `APPLE_SIGNING_IDENTITY=-`；凭证部分存在时失败；完整时将证书、密码、Developer ID identity、Apple ID、app-specific password、Team ID 交给同一个 `tauri-action`。
- 构建后执行 `codesign --verify --deep --strict`；不编写自行递归签名脚本，不执行未公证包必然失败的 `spctl --assess`。
- 下载页、安装器和应用内不增加未签名/未公证提示。

## 6. 迁移范围

- ACP adapter/connection。
- MCP stdio health check 与 tools/list。
- Agent doctor（通过 ACP connection）。
- 登录 Shell PATH 探测。
- 工作空间与会话目录 reveal。
- Windows Toast 和 macOS/Linux notify-rust 点击导航。
- 两份 macOS release workflow。

正常运行路径已删除分散的 `child.kill()`、`taskkill` 和手写 Unix PID kill；唯一保留的 taskkill/PGID 逻辑位于崩溃恢复适配器。

## 7. 验收

- 进程组：子进程创建孙进程并继承管道，TERM 宽限期后 KILL，组退出且 stdout/stderr EOF；Windows 启动标志保持隐藏控制台。
- 生命周期：macOS 红色关闭不清 runtime；Dock 可显示或重建；退出握手可取消；清理只执行一次；Windows/Linux 关闭仍退出。
- 通知：默认点击/View 均导航；窗口销毁后恢复；监听注册竞态不丢失、不重复。
- reveal：仅授权 canonical path 进入 opener，业务代码无 Explorer/xdg-open 分支。
- 发布：两架构 DMG；无凭证严格 codesign 验证；部分凭证失败；完整凭证仍走同一步骤；产物名不变。
- 自动化：`cargo test --workspace`、`npm run web:test`、`npm run web:build`、macOS 签名脚本测试和 release/channel 配置测试。
- 真机：macOS 红色关闭、Dock 重开、Finder reveal、通知点击、无凭证 DMG Gatekeeper 首次流程与 codesign 验证。
