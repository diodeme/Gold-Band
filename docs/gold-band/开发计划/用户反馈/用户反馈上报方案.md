# 用户反馈上报实现方案

## 1. 范围与设计判断

本期只实现主动反馈。问题根因不是单个路径校验遗漏，而是旧接口把前端文件系统路径当成可信数据，并把完整任务 ZIP 放入内存；因此采用破坏式接口替换，不保留 `sessionWorkspace`、`screenshotPaths` 或旧渠道字符串判断的兼容层。

复用成熟组件：

- UI：shadcn/ui 与现有附件 copy-in 组件。
- 文件遍历：`walkdir`。
- 临时归档：`tempfile` + `zip`。
- 图片安全解码与重编码：`image`。
- 流式 multipart：reqwest `stream` + `tokio-util::io::ReaderStream`。
- workspace 解析：现有 `workspace_entry_for_project` / `app_for_workspace`。

实现顺序遵循：先确定 `FeedbackInput`、`ArchivePlan`、截图规范化结果和错误码，再定义 Tauri/Runtime API，最后补上传实现与 UI。

## 2. 数据结构

```rust
FeedbackInput {
    description: String,
    project_id: Option<String>,
    task_id: Option<String>,
    screenshots: Vec<FeedbackScreenshotInput>,
    include_logs: bool,
}

FeedbackScreenshotInput {
    name: String,
    mime: String,
    size: u64,
    data_base64: String,
}
```

内部结构：

- `ArchivePlan`：canonical task root、文件清单、ZIP 相对名、未压缩字节数、文件数、是否在策略内。
- `PreparedArchive`：持有 `NamedTempFile` 直到 HTTP 完成，并记录压缩大小。
- `PreparedScreenshot`：只包含规范化 PNG 文件名和字节。
- `FeedbackArchivePreview`：`uncompressedBytes`、`fileCount`、`withinLimits` 及对应上限。

## 3. 后端流程

### 3.1 能力与基础校验

1. `current_channel_config().feedback_enabled` 为 false 时返回 `feedback.disabled`。
2. 描述 1–2000 字符，截图最多 4 张。
3. `projectId/taskId` 同时有值或同时为空。
4. `taskId` 只允许单一普通路径组件。

### 3.2 截图

1. 限制 base64 文本长度，解码并核对声明大小。
2. `image::guess_format` 只接受 PNG/JPEG/WebP，且必须与 MIME 一致。
3. 设置最大 8192×8192 与 128 MiB 解码分配限制。
4. 重编码为 PNG，输出仍须 ≤5 MiB。

### 3.3 会话归档

1. 从全局 state 用 `projectId` 解析 workspace，不接收 workspace path。
2. 验证 task 目录和 `task.json` 存在。
3. canonicalize `tasks_dir`、task root 和每个文件；任何越界均拒绝。
4. `WalkDir::follow_links(false)`，跳过 symlink。
5. 预览与提交使用相同 `ArchivePolicy`：100 MiB 未压缩、20 MiB 压缩、5000 文件。
6. `spawn_blocking` 内以 `std::io::copy` 写入 `NamedTempFile`，不构造 `Vec<u8>` ZIP。
7. 写 ZIP 前重新核对 canonical path 与文件长度，降低预览到提交之间的 TOCTOU 风险。

### 3.4 上传

1. 日志通过 seek 只读取尾部 512 KiB。
2. metadata 与 description 始终作为 text part。
3. 临时 ZIP 用 `tokio::fs::File + ReaderStream` 进入 multipart。
4. 计算有效载荷总量，超过 30 MiB 返回 `feedback.payload-too-large`。
5. reqwest client 使用 10 秒连接超时与 60 秒总超时。
6. 网络原始错误写 `metrics.log`；command 只返回结构化 code/params。

## 4. 渠道能力链路

1. `configs/channels/default.json`: `feedbackEnabled=false`。
2. `configs/channels/wb.json`: `feedbackEnabled=true`。
3. `src-tauri/build.rs` 输出 `GOLD_BAND_FEEDBACK_ENABLED`。
4. `DesktopChannelConfig.feedback_enabled` → `AppInfoVm.feedbackEnabled`。
5. `App → Shell → ConversationShell/WorkbenchShell → AppTitleBar` 只透传 boolean。
6. AppTitleBar 用事件回调关闭菜单，并在下一 animation frame 打开 Dialog，不用 state+effect 模拟用户事件。

---

## 5. 前端截图链路

`useAttachmentPicker` 增加：

- `maxFileSize` 与精确 MIME allowlist。
- `resolveAttachmentInputs()`：只把持有 `File` 的项序列化为 `{name,mime,size,dataBase64}`；path-only 项直接失败。

FeedbackDialog 点击附件区只触发隐藏的 HTML file input；拖放与粘贴同样产生 `File`。反馈不调用通用 Tauri picker，也不把截图 materialize 到磁盘路径。

关联会话选项保存 `projectId/taskId`。preview 返回 `withinLimits=false` 时展示本地化超限信息并禁用提交。

## 6. 错误码

- `feedback.disabled`
- `feedback.endpoint-unconfigured`
- `feedback.validation-failed`
- `feedback.session-not-found`
- `feedback.attachment-invalid`
- `feedback.payload-too-large`
- `feedback.network-failed`
- `feedback.server-error`

前端只按 code 映射文案；后端不返回 reqwest 原始 message。

## 7. 回归测试

Rust 接口/领域测试覆盖：

- 渠道能力拒绝。
- 描述、会话组合、绝对路径与 `..` task id。
- 未知 task。
- PNG/JPEG/WebP 识别、PNG 规范化、无效/伪造 MIME。
- symlink 不进入归档。
- 未压缩大小、压缩大小、文件数策略。
- multipart 固定字段名与 description 常驻。
- 日志尾部大小和 UTF-8。
- ACP 不支持 MCP transport 的 accepted/skipped 结构与 diagnostic data。
- stale config option 的纯函数规范化和输入不变性。

前端要求通过全量 Vitest、TypeScript production build，并启动 wb 前端验证：帮助入口、文件选择/拖放/粘贴、会话预览、超限禁用、错误状态和成功状态。
