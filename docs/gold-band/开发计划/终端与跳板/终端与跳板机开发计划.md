# Gold Band 终端与跳板机功能开发计划

## 1. 目标与范围

在 Gold Band 桌面客户端内新增受管「连接 / 终端」能力：用户维护**用户级全局**的服务器连接配置（仅限**测试环境**），从应用内打开**本地工作目录终端**或**远程 SSH 终端**（目标机可**直连**，也可**经跳板网关转发**），用于登录测试服务器、查看日志与执行排障命令。

产品心智同步修订为：**Gold Band 不是通用终端模拟器；它在任务编排 / 会话等主路径不使用 command bar / slash command / chat input 心智，但提供受管、独立的「连接 / 终端」模块，用于受控的测试环境远程接入**。旧文档中「不是终端模拟器」等绝对表述需要在本能力边界内显式改写（见第 9 节同步清单）。

完整产品设计见 `docs/gold-band/产品设计文档/interaction/app/terminal-and-connections.md`。

### M1 范围（做）

1. 连接配置 CRUD（用户级全局；稳定 ID、环境标签、可选跳板引用）。
2. 本地终端：完整交互 shell，默认落在当前 workspace 根目录，可自由 `cd` / 另开任意目录。
3. 远程终端：目标机直连 + 经跳板网关转发。
4. 多会话标签页并发（上限 4–8 个）。
5. 最近连接历史（纯元数据：主机 / 账号 / 时间 / 环境）。
6. 认证：SSH 密钥 + 口令；口令 / 密钥口令可选择性存入系统钥匙串自动喂入；OTP / 键盘交互动态口令由用户连接时实时输入。

### M1 暂不做（明确排除）

- Agent（ACP）远程执行 / 自动上服务器排障。
- SFTP / 文件浏览 / 文件下载。
- 受管 log-tail 面板、输出过滤高亮等便利层。
- 连接配置团队共享 / 导入导出。
- 生产环境连接（范围外）；连接必填「环境」标签，生产红标展示。
- 会话持久化 / 断线重连恢复 shell 状态（会话瞬态）。
- 主机指纹人工确认 UI。
- 指纹变更弹窗以外的增强信任管理。

## 3. 现状摸查结论（本计划的设计基线）

- **后端**：Tauri v2（Rust edition 2024），单主窗口。子进程统一由 `src/process.rs` 的 `background_command` + `ManagedProcessGroup` 管理（Windows 统一 `CREATE_NO_WINDOW` + Job Object），当前**不存在任何 SSH / PTY / 交互终端代码**。前后端流式目前是 event-emit + jsonl 查询 + 自定义 URI 协议。新受管实体沿用 JSON 原子写（`AtomicWriteFile`）+ `with_file_lock` + 结构化错误 `{ code, params }` 的既有模式，身份沿用现有稳定 identity / 文件锁规范。
- **前端**：React 19 单窗口、无路由库、基于 pathname 的自定义路由；会话模式是当前主路径。右侧工作区已有通用资源 Tab（`RightWorkspaceResource`）与面板注册机制。`package.json` **没有** xterm / ssh / pty 依赖；`src-tauri/Cargo.toml` **没有** russh / ssh2 / portable-pty。
- **产品约束**：产品文档多处出现「不是终端模拟器」「避免终端心智」「源码管理不把终端命令暴露给用户」等绝对化表述，需在本能力的边界声明中修订，避免与既有任务编排心智冲突。
- **内部跳板机**：内网跳板机基于 WindTerm 二次开发，存在非标准握手 / 认证协议的可能，**不可默认假设为标准 SSH 网关**。

## 5. 关键风险与前置 Spike（阶段 0）

### 风险清单

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| WindTerm 二次开发网关为非标协议，标准 SSH 客户端连不上 | 跳板段功能不可用，波及「经跳板连目标机」核心路径 | 阶段 0 spike 先行验证；跳板段做成传输适配器抽象，非标时改接公司 CLI / 客户端 |
| 测试服务器认证形态未知（静态口令 / 密钥 / OTP / 域账号） | russh 认证流程设计与凭据存储方案不稳 | 设计已按口令 + 密钥 + OTP 实时输入支持；spike 阶段用真实网关账号确认实际认证流 |
| Windows/macOS 双端 PTY 行为差异（ConPTY vs forkpty） | 本地终端在某一平台不可用 | pty 层按平台隔离封装，先 Windows 后 macOS，两侧分别验收 |
| 终端字节流吞吐（如 `tail -f` 高流量日志）压垮 WebView / IPC | 前端卡顿、会话假死 | 后端分块 + 背压，前端按帧合并渲染；会话上限 4–8；性能边界见第 8 节 |

### 阶段 0：WindTerm 跳板网关协议验证（1–2 天）

目标：确认内网跳板网关是否接受**标准 SSH 客户端**登录与转发，明确实际认证流，作为阶段 C/D 技术路线开关。

步骤：

1. 由运维/网关负责人提供一个**测试网关账号**与允许登录的目标测试机（或仅网关可达验证即可）。
2. 使用 `ssh` / 自写最小 russh 客户端分别验证：
   - 网关 22 端口是否标准 SSH banner；
   - 口令 / 密钥 / 键盘交互（OTP）哪一种认证能成功；
   - 登录后能否 `direct-tcpip` 转发到目标测试机 22 并嵌套 SSH 成功。
3. 若标准 SSH 不可用：确认公司是否提供**可程序化调用的 CLI / helper**（WindTerm 定制客户端命令行模式等），并验证其调用形态（参数 / stdin / 输出 / 退出码）。
4. 输出结论：跳板段采用「标准 SSH 网关」还是「公司 CLI 适配器」，并更新本文档阶段 D 的路线与风险表。

验收：spike 报告记录网关 banner、认证流、嵌套转发结果（或 CLI 调用样例），并给出阶段 D 的明确选型结论。无法连通的环节如实记录，不把「能打开定制客户端」冒充为「标准 SSH 可用」。

## 6. 分阶段实现顺序与验收

> 每个阶段遵循仓库 Bug 修复 / 开发验证规则：先定数据结构与接口、再补实现；先写最小接口失败测试固定契约，再实现使其转绿；实现后同步维护产品设计文档与本计划。

### 阶段 A：后端连接实体与凭据管理

1. 定义 `ServerConnection` 数据结构与持久化：稳定 ID、name、host、port、username、auth 类型（key / password）、密钥引用或凭据引用、可选跳板连接引用、环境标签（test / stage / prod）、展示字段（禁止用名称作身份）。
2. 用户级存储：`.gold-band/` 下独立 JSON 文件，沿用原子写 + 文件锁 + schema 版本化迁移；列表/详情接口分开，避免大字段进列表。
3. 凭据管理：口令 / 密钥口令进系统钥匙串，连接引用凭据 ID；配置 JSON 只存非敏感元数据与凭据引用；删除连接时同步删除对应凭据。
4. 结构化错误码（草案见第 7 节），后端只返回 `code + params`，前端做本地化文案。
5. 环境与范围约束：连接创建/编辑必填环境标签；MVP 不阻断非 test 标签，但 UI 对非 test 红标提示；代码与文档明确「生产连接不在能力范围内」。
6. 接口测试固定：CRUD 原子性、文件锁并发、损坏单条隔离、凭据读写分离、schema 迁移、结构化错误返回。

### 阶段 B：本地终端

1. 后端：`portable-pty` 封装本地 shell 子进程（Windows ConPTY / Unix forkpty），与既有 `background_command` 的非交互约束分界（交互终端是本模块的显式例外，但不得弹独立控制台窗口）。
2. 前后端流式通道：采用可承载二进制/非 UTF-8 字节的分块通道 + 背压（通道选型见设计文档技术章节，结合 spike / 核验结论定案）；后端按分块转发 pty 输出，前端按键/粘贴上行。
3. 前端：xterm.js 渲染 + fit 插件；粘贴、复制、UTF-8 与宽字符、窗口 resize（pty 尺寸同步）、退格 / 信号键正常。
4. 目录：本地会话默认落在当前 workspace 根目录；「新本地会话」支持另选任意目录；会话进程生命周期与标签页生命周期绑定（关标签即终止进程组）。
5. 验收：Win / mac 双端分别最小交互测试 + 接口层回归（pty 读写、resize、进程终止、编码边界）。
6. **已实现（2026-09-02）**：pty 用 `portable-pty`（本地 shell 子进程，Windows ConPTY / Unix forkpty，`set_controlling_tty` + `setsid` 进程组）；流式走 `app.emit` 事件（`gold-band://terminal-output` / `terminal-exited`，payload 用 `#[serde(tag="event")]` 的 `TerminalEvent`，输出 base64 分块、输入 base64 解码上行，背压来自 pty reader 阻塞）；xterm.js + FitAddon 渲染，resize 经 `resize_terminal` 同步 pty 尺寸，关标签即 `close` 终止进程组；本地会话 `openLocalTerminal` 默认落在 workspace 根目录。接口层回归见单元测试 `terminal_sessions`（`open_local_spawns_shell_and_streams_echo_output` 真实 spawn shell 断言 pty 回显、`session_limit_is_enforced`、`write_to_unknown_session_is_not_found`、`open_local_rejects_missing_cwd`）与前端 `connections-terminal.test.ts`。真实双端交互实测归入阶段 F。
7. **修复（2026-09-03）**：新建终端时 xterm 崩溃（`undefined is not an object (evaluating 'this._renderer.value.dimensions')`），并导致无法输入。两条根因（StrictMode 开发态 mount→unmount→remount）：
   - **写过期订阅**：`TerminalView` 的 `subscribeTerminalEvents(...).then(...)` 在首次 unmount 后才 resolve，旧监听未注册成 `unlisten` 而泄漏，随后向已 `dispose` 的终端 `write` 输出 → 触发 xterm `_renderer.value` 空。修复：回调与 `.then` 加 `disposed` 守卫、反解后立即 `fn()` 取消、ResizeObserver 回调守卫。
   - **xterm 内部延迟 timer（主因）**：xterm `Viewport` 构造时 `setTimeout(() => this.syncScrollArea())`，而 `syncScrollArea` 读**无守卫**的 `_renderer.value.dimensions`（`@xterm/xterm/src/browser/Viewport.ts:84/156`）。当终端在首次挂载的同一 tick 被 dispose（StrictMode），该 timer 稍后对着已清空的 renderer 触发 → 崩溃。修复：`TerminalView` 把 `term.dispose()` **延迟到当前 macrotask 之后**（`setTimeout(0)`），由于 Viewport 的 timer 在 `open()` 中先入队，它先于延迟 dispose 触发（终端仍存活）→ 不再命中已清空 renderer。
   - 回归：`web/tests/terminal-view-lifecycle.test.tsx` 覆盖写订阅竞态（修复前 `writesAfterDispose=1` 红、后 `0` 绿）。xterm 内部 timer 竞态因 jsdom 无 canvas 无法自动复现，依源码证据与运行日志（崩溃聚集于 StrictMode 下终端创建）定位，需真机刷新复测复核。
   - **输入排查（2026-09-03 15:50 后，真正根因）**：用后端日志（sink 事件 + `write_terminal_input` 调用）逐段验证：`open_local` spawn 出 `/bin/zsh` 且 shell 交互并回显（日志出现 output 事件）、前端 `term.onData→writeTerminalInput` 确有调用（日志见 `write_terminal_input invoked`）、shell 对输入产生回显（写入后立即出现 output 事件）——**整条链路后端与前端接线都通**，唯独前端 xterm 不渲染。定位到真正根因：`TerminalEvent` 用 `#[serde(tag="event", rename_all="camelCase")]` **只重命名枚举变体名，不重命名 struct 变体字段**，导致事件 payload 里是 `session_id`（下划线），前端读 `event.sessionId`（camelCase）永远 `undefined`，`sessionId !== sessionId` 过滤恒真 → 输出从不写入 xterm（黑屏、无提示符）；输入因走 `invokeCommand` 不受影响。**修复**：枚举加 `rename_all_fields = "camelCase"`，使 payload 输出 `sessionId`/`exitCode`。回归测试 `terminal_sessions::tests::terminal_event_payload_uses_camel_case_fields`（用 serde 序列化断言 `sessionId` 存在、`session_id` 不存在）。该前端过滤问题此前在单元测试中未暴露（测试数据手写 camelCase，未过真 serde 序列化）。

### 阶段 C：远程直连 SSH 会话

1. 后端：`russh` 连接目标机（直连，无跳板）；支持口令（从钥匙串或本次输入）、密钥（含 passphrase 走钥匙串）、host-key 校验策略（沿用设计决策：首次静默接受并按主机记录，复用遇不匹配返回结构化错误，不做 UI 确认）。
2. 认证流程：支持 OTP / 键盘交互，连接中需要动态口令时后端发出「等待用户输入」事件，前端会话内提示输入一次，不落盘。
3. 远程 pty 请求、shell 启动、窗口尺寸变化、字节流与本地终端同一套 xterm 渲染。
4. 会话生命周期：关标签即断开；连接失败 / 中途断开给出结构化错误与明确文案。
5. 验收：接口测试固定认证成功/失败、键盘交互、host-key 记录与不匹配、断开清理、错误码。
6. **已实现（2026-09-03）**：后端 `russh` 直连（`SshSessionManager`，独立 tokio `Runtime`，与本地会话共用全局 4–8 会话上限与事件 sink）；认证支持口令 / 密钥（passphrase 走钥匙串）并回退键盘交互（OTP，`AuthPrompt` 事件 + `provide_terminal_auth` 一次性回传，不落盘）；host-key 复用受管 `KnownHostsStore`（首次记录、复用不匹配返回 `terminal.host-key-mismatch`）；远程 pty 请求 / shell 启动 / 窗口尺寸同步（`resize`）与本地会话共用 xterm.js 渲染与 `write` 字节流；断开 / 连接失败给出结构化错误（`Failed` 事件 + 错误码）。命令面：`open_remote_terminal`（经 `resolve_ssh_request` 从受管连接 + 钥匙串解析凭据，拒绝非空跳板）、`provide_terminal_auth`。接口层回归见单元测试 `ssh_sessions::tests`（含内置 `russh::server` 端到端登录 + 双向字节流，`known_hosts::tests` 覆盖首连记录/复用不匹配/散列行跳过）。真实双端交互实测归入阶段 F。

### 阶段 D：经跳板网关会话

1. 跳板段传输适配器抽象：会话描述为「目标连接 + 可选跳板连接」；跳板段接口统一（open -> authenticated channel -> forward target），实现按 spike 结论选择标准 SSH 网关路径或公司 CLI 适配器。
2. 标准 SSH 网关路径：先连网关认证，再 `direct-tcpip` 转发到目标机 22，嵌套启动第二个 SSH 会话；网关与目标机可分别使用不同凭据。
3. 非标 fallback（spike 判定时）：适配器调用公司提供的 CLI / 定制客户端，把它的 stdio/pty 接到同一会话抽象；该路径不承诺自动喂密，凭据输入策略单独说明。
4. 验收：直连与经跳板的最小接口测试 + 网关不可达 / 认证失败 / 转发失败 / 断开清理的结构化错误。

### 阶段 E：前端「连接 / 终端」页面与会话管理

1. 新增顶层「连接 / 终端」入口：会话模式主路径可达；无 workspace 时不要求打开项目即可管理连接与打开远程会话，本地会话在无 workspace 时要求用户选择目录。
2. 页面构成：连接列表（名称 / 主机 / 用户 / 环境标签 / 最近连接时间）、新建/编辑连接（表单：host/port/user/auth/跳板引用/环境）、会话区（多标签页，每标签一个终端）、最近连接历史、关闭与重连。
3. 打开远程连接时若目标经跳板，展示连接链路（本机 → 跳板 → 目标）与断开/重连控件。
4. 会话上限 4–8：达到上限时禁用新建并提示；标签关闭释放 pty / SSH 进程组。
5. i18n：新增 `navigation` / `connections` / `terminal` 等命名空间，zh-CN / en 同步；错误码文案走 `displayAppError` 映射。
6. 组件：复用 shadcn/ui（表单、Tabs、Dialog、Tooltip、Badge、Select 等），xterm 终端容器组件化；不手写基础控件。
7. 验收：DOM / 交互测试覆盖入口、新建连接、环境标签展示、会话标签开/关/上限、最近连接；前端生产构建 + 双端页面实操（deep link 直达）。

## 7. 结构化错误码草案（后端只返回 code + params）

| code | 场景 |
| --- | --- |
| `connection.not-found` / `connection.invalid` / `connection.conflict` | 连接 CRUD 读写 |
| `connection.environment-prohibited` | 显式禁止的连接环境（预留，MVP 范围外不启用阻断） |
| `credentials.not-found` / `credentials.access-denied` | 凭据引用失效或钥匙串访问失败 |
| `terminal.ssh-auth-failed` | 认证失败（口令 / 密钥 / 键盘交互） |
| `terminal.host-key-mismatch` | 复用主机指纹不匹配 |
| `terminal.connect-timeout` / `terminal.connection-lost` / `terminal.gateway-unreachable` | 连接与中断 |
| `terminal.jump-forward-failed` | direct-tcpip / 适配器转发失败 |
| `terminal.otp-required` | 需用户输入动态口令（连接中事件，不落盘） |
| `terminal.spawn-failed` | 本地 shell 启动失败 |
| `terminal.session-limit` | 超过多会话上限 |

> 错误码只做最小草案，随阶段实现收敛；前端文案按 code 本地化，禁止后端拼对客文案。

## 8. 性能与数据规模边界

- 连接配置为用户级低频实体，规模预计数十以内；列表只返回摘要（稳定 ID + 名称 + host + 环境），详情按需读取；不进入会话 / run / 任务关键路径。
- 终端字节流：后端分块发送 + 有界队列 + 背压；慢消费者丢帧保护采用「丢弃渲染帧、保留最新状态」而非无界积压；xterm 输出按动画帧/时间窗合并，避免逐块重排。
- 会话上限 4–8 个，每个会话独立进程 / 连接；关标签即终止进程组并释放句柄，避免资源泄漏。
- 高流量日志（`tail -f`）按 64–256 KiB 窗口分块；不做全量缓冲；断开即停止读取。
- 凭据只存在于系统钥匙串与运行期内存，配置加载不读取、不透传密钥内容。

## 10. 方案自评审

### 过度设计评审

- 跳板段抽象为「传输适配器」并非为假设需求加层：WindTerm 二次开发网关存在真实非标风险，抽象与 spike 是风险对冲而非空泛扩展；若 spike 证明标准 SSH 可用，适配器只保留接口面，不实现第二套传输。
- 不引入生产阻断机制、团队共享、SFTP、log-tail 面板、agent 远程执行、会话恢复等假设性能力；凭据只进系统钥匙串，不新增 GB 自管加密体系。
- 新增实体仅一个 `ServerConnection` + 凭据引用；状态机仅「连接 / 会话」的瞬态生命周期，不新增持久 lifecycle aggregate；复用既有原子写、文件锁、结构化错误与 i18n。

### 性能影响评审

- 见第 8 节：数据规模小、字节流有界背压、会话数有上限、凭据不走配置文件。正常操作均为 O(连接数) 与 O(分块数)，不引入全量扫描、N+1、无界缓存或队列。
- 风险集中在高流量日志流与 WebView 渲染，已定义分块 + 帧合并 + 会话上限与阶段 F 的性能验收；其余路径无需专项 benchmark。
