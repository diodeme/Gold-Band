# 阶段 F 真机验收操作手册（受管连接与终端 + 连接→对话）

> 适用版本：feature/terminal-bastion 分支（2026-09-15）。全量自动化回归已绿。本手册只覆盖**必须真机实操**的部分。
> 前置：Windows EXE 与 macOS 分别执行一遍；渠道说明——**default（外网）渠道远程连接功能整体隐藏/被守卫**，远程相关用例须在 **wb（内网）渠道**构建上执行（本地终端两渠道都可用）。
>
> **已知点**：
> 1. **重启到新构建后需重新附连接**——连接绑定持久在 run.json 的 `connection_specs`；若一个旧构建实例（无该字段）在运行中重写了 run 状态，绑定会丢失。重启到新构建后如会话顶部没有连接 chip，重新「+ 附连接」即可。
> 2. **端点监听日志是注入前提**——应用启动日志里必须出现 `connection MCP endpoint listening on 127.0.0.1`；没有这行 = agent 不会拿到连接工具（`session/new` 的 `mcpServers` 为空）。排查 agent「卡在连接上/自己摸 SSH」时先看这行。**注意日志文件位置**：wb 渠道 dev 实例的数据目录是 `~/.maling/`（环境变量 `GOLD_BAND_CONFIG_DIR_NAME=.maling`），日志在 `~/.maling/logs/runtime.log`，不是 `~/.gold-band/`。该日志行在 `init_tracing` 之后打（2026-09-15 修复：之前在 tracing 初始化前打、被静默丢弃）。
> 3. **端点 400 自检**（2026-09-17 修复后可用）：`curl -s -X POST "http://127.0.0.1:<port>/mcp?projectId=<项目id>&taskId=<task>&runId=<run>" -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"1"}}}'`——应返回 JSON-RPC result 而非 400。端口取自端点监听日志行；`projectId` 即会话所属工作区的 project id（2026-09-17 修复前：工厂持有全局 App、URL 无工作区标识，对所有对话工作区的请求一律 400，agent 工具从未注册）。
> 4. **注入配置必须带 `headers: []`**（2026-09-17 根因）：ACP SDK 的 `session/new` 校验会静默丢弃缺 `headers` 的 http MCP 条目——后端 `connection_mcp_server_config` 已显式携带；若未来调整注入配置字段，必须保留 `headers`。
> 5. **agent 收到的隐藏上下文含工具使用契约**——告诉它只能用 `open_connection` 等工具、禁止自行 `ssh`/`expect`；若 agent 仍用 Bash SSH 并卡在口令提示，属于 agent 违约行为，如实记录。

## 0. 启动与入口

1. 启动 EXE，进入主窗口（会话模式）。
2. 左侧边栏 →「连接」（进入连接/终端页）；或顶部「打开终端」按钮 → 右侧工作区「终端」面板。
3. 深链（可粘贴到地址栏直达）：`/chat/connections` 为连接页；会话运行页 `/chat/projects/{项目}/tasks/{任务}/runs/{运行}`。

## 1. 连接 CRUD + 凭据

1. 连接页 →「新建连接」：填名称/主机/端口/账号，认证方式选「口令」，输入口令并勾选「保存到系统钥匙串」，环境选「测试」→ 保存。
2. 列表确认：新连接出现，凭据列显示「已保存」。
3. 编辑：改名、改主机 → 保存 → 列表即时反映（以保存后返回的最新实体为准）。
4. 新建第二个连接「经跳板」：跳板下拉选择第一个连接 → 保存 → 列表显示「经跳板」标记。
5. 删除第一个连接（被引用为跳板）→ 应被拒绝（结构化错误：连接正被引用）；先解除第二个连接的跳板引用后再删 → 成功，且系统钥匙串中对应凭据一并清除（钥匙串应用中确认 `gold-band-ssh` 服务下该条目消失）。
6. 断言：任何界面/弹窗均不出现明文口令。

## 2. 本地终端（两渠道都验）

1. 右侧工作区「终端」面板 →「新建本地终端」→ 默认落在当前 workspace 根目录（cwd 栏可见路径）。
2. 交互：`echo hello`、退格、Tab 补全、中文输入与宽字符、粘贴（含多行）。
3. 拉伸窗口/分栏 → 终端自适应（fit），`resize` 后远端行宽正确（`st size` 或 `tput cols`）。
4. `top` / `tail -f` 大输出滚动流畅，无卡死。
5. 关闭标签 → 进程组终止（`ps` 确认 shell 退出）。
6. 会话上限：开到第 9 个会话（上限 8）→「新建」禁用并提示上限。

## 3. 远程直连 SSH

1. 终端面板「直连远程终端」下拉 → 选择连接 → 打开。
2. 观察 tab 状态流转：连接中 → 已连接；输出正常（`hostname` 确认到达目标机）。
3. **OTP/键盘交互**（用需动态口令的账号）：口令留空保存的连接，打开时终端内出现「等待验证」提示行 + 输入框 → 输入 OTP → 认证通过进入 shell。断言：OTP 不落盘（重启后仍需输入）。
4. **OTP 超时**：弹出输入后等待 2 分钟不输入 → 会话以结构化失败收尾（`terminal.auth-required`，面板错误条显示「等待输入动态口令超时」）。
5. 认证失败：错误口令 → `terminal.ssh-auth-failed` 文案；主机指纹变化 → `terminal.host-key-mismatch` 安全拒绝文案。

## 4. 经跳板网关（阶段 D）

1. 目标连接的跳板选真实内网网关连接 → 打开。
2. 断言链路：本机 → 网关（网关认证，含 OTP 时先弹网关口令）→ 目标机 shell（`hostname` 确认是目标机而非网关）。
3. 网关不可达/目标端口被网关过滤 → 错误条显示 `terminal.jump-forward-failed`（转发失败）文案，而不是挂起。
4. **WindTerm 网关注意**：若内部网关为非标协议导致连接失败，如实记录 banner/现象——按既定对冲方案转公司 CLI 适配器路线（不是本版 bug）。

## 5. 附连接给 Agent（连接→对话 全链路）

> **前置条件（看不到入口时按序排查）**：
> 1. **必须先创建连接**——「+ 附连接」菜单列出的是已有连接；一个连接都没有时整行不渲染（这是设计行为：空能力面不显示空菜单）。先完成第 1 节建好连接再验本节。
> 2. **必须在 Tauri 桌面窗口里看**——`npm run dev:wb` 会启动桌面窗口；如果是在浏览器里开 `http://127.0.0.1:1420`，那是浏览器预览（mock 环境），其 appInfo 曾硬编码 `remoteConnectionsEnabled: false`（2026-09-09 晚已改为 true 并标注 channel wb，但预览下会话运行页有独立的加载门限制，仍以桌面窗口为准）。
> 3. **渠道必须是 wb/内网**——default 渠道远程能力整体关闭。确认方法：连接页侧栏入口存在 = wb 生效；若怀疑编译缓存，`rm -rf src-tauri/target` 后重跑 `npm run dev:wb`。
> 4. **Direct 会话也应有入口**——2026-09-09 晚修复：连接参考行从 run header 提升为页面级渲染，Direct 选中会话（header 被标题替代）时入口同样出现。若你的运行实例早于该修复，重启 `npm run dev:wb`。

0. **（推荐）发消息前预附**：首页 greeting 的 composer 工具栏有「附连接」按钮（内网渠道、已有连接时出现）→ 选中连接（选中态显示连接名，再点取消）→ 发第一条消息 → 创建 run 时自动绑定，agent 的第一个会话就带有连接工具与隐藏上下文。
1. 打开一个会话（Direct 或工作流均可），会话顶部出现「连接参考」行（未绑定时只有「+ 附连接」虚线按钮）。
2. 「+ 附连接」→ 下拉列出该渠道可用连接（已绑定的不出现）→ 点选 → chip 出现（名称 + host:port）。
3. 对话中发一句：「连接 wb 测试机，查看 /var/log 下最新日志并总结」。确认 agent：
   - **调用 `open_connection` 等 MCP 工具，而不是用 Bash 自己跑 `ssh`/`expect`**（2026-09-15 修复前的事故模式：工具未注入时 agent 即兴 SSH，卡在动态口令提示上）；
   - 打开的会话**自动出现在右侧「终端」面板**（用户可随时查看/接管输入）；
   - 若需 OTP：**终端面板会自动弹出**（authPrompt 干预事件触发 `TerminalAuthAutoOpen`，右侧工作区自动展开并高亮），等待验证的 tab 直接显示口令输入框（派生自会话状态，不依赖事件时机）——输入后 agent 的会话继续。
   - **命令执行语义**：`send_input` 自动补回车，agent 发的命令直接执行（2026-09-21 修复：此前缺行尾导致命令在堡垒机里永远不执行，agent 盲等空输出）。
   - **每帧带状态**：`read_output` 每帧附 `status`（connecting/awaiting-auth/connected）——agent 可区分「等口令」与「网络慢」；会话死亡时错误带结构化原因（如 auth-required → agent 自动重试 open_connection）。
   - **会话保活**：远程会话存活期间双层自动保活（传输层 30s keepalive + pty 层 60s 注入 space+backspace 计入堡垒机活动计时）——堡垒机不因空闲自动登出，无需反复输 OTP。**真机验证项**：长时间静置（>10 分钟）后 agent 继续操作，确认会话仍存活；若齐治不将 space+backspace 计为活动，如实记录并调整注入字节。
   - **齐治堡垒机特性**：登录后可能自动连默认目标机（正常）或呈现文本菜单——agent 会读菜单并发送选项数字。验证时观察 agent 是否自主完成「读菜单 → 选目标 → 执行命令」；用户只需输 OTP。
4. 点击 chip → Popover 显示完整非密钥 spec（主机/端口/账号/认证方式/环境/跳板）→「移除」→ chip 消失；下一轮对话 agent 不再能打开该连接（`open_connection` 被拒）。
5. 移除后「+ 附连接」菜单重新出现该连接（双向自动）。
6. 断言：agent 的回复/工具参数中不出现任何密钥或密钥路径。
7. **中途绑定生效**：先发一轮对话（不开连接）→ 再「+ 附连接」→ 继续让 agent 连接 → agent 应能调用 `open_connection`（工具集在会话创建时注入且无条件注入，中途绑定经 URL 作用域即时生效）。**注意：修复（2026-09-15 深夜）前创建的旧会话工具集已固化，需新开会话验证。**

## 6. Pop-out 独立窗口

1. 终端 tab 上「在新窗口打开」→ 会话迁移为独立 OS 窗口；主窗口 tab 暂时隐藏。
2. 独立窗口内输入/输出正常；关闭独立窗口 → 会话回到主窗口面板（历史不丢）。
3. 主窗口在会话迁出期间收到新输出 → 重新打开后历史补齐（后端历史缓冲）。

## 7. 渠道门控（default 外网渠道构建）

1. 「连接」侧栏入口隐藏 / 连接页显示禁用说明；终端面板无「直连远程终端」下拉。
2. 「+ 附连接」入口不出现（连接参考行为空时不渲染）。
3. 本地终端功能完整可用。

## 8. 明暗主题 + 窄窗

1. 设置切换深色/浅色，重复 1–5 的关键界面（连接表单、列表、终端面板、连接参考卡、OTP 输入行）检查静态/hover/选中/禁用态。
2. 窄窗口：连接参考 chip 行可换行；终端面板列宽不横向溢出；长主机名截断有 Tooltip。

## 记录要求

每项结果记 通过/失败 + 截图；失败附错误码（面板错误条显示的是**错误码文案**，原始 code 在日志 `gold-band.log`）。外部依赖（真实网关账号、OTP 策略）不可得时如实标注「待补」，不冒充通过。
