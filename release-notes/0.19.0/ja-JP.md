## 機能の追加・変更

### 1.Direct セッションがバックグラウンドのメッセージ受信と常駐に対応

Agent が 1 回の返信を終えた後も作業を続ける場合（スケジュールタスクの実行やバックグラウンドでの子 Agent の実行など）、Direct セッションはその返信、ツール呼び出し、権限の確認、質問を引き続き受信するようになりました。返信の終了後に失われることはありません。（現在は主に Claude Code に対応）

![image.png](https://static.dion.blue/2026/10/20261010151334594.png)

1.バックグラウンドで新しい返信本文が届くと 1 回だけ通知されます。同じ返信の続きでは再度通知されません。
2.バックグラウンドで活動があるときは入力欄に停止ボタンが表示され、バックグラウンドの作業を停止できます。新しいメッセージの送信には影響しません。

Direct セッションを右クリックして「セッションを常駐させる」を選ぶと、タイトルの横にピンが表示されます。もう一度右クリックして「常駐を解除」を選ぶと元に戻せます。セッション上部の「生のフレーム」の左にあるピンボタンからも常駐の設定・解除ができます。
![企业微信截图_17916164711387.png](https://static.dion.blue/2026/10/%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E6%88%AA%E5%9B%BE_17916164711387.png)

![image.png](https://static.dion.blue/2026/10/20261012140125448.png)

Direct、ワークフロー、AUTO のセッションは同じ回収ルールを使います。10 分を超えてアイドル状態のセッションは回収され、アイドル状態のセッションが 8 個を超えると、最も長く活動していないものから回収されます。常駐中、実行中、または権限や質問への対応を待っているセッションは回収されません。Agent にスケジュールタスクなど長時間の作業がある場合は、常駐させてください。

> [!WARNING]
> 1.常駐はアプリの実行中のみ有効で、アプリを再起動しても常駐セッションは自動的に起動しません。常駐していないセッションが回収されると、その中のスケジュールタスクが中断される場合があります。バックグラウンド作業の停止は Agent にキャンセル要求を送るだけで、スケジュールタスクを削除するかどうかは Agent が判断します。
> 2.ACP には現在、バックグラウンドタスクの完了を示す情報がないため、「実行中のバックグラウンド活動がなく、10 秒間新しい活動がない」ことをもって完了と判断しています。そのため、バックグラウンドタスクが終了した後も、セッションが最大 10 秒間アクティブな状態のままになることがあります。


### 2.Markdown で Mermaid 図と GitHub のアラートに対応

会話とファイルプレビュー内の ` ```mermaid ` コードブロックが図として描画され、色は現在のテーマに合わせて表示されます。図をクリックすると右側のワークスペースで開き、拡大縮小や移動、PNG としてのコピー・保存ができます。

![image.png](https://static.dion.blue/2026/10/20261010151001399.png)


会話とファイルプレビューでは、GitHub の 5 種類のアラート `[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` も表示できます。

![企业微信截图_17916161364315.png](https://static.dion.blue/2026/10/%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E6%88%AA%E5%9B%BE_17916161364315.png)


### 3.Web 画像は信頼済みのドメインからのみ読み込み

ドキュメントや Agent の返信によってクライアントが任意のサーバーへリクエストを送ることを防ぐため、Markdown 内の Web 画像は信頼済みドメインのものだけが自動で読み込まれるようになりました。

1.会話では、信頼されていない画像はプレースホルダーとして表示され、「読み込む」をクリックするとそのドメインを信頼して画像を表示します。
![企业微信截图_17916165045640.png](https://static.dion.blue/2026/10/%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E6%88%AA%E5%9B%BE_17916165045640.png)
![企业微信截图_17916165149409.png](https://static.dion.blue/2026/10/%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E6%88%AA%E5%9B%BE_17916165149409.png)

2.ファイルプレビューでは、信頼されていない画像はリンクのまま表示され、上部の案内からドキュメント内のすべてのドメインをまとめて信頼できます。
![企业微信截图_17916165865322.png](https://static.dion.blue/2026/10/%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E6%88%AA%E5%9B%BE_17916165865322.png)

3.「設定 → 詳細設定 → 信頼済みの画像ドメイン」で、信頼済みのドメインを確認・削除できます。

![image.png](https://static.dion.blue/2026/10/20261010151155662.png)

### 4.コンテキスト圧縮の要約を表示

Agent がコンテキストの圧縮を完了してテキストの要約を返した場合、圧縮の記録に「要約を表示」が表示されます（Agent が要約を返した場合のみ）。クリックすると右側のワークスペースで要約が開きます。既定では Markdown として表示され、ソース表示への切り替えやコピーもできます。
![企业微信截图_17916167016992.png](https://static.dion.blue/2026/10/%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E6%88%AA%E5%9B%BE_17916167016992.png)


### 5.モデルごとに設定を取得

ワークフローのノード、AUTO 設定、ホームの入力欄、またはセッションで、まだ使用していないモデルを選ぶと「このモデルの設定は未取得です」と「モデル設定を取得」ボタンが表示されます。クリックすると、そのモデルで Agent を 1 回起動して実際に選択できる設定を読み取ります。メッセージは送信されず、タスクも作成されません。

![企业微信截图_17916167706477.png](https://static.dion.blue/2026/10/%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E6%88%AA%E5%9B%BE_17916167706477.png)


クリックしなくても、編集、保存、タスクの開始は続けられます。サポートされていない設定は、セッション開始時に「指定なし」として扱われます。

### 6.ワークフロー図のレイアウトを刷新

ワークフローエディターと実行図に新しい自動レイアウトを採用し、ノードと接続線の配置がより見やすくなりました。AI-DYNAMIC が動的に作成したグループは入れ子の枠で表示され、レイアウトに時間がかかる場合は読み込み中の状態が表示されます。


## エクスペリエンスの改善

### 1.AUTO の成果は検収を経て完了

AUTO の開発が完了すると、検収ノードが元の要件と照らし合わせてまとめて確認します。検収が通らない場合は修正を割り当てて再度検収し、通過した場合にのみ終了します。検収は元の要件だけを根拠とし、計画で要件の内容を除外している場合はブロッカーとして扱われます。変更された既存のテストは元のバージョンで再検証する必要があります。

Agent が提出する長い要約やタスクの説明はファイル経由で受け渡すようになり、出力形式のエラーによる再試行が減りました。AUTO が一時停止したときは、通知バーに具体的なエラーのタイトルが表示されます。

### 2.Claude と Codex の連携をアップグレード

Claude ACP を `0.87.0`、Codex ACP を `2.1.1` にアップグレードしました。

1.セッションにコンテキスト圧縮の状態、所要時間、圧縮前の使用量が表示されます。
2.Codex が実行したコマンドの出力はツールの詳細に継続して蓄積され、最大 256,000 文字まで保持されます。
3.Claude の質問に対するカスタム回答を正しく送信できます。
4.Agent の再ログインが必要な場合は明確に案内されます。ログイン後に手動で再送信してください。

### 3.セッションの安定性を向上

1.セッションに再度入ったときに、読み込み中の状態が繰り返し表示されたり、古い内容が先に表示されたりしなくなりました。
2.ディスクの空き容量不足や書き込み権限がないといった実行エラーはすぐに表示され、入力欄が待機状態のままになることはなくなりました。結果が返されなかったツールには「結果未確認」と表示され、既存の返信と下書きは保持されます。
3.返信を停止した後、セッションは常に現在のターンを正しく終了し、「停止中」のままになることはなくなりました。

### 4.ファイル変更の記録をより正確に

1.Claude などの Agent が同じファイルを断片的に複数回編集したときに、ターン全体の変更が不完全と表示される問題を修正しました。
2.Cursor が新規作成したファイルが変更として記録され、内容に Diff の記号が混入する問題を修正しました。
3.ファイル変更の行には、ファイル名、ディレクトリ、追加・削除行数が統一して表示され、複数回編集されたファイルには編集回数も表示されます。

### 5.リソース使用量の削減

1.アイドル状態のセッションは上記のルールで速やかに回収され、Agent のプロセスを長期間占有しなくなりました。
2.内蔵ブラウザーは 1 時間を超えて非表示の状態が続くとページを解放し、再表示時に元のアドレスから再読み込みします。
3.インストール済みの npx Agent は直接起動するようになり、常駐していた npx のラッパープロセスが不要になりました。
4.セッションが返信を出力している間、サイドバー全体が再描画されなくなりました。

### 6.その他の改善

1.会話とドキュメント内の Markdown の表は本文の幅いっぱいに表示され、自動で折り返されます。長いリンクやコードで表が広がることはなくなりました。
2.画像プレビューを統一しました。ファイルの画像とセッションの画像のどちらもマウスホイールで直接拡大縮小でき、初回表示時はウィンドウに合わせて表示されます。元のサイズを表示する「100%」ボタンもあります。
3.内蔵ブラウザーでローカルの HTML を開いたときに、親ディレクトリのリソースを正しく読み込めるようになりました。許可範囲外のディレクトリにアクセスする場合は、通知から「アクセスを許可」を選べます。
4.会話内の見出しの階層がより明確になり、ストリーミング出力中も見出しの間隔が保たれます。「リリースノート」はヘルプメニューの末尾に移動しました。
5.異なるチャネルのクライアントを同時にインストールしている場合に、一方をインストールまたは更新すると実行中のもう一方が終了してしまう問題を修正しました。
6.ACP Registry と Agent カタログを更新しました。
