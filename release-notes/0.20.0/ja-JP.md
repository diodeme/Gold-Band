## 機能の追加・変更

### 1.Feishu / Lark でのリモート介入に対応

WeCom に加えて、タスクを止めている権限リクエスト、追加質問、手動チェックを Feishu / Lark で処理できるようになりました。Run やターン終了の通知も受け取れます。

1. 「設定 → 一般 → IM リモート介入と通知」を開き、「Feishu / Lark」を展開して「スキャンして接続する」をクリックします。
2. 必要な権限を確認して「同意して QR コードを生成」をクリックし、スマートフォンの Feishu / Lark でスキャンします。既存の Feishu / Lark アプリを選ぶことも、新しく作成することもできます。
3. 承認が完了したら、Feishu / Lark でボットにメッセージを 1 件送り、1 対 1 のプライベートチャットをバインドします。
4. タスクで対応が必要になると、Feishu / Lark に操作可能なカードが届きます。カードには ID、ノード、タスク、ワークスペースが表示され、権限の許可・拒否、追加質問への回答（単一選択、複数選択、カスタム回答、テキスト）、手動チェックの成功・失敗の判定ができます。

送信後、カードには回答が残り、コントロールは無効になります。デスクトップや WeCom で処理済みのリクエストには、処理元が表示されます。停止やタイムアウトなどで終了したリクエストは「キャンセル済み」と表示され、拒否としては表示されません。送信の処理が遅れ、最終的に受け付けられなかった場合は、ボットが理由を別のメッセージで知らせます。

「設定メニュー」から、受信アカウントの再バインド、Feishu / Lark アプリの切り替え、再承認、設定の削除ができます。

> [!NOTE]
> 1 つのボットが接続できるデバイスは 1 台のみです。現在は 1 対 1 のプライベートチャットのみに対応しており、Feishu / Lark カードの追加質問は最大 5 問です。それを超えるリクエストはデスクトップで処理してください。名前の読み取り権限は任意で、付与しない場合、受信アカウントは「1 対 1 のチャットにバインド済み」と表示されます。

> [!WARNING]
> アップグレード後、IM データは新しい形式に移行され、旧バージョンのクライアントでは読み込めなくなります。ダウングレードするには先にバックアップを復元する必要があります。アップグレード前に送信され、まだ処理されていない WeCom カードは無効になるため、デスクトップで処理してください。

### 2.送信待ちキューに「今すぐ送信」と「自動送信」を追加

Agent の返信中にキューへ追加したメッセージの送信タイミングを、より柔軟に制御できるようになりました。

1. 「今すぐ送信」：送信待ちの内容をすぐに送信します。返信が進行中の場合は、現在の返信を停止するか先に確認します。「今後表示しない」をオンにすると確認しなくなります。「設定 → 詳細設定 → 送信待ち」で再びオンにできます。
2. 「自動送信」スイッチ：オンにすると、各ターンの返信終了後に順番に自動送信します。オフにすると内容はキューに残り、1 件ずつ「今すぐ送信」で送ります。
3. セッションを停止した場合や前回の送信に失敗した場合、キューに一時停止中であることとその理由が表示されます。「再開」をクリックすると自動送信を再開します。
4. 「その他の操作」から送信待ちキューをクリアできます。

### 3.下書きボックスを追加

入力欄のツールバーに「下書きボックス」を追加しました。「下書きボックスに保存」で入力中の内容を一時保存し、あとで「入力欄に戻す」で編集を続けられます。下書きは現在のセッションにのみ保存され、自動送信されることはありません。1 セッションあたり最大 20 件まで保持します。

### 4.Claude のネイティブ子 Agent に対応

Claude ACP `0.90.0` 以降を使用している場合、Gold Band は Claude が報告する子 Agent の状態を読み取り、実行中、操作待ち、完了、中断、失敗を正確に表示します。メインターンが終了しただけで子 Agent が中断と表示されることはなくなりました。

1. 子 Agent が実行中のときは、入力欄の上に実行中の子 Agent の概要が表示されます。クリックすると、右側のワークスペースで完全な記録を確認できます。
2. メインターンの終了後も、子 Agent がバックグラウンドで実行中または権限待ちである限り、入力欄に「停止」ボタンが残ります。
3. セッションでバックグラウンド作業が発生すると、Token 使用量のツールチップに「バックグラウンド起動による使用量は含まれません」と表示されます。

> [!IMPORTANT]
> Claude ACP を `0.90.0` にアップグレードしました。バージョンが古すぎる場合はアップグレードを促すメッセージが表示されます。Gold Band がインストール設定を自動で変更することはありません。

### 5.プッシュ前にターゲットを確認

ソース管理でブランチをプッシュすると、まずソースブランチ、ターゲットのリモートリポジトリ、ターゲットブランチが表示され、確認後にプッシュされます。初めて公開するブランチではリモートリポジトリを選択でき、公開に成功したらターゲットブランチを upstream に設定できます。upstream のないブランチには `new` と表示されます。

### 6.Ctrl+K でセッション検索を開く

`Ctrl+K`（macOS では `Command+K`）でセッション検索を開きます。開いている状態でもう一度押すとキーワードが選択され、`Esc` で閉じます。`Ctrl+F` はエディターのファイル内検索用に残しています。


## 使い勝手の改善

### 1.IM 設定ページとカードの改善

1. 「IM リモート介入と通知」を WeCom と Feishu / Lark の 2 枚の折りたたみ可能なカードに変更し、通知の種類を「対応が必要」と「実行結果」の 2 グループに分けました。
2. WeCom と Feishu / Lark のカードはデスクトップの言語に従い、7 つのインターフェース言語すべてに対応します。
3. 処理済みの WeCom カードには、すべての質問とカスタム回答が表示されます。WeCom の複数問の単一選択カードは最大 3 問です。それを超えるリクエストはデスクトップで処理してください。

### 2.セッションの安定性を向上

1. Agent の起動段階で失敗した場合、自動リトライが正しく再実行されるようになりました。メッセージが Agent に届いた後に失敗したターンは、重複実行を避けるため手動復旧になります。起動中は入力欄に「Agent を準備中」と表示されます。
2. セッションを作成できなかった場合、読み込みが続くのではなく、失敗の理由がすぐに表示されます。
3. クライアントが異常終了した後に残った質問や権限リクエストは無効になり、回答すると明確なメッセージが表示されます。送信成功とは表示されなくなりました。
4. セッションを続行するときは、そのセッションの元のモデルと権限モードを引き継ぎます。
5. 回収された Direct セッションで会話を続けると Token 使用量が二重に計上される問題を修正しました。

### 3.スクロールをより自然に

1. 入力欄が高くなっても、メッセージリストは最下部に固定されたままです。
2. 履歴を読んでいる間、新しい内容によって最下部に戻されることはありません。最上部でさらに上へスクロールすると、内容が 1 画面に満たない場合でも、より古い履歴を読み込めます。
3. 長い下書きを入力しているときに、入力欄のスクロール位置が飛ばなくなりました。

### 4.その他の改善

1. 入力欄の `/` と `@` メニューは、開くたびにスキルとロールを読み込み直すため、追加したスキルを再起動せずに使えます。
2. 会話内で同じ名前の添付ファイルが過去の添付ファイルを上書きしなくなりました。セッションのデータディレクトリの階層が深すぎて添付ファイルを保存できない場合は、明確なメッセージが表示されます。
3. 会話内のローカル画像はセッションのワークスペースを基準に解決されます。内蔵ブラウザーでローカル HTML のリンクを開くと、クエリパラメーターとアンカーが保持されます。
4. Markdown のライブプレビューがパネルの幅いっぱいに表示されるようになりました。エディターの既定のフォントサイズを 13px に変更しました。
5. 右側のワークスペースでタブにエラーが発生した場合、そのタブにのみ「このタブを表示できません」と表示され、ほかのタブには影響しません。
6. `npx` や `uvx` で起動する MCP サーバーは、初回チェック時に依存関係のダウンロード完了を最大 180 秒待つようになり、ダウンロード中に失敗と判定されなくなりました。
7. システム言語が中国語の場合、地域ではなく簡体字・繁体字の文字タグによってインターフェース言語を選択するようになりました。
8. ダイアログやメニューをクリックした後にツールチップが勝手に表示される問題を修正しました。
9. ACP Registry と Agent カタログを更新しました。
