## 需求身份前置检查

本节优先于拓扑枚举、访谈 Round 0 或拷问分支枚举执行。本节开始时先调用 `memory_read`，再执行身份判断。

1. 使用 `memory_read` 读取当前任务与工作空间记忆。只检查返回快照中的 `task` 条目，不把工作空间 `storyId` 或 `storyName` 当作当前任务已有身份。
2. 仅当 `task` 中同时存在非空、非纯空白的 `storyId` 和 `storyName` 时，视为需求身份完整并继续原角色流程。
3. 任一 key 缺失、为空或不成对时，必须先提一个问题确认需求身份，选项语义固定为：
   - `不存在`
   - `其他（用户自行输入）`
4. 有 `AskUserQuestion` 或同等 elicitation 工具时使用结构化提问；没有时使用纯文本，但不得省略上述两个选项语义。该问题不计入拓扑、歧义评分、Round 数或拷问分支数，用户回答后继续原流程。
5. 用户选择 `不存在` 时：
   - `storyId` 固定为字符串 `0`。
   - `storyName` 从需求内容提取简短名称：优先使用明确标题或首行摘要，其次使用需求目标中的核心名词短语，仍无法提取时使用 `系统需求`。
   - 去除模板标签、状态说明、Markdown 标记和无关标点，保存为单行字符串，最多 40 个 Unicode 字符。
6. 用户选择 `其他（用户自行输入）` 时，必须同时取得需求 ID 和需求名称。自由文本无法明确拆成两个值时继续追问一次；仍不明确就等待用户澄清，不猜测。两个值分别去除首尾空白，并保存为单行字符串。
7. 使用 `memory_write` 将两个条目写入任务作用域。写前使用最近一次 `memory_read` 的目标 key revision：key 不存在时使用 `operation="create"` 并省略 `expectedRevision`；已有但需纠正时使用 `operation="update"` 并传入对应 revision。不得写入工作空间作用域。
8. 两次写入后重新调用 `memory_read`，确认任务作用域中的 `storyId` 和 `storyName` 与用户确认值完全一致。
9. `gold-band-memory` 工具不可用或读取失败时，说明需求身份未读取，并按第 3 条正常提问；任一写入失败或写后核验失败时，说明需求身份未持久化。二者都不是阻塞，不阻断当前角色流程。使用用户已确认或补充提供的 `storyId`、`storyName` 继续当前执行；后续节点仍可能重新询问。
10. 不得直接编辑记忆文件。需求身份取得后，采访角色继续原有访谈初始化，拷问角色继续原有决策树枚举；工具写入成功时继续保持任务作用域副本。
