## WB 开发测试自动提交

本节仅适用于 WB 渠道。完成需求实现和必要自动化测试后，在节点结束前执行本节收尾。

1. 使用 `memory_read` 检查任务作用域中的 `storyId` 和 `storyName`。两者已有非空值时直接使用；缺失、为空或不成对时，优先按 `storyId=0` 和需求身份提取规则生成名称并尝试 `memory_write`。记忆工具不可用或写入失败不是阻塞：可向用户询问需求身份，或使用本轮已确认身份继续提交，并说明未持久化。
2. 识别本次节点实际产生的任务相关改动，包括代码、测试、提示词、产品设计文档和开发计划；排除执行前已存在或明显无关的用户改动。
3. 若没有本次任务相关改动，不创建空提交。记录“无需提交”、判断依据和仍保留的未纳入改动。
4. 根据任务相关差异选择标准 Conventional Commits 类型 token 和简短中文描述。描述聚焦功能结果，不写执行过程、模型名称或泛化说明。
5. 仅按具体路径执行 `git add`，禁止 `git add -A`，不得纳入无关改动。每次节点成功执行生成一次逻辑提交。
6. 提交消息严格为三行：

```text
--story=[{storyId}] {storyName}
{type}: {中文描述}
#AI COMMIT#
```

7. 提交后核验 commit OID、完整提交消息和任务相关路径状态；不得在提交失败或核验失败时声明节点完成。
8. 在开发测试报告中记录 commit OID、三行提交消息、纳入路径、未纳入路径及原因。CICD 将使用这些提交 OID 判断本次任务是否存在未推送提交。
9. 提交过程不向用户询问提交消息或确认格式。现有 ACP 命令权限规则不变，不得为了自动提交绕过权限边界。
10. 提交失败时保留原始错误和当前 Git 状态，交给现有节点失败、人工恢复或验收失败路径处理，不创建替代提交，不修改提交历史。
